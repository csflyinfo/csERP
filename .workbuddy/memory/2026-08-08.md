## 飞单模块开发方案更新

- **用户确认的3项决策**：
  1. 采购价和销售价自动带出（非手动录入）
  2. 明细独立税率，自动带出
  3. 独立权限（不复用销售模块权限）

- **统计影响分析**（用户问"飞单不写出入库单据是否影响数据统计"）：
  - 结论：**不影响**。全部12个统计/报表接口逐一核查
  - 销售统计查 `sales_order`（飞单审核生成）→ 包含 ✅
  - 采购统计查 `pur_order`（飞单审核生成）→ 包含 ✅
  - 库存统计查 `inv_stock_balance`（飞单不写）→ 正确不包含 ✅
  - 应收/应付统计查 `fin_ar`/`fin_ap`（飞单审核生成）→ 包含 ✅
  - 出入库单据（sales_outbound/purchase_inbound）不参与任何统计报表
  - 利润统计当前硬编码 `amount * 0.12`，不使用真实成本（全局已有问题，非飞单引入）

- **价格自动带出数据源确认**：
  - 采购价：`pur_order_detail` 查供应商最近采购价 → 兜底 `base_goods.latest_purchase_price` → 已有API `/base/goods/latest-purchase-price`
  - 销售价：客户价格组 `base_price_group_item.price` → 兜底客户最近售价 → 兜底 `base_goods.suggested_retail_price` → 已有API `/base/goods/latest-sales-price`
  - 税率：`base_goods.tax_rate`，每行独立

## 修复飞单保存后列表不显示问题

- **根因**：`FlyOrderController.page()` 先用 SQL 过滤（正确），但接着 `PageResult.of(mapped, request)` 又做了一次文本过滤 — 要求每条记录的文本中必须包含所有 filter 值。`dateFrom: "2026-07-08"` 不在今天创建的单据文本中，导致被过滤掉
- **对比**：salesOrder/page 不走 SQL 过滤，只依赖 `PageResult.of` 的文本过滤，因此没有此问题
- **修复**：`FlyOrderController.page()` 中，SQL 过滤完成后，创建只含分页信息的 `PageRequest` 传给 `PageResult.of()`，避免二次过滤
- **文件**：`backend/src/main/java/com/erp/sales/FlyOrderController.java` — 第199行改为 `new PageRequest(..., Map.of())`

## 修复 FlyOrderDrawer 表格列宽问题

- **根因**：`.fly-table` 缺少 `table-layout: fixed`，`<th>` 的 `width` 只是建议值；输入框无 `width: 100%` 反而撑大单元格
- **修复**：`.fly-table` 加 `table-layout: fixed`；`.fly-table td .fly-input` 加 `width: 100%; box-sizing: border-box;`
- **文件**：`frontend/src/components/FlyOrderDrawer.vue`（CSS 部分）

## 修复 PageRequest record 访问方式错误

- **现象**：`request.getFilters()` 编译失败，Java record 没有 getter 方法
- **根因**：PageRequest 是 Java record（`public record PageRequest(...)`），字段访问用 `request.filters()` 而非 `request.getFilters()`
- **修复**：`FlyOrderController.java` 第159行 `request.getFilters()` → `request.filters()`
- **编译验证**：mvn compile 通过
