## 销售退货单 Bug 修复验证

### Bug 1: 新建销售退货单没有生成退货单号，列表退货单号为空
- **根因**: 前端 `module-api.js` 中列标题"退货单号"的字段映射只有 `['returnNo']`，但 API 返回的字段名是 `applyNo`（底层表为 sales_return_apply）
- **修复**: 将映射改为 `['returnNo', 'applyNo']`，兼容采购退货(returnNo)和销售退货(applyNo)
- **文件**: `frontend/src/module-api.js` 约第 349 行

### Bug 2: 审核销售退货单报错
- **根因**: `SalesReturnController.java` 的 `auditReturnOrder` 方法中 `queryForList` 参数顺序错误
  - 错误代码: `queryForList(sql, applyNo, String.class)` — `applyNo`(String) 不是 `Class<T>` 类型，编译器选错重载
  - 编译错误: `Type mismatch: cannot convert from List<Map<String,Object>> to List<String>`
- **修复**: 交换参数顺序为 `queryForList(sql, String.class, applyNo)`
- **文件**: `backend/src/main/java/com/erp/sales/SalesReturnController.java` 约第 503 行
- **额外修复**: 在 `returnOrderPage` 行映射中添加 `creatorInfo` 派生字段

### Maven 在 Git Bash 下的路径问题
- **问题**: Git Bash (MINGW64) 下 `mvn` 命令报 `ClassNotFoundException: org.codehaus.plexus.classworlds.launcher.Launcher`
- **根因**: mvn shell 脚本计算的 `CLASSWORLDS_JAR` 路径为 Unix 格式 (`/c/Soft/...`)，Java (Windows exe) 无法识别
- **解决**: 直接用 Java 命令运行 Maven Launcher，所有路径使用 Windows 格式 (`C:/Soft/...`)
```bash
"C:/Users/Administrator/jdk21/bin/java.exe" \
  -classpath "C:/Soft/apache-maven-3.9.16/boot/plexus-classworlds-2.11.0.jar" \
  "-Dclassworlds.conf=C:/Soft/apache-maven-3.9.16/bin/m2.conf" \
  "-Dmaven.home=C:/Soft/apache-maven-3.9.16" \
  "-Dlibrary.jansi.path=C:/Soft/apache-maven-3.9.16/lib/jansi-native" \
  "-Dmaven.multiModuleProjectDirectory=E:/我的工作项目/erp-wms-tms/backend" \
  org.codehaus.plexus.classworlds.launcher.Launcher spring-boot:run \
  -Dmaven.resources.skip=true -Dmaven.test.skip=true
```
