# 优化记录：商品档案全部下拉支持关键字搜索 + 修复商品分类下拉显示不全

- 日期：2026-09-14
- 分支：feat/base-goods-searchable-selects
- 模块：base（商品档案）
- 涉及文件：
  - `frontend/src/components/SearchSelect.vue`（新增，通用可搜索下拉）
  - `frontend/src/composables/useAnchoredPanel.js`（新增，Teleport 浮层定位组合式函数）
  - `frontend/src/views/goods/components/CategoryTreeSelect.vue`（改用公共定位逻辑、面板加宽、搜索支持拼音首字母）
  - `frontend/src/views/goods/components/BaseInfoForm.vue`（11 个原生 select 替换）
  - `frontend/src/views/goods/components/StockPurchaseForm.vue`（2 个替换）
  - `frontend/src/views/goods/components/MultiUnitMatrix.vue`（3 个表格内 select 替换）
  - `frontend/src/views/goods/components/BatchEditDrawer.vue`（批量弹窗动态 yesno/select 替换）

## 一、需求

1. **商品档案所有下拉选择字段组件都要支持输入关键字搜索定位选项值**——新增/编辑抽屉与批量编辑弹窗中原生 `<select>` 选项多（品牌 200、单位 51、分类 480），只能滚动逐个找，效率低；
2. **商品分类下拉值显示不完全**——四列表单中控件仅约 112~123px 宽，末级分类名与「祖先路径」被省略号截断，存在同名末级时无法区分（如各级「饼干」下的多个末级）。

## 二、原实现问题

- 商品档案抽屉 16 个、批量编辑弹窗 13 个下拉全部是原生 `<select>`，不支持输入过滤；
- 分类树面板宽度等于控件宽度（约 112px），长名称与路径被 CSS ellipsis 截断；
- 分类树浮层的 Teleport + fixed 定位/滚动跟随逻辑是上一次优化写在 CategoryTreeSelect 内部的，
  新组件若复制一份会造成两套并行维护。

## 三、实现方案

### 1. 新增通用组件 SearchSelect.vue（手写，项目不引入 UI 库）

- **options 双形态**：既支持字符串数组（品牌/仓库等接口名列表），也支持
  `{ value, label, disabled? }` 对象数组（枚举/布尔）。**value 原样 emit**，
  布尔字段用 `{value:true,label:'是'}/{value:false,label:'否'}`，保存 payload 中
  `canReturn/isWeighted` 等仍为严格 boolean（已在 create 抓包断言），不会退化成字符串。
- **关键字过滤**：对 label 做不区分大小写包含匹配；中文 label 额外用 pinyin-pro
  取拼音首字母匹配（输 `fwsp` 命中「服务商品」、`clbg` 命中「粗粮饼干」），无需切输入法。
- **键盘操作**：↑↓ 移动高亮（不循环）、Enter 选中、Esc 关闭；点组件外部（document mousedown 判定）关闭；× 清除。
- **空态区分**：options 本身为空时显示维护提示（如「请先在【品牌管理】维护」），
  过滤无命中时显示「未找到匹配项」。
- **历史值保护**：当前值不在选项里（停用/删除的参照数据）时原值原样显示、橙色边框警示，不丢值、不阻止保存。
- **紧凑规格**：`size="small"` 为 28px 高/11px 字、居中显示，用于多单位矩阵 36px 高的表格单元格。
- 面板结构：顶部常驻搜索输入框，下方选项区内部滚动；已选项带 ✓ 高亮。

### 2. 抽出公共浮层定位 useAnchoredPanel.js

把 CategoryTreeSelect 内的浮层逻辑提炼为组合式函数，SearchSelect 与 CategoryTreeSelect 共用：

- `<Teleport to="body">` + `position: fixed`，z-index 1200（高于抽屉遮罩 500、批量弹窗 1000），
  解决 `.drawer-body { overflow-y:auto }` 裁剪 absolute 面板的老问题；
- 打开时按控件 `getBoundingClientRect()` 计算：宽度 = `max(控件宽, minWidth)` 且不超出视口（两侧各留 8px），
  下方空间 <200px 自动向上翻转，高度限制 340px、小屏保底 160px；
- 捕获阶段监听 scroll（含抽屉内滚动）/resize，rAF 节流重算，实测滚动后面板与控件偏差 0px；
- 卸载时自动解绑全部监听。

### 3. 商品分类「显示不完全」修复

- CategoryTreeSelect 改用 useAnchoredPanel，**minWidth 提到 260px**：
  控件仍随表单列宽（约 123px），展开面板固定 ≥260px 且按视口宽度夹紧，不再随窄控件被压窄；
- 搜索结果的末级名与祖先路径（如 `休闲零食 / 饼干点心 / 粗粮饼干`）在 260px 下完整显示，
  名称/路径节点均加 `title` 全文字悬停兜底；实测 10 条「饼干」结果名称、路径零截断；
- 搜索关键字在原有中文包含匹配基础上增加拼音首字母匹配（clbg→粗粮饼干）。

### 4. 各表单替换明细（共 16 + 13 处，0 个原生 select 残留）

- **BaseInfoForm（11）**：默认供应商、品牌、默认仓库、商品负责人（接口数组，
  无数据时占位文案提示去对应档案维护）；商品类型、商品等级、税率（0% 显示「免税」）、
  状态、可退货、是否称重、是否预售（枚举/布尔）。分类→税率联动、拼音助记码等既有逻辑不变。
- **StockPurchaseForm（2）**：存储属性；默认采购单位（选项随多单位矩阵启用行动态联动，
  保留「未设置（按大→中→小）」空值项，label 带单位类型如「箱（小单位）」）。
- **MultiUnitMatrix（3）**：小/中/大三列单位选择，small 规格、minWidth 220；
  列选项仍按 canMiddleUnit/canLargeUnit 过滤（实测 11/8），未启用单位行的控件保持禁用，
  「启用中单位前请先启用大单位」等联动不变。
- **BatchEditDrawer（13，4 个数字字段不涉及）**：字段勾选前控件全部禁用，勾选后解禁可搜索；
  布尔字段解禁后选「否」写入的仍是 boolean false；品牌等仍走全量翻页加载。
