## 一、这个模块管什么

每个客户在系统里有一个账户、两本往来账：

- **应收账**：客户欠我们的钱。发货签收形成应收，收款结算/预收核销减少应收；
- **预收账**：客户提前付给我们、尚未核销应收的钱。预收收款增加，预收退款、预收核销（冲应收）减少。

两本账都按时间顺序记**流水**（增加/减少/滚存余额/结算标志），余额由流水滚存得出，
点余额数字就能下钻查流水，往来对账以这里为准。

| 菜单 | 位置 | 用途 |
|---|---|---|
| 客户账户 | 财务管理 → 客户账户 | 每客户一行的应收/预收余额、账期快照、往来流水抽屉、数据修复 |
| 收款单 | 财务管理 → 收款单 | 应收结算收款 / 预收收款 / 预收退款（单据上选收款类型） |
| 预收核销单 | 财务管理 → 预收核销单 | 把预收余额冲成应收结算（预收冲应收，单号 XH 开头） |
| 应收结算 / 客户对账 | 财务管理 → 应收结算、客户对账 | 结算时可直接勾「使用预收款」 |
| 客户期初预收 | 财务管理 → 客户期初预收 | 上线时把存量预收余额建进账户 |

### 权限点（找系统管理员在角色里勾）

| 前缀 | 控制 |
|---|---|
| `fin.customer_account.view` | 进客户账户、查流水 |
| `fin.customer_account.repair` | 数据修复（按应收真值重算余额、补缺流水） |
| `fin.advance_writeoff.view/add/edit/audit/unaudit/delete` | 预收核销单的查看/新建/编辑/审核/反审核/删除 |
| `fin.receipt.unaudit` | 收款单反审核（含自动生成的溢收预收单） |
| `fin.init_adv.*` | 客户期初预收六个功能点，见期初手册 |

超管默认拥有全部。

## 二、查客户余额与往来流水

**财务管理 → 客户账户**：

- 可按渠道、业务员、客户分类、关键字（客户编号/店名/助记）筛选，可勾「本页不体现余额为 0」；**筛选条件点「查询」才生效**；
- **应收余额、预收余额是蓝色链接**，点开该客户的往来流水抽屉（应收/预收两个页签，点哪个余额就默认开哪本账）；
- 流水抽屉默认查近三个月，可换快捷期间（昨天/上周/本周/上月/本月）或自选起止日期；列里有此前余额、每笔增减、滚存余额、结算标志（未结算/部分/已结算）以及来源单据（要货 YH、出库/退货、收款 SK、核销 XH 单号，可联查）；
- 余额与流水是系统按业务单据自动维护的缓存，**不能手工改**；发现历史原因造成的差异，用「数据修复」按应收真值重算（操作留痕）。

## 三、日常预收业务怎么走

### 3.1 收一笔预收款

财务管理 → 收款单 → 新建，**收款类型选「预收收款」**（默认是应收结算）：

- 往来单位强制为客户；填资金账户与金额（多行资金账户可拆分）；
- 审核后：资金账户增加、客户**预收余额增加**，不核销任何应收；总账生成「借 资金科目 / 贷 2203 预收账款」凭证事件（2203 带客户辅助核算）。

### 3.2 退预收

收款单新建，类型选「预收退款」：选客户后界面显示当前预收余额，**退款额不能超过余额**（前端置灰 + 后端拒绝双保险）。
审核后资金流出、预收余额减少，凭证「借 2203 / 贷 资金科目」。

### 3.3 用预收冲应收（预收核销单 XH）

财务管理 → 预收核销单 → 新建：选客户后，右侧按**先到期先冲（FIFO）**列出未结应收行，勾选并可逐行改本次核销额，
合计不能超过客户预收余额，也不能超过各行未结额。审核后一笔动作同时完成：预收余额减少、所选应收被结算、两本账流水齐全、
发货单收款状态回写、总账生成「借 2203 / 贷 1122」凭证。

待审核单可改可删；已审核单可「取消审核」整笔复原（预收加回、应收恢复未结）。
应收结算/对账单结算自动生成的核销单带「结算生成」标记，**不能单独反审核**——要从对应的收款单反审核级联冲回。

### 3.4 结算时直接用预收

在 **应收结算**（客户应收明细里勾选未结应收行结算）或 **客户对账**（按对账单结算）弹窗里：

- 上方灰底「使用预收款」面板显示该客户 ERP 预收余额，勾选后填本次用预收的金额；
- 预收最多可填 `min(本次结算净额, 预收余额)`，剩余部分照常配资金账户；账户合计与预收必须正好等于结算净额，否则确认按钮置灰；
- 提交后：预收部分自动生成并审核一张 XH 核销单，现金部分正常生成收款单；哪怕全额用预收、现金为 0，也会照生一张 0 现金收款单作为以后反审核的锚点；
- 冲回路径：收款单「取消审核」会连带把自动 XH 作废、应收/预收全部复原。

## 四、TMS 门店溢收自动转预收（参数 P0189，默认开）

司机交账审核核销时，某门店**实缴 > 本次核销应收**的多收款处理方式，由系统参数
`tms.settle.overpay-to-advance` 控制（系统管理 → 系统参数管理，TMS配送 分组，参数编号 P0189；参数说明另见
`docs/TMS系统参数设置.md` 第 11 条）：

- **Y（默认）**：自动生成并审核一张收款类型为「预收收款」的收款单，溢收额计入该客户预收余额，之后可正常做预收核销或结算用预收；
- **N**：不生单，仅保留日志提示，财务按老办法人工处理。

使用与核对要点：

1. **资金只记一次**：钱已随司机结算收款单按实缴全额入资金流水，自动单**不再记资金流水**，只补客户预收账和总账凭证（借资金/贷2203）。所以银行/现金账不会多出一笔；
2. **前提配置**：总账启用后，自动单的凭证依赖「资金账户 → 总账科目」映射。没配映射时凭证会生成失败（待生成凭证里给中文原因「资金账户『X』未映射总账科目」），到 总账管理 → 档案科目映射 补齐（如 现金→1001）后重生成即可，不影响往来账；
3. **在哪找**：财务管理 → 收款单，自动单与普通预收单外观一致，用的是正常 SK 单号；摘要/来源单据可追溯到对应的门店结算单（需要的话按门店结算单号在列表检索）；
4. **怎么冲回**：在收款单列表对该自动单做**「取消审核」**（需 `fin.receipt.unaudit` 权限）——预收余额、往来台账、总账凭证对称冲回；因原本就没有资金流水，红字冲回也不动资金。门店结算单反审核不隐式级联，需要财务先/后手工处理这张预收单。

## 五、上线时的存量预收

走 **财务管理 → 客户期初预收**（下载模板 → 导入/录行 → 期初建账），建账只生成预收流水、
不生成收款单不动资金；2203 期初数随总账「一键引入业务期初」带入。详见
`docs/操作手册-业务期初初始化.md` 第五章。历史遗留的多收款经财务核对客户后也从此入口录入，
系统不自动划转。

## 六、封账与查错

- **日结封账**：记账日期落在已封账日期的审核/反审核一律被硬拒并提示封单日，需走 财务管理 → 日结管理 的反日结流程（见日结手册）；
- **日结核对**：日结向导有客户预收合计勾稽提示；应收定版台账与 RJ 日结单印有「预收余额（账户）」列（取客户账户）与「预收（重分类）」兜底列，正常两列应相等；
- **常见拒绝提示**：
  - 「退款额/核销额超过客户预收余额」——先查客户账户预收余额，超额部分不能走预收；
  - 「该预收款已被预收核销或退款使用……请先反审核相关单据」——反审核顺序要从下游往上游：先反 XH/退款，再反预收收款；
  - 已封账日、已被结算占用的应收不能撤销签收，先反结算（收款单/XH）再动发货单。

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 客户账户没出现某客户 | 账户在首次发生往来业务或跑过「数据修复」后自动建立；只录了客户档案、没有任何应收/预收的不显示 |
| 余额和手工账对不上 | 先点余额查流水抽屉逐笔对；确属历史数据问题，由有权限的人跑「数据修复」按应收真值重算，不要直接改数据库 |
| 收款单里选不了「预收收款」 | 该往来单位是供应商：预收类型只对客户开放，选客户后类型可选 |
| 溢收后没看到预收单 | 先确认参数 P0189=Y；参数 N 只留日志不生单。已生单在收款单列表按客户与交账日期检索，单据关联的来源号即门店结算单号 |
| 自动溢收单凭证生成失败 | 资金账户没配总账科目映射，总账管理 → 档案科目映射补配后在待生成凭证里重生成 |
| 预收核销单选客户后没有应收行 | 该客户没有未结算的应收；可先签收发货/建应收期初，或用预收退款把钱退给客户 |
| 自动 XH 单没有反审核按钮 | 结算生成的 XH 不允许单拆，打开对应收款单做「取消审核」级联冲回 |
