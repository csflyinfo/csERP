## 1. 背景与目标

### 1.1 行业实践：商贸经销的厂家费用怎么跑

在品牌厂家→经销商→零售终端的链条里，经销商大量"替厂家花钱、再向厂家要钱"：

1. **代垫（垫付）**：终端促销、陈列、堆头、返利等费用先由经销商垫付给客户/终端（付款时已走**客户费用单 FE**，借销售费用）；
2. **申报立账**：经销商把费用凭据报给厂家，厂家确认后形成经销商对厂家的债权（会计科目 **1221 其他应收款，供应商辅助核算**）；
3. **兑现（结算）** 有三种主流出路：
   - **现金结算**：厂家直接打款到账（资金 IN，借资金/贷 1221）；
   - **冲应付（账扣）**：月结货款里直接抵扣，勾选具体应付单核销（借 2202/贷 1221，不动资金）；
   - **其他核销**：货补（厂家以货抵费）、谈定减免/坏账（费用转回我方承担）、费用转预付（抵作下批货款预付）；
4. **执行跟踪**：一张费用单申报多少、已兑现多少、谁未兑、压了多久，是经销商与厂家月结对账的核心资料。

行业里同时存在**预付账款（1123）**：先打款后提货，预付要能付、能退、能冲应付，并能在应付结算/对账单结算时直接使用。

### 1.3 目标

1. **应付余额**（镜像客户应收）：采购收货/退货/期初形成，付款/预付核销/费用冲应付减少；
2. **预付余额**（镜像客户预收）：预付付款增加，预付退款/预付核销（FX）/费用转预付增加等减少/增加，恒 ≥ 0；
3. **费用余额**（供应商侧新增）：厂家费用单 JF 审核立账增加（1221 债权），兑现单 DX 减少；待兑现/部分兑现/已兑现全程跟踪；
4. 三个余额各一本**带滚存的往来流水**，可下钻、可联查单据、可按真值修复；
5. 厂家费用三种兑现方式齐备（现金/冲应付/其他核销），月结对账可打印扣款通知；
6. 预付能付款、能退款、能冲应付、能在结算时使用；
7. **期初**：**预付期初并入现有「供应商应付期初」**模块（评审决策 §15-6），同一模板加一列「期初预付金额」，过账时应付立 fin_ap、预付写 PREPAY_OPENING 流水；另为**已上线运行的环境**提供独立批号的预付补录通道（§7.2）。1123 随总账「一键引入业务期初」。**历史代垫/历史厂家费用不做期初模块**（评审决策 §15-5）：上线时由财务按日常单据**手工录入带补录标志的 JF**（不生 GL 凭证，避免与 1221 总账期初重复），审核后形成费用余额。

## 3. 总体模型

```
                         供应商（一个供应商一条账户行，三个余额）
 ┌────────────────────────────┬──────────────────────────┬────────────────────────────┐
 │ AP 应付账（真值=fin_ap）    │ PREPAY 预付账（流水即真值）│ EXPENSE 费用账（真值=已审JF）│
 ├────────────────────────────┼──────────────────────────┼────────────────────────────┤
 │ 增：采购收货生应付          │ 增：预付付款/费用转预付    │ 增：厂家费用单立账/红字(负)  │
 │    采购退货(负红字)/期初    │    预付补录(QCYF)         │                            │
 │ 减：付款结算/FX 预付冲应付  │ 减：预付退款/FX 核销       │ 减：现金兑现/冲应付/其他核销 │
 │    DX 费用冲应付            │                          │                            │
 └─────────────┬──────────────┴────────────┬─────────────┴──────────────┬─────────────┘
               ▼                           ▼                            ▼
        付款单 FK（SETTLE）          预付核销单 FX               厂家费用兑现单 DX
        核销 fin_ap（FIFO）          预付冲应付                  ├ CASH  厂家打款（资金 IN）
        资金 OUT                     ├ 核销记录 PREPAY_WRITE_OFF  ├ OFFSET 勾选 fin_ap 账扣
        核销记录 PURCHASE_PAYMENT    ├ AP↓ fin_ap 回写            └ OTHER  货补/减免/转预付
        （自动 FK：对账单结算）      └ 借2202/贷1123
 预付付款 FK ─► PREPAY 增（资金 OUT）；预付退款 FK ─► PREPAY 减（资金 IN，余额守卫）

 厂家费用单 JF 审核 ─► EXPENSE 增（借 1221/贷费用科目；补录单不生凭证）
        ▲ 明细来源：客户费用单 FE 行（代垫）/ Excel 导入 / 手工（历史费用同走手工+补录标志）
        │
 厂家费用兑现 DX ─► CASH：资金 IN+费用减 / OFFSET：AP↓费用↓（不动资金）
                  OTHER：费用减，对方科目=1123（预付增）/1405/费用类/5711
```

**真值/缓存分层（镜像客户账户）**：

- AP 真值 = `fin_ap` + `fin_reconcile_record`；PREPAY 真值 = PREPAY 流水（期初/付款/退款/FX/转账即发生）；EXPENSE 真值 = 已审 JF 单与 DX 核销明细；
- 账户余额列、账户流水均为**可重建缓存**：数据修复按真值重算、补缺、重排；
- 所有写入 biz_key UNIQUE 幂等；红字只增不删（未结 AP 形成行随源单 DELETE 是唯一例外）；post_date 封账守卫；锁账户行 FOR UPDATE。

### 4.7 迁移与历史回填（V128 同脚本）

口径与 V124 §4.5 完全对称：

1. 建上述表/约束/索引；付款单历史行 `SETTLE`。
2. 为每个 `base_supplier` 建账户行（MERGE，已存在行余额回填自身，禁止清零）。
3. 从 `fin_ap` 回填 **AP 形成流水**（一行 fin_ap 一行，biz_key=`AP:`+ap_no）。供应商编码解析链（弱引用同客户侧）：
   `pur_receipt.supplier_code`（source_bill=CGSH 收货单号）→ `pur_return.supplier_code`（CGTH）→ 期初应付批号行 → `base_supplier` 按名称 → 名称兜底。
   负向退货行 `increase_amount=负、is_red='Y'`；settled_amount=paid_amount，状态按 0/部分/全额推导。
4. 从 `fin_reconcile_record` 回填 **AP 结算流水**（counterparty_type='SUPPLIER' 且 business_no/ar_no 能命中 fin_ap 的行；biz_key=`APR:`+record_id）。
   **费用类核销记录（business_type='EXPENSE'/'EXPENSE_WRITEOFF' 等，命中不到 fin_ap）一律排除**——不把非 AP 结算塞进 AP 流水。
5. 窗口函数按 `(occurred_at, 形成优先, flow_id)` 交错重排 AP 余额链，账户 `ap_balance=末笔`，与 Σ fin_ap.unpaid 校验，不一致写迁移日志（不阻断）。
6. PREPAY / EXPENSE 流水起步为空，两个余额 = 0：
   - 历史「负应付」（已由日结 prepaid_amount 重分类体现的预付）**不自动转预付**：新库在「供应商应付期初」模板的「期初预付金额」列核对录入；**已上线库走 §7.2 独立补录**。系统提示该供应商负 AP 合计防双计（§6.13）；
   - 历史代垫/历史厂家费用**不自动生成 JF、也不设期初导入**：上线后由财务录 OPENING_BACKFILL JF（§7.3）。
7. 回填后跑 §8.1 不变量校验，输出对账差异到迁移日志。

## 6. 上下游流程（逐个场景说清）

### 6.1 厂家费用单：代垫关联客户费用单（行级、FE:JF=N:1）

代垫在系统里的典型前序：我方付钱给客户/终端做市场活动——该笔支出已通过**客户费用单 FE**（counterparty=CUSTOMER、direction=OUT，审核时借销售费用；有资金账户的自动生 FK 付款）走完。

JF 新建（claim_type=ADVANCE）明细行点「**选择客户费用单**」：

1. 选择器以 **FE 明细行**为粒度列出：`fin_expense_bill` 中 counterparty_type='CUSTOMER'、direction='OUT'、status='APPROVED' 的费用单**未被占用的明细行**（按客户/日期/费用类型筛选，支持跨单多选）；
2. 占用判定：该 FE 行的 id 已存在于 JF detail.customer_expense_detail_id → 排除；**一张 FE 已有任一行被关联（含只记单号的导入/手工关联），整单其余行也不允许再选**（评审决策：一张 FE 只能被一张 JF 关联，不支持 FE 拆两张 JF 分次申报）；
3. 选中行带回 JF 明细：客户、费用类型、金额（可改小）、customer_expense_no、customer_expense_detail_id、gl_credit_subject（默认 FE 行费用类型的 gl_expense_account_code，**原路冲回**）；行金额允许小于原 FE 行金额（差额视为我方自行承担、不再申报，列表红字提示）；保存逐行判重；
4. **JF:FE = 1:N**：一张 JF 可关联多张 FE 的多个明细行；审核时在所有涉及 FE 头上回写 `factory_expense_no`（同一 JF 号）；JF 反审核/删除（PENDING/未兑现）时清空全部回指；
5. 不强制 FE 已走资金（存在先申报后补单场景）：FE 已审核即可选；未审核 FE 不能选；
6. 导入/手工场景只录 FE 单号、不录明细行 id 的，按**整单占用**处理（选择器排除整单），明细费用类型与金额由用户在 JF 行录全；
7. 历史代垫费用上线补录同样在本入口/手工行完成（§7.3）。

### 6.2 厂家费用单：导入与手工增行

- **Excel 导入**：走现有导入框架（部分成功、VALID/ERROR 全行落暂存、失败文件下载），模板列：供应商编码（必填）、费用类型（必填，末级档案名）、费用性质（代垫/其他）、垫付客户编码（可空）、关联客户费用单号（可空，校验存在且未被关联，整单占用）、费用日期、金额（含税，>0）、厂家协议号/票据号（external_voucher_no）、贷方科目（可空，覆盖默认）、备注。建议**按供应商+日期分组生成 PENDING JF**，供财务复核后审核；
- **手工增行**：抽屉明细表格直接录费用类型/客户/金额/贷方科目/备注；claim_type=OTHER 默认走手工；
- PENDING 单可改可删；APPROVED 单只能反审核（见 6.5）。

### 6.3 JF 审核（费用债权立账）

一个 `@Transactional`：

1. 封账守卫：`assertWritable(expense_date, "厂家费用单", jfNo)`；状态 PENDING→APPROVED、auditor/audit_time；
2. `lockAccount(supplierCode)` 后写 EXPENSE 形成流水（每张 JF 一行汇总，biz_key=`FEX:`+jfNo；明细不拆流水）：increase=total，settle_status='待兑现'，回写 factory_expense_no/source_bill/post_date；费用余额增加并重排余额链；
3. JF 主单 settled/unsettled/settle_status 落初值；代垫行回写 FE 头回指；
4. **GL 事件分支**：business_source='BACKOFFICE' 发 `onFactoryExpenseAudited`（§9.1）；**'OPENING_BACKFILL' 不发任何 GL 事件/不进会计事件池**（§7.3/§9.3）；
5. 操作日志（新模块 `finance.factoryExpense`，AUDIT，日志中体现补录标志）。

### 6.4 红字厂家费用单

已审核 JF 在**未封账日期**优先走反审核（回 PENDING）。已封账或需要留痕调整（厂家驳回、申报 100 核准 98 的差额等）的，开**红字 JF**：

- 红字单引用原单（red_source_no），total_amount 为负（明细负），审核写 `FACTORY_EXP_RED` 负向形成行（is_red='Y'），冲减费用余额与原单未兑现额；
- 冲减以原单**剩余未兑现额**为限（已兑现部分不能红冲，须先反审核对应 DX）；红字单自身不可再被兑现；
- 原单 settle_status 按冲减后金额重算；红字单 GL 同构红字事件（OPENING_BACKFILL 原单的红冲单同样不发事件）；
- **FE 回指策略**：红字冲减不释放 FE 关联（该 FE 确实申报过，保留审计轨迹）；确需就同一 FE 重新申报的，走红字冲回后新建 JF 走**手工行**并在备注注明原 FE 单号（选择器中该 FE 不再出现）。

### 6.5 JF 反审核

- 守卫：状态 APPROVED；`expense_date` 未封账；**该单不存在仍生效的 DX 兑现明细**（已兑现必须先反 DX；已红冲部分不拦）；
- 动作：APPROVED→PENDING；原形成流水置 REVERSED + 追加 `FACTORY_EXP_REVERSE` 红字冲回行；清全部 FE 回指；GL reverse 事件（补录单无事件）；操作日志；
- 已封账日不能反审核，走红字 JF（§6.4）；历史补录单与普通单同链。

### 6.6 厂家费用兑现单：现金结算（CASH）

厂家银行/现金打款兑现费用。新建 DX 选供应商 + settle_type=CASH：

1. 上半区列出该供应商未兑现完的 JF 行（待兑现/部分兑现，按费用日期 FIFO 默认勾选填额，可手工调整）；下半区录资金账户多行（到账）；两区合计必须相等；
2. 审核一个事务：
   1. DX → APPROVED；`lockAccount`；
   2. **资金侧**：逐资金行写 `fin_fund_ledger` IN、`base_fund_account.balance` 增加、`rebuildFundChain`（完全复用收款单资金段；日结资金定版自动覆盖，无需额外接线）；
   3. **往来台账**：写 `fin_counterparty_ledger` IN（SUPPLIER，不断档）；
   4. **费用侧**：逐 JF 行回写 settled/unsettled/settle_status；写 EXPENSE 流水 `FACTORY_EXP_SETTLE_CASH`（decrease=合计，biz_key=`DXC:`+dxNo，payment_no 列存 DX 号），回写对应形成行 settle_status/settled_amount；费用余额下降；
   5. 不写 fin_ap、不写 fin_reconcile_record；
   6. GL 事件 `onFactorySettleAudited`（CASH：借资金/贷1221，**现金流量项目固定「收到其他与经营活动有关的现金」**，§9.1）；
3. **DX 反审核**：守卫未封账；资金追加红字 OUT 行（只增不删，照收款反审核口径）、往来红冲；费用侧原流水 REVERSED + `FACTORY_EXP_REVERSE`，回退 JF 三金额与状态；DX→PENDING；GL reverse。

### 6.7 厂家费用兑现单：冲应付（OFFSET，账扣）

月结货款抵扣（行业主场景）。选 settle_type=OFFSET：

1. 上半区勾选 JF 行；下半区列出该供应商未结清 **fin_ap 行**（unpaid>0，按 due_date FIFO；负 AP 行不可选），勾选并录本次冲销额（默认按 JF 合计 FIFO 预填，可改）；两区合计相等才可审核；
2. 审核一个事务：
   1. DX → APPROVED；`lockAccount`；
   2. **AP 侧逐行**：更新 `fin_ap.paid_amount/unpaid_amount/status`（全结 VERIFIED，部分 UNVERIFIED；H2 同 UPDATE SET 读旧值坑，派生值 Java 侧算）；
   3. 逐行写 `fin_reconcile_record`（走 `writeReconcileRecordV2`：receipt_no 位存 DX 号、business_no=ap_no、source_bill 带 CGSH/CGTH、**business_type=`FACTORY_EXPENSE_OFFSET`**、cpType=SUPPLIER，中文类型名「厂家费用账扣」）；
   4. 同步回写 pur_receipt.pay_status（复用现有付款回写口径）；
   5. **费用侧**：回写 JF 三金额状态 + EXPENSE 流水 `FACTORY_EXP_SETTLE_OFFSET`（biz_key=`DXO:`+dxNo；每个 AP 行另有明细锚点键 `DXAP:`+dxNo+':'+ap_no 供修复定位）；费用余额下降；
   6. **AP 侧**：每个 AP 行写一行 `AP_SETTLE_EXPENSE` 流水（回写形成行结算标志），应付余额下降；
   7. **不动资金、不写往来资金台账**（纯往来转账，同 FX/XH）；
   8. GL 事件（借 2202/贷 1221，供应商辅助，无现金流量）；
3. **DX 反审核**：守卫未封账；删除本 DX 的核销记录（按 DX 号删 record 后**按剩余核销记录重算** fin_ap 三金额，而非直接减，避免与后续付款交错算错）；回退 pur_receipt 付款状态；费用侧/AP 侧双边红字冲回、形成行标志回置；DX→PENDING；GL reverse。

### 6.8 厂家费用兑现单：其他核销（OTHER，货补/减免坏账/费用转预付）

费用债权的非现金、非账扣出路，防止费用余额死挂。选 settle_type=OTHER，一单一个对方科目：

| 对方科目 | 业务含义 | 审核额外动作 |
|---|---|---|
| **1123 预付账款** | 费用转预付（厂家把应兑费用转作下批货款预付） | 除 EXPENSE 减（`FACTORY_EXP_SETTLE_OTHER`，biz_key=`DXOT:`）外，**PREPAY 增**流水 `PREPAY_EXPENSE_TRANSFER`（biz_key=`DXP:`+dxNo），预付余额上升；之后可正常 FX/退款 |
| **1405 库存商品** | 货补（厂家以货抵费） | 只做往来结转；**实物入库另走正常采购入库/盘盈单**，related_bill_no 记入库单号备查；存货商品辅助明细由会计在事件工作台补（§9.1） |
| **5601/5602 费用类**（默认 560199） | 厂家不承担、费用转回我方（谈定减免、驳回） | 无 |
| **5711 营业外支出** | 债权坏账核销 | 必填原因，操作日志重点留痕 |

流程与守恒：

1. 上半区照常勾选 JF 行（FIFO），头录对方科目（候选白名单常量：1123、1405、5601%/5602% 末级、5711）、related_bill_no（可空）、原因备注（必填）；Σ JF 行 = total；
2. 审核：DX→APPROVED；lockAccount；费用侧同 6.6 第 2.4 步（biz_type 改为 OTHER）；1123 场景加写 PREPAY 增流水并重排预付链；**不写资金、不写 fin_ap、不写核销记录**；GL 事件（借对方科目/贷1221，§9.1）；往来台账写一条 SUPPLIER 方向转账类记录（business_type='FACTORY_EXPENSE_OTHER'，摘要带科目与原因）；
3. 反审核对称冲回（含 1123 场景的预付增红字——守卫：该笔转预付已被 FX/退款使用时先反下游）；封账日禁反。

### 6.9 付款单三类型（应付结算/预付付款/预付退款）

扩展 [FinanceController `/payment/audit`](../backend/src/main/java/com/erp/finance/FinanceController.java) :2156 与反审核 :2233，按 payment_type 分支（SETTLE 全现状）：

| 类型 | 审核 | 流水/凭证 | 反审核 |
|---|---|---|---|
| SETTLE 应付结算 | 现状：FIFO 核销 AP + 资金 OUT + 往来台账 OUT | **新增** AP 流水 `AP_SETTLE_CASH`（逐 AP 行，回写形成行标志）；GL 现状模板 | 现状回退 + AP 红字流水/标志回置 |
| PREPAY 预付付款 | **不**调 reconcileAndRecord；资金 OUT；往来台账照写 OUT | PREPAY 流水 `PREPAY_PAYMENT`（增），预付余额↑；GL：借 1123/贷资金 | 守卫：该预付已被 FX 使用须先反 FX；PREPAY_REVERSE 红字、余额回减 |
| PREPAY_REFUND 预付退款 | 资金 IN；**校验退款额 ≤ 当前预付余额**，否则中文报错「预付余额不足」 | PREPAY 流水 `PREPAY_REFUND`（减）；GL：借资金（**收到其他经营现金**）/贷1123 | 对称冲回 |

自动付款单（费用单审核 FK、供应商对账结算 FK）business_source 不变，payment_type 默认 SETTLE。付款单选供应商后界面展示三余额（只读提示）。

### 6.10 预付核销（预付冲应付，FX）

完全镜像客户侧 XH：选供应商后右侧 FIFO 列未结 AP 行，勾选+逐行本次核销额，合计 ≤ 预付余额、≤ 各行未付。审核：FX→APPROVED；逐行写核销记录（**business_type=`PREPAY_WRITE_OFF`**，receipt_no 位存 FX 号，business_no=ap_no）；更新 fin_ap 三金额与 pur_receipt.pay_status；PREPAY 账户写 `PREPAY_WRITE_OFF`（减），AP 账户逐行写 `AP_SETTLE_PREPAY` 并回写形成行；不碰资金；GL 借 2202/贷 1123；反审核对称回退（删记录→重算 AP→双边红字），封账日禁反。

### 6.11 应付结算 / 供应商对账单结算使用预付

镜像客户侧：`/finance/supplier-statement/settle`（:2951）与应付结算弹窗入参加 **`usePrepayAmount`**（≤ min(待结净额, 预付余额)，默认 0）。确认后一个事务：预付部分自动生并审一张 FX（business_source=STATEMENT_SETTLE/AP_SETTLE，source_bill_no 带对账单号，不能单拆反审核），现金部分照常生 FK（**0 现金也生 0 额 FK 作级联锚点**）；抹零沿用现状（供应商对账抹零当前只轧差+write_off_amount，不生费用单，本期不改）。反审核从 FK「取消审核」级联作废 FX。

### 6.12 采购收货/退货/期初 → AP 形成流水

现状立账口径一律不改（含税 final_amount、负向退货、+30 天到期、QCAP），仅在各自审核事务内同事务追加 AP 形成流水（`AP_RECEIPT/AP_RETURN/AP_OPENING`，biz_key 幂等，失败整体回滚不 catch）。

采购收货反审核/采购退货反审核现状守卫（已付≠0 拒）补表述：凡被付款/FX/DX-OFFSET 结算过的 AP，先反下游单据；守卫通过且现状 DELETE fin_ap 的，同事务 DELETE 对应未结形成流水（"只增不删"唯一例外，口径同客户侧）。

### 6.13 日结封账、重分类与双计防护

- 所有流水 post_date 取单据记账日期（收货=审核生效日、付款=付款日、JF=费用日、DX/FX=兑现/核销日，不回填）；落已封账日的审核/反审核硬拒；
- 应付定版取数：`ap_balance` 取账户；**新增快照列 `prepay_account_balance`、`expense_account_balance`** 结账时点固化；
- **负应付重分类与预付账户分列并存**（修正口径）：采购退货等形成的负 AP 是真实的"预付性质"挂账，不会因录了期初预付而消失；资产负债表「预付款项」= 1123 账户余额 + 2202 负余额重分类，二者**不要求相等**。向导分列展示：`prepaid_amount`（负 AP 重分类，fin_ap 真值推导）、`prepay_account_balance`（1123 账户）；要防的是**同一笔负应付又录一遍期初预付**（双计）——期初/补录录入页对该供应商展示「负应付合计」并红字提示，不硬阻断（允许两笔真实资产并存）；定版台账与 RJ 打印单加「预付余额（账户）」「费用余额」两列。

### 6.14 供应商档案联动

- 供应商账户行在首次业务/修复时 ensureAccount；档案改名后账户名随修复/下次业务刷新快照；
- 停用/删除守卫：三余额任一 ≠0、存在未结 fin_ap、未兑现 JF、PENDING/已审 DX/FX 时拒绝，中文提示先清理；
- base_supplier.ap_balance 旧列停用（§4.6）。

## 8. 余额一致性、并发与数据修复

### 8.1 不变量

1. `ap_balance` = Σ `fin_ap.unpaid_amount`（按解析后的供应商编码；含负行）。
2. `prepay_balance` = Σ PREPAY 流水带符号发生额 = 末笔 balance_after，**恒 ≥ 0**。
3. `expense_balance` = Σ 已审 JF（含红负）未兑现额 = Σ EXPENSE 流水带符号发生额 = 末笔余额，**恒 ≥ 0**。
4. 任一 AP 形成流水 settled_amount = Σ fin_reconcile_record 同 ap_no 金额（业务类型 PURCHASE_PAYMENT/PURCHASE_RECEIPT/SUPPLIER_STATEMENT/PREPAY_WRITE_OFF/FACTORY_EXPENSE_OFFSET；EXPENSE_WRITEOFF 不计入按单归集）。
5. 任一 JF settled_amount = Σ 已审 DX 费用核销明细金额；状态三档自洽。
6. FX 守恒：预付核销额 = Σ 明细 = Σ AP 行核销额；DX 守恒见 §4.4；DX-OTHER-1123：费用减少额 = 预付增加额。
7. 三个账户余额链逐笔连续，末笔 = 账户缓存列。

### 8.2 并发与实现骨架

- 审核类事务先 `SELECT … FROM fin_supplier_account WHERE supplier_code=? FOR UPDATE` 再写流水；同供应商串行，不同供应商不阻塞；
- 新建 `com.erp.finance.account` 下：`SupplierAccountConst`（三类账户+biz_type 词汇+BIZ_LABELS（含中文类型名「厂家费用账扣」「预付核销」「费用转预付」等）+形成类判定）、`SupplierAccountService`（ensureAccount/lockAccount/writeFlow/rebuildChain/currentBalance/repair；AP 编码解析链）、`PrepayWriteoffService`（FX）、`FactoryExpenseService`（JF 立账/红冲/反审/回写/补录分支）、`FactorySettleService`（DX 现金/冲应付/其他三套审核反审）、`SupplierAccountController`（page/flow/repair）。Controller 薄层，SQL 全走服务；H2 同 UPDATE 读旧值坑处一律 Java 侧算派生值；
- 余额链 CHAIN_ORDER：同刻先形成（AP_RECEIPT/AP_RETURN/AP_OPENING、PREPAY_OPENING、FACTORY_EXP_FORM/RED）后结算。

### 8.3 数据修复

供应商账户列表「数据修复」（独立权限+日志+二次确认，选定供应商或全部）：① upsert 账户与档案快照；② 按真值重算三个余额；③ 按核销记录回填 AP 流水结算标志；④ 按 DX 明细回填 EXPENSE 流水/JF 兑现状态；⑤ 重排三本账余额链；缺流水（有 fin_ap 无流水等）按 §4.7 口径补行；差异报告（修复前后余额、补笔数）入操作日志并返回页面。不删业务流水。

### 9.2 贷方科目取数规则（防销售费用明细串科目）

- **代垫行（claim_type=ADVANCE，关联 FE）**：`gl_credit_subject` 默认 = 关联 FE 行费用类型的 `gl_expense_account_code`——**原路冲回**（FE 借了 560102 陈列费，JF 就贷 560102），允许会计改；
- **其他费用行（claim_type=OTHER，返利/补贴/奖励）**：默认取费用类型档案新增的 `factory_gl_credit_subject_code`；未配置默认 **5401 主营业务成本**（平销返利冲成本）；会计可改 5301（营业外收入）、5051（其他业务收入）等；
- 代垫行不使用 5401 默认、其他行不继承 FE 科目，两条规则在抽屉上以提示文案区分。

### 9.3 历史补录单不生凭证

business_source='OPENING_BACKFILL' 的 JF（及其红字单）审核/反审核**只动业务账，不写 fin_gl_event**，避免与总账 1221 期初双计；参数 P0190 关闭后无法再建补录单。业财对账公式见 §7.3-5/§10.4。

### 9.4 税务口径声明（V1 含税总额管理）

1. JF、DX 金额一律含税；`total_tax_amount/total_excluding_tax_amount` 仅登记备查，**模板不拆进项/销项**；
2. **现金兑现给厂家开具服务费/促销费发票**产生的销项税、**平销返利账扣**按税法应做的进项税额转出/红字发票，均由会计在**总账模块手工凭证**处理，业务模块不联动；external_voucher_no 登记厂家确认函/票据号作为核对锚点；操作手册附标准调整分录示例（如：现金兑现开票时 借1221 贷应交税费/对应收入科目；返利进项转出 借主营业务成本 贷应交税费—进项转出）；
3. 代垫 FE 自身的进项待认证（222103）沿用现有费用单模板，与 JF 链路无关；
4. DX 单打印/导出列含税额登记位与厂家票据号字段（§10.2）。

### 9.5 科目现状

1221 为末级科目、aux 已含 supplier；1123 同理；2202 供应商辅助已在 EXPENSE 模板使用——**无需新增科目**（V1 不拆 122101/122102，§15-1）。

### 10.1 报表中心核销类型白名单（硬缺口，M2/M3 交付）

### 10.3 费用执行跟踪（本期导出，正式报表二期）
