## 1. 商品类型收敛为 5 类（数字码库存，中文显示）

`base_goods.goods_type`（VARCHAR）库存字符串数字码，页面统一显示中文：

| 码 | 显示 | 可采 | 可销 | 可采退 | 可销退 |
|---|---|---|---|---|---|
| 0 | 正常商品 | ✓ | ✓ | ✓ | ✓ |
| 1 | 赠品 | ✓ | ✓ | ✓ | ✓ |
| 2 | 设备辅材 | ✓ | ✗ | ✓ | ✗ |
| 3 | 包装物 | ✓ | ✗ | ✓ | ✗ |
| 4 | 兑换物 | ✗ | ✗ | ✓ | ✓ |

- 前端集中维护 `views/goods/goodsConstants.js`：`GOODS_TYPES` 五选项 + `goodsTypeLabel(code)`（未知值/旧中文值兜底原样显示）。表单、批量编辑、筛选条、module-api 显示/导出共用。
- 后端 `GoodsBizPolicy` 统一派生采销/退货标志；保存时 `canSale/canPurchase` 由类型码强制计算（忽略前端传值）。
- **旧类型「组合商品/服务商品」保留原值不动**（用户决策）：列表照常显示原值，策略一律按 true/true 放行；手工编辑保存时需从新 5 类重选。
- 采销约束 = **候选过滤 + 保存硬校验**：
  - 候选过滤：`/base/goods/page` 新增可选 `bizScene=purchase|sale|purchaseReturn|salesReturn`（COALESCE 布尔列；退货场景额外放行类型 4）；`sale-ranking` SQL 固定加可销；`/base/goods/selector` 支持 `scene=sale`（飞单）；采购退/销售退两个 goods-options SQL 加退货准入。
  - 保存硬校验：销售订单/采购订单创建更新、飞单创建、采购退货/销售退货申请创建更新，首个违规商品即抛中文 `IllegalArgumentException`（指明编码/名称与原因）。入库/出库审核环节不重复拦截，在途单据不受影响。

## 2. 是否生鲜 + 税率手工录入

- V122 新增 `base_goods.is_fresh BOOLEAN DEFAULT FALSE`；新建商品默认否。前端「是否生鲜」是/否下拉。
- **税率库存纯数字**（VARCHAR，`"13"`），页面显示 `13％`；录入仅接受 0–50 的两位正整数（失焦 clamp，字母剔除），空白默认 0。导入/保存兼容老写法 `13%`（归一化去 %），非法值中文报错。分类默认税率仍存 `13%`，选中分类时前端去 % 带出数字（如分类「粗粮饼干」带出 9）。单据明细硬编码税率不受影响；飞单 goods-price 返回前端时补 `%`。

## 4. 导入三件套（入口：商品列表「导入」下拉）

| 入口 | 端点 | 说明 |
|---|---|---|
| 导入新增 | `POST /base/goods/import` | 48 列，逐行校验，整批不中断 |
| 导入修改 | `POST /base/goods/import-update` | 弹窗先勾可修改字段（40 复选 = 39 字段 + 锁定的商品编码），下载/上传都按勾选字段动态生成 |
| 导入查询 | `/base/goods/page` 新增 `goodsCodeList` | 模板仅【商品编号】列，上传按编号 IN 过滤返回 |

导入新增字段口径（空值默认/联动）：

- 商品编码空 → 大类编号 + 5 位流水（复用 `generateGoodsCodeByCategory`）；条码空 → 取商品编号；编码重复/批内重复 → 失败行。
- 分类：**编号优先，兼容分类名称**（同名唯一才匹配；重名/不存在 → 失败行）。
- 税率空 → 0（0–50 整数校验）；品牌不存在自动新建（brandCode 用 genId，同批缓存），品牌列空 → 「未维护」（不存在则建）。
- 价格联动空 → 是；类型空 → 正常（中文/数字码均接受，归一化落码）；保质期空 → 0；存储属性空 → 常温；预售/生鲜/称重空 → 否。
- 可退空 → 类型 0/4 默认是、其余否。
- 必填：名称、规格、分类、基本单位、默认供应商、默认仓库；单位/仓库/供应商按名称查主数据，不存在 → 失败行。
- 单位：大单位名非空即启用且换算数量必填；中单位必须先有大单位；大/中价格空 → 小单位对应价 × 换算数量；重量/体积任填一个启用单位，反推小单位后自动补齐其余启用单位空缺值。

导入修改要点：

- 商品编码默认勾选且**锁定不可取消**；默认全选，可全部取消（取消后下载模板/确认导入/文件选择全部禁用）。
- 弹窗顶部两条逐字警示：
  1. 「请谨慎修改大/中单位及对应的换算数量，修改会影响在途单据的数量出入库校验，请在库存数量为0的情况下再做修改。」
  2. 「修改了单位及换算数量后及时核查销售价格是否需要同步更新。」
- 下载模板按勾选项动态生成表头；上传按字段名匹配，**字段值为空（空单元格）则不更新该字段**；查无此编码 → 失败行。

## 5. 导入列表与真实失败文件

- 商品两个导入端点尾部写 `sys_import_task_runtime`（module_code=`goods`，task_name=`商品导入新增/修改`，success_rows/failed_rows/result_text，V122 新增 `failure_file` 列存落盘相对路径）。
- 失败文件用 EasyExcel 落盘 `backend/data/import-failures/{taskNo}.xlsx`（sheet「失败明细」，列 = Excel 行号 + 原始填报列 + 失败原因，仅失败行），`GET /system/import-list/failure-file/{taskNo}`（basename 防穿越）流式下载；无失败文件/0 失败行时前端提示「该任务无失败记录」。

### 顺带修复的真实缺陷：导入列表整行空白

排查时发现【系统管理-导入列表】页面除「查看」外整列空白：

1. `SystemController` 的 `/import-list/page` 用 `JdbcTemplate.queryForList` + 驼峰别名，而本库 H2 带 `CASE_INSENSITIVE_IDENTIFIERS=TRUE`，列别名一律回大写 key（`CODE/NAME/FAILEDROWS…`），前端 `EXACT_TITLE_MAP` 按驼峰取值全部 miss。改为显式 `RowMapper` 输出驼峰键；时间戳经 `fmtTs` 统一格式化为 `yyyy-MM-dd HH:mm:ss`（原先 `rs.getString` 带纳秒尾巴），并补 `action="查看 下载失败原因"`。
2. `module-api.js` 操作列渲染优先使用 `record.action`；`GenericBusinessList.vue` 失败下载取号加 `raw.taskNo` 兜底。
