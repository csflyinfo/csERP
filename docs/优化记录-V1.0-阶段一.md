### 🟢 待办 #5 — H2 → MySQL 迁移（步骤 A–D 已完成，E–H 待联调）

#### 5.1 现状盘点（数字来自实测 grep）

|项|H2 现状|MySQL 兼容性|
|---|---|---|
|`data.sql` 里 `MERGE INTO ... KEY(pk) VALUES(...)`|**20 处**|❌ 完全不支持，必须改写|
|`schema.sql` 里 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...`|**56 处**|❌ MySQL 至 8.4 仍不支持（MariaDB 才支持），必须改写或换方案|
|`schema.sql` 里 `CREATE INDEX IF NOT EXISTS ...`|**49 处**|❌ MySQL 8+ 不支持（8.0.29+ 也没加），必须改写|
|`BOOLEAN` / `TINYINT(1)` 字段|25 处|✅ 兼容（`BOOLEAN` 是 `TINYINT(1)` 别名）|
|`spring.sql.init.mode=always` + `schema-locations` + `data-locations`|dev 用|⚠️ 每次启动都跑 → 生产危险，MySQL 也不能容忍幂等问题|
|`MERGE INTO base_fund_account (...列名...) KEY(pk) VALUES(...)`|见 `data.sql` L20+|❌ 需改为 `INSERT ... ON DUPLICATE KEY UPDATE`|
|日期时间字段 (`created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP`)|兼容|✅ 兼容，但 JDBC 返回类型 H2 是 `LocalDateTime`，MySQL 5+ 是 `Timestamp` — Jackson 序列化格式可能有差异，需要在应用层统一|
|应用层直接依赖 `MODE=MySQL;CASE_INSENSITIVE_IDENTIFIERS=TRUE`|见 `application.yml` L19|H2 兼容模式，MySQL 天然不需要|
|应用 `application-prod.yml` 已配 MySQL 8|已就绪|✅ 待实测|
|Flyway / Liquibase|❌ 未接入|建议接入，替代 `spring.sql.init.always`|

#### 5.2 目标形态

**开发和生产都用 MySQL 8.0**，H2 作为**测试环境的 fallback**（`profile=test` 才用，配合 `MODE=MySQL`）。DB 结构演进走 **Flyway** 版本化脚本，脱离 `spring.sql.init.always`。

#### 5.3 分步执行清单（按依赖顺序，可各自独立提交）

##### ✅ 步骤 A：接入 Flyway，替代 `spring.sql.init.always`（本次已完成）

1. `backend/pom.xml` 加 `flyway-core` + `flyway-mysql`（版本由 Spring Boot BOM 管理）。
2. `application.yml` 关闭 `spring.sql.init.mode=always`，改为 `spring.sql.init.mode=never`；开启 `spring.flyway.enabled=true`，`baseline-on-migrate=true`，`baseline-version=0`。
3. 迁移脚本目录 `backend/src/main/resources/db/migration/`：
   - `V1__schema.sql` — 49 张表 DDL + 49 条索引，纯 MySQL 兼容语法（无 `IF NOT EXISTS`）
   - `V2__seed_data.sql` — 20 条 seed（sys_user / sys_role / sys_param / sys_bill_no_rule / base_counterparty_type / base_fund_account 系统默认）
4. 删除旧 `schema.sql` / `data.sql`，避免 sql.init 和 Flyway 双跑冲突。
5. 首次跑：清 `data/erp-v1.mv.db` → 后端启动 → Flyway 84 ms 内应用 V1+V2 → admin/admin123 登录 → 6 条默认资金账户已入库。

**验证**：H2（MODE=MySQL）下 `flyway_schema_history` 表出现 V1、V2 两条记录，`SUCCESS=true`。

##### ✅ 步骤 B：改写 20 处 `MERGE INTO`（本次已完成）

原 H2 `MERGE INTO ... KEY(pk) VALUES(...)` 全部改写为 MySQL 兼容语法：

```sql
-- V2__seed_data.sql 示例
INSERT INTO sys_user_runtime (user_id, username, display_name, password, mobile, role_name, data_scope, status)
VALUES ('U0001', 'admin', '系统管理员', '$2a$10$HvMZK...', '13800000000', '管理员组', '全部', 'NORMAL')
ON DUPLICATE KEY UPDATE display_name = VALUES(display_name), password = VALUES(password), role_name = VALUES(role_name);
```

H2 在 `MODE=MySQL` 下也支持该语法，双端同一份 seed。

##### ✅ 步骤 C：改写 56 处 `ADD COLUMN IF NOT EXISTS`（本次已完成）

采用推荐方案 1：**把 ALTER 合并进 CREATE TABLE**。理由：Flyway 保证 V1 只跑一次，无需幂等；合并后 schema 一目了然，也不用 IF NOT EXISTS 方言。

自动化处理：用 Python 脚本扫 V1__schema.sql，把 11 张表的 56 条 ALTER ADD COLUMN 合并到对应 CREATE TABLE 的末尾（列名去重），然后删掉所有 ALTER 行。

**验证**：`grep -c '^ALTER TABLE' V1__schema.sql` → 0；`base_goods` 的 CREATE 包含全部 40 列（原 22 + 18 补充）。

##### ✅ 步骤 D：改写 49 处 `CREATE INDEX IF NOT EXISTS`（本次已完成）

同 C：Flyway 里保证只跑一次，去掉 `IF NOT EXISTS` 关键字，保留 49 条 `CREATE INDEX`。

##### 🟡 步骤 E：本地起 MySQL 8 联调（待办 — 需要 Docker 环境）

`docker-compose.yml` 已有 mysql 8.0 服务（`erp_v1` / `erp_user` / `erp_pass_2024`）。**本次已改动**：删除 `docker-entrypoint-initdb.d` 的 db/migration 挂载，避免 MySQL 首次启动跑一遍脚本（会与 Flyway 冲突）。

启动步骤：

```bash
docker compose up -d mysql
docker exec -it erp-mysql mysql -uerp_user -perp_pass_2024 erp_v1
SPRING_PROFILES_ACTIVE=prod SPRING_DATASOURCE_URL='jdbc:mysql://localhost:3306/erp_v1?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true' mvn spring-boot:run
```

预期：Flyway 用 `flyway-mysql` 模块跑同一份 V1/V2，MySQL 里应出现 49 表 + 20 seed 行。

逐项回归：登录 / 各主档 CRUD / 分页排序 / 部门树 / 导入 / 保存子表。

##### 🟡 步骤 F：默认 profile 切换（待办）

E 通过后：

- dev profile 也切 MySQL（开发者本地必须 `docker compose up -d mysql`）；H2 沦为 `--profile=h2` 备选

- 更新 `README.md` / `DEPLOY.md`

##### 🟡 步骤 G：查询兼容性回归（待办 — 联调时同步做）

- H2 的 `DATE_FORMAT`、`GROUP_CONCAT` 等函数与 MySQL 略有差异，需 grep `jdbcTemplate.queryForList` 里的 SQL 逐一验证。
- `LIMIT ?,?` 语法两边都支持，无需改。
- `CURRENT_TIMESTAMP` 两边都支持。
- 大小写：H2 默认全部大写返回列名，MySQL 保持原大小写。当前代码里 `toCamel()` 已经先 `.toLowerCase()`，兼容。
- 布尔值：H2 返回 `Boolean true/false`；MySQL 返回 `Integer 0/1`。代码里 `coerce()` 和 `parseBool()` 需覆盖两种情况（现已支持 Integer→boolean）。
- 日期字段：H2 是 `LocalDateTime`，MySQL 5+ 是 `java.sql.Timestamp`。Jackson 序列化 JSON 格式可能不一致，前端 `createdAt` 显示需验证。

##### 🟡 步骤 H：数据迁移（待办 — 生产切换时）

- 或 JDBC 抽取每表 `SELECT * FROM ...` 转换 INSERT
- 建议先在测试库跑通再迁生产
