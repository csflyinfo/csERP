## 四、关键技术要点（施工时对照）

1. **表达式引擎**：手写词法+递归下降；节点白名单（数字/变量/+-*/括号/一元负号/比较）；变量只从 payload Map 取；BigDecimal HALF_UP 2 位；除零报错。**禁止** SpEL/JS/反射。报表模式增加函数白名单（QM/QC/FSD/FSC/LJFS/CF）与区间参数。
2. **事件钩子**：业务方法内 `applicationEventPublisher.publishEvent(new GlBizEvent(...))`，监听器 `@TransactionalEventListener(phase=AFTER_COMMIT)`；**绝不在业务事务里写 fin_gl_event**；监听器内 catch 一切异常（记日志即可，事件池机制本身兜底——发布后落池失败要靠日志告警，故落池 SQL 要极简、只插一张表）。
3. **取数聚合口径**：发生额=fin_voucher_entry 按期间+状态"已过账"汇总；期初=启用期前取 fin_init_balance，其后取上期期末滚动（单条 SQL 按 period<当前 汇总借-贷，按科目方向取净值）；辅助核算维度按 aux_key 分组；科目汇总用编码前缀按层级（`LIKE concat(code,'%')` 且长度=下级长度）。
4. **凭证号**：`字 + '-' + yyyyMM + '-' + 4位`，`SELECT MAX(voucher_no) ... LIKE '记-202609-%'`；红冲/作废都用新号。
5. **H2 坑**：queryCamel 转键；MERGE INTO KEY 替 UPDATE...FROM；JOIN 同名列加别名；SQL 普通字符串显式空格；CLOB 字段 payload_json 用 `CLOB` 类型。
6. **进项税方向**：2221 下所有明细 balance_direction='贷'，科目保存后端校验。
7. **菜单双份**：SystemController.userMenuTree() + fallback-menus.js 同步，每个里程碑结束前核对。
8. **状态值中文**：草稿/已审核/已过账/已作废/已冲销；待生成/已生成/已忽略/生成失败/已冲回；未开始/进行中/已结账/已冻结；使用中/已停用/已清理/已拆分/已合并。
9. **费用单按明细行展开**：费用单 payload 必须带明细行（每行费用类型编码+金额+税率），模板 EXPENSE_LINE 行逐行解析费用类型 → gl_expense_account_code；映射缺失用默认科目（5602/5051）+ warn_msg，不阻断生成。
10. **档案映射引导**：总账初始化完成后，初始化页/工作台提示"未映射 GL 科目的资金账户/费用类型/商品分类清单"，引导到对应档案页补全；业务档案页的科目下拉数据来自 /gl/account/tree（末级+启用过滤）。
11. **业务类型映射不剥离字典**：其他出/入库类型继续用 sys_dictionary 维护（库存模块零改动）；科目关系在 GL 侧 fin_gl_biz_subject_map 维护，页面类型名下拉从字典读取、科目从科目树读取，未配映射的字典值红字列出；字典新增类型值后事件生成失败属正常兜底链路（err_msg 指类型名→补配→重试），不改字典表结构。
