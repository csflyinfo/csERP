## 一、业务模型

### 1.1 业务定义

飞单 = 供应商直接向客户送货，**跳过仓库入库/出库环节**，但走完整的采购和销售财务闭环：

```
供应商 ──直送──→ 客户
   │                    │
   ├─ 采购订单（已审核，无需入库）
   └─ 生成应付 fin_ap
   │                    │
   ├─ 销售订单（已审核，无需出库）
   └─ 生成应收 fin_ar
```

### 1.2 核心规则

| 规则                 | 说明                                                                     |
| ------------------ | ---------------------------------------------------------------------- |
| 不经过仓库              | 不调用 `InventoryCostService.purchaseInbound`，不写 `inv_batch_stock`，不生成出库单 |
| 采购+销售闭环            | 审核时同时生成采购订单（APPROVED）和销售订单（APPROVED）                                   |
| 财务闭环               | 采购订单生成 `fin_ap`（应付），销售订单生成 `fin_ar`（应收）                                |
| 一张飞单 = 一笔采购 + 一笔销售 | 供应商→客户直达，商品明细一致                                                        |
| 利润可见               | 飞单明细同时记录采购价和销售价，审核后可计算毛利                                               |

### 1.3 与现有模块的关系

```
飞单（新建）
  ├─ 生成 → purchase_order（状态=APPROVED, inbound_status=无需入库）
  ├─ 生成 → sales_order（状态=APPROVED, outbound_status=无需出库）
  ├─ 生成 → fin_ap（应付）
  └─ 生成 → fin_ar（应收）

不调用：
  ✗ InventoryCostService.purchaseInbound（不入库）
  ✗ 入库单 / 出库单流程
  ✗ inv_batch_stock 写入
```

## 二、数据库设计

### 2.1 新增表：fly_order（飞单主表）

迁移脚本：`V34__fly_order.sql`

```sql
CREATE TABLE fly_order (
    fly_id          VARCHAR(36) PRIMARY KEY,          -- 飞单ID
    fly_no          VARCHAR(32) NOT NULL UNIQUE,      -- 飞单号（FD前缀）
    supplier_code   VARCHAR(32),                      -- 供应商编码
    supplier_name   VARCHAR(128),                     -- 供应商名称
    customer_code   VARCHAR(32),                      -- 客户编码
    customer_name   VARCHAR(128),                     -- 客户名称
    salesman        VARCHAR(64),                      -- 业务员
    bill_date       DATE NOT NULL,                    -- 单据日期
    purchase_amount DECIMAL(14,2) DEFAULT 0,          -- 采购总额（应付）
    sales_amount    DECIMAL(14,2) DEFAULT 0,          -- 销售总额（应收）
    profit_amount   DECIMAL(14,2) DEFAULT 0,          -- 毛利 = 销售总额 - 采购总额
    status          VARCHAR(16) DEFAULT 'DRAFT',      -- DRAFT / APPROVED / CANCELLED
    purchase_order_id  VARCHAR(36),                   -- 关联采购订单ID（审核后填充）
    purchase_order_no  VARCHAR(32),                   -- 关联采购订单号
    sales_order_id     VARCHAR(36),                   -- 关联销售订单ID（审核后填充）
    sales_order_no     VARCHAR(32),                   -- 关联销售订单号
    remark          VARCHAR(512),                     -- 备注
    creator_name    VARCHAR(64),                      -- 创建人
    create_time     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    audit_user      VARCHAR(64),                      -- 审核人
    audit_time      TIMESTAMP,                        -- 审核时间
    audit_info      VARCHAR(512)                      -- 审核信息
);
```

### 2.2 新增表：fly_order_detail（飞单明细表）

```sql
CREATE TABLE fly_order_detail (
    detail_id       VARCHAR(36) PRIMARY KEY,
    fly_id          VARCHAR(36) NOT NULL,             -- 飞单ID
    goods_code      VARCHAR(32) NOT NULL,             -- 商品编码
    goods_name      VARCHAR(128),                     -- 商品名称
    spec            VARCHAR(128),                     -- 规格
    unit_name       VARCHAR(32),                      -- 单位名称
    qty             DECIMAL(14,3) NOT NULL DEFAULT 0, -- 数量
    purchase_price  DECIMAL(14,4) DEFAULT 0,          -- 采购价（自动带出：供应商最近采购价 → base_goods.latest_purchase_price 兜底）
    sales_price     DECIMAL(14,4) DEFAULT 0,          -- 销售价（自动带出：客户价格组 → 客户最近售价 → 商品建议零售价 兜底）
    purchase_amount DECIMAL(14,2) DEFAULT 0,          -- 采购金额 = qty * purchase_price
    sales_amount    DECIMAL(14,2) DEFAULT 0,          -- 销售金额 = qty * sales_price
    tax_rate        VARCHAR(20),                       -- 税率（自动带出：base_goods.tax_rate，每行独立）
    remark          VARCHAR(256)
);
```

### 2.3 BillType 新增

`BillNoGenerator.java` 新增：

```java
public static final String FLY_ORDER = "FD";  // 飞单号前缀
```

飞单号格式：`FD` + `yyyyMMdd` + `0001`（4位流水），如 `FD202608070001`

## 三、后端 API 设计

### 3.1 新增 Controller：FlyOrderController

路径：`backend/src/main/java/com/erp/sales/FlyOrderController.java`

| 方法     | 路径                         | 说明                  |
| ------ | -------------------------- | ------------------- |
| POST   | `/sales/fly-order/create`  | 创建飞单（草稿）            |
| GET    | `/sales/fly-order/page`    | 分页查询飞单列表            |
| GET    | `/sales/fly-order/detail`  | 查询飞单明细（含明细行）        |
| POST   | `/sales/fly-order/audit`   | 审核飞单（生成采购+销售+应付+应收） |
| POST   | `/sales/fly-order/unaudit` | 反审核（删除关联单据）         |
| POST   | `/sales/fly-order/cancel`  | 作废飞单                |
| DELETE | `/sales/fly-order/delete`  | 删除飞单（仅草稿可删）         |

### 3.2 审核流程（核心逻辑）

```
POST /sales/fly-order/audit
  │
  ├─ 1. 校验：飞单状态必须为 DRAFT
  ├─ 2. 生成采购订单
  │     ├─ 采购单号：BillNoGenerator.generate(PURCHASE_ORDER)
  │     ├─ 状态：APPROVED（直接审核）
  │     ├─ inbound_status：'无需入库'
  │     ├─ 金额：sum(明细.purchase_amount)
  │     └─ 明细：从 fly_order_detail 复制（采购价）
  │
  ├─ 3. 生成销售订单
  │     ├─ 销售单号：BillNoGenerator.generate(SALES_ORDER)
  │     ├─ 状态：APPROVED（直接审核）
  │     ├─ outbound_status：'无需出库'
  │     ├─ 金额：sum(明细.sales_amount)
  │     ├─ cost_amount：sum(明细.purchase_amount)  -- 成本=采购金额
  │     └─ 明细：从 fly_order_detail 复制（销售价，cost_price=采购价）
  │
  ├─ 4. 生成应付 fin_ap
  │     ├─ ap_no：BillNoGenerator.generate(PAYABLE)
  │     ├─ source_bill：采购单号
  │     ├─ supplier：供应商
  │     ├─ ap_amount：采购总额
  │     └─ status：'未付'
  │
  ├─ 5. 生成应收 fin_ar
  │     ├─ ar_no：BillNoGenerator.generate(RECEIVABLE)
  │     ├─ source_bill：销售单号
  │     ├─ customer：客户
  │     ├─ ar_amount：销售总额
  │     └─ status：'未收'
  │
  ├─ 6. 更新飞单状态
  │     ├─ status → APPROVED
  │     ├─ purchase_order_id / purchase_order_no
  │     ├─ sales_order_id / sales_order_no
  │     └─ audit_user / audit_time
  │
  └─ ✗ 不调用 InventoryCostService（不写库存）
```

### 3.3 反审核流程

```
POST /sales/fly-order/unaudit
  │
  ├─ 1. 校验：飞单状态必须为 APPROVED
  ├─ 2. 删除关联的 fin_ap（WHERE source_bill = 采购单号）
  ├─ 3. 删除关联的 fin_ar（WHERE source_bill = 销售单号）
  ├─ 4. 删除关联的 purchase_order + purchase_order_detail
  ├─ 5. 删除关联的 sales_order + sales_order_detail
  └─ 6. 飞单状态 → DRAFT，清空关联单据字段
```

### 3.4 列表查询 SQL 示例

```sql
SELECT
    f.fly_id, f.fly_no, f.supplier_name, f.customer_name,
    f.salesman, f.bill_date, f.purchase_amount, f.sales_amount,
    f.profit_amount, f.status,
    f.purchase_order_no, f.sales_order_no,
    f.creator_name, f.create_time, f.audit_time
FROM fly_order f
WHERE 1=1
  AND (#{status} IS NULL OR f.status = #{status})
  AND (#{keyword} IS NULL OR f.fly_no LIKE CONCAT('%', #{keyword}, '%')
       OR f.customer_name LIKE CONCAT('%', #{keyword}, '%')
       OR f.supplier_name LIKE CONCAT('%', #{keyword}, '%'))
ORDER BY f.create_time DESC
LIMIT #{pageSize} OFFSET #{offset}
```

### 4.2 新建飞单抽屉：FlyOrderDrawer.vue

新建组件：`frontend/src/components/FlyOrderDrawer.vue`

**布局结构：**

```
┌──────────────────────────────────────────────────────────┐
│  新建飞单                                             [×] │
├──────────────────────────────────────────────────────────┤
│  ── 基本信息 ──                                          │
│  飞单号：自动生成        单据日期：[日期选择器]            │
│  供应商：[选择器]        客户：[选择器]                   │
│  业务员：[选择器]        备注：[文本框]                   │
├──────────────────────────────────────────────────────────┤
│  ── 商品明细 ──                              [+ 添加行]   │
│  ┌──────┬──────┬─────┬──────┬──────┬──────┬──────┬─────┐ │
│  │商品  │规格  │单位 │数量  │采购价│销售价│税率  │金额  │ │
│  │[选择]│自动  │自动 │输入  │自动  │自动  │自动  │自动  │ │
│  └──────┴──────┴─────┴──────┴──────┴──────┴──────┴─────┘ │
│  （采购价/销售价/税率自动带出，均可手动修改）               │
├──────────────────────────────────────────────────────────┤
│  合计：采购金额 ¥0.00  销售金额 ¥0.00  毛利 ¥0.00        │
├──────────────────────────────────────────────────────────┤
│                    [取消]  [保存草稿]  [保存并审核]        │
└──────────────────────────────────────────────────────────┘
```

**关键交互：**

1. **商品选择**：复用现有商品选择器，选中后自动带出规格、单位、税率
2. **采购价自动带出**：选择供应商+商品后，自动查询该供应商对该商品最近一次采购价
   - 数据源：`pur_order_detail` JOIN `pur_order`，按 `supplier_code + goods_code` 查最近已审核采购单的单价
   - 兜底：`base_goods.latest_purchase_price`（商品主数据最近采购价）
   - 已有 API 可复用：`GET /base/goods/latest-purchase-price?goodsCode=X&supplierCode=Y`
3. **销售价自动带出**：选择客户+商品后，自动查询客户价格组中该商品的价格
   - 第一优先：`base_price_group_item.price`（客户价格组 → `base_customer.price_group_code` → 查 `base_price_group_item` 中 `goods_code + price_group_code + unit_level=1`）
   - 第二兜底：该客户最近一次销售单价（`sales_order_detail` JOIN `sales_order`，按 `customer_code + goods_code`）
   - 第三兜底：`base_goods.suggested_retail_price` 或 `base_goods.standard_price`
   - 已有 API 可复用：`GET /base/goods/latest-sales-price?goodsCode=X&customerCode=Y`
4. **税率自动带出**：选择商品后从 `base_goods.tax_rate` 自动带出，每行独立
5. **毛利实时计算**：`毛利 = 销售总额 - 采购总额`，底部实时显示
6. **价格可编辑**：自动带出后仍可手动修改（飞单场景价格灵活）
7. **保存并审核**：一步到位，创建飞单后直接调用审核接口
8. **关联单据跳转**：审核后的飞单在列表中可点击关联采购单号/销售单号跳转

## 七、统计影响分析（飞单不写出入库单据是否影响数据统计）

### 结论：**不影响**。所有统计报表查询的是订单表和财务表，不是出入库单据。

### 详细分析

对系统中全部 12 个统计/报表接口逐一核查，数据源如下：

| 统计维度          | 接口路径                               | 查询的表                                    |    飞单是否写入    | 影响              |
| ------------- | ---------------------------------- | --------------------------------------- | :----------: | --------------- |
| **销售汇总**（仪表盘） | `/report/dashboard/summary`        | `sales_order`                           |    ✅ 审核时生成   | 无 — 飞单的销售订单会被统计 |
| **销售明细报表**    | `/report/sales/page`               | `sales_order`                           |       ✅      | 无               |
| **销售趋势图**     | `/report/chart/sales-trend`        | `sales_order` WHERE status ≠ 'DELETED'  | ✅ (APPROVED) | 无               |
| **客户销售排行**    | `/report/chart/customer-sales`     | `sales_order` WHERE status ≠ 'DELETED'  |       ✅      | 无               |
| **品类销售排行**    | `/report/chart/category-sales`     | `sales_order_detail` JOIN `sales_order` |       ✅      | 无               |
| **采购汇总**（仪表盘） | `/report/dashboard/summary`        | `pur_order`                             |    ✅ 审核时生成   | 无               |
| **采购明细报表**    | `/report/purchase/page`            | `pur_order`                             |       ✅      | 无               |
| **采购趋势图**     | `/report/chart/purchase-trend`     | `pur_order` WHERE status ≠ 'DELETED'    |       ✅      | 无               |
| **库存汇总**（仪表盘） | `/report/dashboard/summary`        | `inv_stock_balance`                     |     ❌ 不写     | 无 — 正确行为，商品没进仓库 |
| **库存明细报表**    | `/report/stock/page`               | `inv_stock_balance`                     |     ❌ 不写     | 无               |
| **库存分布图**     | `/report/chart/stock-distribution` | `inv_stock_balance`                     |     ❌ 不写     | 无               |
| **应收汇总**      | `/report/dashboard/summary`        | `fin_ar`                                |    ✅ 审核时生成   | 无               |
| **应付汇总**      | `/report/dashboard/summary`        | `fin_ap`                                |    ✅ 审核时生成   | 无               |
| **财务明细报表**    | `/report/finance/page`             | `fin_ar` UNION ALL `fin_ap`             |       ✅      | 无               |
| **财务概览图**     | `/report/chart/finance-overview`   | `fin_ar` + `fin_ap`                     |       ✅      | 无               |

### 关键发现

1. **出入库单据不参与任何统计报表**。`sales_outbound`（出库单）和 `purchase_inbound`（入库单）仅在自己的 Controller 中被读写，没有任何报表接口查询它们。
2. **销售统计查 `sales_order`**：飞单审核生成 APPROVED 状态的销售订单，所有销售统计自动包含。
3. **采购统计查 `pur_order`**：飞单审核生成 APPROVED 状态的采购订单，所有采购统计自动包含。
4. **库存统计查 `inv_stock_balance`**：飞单不写库存表，库存统计正确地不包含飞单商品（因为商品从未进入仓库）。
5. **利润统计当前是硬编码 `amount * 0.12`**：不使用真实成本数据，这是全局已有问题，非飞单引入。飞单的 `sales_order.cost_amount` 已记录真实采购成本，后续可优化利润统计为 `amount - cost_amount`。

### 总结

```
飞单审核后生成的单据：
  ✅ sales_order (APPROVED)     → 销售统计 ✅ 包含
  ✅ pur_order (APPROVED)       → 采购统计 ✅ 包含
  ✅ fin_ar (未收)              → 应收统计 ✅ 包含
  ✅ fin_ap (未付)              → 应付统计 ✅ 包含
  ❌ inv_stock_balance          → 库存统计 ✅ 不包含（正确，商品没进仓库）
  ❌ sales_outbound / purchase_inbound → 无报表查询这些表，无影响
```

**飞单不写出入库单据，对现有数据统计零影响。**

## 八、风险与注意事项

| 风险              | 缓解措施                                                          |
| --------------- | ------------------------------------------------------------- |
| 反审核时关联单据已被付款/收款 | 反审核前检查 `fin_ap.paid_amount` 和 `fin_ar.received_amount`，有记录则拒绝 |
| 采购订单/销售订单被独立修改  | 飞单关联的单据 `remark` 标记来源为"飞单生成"，独立编辑时提示                          |
| 供应商无历史采购价       | 兜底 `base_goods.latest_purchase_price`，再兜底为 0，用户手动填写           |
| 客户价格组未配置该商品     | 兜底客户最近售价，再兜底 `base_goods.suggested_retail_price`，再兜底为 0       |
| H2 SQL 兼容性      | 迁移脚本使用 H2 MODE=MySQL 兼容语法，DECIMAL/DATE/TIMESTAMP 标准类型         |

## 九、权限设计（独立权限点）

飞单模块使用独立权限，不复用销售模块权限。

### 9.1 权限点定义

在 Spring Security 授权规则中新增飞单相关路径：

| 权限点               | 路径模式                                                           | 说明        |
| ----------------- | -------------------------------------------------------------- | --------- |
| `flyOrder:view`   | `GET /sales/fly-order/page`, `GET /sales/fly-order/detail`     | 查看飞单列表和明细 |
| `flyOrder:create` | `POST /sales/fly-order/create`                                 | 新建飞单      |
| `flyOrder:audit`  | `POST /sales/fly-order/audit`, `POST /sales/fly-order/unaudit` | 审核/反审核飞单  |
| `flyOrder:cancel` | `POST /sales/fly-order/cancel`                                 | 作废飞单      |
| `flyOrder:delete` | `DELETE /sales/fly-order/delete`                               | 删除飞单      |

### 9.2 前端菜单权限

前端 `fallback-menus.js` 中飞单菜单已有，通过用户角色控制是否显示。菜单可见性绑定 `flyOrder:view` 权限。
