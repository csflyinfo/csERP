# 优化记录：商品分类记录表格固定，纵向滚动条移到网格内部

- 分支：`fix/base-category-grid-inner-scroll`
- 迁移：无（纯前端样式修复）
- 需求来源：用户反馈（商品分类优化第 2 轮）
- 影响范围：所有走 `GenericBusinessList.vue` 的左树右表/列表页（`.module-list` 仅该组件使用）
- 验收方式：Edge headless + CDP 断言（仓库外 `e:\work\verify-grid-scroll.mjs`）+ 1600×900 截图肉眼确认

## 1. 问题

商品分类 480 条、选中某一级分类后右侧也有 81 行，行数超出视口时纵向滚动条出现在**整个窗口的内容区**（`.content`），表头、查询栏、分页栏都随页面滚走，需要回到顶部才能翻页/查询。

## 2. 根因

高度链只差一环：`.tablebox`（flex:1 + min-height:0 + overflow:hidden）和 `.scroll`（flex:1 + overflow:auto）本来就是按「表头吸顶、网格内部滚动」设计的（`thead th { position: sticky; top: 0 }` 也已就位），但它们的祖先 `.module-list` 作为 flex/grid 子项缺少 `min-height: 0`，默认 `min-height: auto` 被 80+ 行表格撑到 2870px，导致：

- `.module-list` / `.tablebox` / `.scroll` 全部被撑成内容高，`.scroll` 自身 `scrollHeight == clientHeight` 不产生滚动条；
- 撑破传导到 `.content`（overflow:auto），滚动最终落在窗口内容区。

实测（headless 视口高 487，选中「休闲零食」81 行）：修复前 `.content` 439→scroll 2876；修复后 439→439，`.scroll` 181→scroll 2625。

## 3. 改动

`frontend/src/styles/app.css` 一行：

```css
/* 前 */ .module-list{min-width:0;display:flex;flex-direction:column;flex:1}
/* 后 */ .module-list{min-width:0;min-height:0;display:flex;flex-direction:column;flex:1}
```

修复后布局：操作按钮栏、QueryBar、表头、分页栏全部固定不动；仅表格网格体（`.scroll`）内部纵向滚动，表头 sticky 吸顶，横向超宽时滚动条同样在网格内。`.content` 的 `overflow:auto` 保留，不影响其他页面。

## 4. 验收结果（2026-09-13，5173 + 8080，admin）

- ✅ 选中「休闲零食」（81 行）：窗口/`.content` 无滚动条；滚动条只在网格内；网格内滚动 320px 表头位置不动；分页栏贴底常驻
- ✅ 「全部分类」（480 条，100 行/页）：同样只有网格内部滚动
- ✅ 商品档案（无树模块）回归：窗口不滚动，网格与分页栏正常
- ✅ 仪表盘等非 `.module-list` 页面不受影响
- ✅ 1600×900 截图确认：左树、查询栏、表头、分页栏全固定，数据行在网格内滚动
- ✅ `npm run build` 通过
