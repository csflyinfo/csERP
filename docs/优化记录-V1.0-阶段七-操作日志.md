## 一、背景与目标

PRD 要求：**所有业务操作可追溯**——增、删、改、查、导入、导出、打印全部记日志；修改留改前/改后值；
每张业务单据能查看自己的操作记录；日志集中可查、可配置保留天数自动清理；登录独立成表；敏感操作可标记、
成本/价格对非管理员脱敏。

旧实现的问题：18 份逐字复制的私有 `log()` 直接 INSERT，操作人硬编码「系统管理员」，无改前改后、无 IP/耗时、
无单据类型、无真实操作人；财务/盘点/成本调整/飞单/导入导出等 10+ 模块完全不写日志。

**本期范围（已确认）**：统一底座 + 采购/销售/库存/财务/基础资料五大块；TMS/WMS 仍走 `TmsUtil.log`（新列留空、
向后兼容，下一轮再委托）。「查」只记单据详情查看（受参数开关控制，敏感模块恒记）；列表/搜索/刷新不记。

## 二、数据库（Flyway V92，幂等 `IF NOT EXISTS`）

- 扩展 `sys_operation_log_runtime`：新增 `operator_id / operator_account / module_name / action_name /
  biz_type / biz_id / request_ip / request_url / request_method / cost_time_ms / fail_reason / sensitive /
  before_value(CLOB) / after_value(CLOB) / operation_content`；旧 `detail` 列保留兼容存量与 TMS。
- 索引：`idx_log_biz(biz_type,biz_no)`（单据时间线）、`idx_log_operator(operator_account)`、`idx_log_sensitive(sensitive)`。
- 新建 `sys_login_log`：登录/登出、成功失败、IP、UA、应用类型。
- 系统参数：`OP_LOG_RETENTION_DAYS=180`、`LOGIN_LOG_RETENTION_DAYS=180`、`OP_LOG_ENABLE_DETAIL_VIEW=0`、
  `OP_LOG_SLOW_THRESHOLD_MS=3000`（参数组「日志与安全」）。

## 三、后端统一底座（包 `com.erp.system`，不引新依赖、无 AOP）

- `common/util/RequestContext.java`：ThreadLocal 持账号/姓名/IP/URI/method/起始时间。
- `auth/RequestContextFilter.java`：`OncePerRequestFilter`，请求前填上下文、finally 清理、永不抛异常。
- `system/OperationLogService.java`（核心）：
  - 所有写入 `REQUIRES_NEW` 独立事务 + 整体 try/catch，**审计失败绝不影响业务**；业务回滚后审计仍保留。
  - 真实操作人：账号取 JWT/SecurityContext，姓名优先 JWT claim、回落 `sys_user_runtime` 查库（带缓存），无上下文记 SYSTEM。
  - 自动填充 logId、operate_at=完成时刻、cost_time_ms、IP/URL/method。
  - `logUpdate`：仅对 `KeyFields` 关键字段做字段级 diff，生成 `operation_content` 摘要与 before/after JSON；
    明细按行级 diff（新增/修改/删除，按 detail_id 优先 goods_code 配对）；备注等非关键字段变化只标「非关键字段有修改」；
    命中敏感字段（成本/采购价/价格体系/信用额度）整条 `sensitive=Y`；password/token/secret/pwd 一律 `***`。
  - 便捷方法：`log / logSensitive / logFail / logView（受开关控制）/ logUpdate`。
- `OperationAction.java` / `OperationModule.java`：动作码、点分模块码 + 中文名；历史大写下划线码与各控制器
  旧字符串（`inventory.otherInbound`、`purchase.return.apply`、`sales.rejectInbound` 等）全部补中文名映射。
- `KeyFields.java`：各业务对象关键字段清单（商品/客户/供应商/仓库/采购订单/销售订单主表 + 订单明细行），
  以及 `BIZ_*` 单据类型常量、敏感字段集合。
- `LogCleanupTask.java`：每日 03:30 按保留天数清理两张表（Java 层算截止时间、分批删），清理后写一条 CLEANUP 日志。
- `OperationLogController.java`（业务用户，`/operation-log/**`，登录即可）：`bill-timeline`（按 biz_type+biz_no
  时间正序，含 diff，非管理员敏感字段脱敏）、`print`、`export` 打点。
- `SystemLogController.java`（管理员，`/system/**` ADMIN）：操作日志 SQL 分页/详情/导出/手动清理、登录日志分页/导出。
  > CLOB 列（before_value/after_value）必须 `rs.getString()` 读取——`getObject()` 返回 `JdbcClob`，强转 String 会
  > ClassCastException，被全局吞成「系统繁忙」500。
- `AuthController.java`：登录成功/失败、登出写 `sys_login_log`，不再双写操作日志。

## 四、核心模块迁移

### 样板（阶段六已验证）
- `sales/OrderController.java`、`purchase/OrderController`（采购/销售订单）：CREATE 普通日志；UPDATE/AUDIT
  走 `logUpdate`。**改后快照必须在同事务内回查持久化状态**（`orderHeadForLog/orderLinesForLog`），不能用请求体手拼，
  否则字段/格式不一致会产生假 diff。

### 铺开（本阶段）

**Tier 1 —— 私有 `log()` 委托统一服务**（真实操作人/IP/耗时/中文名/单据时间线，调用点零改动）：
注入 `OperationLogService`，私有 `log()` 改为 `opLog.log(模块码, action, bizType, null, bizNo, detail)`：

| 控制器 | 模块码 | bizType |
|---|---|---|
| inventory/OtherInboundController | inventory.otherInbound | other_inbound |
| inventory/OtherOutboundController | inventory.otherOutbound | other_outbound |
| inventory/DamageController | inventory.damage | damage |
| transfer/TransferController | transfer.apply/inbound/outbound | transfer |
| purchase/PurchaseController | purchase.inbound | purchase_receipt |
| purchase/PurchaseReceiptController | purchase.receipt | purchase_receipt |
| purchase/PurchaseReturnController | purchase.return(.apply/.outbound) | purchase_return |
| sales/SalesOutboundController | sales.outbound | sales_outbound |
| sales/SalesReceiptController | sales.receipt | sales_receipt |
| sales/SalesReturnController | sales.return(.inbound/.order) | sales_return |
| sales/RejectInboundController | sales.rejectInbound | reject_inbound |
| base/BaseMasterController | base.<module> | base_<module>（customer/supplier 与 BaseController 对齐） |

**Tier 2 —— 基础资料改前改后**（`base/BaseController.java`）：
商品/客户/供应商/仓库 的 create 记 CREATE 普通日志；update / stop(停用) / delete(软删) 走 `logUpdate`
（停用 DISABLE、删除 DELETE、冻结 DISABLE）。快照来源 = **实体对象经 Jackson 转蛇形 key Map**（只含真实字段、
改前改后同构、无 SQL 列名风险）；改后在 update 后回查持久化实体。成本/标准售价/最低售价/建议零售价/信用额度
等敏感字段变化自动 `sensitive=Y`。

**新增/补齐日志**：
- `inventory/StockTakeController.java`：盘点 新建/录入实盘/审核/反审核/删除（模块 inventory.stock-take，bizType stock_take）。
- `inventory/InventoryController.java`：**成本调整审核 = `logSensitive`（敏感，模块 inventory.cost-adjust）**；
  库存调拨审核普通日志。
- `finance/FinanceController.java`：收款单/付款单/费用单 新建/修改/删除/审核/反审核/批量审核，应收应付核销
  （ar/settle、ap/settle、reconcile/receive|pay、receipt/reconcile）记 WRITE_OFF。财务原有 0 行日志。
- `sales/FlyOrderController.java`：快速开单（飞单）新建/修改/审核/反审核/作废/删除/批量/导出；日志文案不含采购价/利润。
- `system/ExcelController.java`：通用导入记 IMPORT（含成功/失败行数）、通用导出记 EXPORT。
- `report/ReportController.java`：报表导出委托统一服务（原硬编码「系统管理员」）。

## 五、前端（Vue 3 手写，无 Element Plus）

- 管理端操作日志页：操作人显示**账号**（名称回落）；去掉「操作内容」列，操作列只留「详情」，点击开详情抽屉看改前改后。
- `components/OperationLogTimeline.vue`：单据内操作记录时间线改为**右侧 1/4 宽小抽屉**（25vw，min 320/max 480），
  点击遮罩空白处自动关闭；敏感字段对非管理员显示 `***`。
- `views/GenericBusinessList.vue`：
  - `BIZ_TIMELINE_MAP` 从仅采购/销售订单扩到**全部业务单据 + 基础资料**（采购入库/收货/退货、销售出库/签收/退货/拒收、
    其他入出库、报损、盘点、调拨、收款/付款/费用、快速开单、商品/客户/供应商/仓库），每行「记录」按钮打开该单据时间线。
  - `OP_MODULE_CODE` 打点归因补全；`rowBizNo/rowBizId` 按各类单号字段候选提取、回落首列。
  - 导出/打印 fire-and-forget 打点（失败静默）。

## 六、安全与脱敏

- `/system/**` 仅 ADMIN；`/operation-log/**` 登录用户即可（单据用户看自己单据的时间线）。
- 敏感日志 `sensitive=Y`；非管理员在时间线/详情接口看到的敏感字段值由后端脱敏为 `***`。
