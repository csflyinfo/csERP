## 1. 业务背景与设计目标

### 1.1 业务背景

商贸经销商的日常配送中，销售退货是高频业务。典型场景：

- 客户因质量问题、错发、过期、个人原因等提出退货
- 配送司机上门送货时同步回收退货商品，并现场退还货款
- 退回商品需经仓库验收质检后才能确认入库
- 财务需要准确冲减收入、回冲成本、处理退款资金流

实际业务中存在两个关键现实：

1. **大部分退货对不上原订单**——客户说"上次那批货有两箱坏的"，但"上次"可能是多张单子混在一起的，无法精确关联。
2. **司机现场即退款**——司机上门时客户把货退给司机，司机当场退现金，不可能"回仓验完再退"。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 全链路可追溯 | 从客户退货到财务关账，每一步有单据、有责任人、有时间戳 |
| 财务准确 | 库存、收入、成本、资金流四账合一，月结无差异 |
| 灵活适配 | 支持按单退货和不按单退货，支持不同入账方式 |
| 低系统复杂度 | 复用现有单据类型，不新增特殊单据类型，差异处理不调账 |
| 职责清晰 | ERP 管资金流，WMS 管实物流，TMS 管配送流，各司其职 |

## 2. 业务场景概述

### 2.1 退货原因分类

| 原因码 | 说明 | 后续链路影响 |
|--------|------|-------------|
| 质量问题 | 商品过期、变质、破损等 | 可能触发供应商索赔 |
| 错发 | 发错商品或规格 | 正常入库，重新发货 |
| 多发 | 发货数量超出订单 | 正常入库 |
| 客户原因 | 客户不需要了、下错单 | 正常入库 |
| 运输损坏 | 配送途中损坏 | 司机责任或物流索赔 |

### 2.2 退货模式

| 模式 | 说明 | 占比（经验值） | 退款单价来源 |
|------|------|--------------|-------------|
| 按单退货（ORDER_BASED） | 关联原销售订单，退款单价取原订单行单价 | ~20% | 原订单行单价 |
| 按品退货（GOODS_BASED） | 不关联原订单，直接选商品退货 | ~80% | 客户价格组当前售价 |

> **设计要点**：两种模式共存，不强制按单。按品退货需主管审批，退款单价取"客户价格组当前售价"与"商品最低售价"的较大值。

## 3. 全链路流程总览

退货全链路分为四个阶段，每阶段有独立的责任主体和状态机：

| 阶段 | 责任主体 | 所属系统 | 触发时机 | 关键产物 |
|------|---------|---------|---------|---------|
| ① 退货申请 | 销售客服 | ERP | 客户提出退货 | 退货单（已审核） |
| ② 司机回收 | 配送司机 | TMS / PDA | 线路任务推送 | 回收任务（已回收） |
| ③ 仓库验收 | 仓库人员 | WMS | 司机交回仓库 | 验收单（已验收） |
| ④ 财务结算 | 财务 | ERP | 验收确认 / 司机签收 | 会计凭证 |

**核心设计原则**：

- 退货必须关联原销售订单（按单模式）或选择商品+客户（按品模式），不允许无源退货
- 退货数量受控：按单模式 ≤ 原订单已出库数量 − 已退数量
- 司机回收时现场退款，日终轧差上缴
- 差异处理不调账，用正常业务单据补差
- 残次品处理是 WMS 物理管理，与财务入账解耦

## 4. 阶段一：退货申请

### 4.1 操作流程

```
客服创建退货单
  ├─ 选择退货模式（按单 / 按品）
  ├─ 选择客户
  ├─ [按单] 选择原销售订单 → 自动带出商品明细和单价
  ├─ [按品] 选择商品 → 取客户价格组当前售价作为退款单价
  ├─ 填写退货原因（必选）
  ├─ 填写期望退货数量（按单模式受可退数量限制）
  ├─ 选择预期退回仓库
  └─ 提交审核

主管审核
  ├─ [按单] 常规审核
  ├─ [按品] 强制主管审批
  └─ 审核通过 → 锁定可退数量 → 推送 TMS
```

### 4.2 退货单字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| returnId | String | 是 | 退货单号，系统生成 |
| returnMode | Enum | 是 | ORDER_BASED / GOODS_BASED |
| customerId | String | 是 | 客户ID |
| originOrderId | String | 按单必填 | 原销售订单ID，按品模式为空 |
| priceGroupId | String | 按品必填 | 客户价格组ID，用于取退款单价 |
| returnReason | Enum | 是 | 退货原因码 |
| expectedReturnDate | Date | 是 | 期望回收日期 |
| accountingTrigger | Enum | 否 | 入账方式覆盖（见第8章） |
| needApproval | Boolean | 是 | 是否需审批，按品模式自动为 true |
| status | Enum | 是 | 单据状态（见第12章） |

### 4.3 退货明细字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| goodsId | String | 是 | 商品ID |
| originOrderDetailId | String | 按单必填 | 原订单明细ID，按品模式为空 |
| expectedQty | Decimal | 是 | 期望退货数量 |
| unitPrice | Decimal | 是 | 退款单价（按单取原订单，按品取价格组） |
| warehouseId | String | 是 | 预期退回仓库 |

### 4.4 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| R-001 | 按单退货数量 ≤ 原订单已出库数量 − 已退数量 |
| R-002 | 按品退货退款单价 = MAX(客户价格组当前售价, 商品最低售价) |
| R-003 | 按品退货必须填写退货原因，且不允许选"其他" |
| R-004 | 审核通过后锁定可退数量，防止重复退货 |
| R-005 | 退货单审核后自动推送 TMS，生成回收任务 |

## 5. 阶段二：司机回收

### 5.1 操作流程

退货任务嵌入配送线路，不单独派车。司机在配送过程中顺路回收退货：

```
系统推送回收任务到司机PDA（关联配送线路）
  ↓
司机到达客户处
  ├─ 扫码确认退货单
  ├─ 逐品核对商品和数量
  ├─ 拍照留底（每箱拍照）
  ├─ 客户签字确认
  ├─ 现场退还货款（现金/COD抵扣）
  └─ PDA 提交回收确认
```

### 5.2 回收任务字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| taskId | String | 是 | 回收任务ID |
| returnOrderId | String | 是 | 关联退货单 |
| routeId | String | 是 | 关联配送线路 |
| driverId | String | 是 | 司机ID |
| status | Enum | 是 | PENDING → COLLECTING → COLLECTED |
| collectTime | DateTime | 是 | PDA提交时间 |
| actualQty | Decimal | 是 | 实际回收数量（可部分回收） |
| refundAmount | Decimal | 是 | 实际退款金额 |
| rejectReason | String | 否 | 拒收原因 |
| photos | Array | 是 | 拍照留底（URL列表） |
| signImage | String | 是 | 客户签字图片URL |

### 5.3 司机日终轧差上缴

司机一天的业务包含 COD 收款和退货退款，采用**轧差上缴**模式：

```
司机当日业务：
  COD 收款合计    ¥10,000（送10单货）
  退货退款合计    ¥2,000（退3单货）
  ────────────────────────
  日终上缴净额    ¥8,000
```

**关键原则**：司机端（TMS）只记流水，不做会计凭证。财务端（ERP）日终拉司机结算单，一次生成全部凭证。

### 5.4 司机结算单字段

| 字段 | 类型 | 说明 |
|------|------|------|
| settlementId | String | 结算单ID |
| driverId | String | 司机ID |
| routeId | String | 配送线路ID |
| settlementDate | Date | 结算日期 |
| codCollections | Array | COD 收款流水（orderId, amount） |
| returnRefunds | Array | 退货退款流水（returnId, amount） |
| totalCollected | Decimal | 收款合计 |
| totalRefunded | Decimal | 退款合计 |
| netAmount | Decimal | 实缴金额 = 收款 - 退款 |
| status | Enum | SUBMITTED → VERIFIED |

### 5.5 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| R-006 | 回收任务必须关联配送线路，不单独派车 |
| R-007 | 实际回收数量 ≤ 退货单期望数量，司机可部分拒收 |
| R-008 | PDA 提交时每箱必须拍照，照片关联到回收明细 |
| R-009 | 回收完成 → 退货单状态变为"已回收(在途)"，但**不更新库存**（仓库入库入账模式） |
| R-010 | 在途期间责任归属司机，丢失走司机赔偿流程 |
| R-011 | 司机端不做会计分录，日终轧差上缴后由 ERP 统一记账 |

## 6. 阶段三：仓库验收

### 6.1 操作流程

```
司机回仓交货
  ↓
仓库收货清点（核对接收数量）
  ↓
质检分流
  ├─ 合格品 → 上架正常库位 → 库存增加
  ├─ 残次品 → 移入残次库区 → 后续处置
  └─ 报废品 → 移入报废区 → 后续报损
  ↓
验收确认 → 回调 ERP
```

### 6.2 三个关键数量

整条链路上有三个关键数量，每个有不同责任人签字：

| 数量 | 确认人 | 含义 | 用途 |
|------|--------|------|------|
| collectedQty | 司机（客户签字） | PDA 确认的回收数量 | 退款基准 |
| receivedQty | 仓库收货员 | 仓库实收数量 | 实物交接 |
| acceptedQty | 质检员 | 质检合格数量 | 入库基准 |

差异检测：

| 比对 | 差异含义 | 责任区间 |
|------|---------|---------|
| collectedQty ≠ receivedQty | 数量缺失——司机收了10箱，仓库只收到8箱 | 司机在途责任 |
| receivedQty ≠ acceptedQty | 品质差异——收了8箱，合格只有7箱 | 质检判定 |
| collectedQty 品种 ≠ receivedQty 品种 | 品种错误——扫码扫错或客户调包 | 司机/客户 |

### 6.3 验收单字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| receiptId | String | 是 | 验收单ID |
| returnOrderId | String | 是 | 关联退货单 |
| collectionTaskId | String | 是 | 关联回收任务 |
| warehouseId | String | 是 | 验收仓库 |
| inspectorId | String | 是 | 质检员ID |
| status | Enum | 是 | PENDING → INSPECTING → ACCEPTED |
| hasDiscrepancy | Boolean | 是 | 是否有差异 |

### 6.4 验收明细字段

| 字段 | 类型 | 说明 |
|------|------|------|
| goodsId | String | 商品ID |
| collectedQty | Decimal | 司机回收数 |
| receivedQty | Decimal | 仓库实收数 |
| acceptedQty | Decimal | 质检合格数 |
| rejectedQty | Decimal | 残次数（入残次库区） |
| scrappedQty | Decimal | 报废数（入报废区） |
| targetLocationId | String | 上架库位 |

### 6.5 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| R-012 | 合格品入库按当前移动加权平均成本计算入库价值，不按原出库成本 |
| R-013 | 验收确认后回调 ERP，触发财务模块 |
| R-014 | 残次品入退货暂存区，不入正式库位 |
| R-015 | 质检分流是 WMS 内部操作，不触发任何会计凭证 |

## 7. 阶段四：财务结算

### 7.1 触发时机

财务结算的触发时机取决于入账方式配置（见第8章）：

| 入账方式 | 触发时机 | 入账数量基准 |
|---------|---------|------------|
| 司机签收入账 | PDA 提交回收确认时 | collectedQty |
| 仓库入库入账 | 仓库验收确认时 | acceptedQty |

### 7.2 财务处理内容

| 处理项 | 说明 |
|--------|------|
| 成本回冲 | 合格入库商品按当前移动加权平均成本回冲主营业务成本 |
| 收入冲减 | 按退款单价冲减主营业务收入和销项税 |
| 资金流出 | 司机退款现金，日终轧差上缴 |
| 退货成本差异 | 入库成本与原出库成本的差额，记入"退货成本差异"科目 |

### 7.3 成本回冲规则

退货入库按**当前移动加权平均成本**计算，不按原出库成本。

示例：某商品 1 月出库时均价 ¥10，3 月退货时均价已变为 ¥12。入库按 ¥12 计算，差异 ¥2/件记入"退货成本差异"科目。

> **设计理由**：库存成本始终反映当前行情，审计合理。商贸行业标准做法。

## 8. 入账方式可配置设计

### 8.1 设计方案

系统支持两种入账方式，由用户自行选择：

| 模式 | 说明 | 凭证生成时机 | 差异处理方式 |
|------|------|------------|------------|
| 模式A：司机签收入账 | PDA 提交即生成会计凭证 | 司机回收时 | 差异用正常单据补差，不调账 |
| 模式B：仓库入库入账（默认推荐） | 验收确认才生成会计凭证 | 仓库验收时 | 差异在入账前已解决 |

### 8.2 配置层级

```
系统级配置（系统参数表）
  return_accounting_trigger: DRIVER_COLLECTION | WAREHOUSE_RECEIPT
      ↓ 可被覆盖
退货单级配置（退货单字段）
  accountingTrigger: DRIVER_COLLECTION | WAREHOUSE_RECEIPT | null
      ↓ null 时取系统级配置
```

### 8.3 两种模式对比

| 维度 | 模式A：司机签收入账 | 模式B：仓库入库入账 |
|------|-------------------|-------------------|
| 凭证生成时机 | PDA 提交即入账 | 仓库验收确认才入账 |
| 入账数量基准 | collectedQty（司机确认数） | acceptedQty（验收合格数） |
| 差异处理 | 事后用正常单据补差 | 事前在入账前解决 |
| 在途期间 | 无挂账，钱和账同时走 | 有挂账，钱已退但凭证未生成 |
| 会计复杂度 | 低——不调账，用新单据补差 | 低——一步到位 |
| 适用场景 | 快消品、信任司机、无质检 | 大宗商品、需质检、财务严格 |

### 8.4 模式A的核心优势：差异不调账

**模式A 下，差异不需要"调整"已有凭证，而是用正常的业务单据"补"出去。原始退货凭证不动，用新单据自然把账拉平。**

示例：司机收10箱退款¥200，回仓只到8箱，2箱司机丢失。

| 步骤 | 单据 | 会计分录 |
|------|------|---------|
| ① 司机签收入账 | 退货单 | 借:库存商品¥110 贷:主营业务成本¥110 / 借:主营收入¥171+销项税¥29 贷:库存现金¥200 |
| ② 回仓验收差异 | 验收单（标记差异） | 无凭证（仅操作记录） |
| ③ 司机买赔 | 销售出库单（客户=司机） | 借:应收-司机¥40 贷:主营收入¥34+销项税¥6 / 借:主营成本¥22 贷:库存商品¥22 |

最终账面验证：

| 科目 | 退货单(10箱) | 司机买赔销售单(2箱) | 净额 | 实际应该 |
|------|-------------|-------------------|------|---------|
| 库存商品 | +¥110 | -¥22 | +¥88 | 8箱×¥11=¥88 ✓ |
| 主营业务成本 | -¥110 | +¥22 | -¥88 | 退8箱成本 ✓ |
| 主营业务收入 | -¥171 | +¥34 | -¥137 | 退8箱收入 ✓ |
| 销项税 | -¥29 | +¥6 | -¥23 | 退8箱税 ✓ |
| 库存现金 | -¥200 | — | -¥200 | 退了¥200 ✓ |
| 应收账款-司机 | — | +¥40 | +¥40 | 司机欠¥40 ✓ |

> **结论**：不需要任何"调整凭证"，全靠正常业务单据自然拉平。

### 8.5 模式B的差异处理

模式B 下，入账前已按实际验收数确认，差异在入账前处理完毕：

- 入账按 acceptedQty（验收合格数），一步到位
- 差异 2 箱在入账前通过差异记录确认责任方，开销售单处理
- 入账凭证 + 差异销售单 = 完整账务

## 9. 差异处理机制

### 9.1 核心原则

**差异不调账，用正常单据补差。**

差异处理不生成特殊的"调整凭证"，而是通过创建正常的业务单据（销售单、采购退货单等）来处理。原始退货凭证保持不动。

### 9.2 差异类型与处理方式

| 差异类型 | 责任方 | 处理单据 | 财务影响 |
|---------|--------|---------|---------|
| 数量缺失——司机丢失 | 司机 | 销售出库单（客户=司机，司机买赔） | 借:应收-司机 贷:主营收入+税 / 借:主营成本 贷:库存商品 |
| 数量缺失——客户少退 | 客户 | 销售出库单（客户补购） | 借:应收-客户 贷:主营收入+税 / 借:主营成本 贷:库存商品 |
| 品质差异——运输损坏 | 司机 | 销售出库单（司机买赔残次品）或报损单 | 借:应收-司机 贷:库存商品 |
| 品质差异——原厂质量问题 | 供应商 | 采购退货单（向供应商退货） | 借:应付-供应商 贷:库存商品 |
| 品种错误——司机扫错 | 司机 | 撤销退货明细 + 销售单追回 | 退款追回，重新处理 |
| 品种错误——客户调包 | 客户 | 撤销退货明细 + 销售单追回 | 退款追回 |

> **设计要点**：全部复用现有单据类型（销售出库单、采购退货单、报损单），零新增单据类型。

### 9.3 差异处理记录（流程追踪，非财务单据）

差异处理需要一个**操作层面的记录**用于流程追踪，但它不是财务单据，不生成凭证：

| 字段 | 类型 | 说明 |
|------|------|------|
| recordId | String | 差异记录ID |
| returnOrderId | String | 关联退货单 |
| receiptId | String | 关联验收单 |
| diffType | Enum | QTY_MISSING / WRONG_ITEM |
| diffQty | Decimal | 差异数量 |
| responsibleParty | Enum | DRIVER / CUSTOMER |
| resolutionDocType | Enum | SALES_ORDER / PURCHASE_RETURN / SCRAP |
| resolutionDocId | String | 处理单据ID |
| status | Enum | PENDING → RESOLVED |

### 9.4 差异处理流程

```
仓库验收发现差异
       ↓
系统自动生成差异处理记录 (status: PENDING)
       ↓
主管审核 → 判定责任方
       ↓
  ┌──────────────────────────┐
  │ 责任方确认                │
  ├──────────────────────────┤
  │ 司机认可 → 开销售单给司机  │
  │ 客户追回 → 开销售单给客户  │
  │ 供应商索赔 → 开采购退货单  │
  └──────────────────────────┘
       ↓
关联处理单据 → 差异记录 RESOLVED
       ↓
退货单可 CLOSED
```

> **关键卡点**：差异未解决前，退货单不能关单，财务不能月结。

### 9.5 容差自动处理

对于极小差异，系统设置容差阈值，在阈值内自动按"正常损耗"处理，不走差异流程：

```
if (|collectedQty - receivedQty| / collectedQty ≤ 容差阈值) {
    // 容差内，自动处理
    // 借:销售费用-正常损耗  贷:库存商品
    // 不生成差异记录，仅记录日志
} else {
    // 超出容差，生成差异处理记录
    createDiscrepancyRecord();
}
```

> 容差阈值建议默认 2%，可在系统参数中配置。

### 9.6 品质差异不纳入差异处理流程

**重要**：品质差异（残次品、报废品）完全由 WMS 质检分流处理，不纳入差异处理记录。详见第10章。

## 10. 残次品处理机制

### 10.1 核心原则

**残次品的处理是 WMS 的物理管理职责，与财务入账完全解耦。**

- WMS 质检后决定商品放哪个库区（正常库 / 残次库 / 报废区）
- ERP 入账时按回收/验收数量入账，不区分库区
- 库位是 WMS 的内部管理维度，ERP 不关心
- 后续处置时才通过正常业务单据产生财务影响

### 10.2 WMS 质检分流

```
司机交回商品
  ↓
WMS 质检
  ├─ 合格品 → 上架正常库位 → 库存增加（ERP已入账）
  ├─ 残次品 → 移入残次库区 → 不触发凭证
  └─ 报废品 → 移入报废区 → 不触发凭证
```

### 10.3 后续处置与财务影响

残次品和报废品的后续处置通过正常业务单据走财务：

| WMS 后续操作 | 触发的业务单据 | 财务影响 |
|-------------|-------------|---------|
| 残次品退给供应商 | 采购退货单 | 借:应付-供应商 贷:库存商品 |
| 残次品折价卖给客户 | 销售出库单（特价） | 正常销售分录 |
| 报废处理 | 报损单 | 借:管理费用/营业外支出 贷:库存商品 |
| 残次转合格（返修后） | 库内调拨单 | 无财务影响，仅库位变动 |
| 一直放着不处理 | 无 | 无（账上还是库存） |

### 10.4 WMS 与 ERP 职责边界

| WMS 管的（物理流） | ERP 管的（资金流） |
|-------------------|-------------------|
| 收了多少箱 | 退了多少箱的账 |
| 质检合不合格 | 成本回冲多少 |
| 放哪个库区 | 收入冲减多少 |
| 残次品怎么处置 | 谁欠谁多少钱 |
| 报废还是退供应商 | 凭证怎么生成 |

> **WMS 的质检分流不触发任何会计凭证。** 只有当 WMS 决定处置方式（退供应商/报废/折价销售）时，才在 ERP 里创建对应的业务单据，走标准流程。

## 11. COD 货到付款联动

### 11.1 场景说明

当原销售订单为 COD（货到付款）方式时，退货退款与 COD 收款存在联动关系：

| 原订单状态 | 退货退款处理 |
|-----------|------------|
| COD 未收款（司机未收） | 退货自动取消应收，司机无需退款 |
| COD 已收款（司机已收，未上缴） | 司机从当日收款中直接抵扣退款 |
| COD 已收款且已上缴 | 走正常退货退款流程，从下次收款中抵扣或单独退款 |

### 11.2 司机 COD 全生命周期

```
COD 订单出库 → 司机送货收款 → 客户退货 → 司机现场退款 → 日终轧差上缴
      ↓                              ↓
  借:库存现金                   借:主营收入
  贷:应收-COD                   贷:库存现金

  日终：司机上缴净额 = 收款 - 退款
  总账：借:银行存款(net) | 借:主营收入(refund) | 贷:应收-COD(total)
```

### 11.3 PDA 提示逻辑

司机回收时，PDA 根据原订单支付方式提示：

- COD 未收款 → "此单为 COD，客户未付款，退货后自动取消应收，无需退款"
- COD 已收款 → "此单为 COD，已收款 ¥X，退货需退款 ¥Y"
- 非 COD → 正常退款流程

## 12. 退货单状态机

### 12.1 完整状态流转

```
DRAFT → 客户确认退货
  ↓
SUBMITTED → 客服/主管审核
  ↓
  ├─ (拒绝) → REJECTED → CLOSED
  └─ (通过) → APPROVED → 推送到 TMS
                ↓
             COLLECTING → 司机 PDA 接单
                ↓
             COLLECTED → 司机回仓
                ↓
             RECEIVING → 仓库验收
                ↓
             RECEIVED → 质检完成
                ├─ (有数量差异) → DISCREPANCY_PENDING → 差异处理中
                │      ↓
                │   DISCREPANCY_RESOLVED → 差异已处理
                │      ↓
                │   SETTLED → 财务已结算
                │      ↓
                │   CLOSED
                │
                ├─ (无差异/品质差异) → SETTLED → 财务已结算
                │      ↓
                │   CLOSED
                │
                └─ (全部拒收) → REJECTED → CLOSED
```

### 12.2 状态说明

| 状态 | 说明 | 责任人 |
|------|------|--------|
| DRAFT | 草稿，客服创建中 | 销售客服 |
| SUBMITTED | 已提交，待审核 | 销售客服 |
| APPROVED | 已审核，待回收 | 主管 |
| COLLECTING | 司机已接单，正在回收 | 配送司机 |
| COLLECTED | 司机已回收，在途回仓 | 配送司机 |
| RECEIVING | 仓库验收中 | 仓库人员 |
| RECEIVED | 验收完成 | 仓库人员 |
| DISCREPANCY_PENDING | 有数量差异，待处理 | 主管 |
| DISCREPANCY_RESOLVED | 差异已处理 | 主管 |
| SETTLED | 财务已结算 | 财务 |
| CLOSED | 已关单 | 系统 |
| REJECTED | 已拒绝 | — |

### 12.3 关键卡点

| 卡点 | 规则 |
|------|------|
| 差异未解决不能关单 | DISCREPANCY_PENDING 状态下不能跳到 SETTLED |
| 差异未解决不能月结 | 有 DISCREPANCY_PENDING 状态的退货单时，财务不能月结 |
| 已关单不能修改 | CLOSED 状态的退货单不可编辑、不可反审核 |

### 14.1 三系统职责划分

```
ERP（自营业务核心）
├── 销售退货管理     ← 退货单 CRUD + 审批 + 差异记录追踪
├── 应收账款(AR)      ← COD 应收 / 退货冲减 / 司机应收
├── 成本核算          ← 移动加权平均成本回冲
├── 财务凭证          ← 自动生成借/贷分录
├── 客户价格组        ← 不按单退时取售价
├── 采购退货管理      ← 残次品退供应商

├── 配送线路管理      ← 退货任务嵌入配送线路

WMS（仓储管理）
├── 退货验收          ← 验收单收货 + 三量比对
├── 退货质检分流      ← 合格/残次/报废 三分流
├── 库存余额          ← 合格品入库 库存+
├── 退货暂存区        ← 残次品暂存
├── 报废区            ← 报废品暂存
└── 库内调拨          ← 残次转合格等库位变动
```

### 14.2 差异处理单归属

**差异处理记录放 ERP，不放 WMS。**

| 归属 | 理由 |
|------|------|
| **ERP** | 差异涉及司机赔款（应收）、客户追回（应收）、成本调整（移动加权平均），这些都是 ERP 的职责 |
| WMS | 仅负责检测——验收时比对三量差异，上报信号给 ERP |
| TMS | 仅提供司机结算数据，配合扣款 |

> 差异处理记录不是财务单据，不生成凭证。它是流程追踪记录，挂在 ERP 里跟着退货单走。

## 15. 会计分录参考手册

### 15.1 退货入账分录（模式A：司机签收入账）

按 collectedQty 入账：

```
// 成本回冲
借: 库存商品                    collectedQty × 当前移动加权平均成本
  贷: 主营业务成本              collectedQty × 当前移动加权平均成本

// 收入冲减
借: 主营业务收入                collectedQty × 退款单价 ÷ (1 + 税率)
    应交税费-应交增值税-销项税    collectedQty × 退款单价 × 税率 ÷ (1 + 税率)
  贷: 库存现金                  collectedQty × 退款单价
```

### 15.2 退货入账分录（模式B：仓库入库入账）

按 acceptedQty 入账：

```
// 成本回冲
借: 库存商品                    acceptedQty × 当前移动加权平均成本
  贷: 主营业务成本              acceptedQty × 当前移动加权平均成本

// 收入冲减
借: 主营业务收入                acceptedQty × 退款单价 ÷ (1 + 税率)
    应交税费-应交增值税-销项税    acceptedQty × 退款单价 × 税率 ÷ (1 + 税率)
  贷: 库存现金                  acceptedQty × 退款单价
```

> **模式B 差异**：collectedQty 与 acceptedQty 的差额部分，退款已出但未入账。差额通过差异处理流程开销售单补回。

### 15.3 司机日终上缴分录

```
// 司机上缴净额
借: 银行存款                    netAmount（收款 - 退款）
  贷: 应收账款-COD              totalCollected（收款合计）

// 退货退款部分（已在退货入账时确认，此处不重复）
// 若退货入账时贷方为"库存现金"，此处需调整为"应收账款-COD"
```

### 15.4 差异处理分录——司机买赔

```
// 司机买赔丢失商品（正常销售分录）
借: 应收账款-司机                diffQty × 退款单价
  贷: 主营业务收入              diffQty × 退款单价 ÷ (1 + 税率)
      应交税费-应交增值税-销项税  diffQty × 退款单价 × 税率 ÷ (1 + 税率)

借: 主营业务成本                diffQty × 当前移动加权平均成本
  贷: 库存商品                  diffQty × 当前移动加权平均成本
```

### 15.5 差异处理分录——客户补购

```
// 客户少退，补购商品（正常销售分录）
借: 应收账款-客户                diffQty × 退款单价
  贷: 主营业务收入              diffQty × 退款单价 ÷ (1 + 税率)
      应交税费-应交增值税-销项税  diffQty × 退款单价 × 税率 ÷ (1 + 税率)

借: 主营业务成本                diffQty × 当前移动加权平均成本
  贷: 库存商品                  diffQty × 当前移动加权平均成本
```

### 15.6 残次品处置分录——退供应商

```
// 残次品退给供应商（正常采购退货分录）
借: 应付账款-供应商              rejectedQty × 采购成本
  贷: 库存商品                  rejectedQty × 当前移动加权平均成本
      营业外收入-成本差异        差额（如有）
```

### 15.7 报废品处理分录

```
// 报废处理
借: 管理费用-报废损失            scrappedQty × 当前移动加权平均成本
  贷: 库存商品                  scrappedQty × 当前移动加权平均成本
```

### 15.8 容差内自动处理分录

```
// 正常损耗（容差内）
借: 销售费用-正常损耗            diffQty × 当前移动加权平均成本
  贷: 库存商品                  diffQty × 当前移动加权平均成本
```

### 15.9 退货成本差异分录

当入库成本（当前移动加权平均成本）与原出库成本存在差异时：

```
// 退货成本差异
借: 库存商品                    差异金额（正数：当前成本 > 原成本）
  贷: 主营业务成本-退货差异      差异金额

// 或（当前成本 < 原成本）
借: 主营业务成本-退货差异        差异金额
  贷: 库存商品                  差异金额
```

## 16. 风控与防呆设计

### 16.1 事前防呆

| 防呆措施 | 说明 |
|---------|------|
| PDA 强制拍照 | 司机回收时每箱拍照，照片关联到回收明细。仓库验收时可调出对比 |
| 重量校验 | PDA 输入箱数后提示标准箱重，司机/仓库可过磅核对，磅差超容差触发差异检测 |
| 容差自动处理 | 极小差异（≤2%）自动按正常损耗处理，不走差异流程 |
| 退货原因必填 | 按品退货模式下退货原因必填且不允许选"其他" |

### 16.2 事中控制

| 控制措施 | 说明 |
|---------|------|
| 按单退货数量限制 | ≤ 原订单已出库 − 已退，系统自动校验 |
| 按品退货审批升级 | GOODS_BASED 模式强制主管审批 |
| 退款单价保护 | 按品退货取 MAX(价格组售价, 最低售价)，防止退款高于售价 |
| 可退数量锁定 | 审核通过后锁定，防止重复退货 |

### 16.3 事后监控

| 监控措施 | 说明 |
|---------|------|
| 差异未解决阻止关单 | DISCREPANCY_PENDING 状态的退货单不能关单 |
| 差异未解决阻止月结 | 有未处理差异时财务不能月结 |
| 退货频次监控 | 同一客户短期内大量按品退，触发风控告警 |
| 司机差异率统计 | 统计各司机的差异率，异常者绩效扣分 |

## 附录 B：与账期管理的关联

退货单的结算日期计算遵循《账期管理-产品说明 V1.4》的规则：

| 退货模式 | 结算日期计算规则 |
|---------|---------------|
| 按单退货 | 取原销售订单的结算方式规则 |
| 按品退货 | 按客户账期规则（同销售出库） |
| 货到付款退货 | 按客户签收日（司机回收日） |

退货金额参与应收账款结算，与销售出库、费用单等一起参与月度结算。
