# B2B-ERP-WMS-TMS 全链路系统 — UI设计总纲与设计系统

> 文档版本：v1.0  
> 编写日期：2026-06-13  
> 适用范围：ERP后台、WMS/PDA、TMS司机APP、B2B客户小程序、入驻商后台  
> 设计目标：高效、清晰、可信、低干扰、强状态识别、强数据操作能力

---

## 一、整体设计定位

### 1.1 产品视觉关键词

```text
专业
高效
清晰
可信
低干扰
强数据密度
强状态识别
弱装饰
强操作反馈
```

本系统不适合做成强视觉营销型界面，而应以 **企业级SaaS后台 + 高密度数据表格 + 强业务状态表达 + 高效单据录入** 为主。

### 1.2 设计目标

| 角色 | 设计目标 |
|---|---|
| 内勤 | 快速开单、快速查库存、少鼠标操作 |
| 财务 | 应收应付清晰、结算核销高效、金额准确 |
| 仓库 | 任务清楚、扫码准确、异常明显 |
| 司机 | 操作少、按钮大、签收拒收流程简单 |
| 老板 | 指标清晰、风险突出、经营状态可一眼判断 |
| 客户 | 下单顺、价格库存清楚、订单状态透明 |
| 入驻商 | 商品、订单、结算简单明了 |

### 1.3 避免的设计方向

不建议采用：

- 过度炫酷大屏风格。
- 大面积渐变和装饰图形。
- 过多卡片导致信息密度下降。
- 所有页面都做成低密度留白型界面。
- 图标使用emoji。
- 状态仅靠颜色表达。
- 表格能力弱、字段不可配置。

## 二、总体风格

### 2.1 推荐风格

建议采用：

> 现代企业级SaaS Admin + 高密度业务表格 + 轻量卡片 + 强状态标签

风格参考方向：

- 金蝶云星空的业务完整度。
- SAP Fiori 的状态和流程清晰度。
- 飞书后台的简洁组件。
- Shopify Admin 的卡片化业务表达。
- 现代WMS/TMS系统的任务化设计。

### 2.2 页面气质

| 场景 | 设计气质 |
|---|---|
| ERP后台 | 专业、高密度、可配置、效率优先 |
| WMS PDA | 大按钮、大字体、强反馈、少输入 |
| TMS司机APP | 极简、流程化、少操作、强安全 |
| B2B小程序 | 类电商、清晰价格库存、复购高效 |
| 入驻商后台 | 简化版商家工作台，少模块、强待办 |

## 三、色彩系统

### 3.1 主色

建议主色使用蓝色，体现专业、稳定和可信。

```text
Primary Blue: #2563EB
Alternative Blue: #1677FF
```

使用场景：

- 主按钮
- 当前菜单
- 链接
- 选中状态
- 关键业务动作

| 语义 | 色值建议 | 使用场景 |
|---|---|---|
| 成功 | #16A34A | 已审核、已完成、已签收、已核销 |
| 警告 | #F59E0B | 待审核、临期、库存不足提醒 |
| 危险 | #DC2626 | 逾期、超信用、报损、异常、拒收 |
| 信息 | #0EA5E9 | 配送中、处理中、同步中 |
| 中性 | #64748B | 草稿、关闭、停用、历史状态 |
| 紫色 | #7C3AED | 冻结、锁定、部分完成等辅助状态 |

### 3.3 背景与边框

| Token | 色值 | 用途 |

## 四、字体系统

### 4.1 字体建议

后台Web：

```text
中文：Microsoft YaHei / PingFang SC / Source Han Sans
数字：Tabular Numbers
```

数字列必须使用等宽数字或 tabular numbers，确保金额、数量、库存列对齐稳定。

### 4.2 字号规范

| 场景 | 字号 | 说明 |
|---|---:|---|
| 页面标题 | 20-24px | 页面主标题 |
| 区块标题 | 16-18px | 卡片、分组标题 |
| 表格正文 | 13-14px | ERP后台主要表格 |
| 表单标签 | 13-14px | 输入项标题 |
| 辅助说明 | 12px | 提示、备注、帮助文字 |
| 大屏指标 | 24-36px | 工作台指标卡 |

### 4.3 字重

| 用途 | 字重 |
|---|---:|
| 页面标题 | 600/700 |
| 区块标题 | 600 |
| 表头 | 500/600 |
| 正文 | 400 |
| 数字重点 | 600 |

## 八、通用交互原则

### 8.1 反馈原则

| 操作 | 反馈 |
|---|---|
| 保存 | Toast提示，按钮loading |
| 审核 | 二次确认，成功后状态刷新 |
| 删除 | 二次确认，危险色按钮 |
| 导出 | 进入导出中心，显示任务状态 |
| 错误 | 字段旁提示，顶部可有错误摘要 |
| 扫码成功 | 绿色反馈/声音/震动，PDA使用 |
| 扫码失败 | 红色提示/声音/震动，PDA使用 |

### 8.2 表单原则

- 必填字段必须有星号。
- 错误提示在字段附近展示。
- 复杂字段提供帮助说明。
- 长表单分区展示。
- 有未保存变更时离开页面需确认。
- 审核、反审核、报损、成本调整等高风险操作必须二次确认。

### 8.3 权限原则

- 无权限菜单不显示或置灰，并说明原因。
- 无字段权限直接隐藏字段，而不是显示星号。
- 导出也必须遵循字段权限。
- 成本、毛利、采购价、客户欠款、供应商余额为敏感字段。

## 九、可访问性与易用性

### 9.1 对比度

- 正文文本与背景对比度至少 4.5:1。
- 状态标签文字必须清晰可读。
- 红色、绿色状态不能只靠颜色，必须有文字。

### 9.2 键盘可用性

- 所有业务单据录入支持快捷键。
- Tab顺序必须符合视觉顺序。
- 当前焦点必须有清晰边框。
- 弹窗打开后焦点进入弹窗。
- 弹窗关闭后焦点回到触发按钮。

### 9.3 触控可用性

PDA、司机APP、小程序触控目标：

```text
最小点击区域 ≥ 44px / 48dp
```
