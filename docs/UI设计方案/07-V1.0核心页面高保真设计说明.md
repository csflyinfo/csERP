## 一、设计目标

核心页面高保真设计应解决三个问题：

```text
1. 用户能否快速找到入口
2. 用户能否快速完成业务操作
3. 用户能否清楚理解数据状态和风险
```

本系统不是低频管理后台，而是高频业务作业系统。高保真页面必须优先保证：

- 信息密度合理。
- 操作路径短。
- 单据状态明确。
- 金额、数量、库存、成本清晰。
- 高风险操作有提示。
- 表格字段可配置。
- 键盘操作友好。

## 二、首页经营概览

### 2.1 页面目标

首页用于老板、管理层、内勤快速了解当天经营情况、异常风险和待处理事项。

### 2.2 页面结构

```text
经营指标区
├─ 动销门店数
├─ 订单金额
├─ 出库金额
├─ 退货金额
├─ 净销售额
├─ 毛利额
├─ 今日收款额 / 总应收
└─ 今日付款额 / 总应付

待办区
├─ 待审核销售单
├─ 待确认收货
├─ 待处理报损
└─ 逾期应收客户

排行区
├─ 商品动销排行
├─ 商品大类动销排行
├─ 门店销售排行
└─ 业务员销售排行
```

### 2.3 指标卡设计

| 项 | 设计要求 |
|---|---|
| 卡片高度 | 92-112px |
| 指标名称 | 12-13px，次级文本 |
| 指标值 | 22-26px，等宽数字，强强调 |
| 趋势 | 可选，显示环比/同比 |
| 点击 | 点击进入对应报表或明细 |

### 2.4 数据口径提示

高保真中建议在指标标题旁提供 tooltip：

```text
订单金额：按销售订单金额统计
出库金额：按销售出库单金额统计
净销售额：销售收货金额 - 销售退货金额
毛利额：签收金额 - 出库成本
```

## 三、商品档案页面

### 3.1 页面目标

商品档案是采购、销售、库存、B2B的核心基础资料。设计重点是：字段完整、分类清晰、单位/价格/库存规则好维护。

### 3.2 列表页结构

```text
左侧：商品分类树
右侧：状态Tab + 查询条件 + 操作按钮 + 商品列表
```

### 3.3 左侧分类树

要求：

- 默认选中“全部商品”。
- 支持三级分类。
- 当前分类高亮。
- 点击分类后右侧显示该分类及下级商品。

### 3.4 商品列表字段

建议默认显示：

```text
商品编号
商品名称
规格型号
商品分类
品牌
基本单位
基本条码
保质期
是否可售
是否可采购
标准售价
参考进价
库存下限
状态
操作
```

成本、参考进价、最低售价等敏感字段受权限控制。

### 3.5 商品编辑页结构

采用单页锚点，不做分页切换。

```text
基础档案
单位设置
价格设置
商品介绍
```

点击顶部标题快速定位到对应区域，滚动时高亮对应标题。

### 3.6 基础档案字段


### 3.7 单位设置



价格设置采用矩阵表格：

```text

```


## 七、业务单据列表页

### 7.1 页面结构

```text
状态Tab
查询条件
操作按钮
数据网格
底部批量操作/分页/合计
```

### 7.2 查询条件

默认一行，支持展开更多。

高频条件：

```text
单据日期
单据编号
客户/供应商
仓库
状态
业务员/采购员
```

低频条件放入“展开更多”。

### 7.3 不展示无关业务模块标签

进入单一业务单据后，不显示其他业务类型标签。

例如：

```text
进入销售订单，不显示：销售单、退货单、换货单、还货单
进入采购订单，不显示：采购订单、采购入库、采购收货、采购费用
```

## 八、业务单据编辑页

### 8.1 页面结构

```text
顶部操作栏
紧凑单据头
明细操作条
明细网格
底部汇总
```

### 8.2 单据头

- 使用 4列或6列紧凑布局。
- 高度不宜超过 140px。
- 低频字段折叠。

### 8.3 明细网格

- 铺满剩余空间。
- 默认多行空白。
- 支持行内编辑。
- 不随记录数量收缩。

### 8.4 明细操作

```text
新增明细行
选择商品/来源单据
导入明细
删除行
```
