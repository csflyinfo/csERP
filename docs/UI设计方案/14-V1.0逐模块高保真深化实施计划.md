> 文档版本：v1.0

> 适用范围：V1.0 ERP核心经营版后续高保真原型、UI设计、前端实现  
> 目标：按模块推进高保真设计深化，保证每个模块从“入口完整”升级为“业务可评审、交互可实现、验收可执行”。

## 一、深化原则

### 1.1 不再扩菜单，转向模块质量深化

后续不再以“增加菜单数量”为主，而以每个模块的真实业务质量为主：

```text
字段完整
查询合理
列表真实
新建/编辑符合业务
明细可录入
状态可流转
异常有提示
权限可表达
导入导出可理解
```

### 1.2 每个模块必须具备的交付内容

每个模块高保真深化时，至少产出：

| 内容 | 说明 |
|---|---|
| 模块定位 | 用户是谁、解决什么问题 |
| 菜单入口 | 一级/二级菜单路径 |
| 查询条件 | 默认条件、展开更多条件 |
| 列表字段 | 默认展示字段、敏感字段、可隐藏字段 |
| 操作按钮 | 新建、编辑、审核、导入、导出、打印等 |
| 新建/编辑页 | 页面结构、字段分组、明细结构 |
| 状态流转 | 草稿、待审核、已审核等 |
| 异常状态 | 库存不足、超信用、已结账、权限不足等 |
| 权限控制 | 菜单、按钮、字段、数据范围 |
| 验收点 | 可直接转测试用例 |

## 三、P0模块深化要求

## 3.1 销售快速开单

### 页面结构

```text
顶部：客户信息 + 信用风险
中部：商品搜索/扫码 + 常购/历史/赠品
主体：商品明细录入网格
底部：收款方式 + 金额汇总 + 审核打印
```

### 必须实现的交互

- F2 聚焦客户。
- F3 聚焦商品。
- Enter 添加商品。
- F7 添加赠品。
- F9 重算金额。
- Ctrl+Enter 审核。
- 客户选择后带出账期、信用、欠款、地址、业务员。
- 商品选择后带出业务单位、换算率、基本单位、默认仓库、价格、库存、成本。
- 修改业务单位后重算基本单位数量。
- 修改明细仓库后刷新可用库存和成本。
- 库存不足时行内红色提示并阻断审核。
- 超信用时顶部风险条提示。

### 明细字段

```text

仓库
业务单位
开单数量
换算率
基本单位
基本单位数量
可用库存
单价
折扣
金额
成本单价
成本金额
毛利
价格来源
赠品
操作
```
