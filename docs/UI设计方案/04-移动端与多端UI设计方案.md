# B2B-ERP-WMS-TMS 全链路系统 — 移动端与多端UI设计方案

> 文档版本：v1.0  
> 编写日期：2026-06-13  
> 适用范围：WMS PDA、TMS司机APP、B2B客户小程序、B2B业务员APP、入驻商后台  
> 设计目标：多端一致、场景适配、操作高效、移动端少输入、多反馈

---

## 一、多端设计原则

### 1.1 多端差异

| 端 | 用户 | 设计关键词 |
|---|---|---|
| WMS PDA | 仓库人员 | 大按钮、大字体、扫码优先、强反馈 |
| TMS司机APP | 司机 | 极简、少操作、强流程、强安全 |
| B2B客户小程序 | 门店客户 | 类电商、复购高效、价格库存清楚 |
| B2B业务员APP | 业务员 | 拜访、代客下单、客户风险提示 |
| 入驻商后台 | 入驻商运营 | 简化商家工作台、订单和结算清楚 |

### 1.2 移动端通用要求

- 触控区域不小于 44px/48dp。
- 主操作按钮固定底部。
- 页面层级不超过3层。
- 避免复杂表格，使用卡片和分组列表。
- 扫码、拍照、签名、定位等能力要有明确状态反馈。
- 离线或弱网必须有提示。
- 危险操作必须二次确认。

## 二、WMS PDA UI设计

### 2.1 设计原则

```text
大按钮
大字体
强反馈
少输入
多扫码
弱层级
强任务状态
```

PDA用户在仓库现场操作，环境可能嘈杂、光线复杂、戴手套、任务紧急，因此界面必须简单直接。

### 2.2 PDA首页

推荐九宫格或任务卡片：

```text
┌────────────────────────────┐
│ 仓库PDA                    │
│ 当前仓库：总仓  在线        │
├────────────────────────────┤
│ 收货 12    上架 8          │
│ 拣货 26    复核 14         │
│ 盘点 3     移库            │
│ 退货入库   库存查询         │
├────────────────────────────┤
│ 同步状态：正常              │
└────────────────────────────┘
```

### 2.3 PDA任务卡片

任务卡片字段：

- 任务类型
- 单号
- 来源单据
- 商品种类数
- 总数量
- 优先级
- 状态
- 操作按钮

### 2.4 收货页面

```text
采购收货
├─ 扫描采购单/选择任务
├─ 当前商品
│  商品名称
│  规格
│  应收数量
│  已收数量
├─ 扫码输入
├─ 数量输入
├─ 批次/生产日期
└─ [确认收货]
```

### 2.5 上架页面

```text
上架任务
├─ 当前商品
├─ 推荐库位：A-01-02
├─ 扫描库位
├─ 上架数量
└─ [确认上架]
```

扫码错误时：

- 红色全屏提示
- 声音提示
- 震动反馈
- 显示正确库位/商品

### 2.6 拣货页面

```text
拣货任务
├─ 当前库位：A-01-02
├─ 商品：农夫山泉 500ml*24
├─ 应拣：10箱
├─ 已拣：6箱
├─ 剩余：4箱
├─ 扫码区
└─ [确认拣货] [缺货] [跳过]
```

### 2.7 复核页面

```text
复核任务
├─ 波次/订单号
├─ 应发商品列表
├─ 扫描商品
├─ 差异提示
└─ [复核通过] [差异处理]
```

### 2.8 盘点页面

明盘：显示系统库存。  
暗盘：不显示系统库存，只显示商品和库位。

盘点页必须突出：

- 库位
- 商品
- 盘点数量
- 差异

## 三、TMS司机APP UI设计

### 3.1 设计原则

```text
极简
少输入
大按钮
一屏一任务
强流程
安全优先
```

司机在路上使用，不能让司机处理复杂信息。

### 3.2 司机首页

```text
┌──────────────────────┐
│ 今日配送              │
│ 待装车 3  配送中 8    │
│ 已完成 12 异常 1      │
├──────────────────────┤
│ [开始装车]            │
│ [配送任务]            │
│ [退货回收]            │
│ [配送历史]            │
└──────────────────────┘
```

### 3.3 配送任务卡片

```text
客户：华联超市
地址：杭州市西湖区...
电话：138****8888
件数：12箱
金额：¥1,250.00
状态：待配送
[导航] [到达] [签收]
```

### 3.4 装车页面

```text
装车确认
├─ 配送单号
├─ 应装客户数
├─ 应装件数
├─ 扫描商品/周转箱
├─ 已装/未装
└─ [确认装车]
```

### 3.5 签收页面

建议分步骤：

```text
1. 核对商品
2. 输入实收数量
3. 现场收款（如需）
4. 拍照
5. 客户签名
6. 提交签收
```

底部主按钮：

```text
[确认签收]
```

拒收按钮放在次级区域：

```text
[客户拒收]
```

并二次确认。

### 3.6 拒收页面

拒收原因使用大按钮选择：

- 包装破损
- 商品临期
- 商品错发
- 客户不要
- 无人收货
- 地址错误
- 价格争议
- 其他

拒收必须拍照或填写说明。

## 四、B2B客户小程序 UI设计

### 4.1 设计原则

B2B小程序更接近电商，但目标不是娱乐化，而是复购高效。

```text
商品好找
价格清楚
库存清楚
复购快
订单状态透明
账期风险明确
```

### 4.2 首页结构

```text
搜索框
Banner
常购商品
促销专区
分类入口
最近购买
欠款/账期提醒
订单入口
```

### 4.3 商品卡片

商品卡片字段：

- 商品图
- 商品名称
- 规格
- 价格
- 库存状态
- 起订量
- 数量加减器
- 加入购物车

示例：

```text
┌──────────────────────┐
│ 商品图                │
│ 农夫山泉 500ml*24     │
│ ¥35.00/箱             │
│ 有货 | 起订1箱         │
│ [-] 1 [+] [加入购物车] │
└──────────────────────┘
```

### 4.4 商品列表

筛选：

- 分类
- 品牌
- 促销
- 常购
- 仅看有货

排序：

- 默认
- 销量
- 价格
- 最近购买

### 4.5 购物车

购物车必须支持：

- 批量修改数量
- 起订量校验
- 库存校验
- 促销优惠展示
- 失效商品提示

### 4.6 下单确认

```text
确认订单
├─ 商品明细
├─ 收货地址
├─ 结算方式
├─ 账期额度提示
├─ 优惠信息
└─ [提交订单]
```

账期客户要显示：

```text
可用额度：¥38,000
本单占用：¥1,250
提交后剩余额度：¥36,750
```

## 五、B2B业务员APP UI设计

### 5.1 首页

```text
今日拜访
待回款客户
待处理订单
客户欠款排行
快捷入口：代客下单、客户拜访、收款登记
```

### 5.2 客户详情

展示：

- 客户基础资料
- 最近订单
- 应收余额
- 逾期金额
- 常购商品
- 拜访记录
- 代客下单入口

### 5.3 代客下单

应复用B2B小程序商品卡片和购物车逻辑，但增加：

- 业务员身份标识
- 客户欠款提醒
- 低价/超信用限制
- 代客备注

## 六、入驻商后台 UI设计

### 6.1 设计原则

入驻商后台不要做成完整ERP，应是“商家工作台”。

```text
少菜单
强待办
订单清楚
结算透明
商品提报简单
售后责任明确
```

### 6.2 菜单结构

```text
首页
商品管理
订单管理
售后管理
库存管理
结算管理
店铺资料
消息公告
```

### 6.3 首页

```text
今日订单
待发货
售后中
待结算金额
商品审核中
平台公告
```

### 6.4 商品提报页面

字段分组：

- 基本信息
- 图片与详情
- 价格与库存
- 履约模式
- 资质材料

状态：

```text
草稿 → 待审核 → 审核通过 → 已上架
       └→ 已驳回
```

### 6.5 订单页面

订单卡片或表格展示：

- 子订单号
- 客户
- 商品数
- 金额
- 履约方式
- 状态
- 操作

自配订单操作：接单、发货、填写物流、售后处理。

### 6.6 结算页面

结算公式必须可视化：

```text
应结金额 = 订单实收 - 平台佣金 - 售后退款 - 罚款 + 补贴
```

结算单详情展示：

- 订单实收
- 平台佣金
- 促销承担
- 售后退款
- 罚款
- 补贴
- 应结金额

## 七、多端一致性

### 7.1 状态一致

同一状态在ERP、PDA、司机APP、小程序、入驻商后台应使用一致的文字和颜色。

例如：

- 待审核：橙色
- 已完成：绿色
- 异常：红色
- 配送中：蓝色

### 7.2 单据号一致

所有端展示同一业务单号，避免客户、司机、仓库、财务对不上。

### 7.3 金额口径一致

- 客户小程序订单金额应与ERP销售订单一致。
- 入驻商结算金额应与平台后台一致。
- 财务端展示的应收应付必须与业务端来源单据一致。
