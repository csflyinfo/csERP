# 业务期初初始化（库存 / 客户应收 / 客户预收 / 供应商应付与预付）— 操作手册

> 适用版本：PRD-34（Flyway V123）、PRD-35 M4 客户期初预收（Flyway V127）、PRD-36 M4 供应商期初预付与上线后补录（Flyway V131）
> 适用对象：财务、仓库主管、系统管理员（新客户上线 / 新账套启用时使用）
> 配套文档：PRD 见 `docs/PRD-版本化产品需求/V1.0-ERP核心经营版/34-V1.0-业务期初初始化PRD.md`，
> 落地记录见 `docs/优化记录-PRD34-期初初始化.md`、`docs/优化记录-PRD35-客户账户.md`（M4 节）、
> `docs/优化记录-PRD36-供应商账户与厂家费用.md`（M4 节），供应商账户业务全貌见 `docs/操作手册-供应商账户.md`

## 一、这三个菜单是做什么的

系统正式启用当天，把启用时刻的存量数据导进来：

| 菜单 | 位置 | 作用 |
|---|---|---|
| **库存期初初始化** | 库存管理 → 库存期初初始化 | 把现有库存的商品、批次、数量、成本单价建进库存三账；启用了 WMS 的还要定位到库位 |
| **客户应收期初** | 财务管理 → 客户应收期初 | 把客户尚欠的未收货款逐笔建成应收单 |
| **客户期初预收** | 财务管理 → 客户期初预收（PRD-35 M4 新增） | 把客户已付未核销的预收货款逐笔建进客户预收余额 |
| **供应商应付期初** | 财务管理 → 供应商应付期初 | 同一张导入表同时建「尚欠供应商的未付货款（应付单）」与「预付给供应商尚未核销的钱（供应商账户预付余额）」 |
| **供应商期初预付补录** | 供应商应付期初页内按钮「期初预付补录」（PRD-36 M4 新增） | **上线后**才发现漏录的预付，走独立批号补进供应商账户预付余额，可多批、不受建账锁定 |

四个初始化模块操作方式完全一样：**下载模板 → 填数 / 手工录行 → 导入暂存核对 → 期初建账**。
建账只是把数据写进正式账表；首次业务日结之前发现错了，满足条件还可以**反建账**重来。

### 权限点（找系统管理员在角色里勾）

每个模块各有 6 个功能点，以库存为例：`inv.init_stock.view`（查看）、`.edit`（手工增改行）、
`.delete`（删除/清空）、`.import`（导入/下载模板）、`.post`（期初建账）、`.reverse`（反建账）。
应收/预收/应付前缀分别为 `fin.init_ar.`、`fin.init_adv.`、`fin.init_ap.`。超管默认自动拥有全部。

## 二、必须遵守的上线顺序

页面顶部蓝条写着固定顺序，**四个业务期初都要赶在首次业务日结之前完成**：

```
① 建库存 / 应收 / 预收 / 应付与预付期初  →  ② 总账「一键引入业务期初」  →  ③ 启用总账  →  ④ 首次业务日结
```

- 只要系统里**还没有任何业务日结记录、总账未启用**，期初数据就可以反复改、反复导入、反建账重来；
- **一旦做了首次业务日结，四个期初模块全部锁定**为只读，不能再改、再导、再反建账；
- 总账启用后同样锁定（此时调整应走总账凭证）。

## 三、库存期初初始化

### 3.1 先确认走哪个页签

| 页签 | 什么时候用 | 模板 |
|---|---|---|
| **按批次（未启用 WMS）** | 不上 PDA / 库位作业，库存只管到商品+批次 | 库存期初_导入模板（按批次），10 列 |
| **按库位（启用 WMS）** | 库存要定位到具体库位（PDA 上架/拣货依赖它） | 库存期初_导入模板（按库位），12 列（多库位编码、容器编码） |

⚠️ **同一「商品+仓库+批号」只能用一种流程**：要么所有行都定位库位，要么都不定位。
混着导，系统会在行里报错并拒绝建账。两个页签的数据在一次「期初建账」里一起过账。

### 3.2 填模板（红底表头是必填）

- **商品编码、仓库编码**：必须与系统档案完全一致；名称列可以不填，系统按编码回写标准名称；
- **批号**：可留空——留空且填了生产日期时，系统自动按生产日期 `yyyyMMdd` 生成批号；
- **生产日期 / 效期日期**：格式 `yyyy-MM-dd`；效期留空时按商品档案「保质期天数」自动推算；两个都没有就不设效期；
- **数量**：必填，>0。按批次模板最多 4 位小数，按库位模板最多 3 位小数；
- **成本单价**：必填，**允许填 0**，最多 6 位小数；
  - ⚠️ 填 0 的行会在页面顶部提示「N 行为 0 成本」。0 成本不拦截建账，但建账后该商品+仓的移动加权成本就是 0，
    要等第一次采购入库后才被重算，期间出库结转的成本会偏低——拿不准就填实际成本；
- **库位编码（按库位页签必填）**：库位必须已在 WMS 档案里建好、状态正常且未冻结；容器编码可空；
- 数字不要带千分位、不要写单位。

### 3.3 导入与核对

1. 点「导入」，可直接下载模板，按表头填好后选择文件导入；
2. 导入是**部分成功**的：对的行进暂存（绿色「有效」），错的行也会留下并标红（红色「错误」+ 失败原因），
   同时可到 系统管理 → 导入列表 下载失败明细 Excel（行号对应 Excel 物理行，第 1 行是表头）；
3. 错误行可以直接在页面「编辑」改对，也可以删掉 / 按批清空后整份重导；导入是追加的，不会覆盖上次的行；
4. 也可以不导 Excel，直接「新增行」手工录入；
5. 顶部汇总条显示：有效行数（批次/库位各多少）、错误行数、数量合计、成本合计、0 成本警示。

### 3.4 期初建账

点右上角「期初建账」并确认。系统在一个事务内完成：

- 按商品+仓库把多行数量加权平均出建账成本，写入库存余额、批次库存、库存台账（来源号 QTRK- 开头）；
- 按库位页签的行同时写库位库存、占用库位容量、库位流水；
- 页面状态变「已建账 · 批号 QCxxxxxxxx-nnnn」。

**整批拒绝的典型情况**（改完再点，不会写一半）：

- 还存在错误行；一行 VALID 都没有；
- **某商品+仓库在系统里已经有库存数量**：为避免重复建账，必须先把该商品仓的库存清零（走其他出库/盘点等），再建期初；
- 库位被停用/冻结；同一商品+仓+批号在两个页签混用。

## 四、客户应收 / 供应商应付与预付期初

两个菜单操作完全一致，以应收为例。供应商模板比客户多一列「期初预付金额」。

### 4.1 填模板

| 列 | 规则 |
|---|---|
| 客户编码（供应商编码） | **必填**，必须与档案一致；只认编码不认名称（避免重名），名称列可留空 |
| 客户名称 / 供应商名称 | 可空，系统按编码回写 |
| 原单据号 / 原单据日期 | **仅留存备查**，可空；不进正式应收/应付单，**不参与账龄** |
| 应收金额（应付金额） | ≥0，含税，填**当前尚未收回/付完的余额**（不是原单全额） |
| 期初预付金额（仅供应商模板，PRD-36 M4） | ≥0，填上线时点已预付给供应商、尚未核销应付的钱；**只登供应商账户预付余额，不生成付款单、不动资金** |
| 业务员 | 仅应收模板有，可空 |
| 备注 | 可空 |

- 同一文件里「客户编码（供应商编码） + 原单据号」不能重复（原单号留空时同往来单位多行请拆清备注）；
- 供应商行的**应付金额与期初预付金额至少一项大于 0**（只建预付、不建应付是允许的），两列缺省都按 0 处理（老模板无预付列可直接导）；
- 同一供应商只有预付、原单号又留空时，**初始化模板里只能有一行**（重复键=供应商+原单号）；上线后还要再补预付请走第六章「预付补录」通道，可分多批；
- 系统**不会**编造历史收款/付款/核销记录：应付行一律按「一分钱没付」立账。

### 4.2 账龄怎么算

账龄**一律从建账日起算**，到期日 = 建账日 + 30 天。模板里填的原单据日期只是留着给人看的。
这样设计是为了保证首次业务日结的往来滚存硬平衡能对上——建账后到总账引数、日结之间不要隔太久。

### 4.3 建账后正式账里的样子

- 应收：生成状态为「未审核（UNVERIFIED）」的应收单（这样结算模块才能选到它去核销）、未开票、已收金额 0、
  来源号 QCAR- 开头；应付：未来票、已付金额 0、来源号 QCAP- 开头；
- 供应商**期初预付行**不造应付/付款单、不写资金流水，只在供应商账户登一笔 `PREPAY_OPENING` 预付流水
  （来源号 **QCYF-批号-序号**），供应商账户的**预付余额**一次性建立，可在 财务管理 → 供应商账户 点预付余额查到；
- 暂存行会回写生成的应收/应付单号与预付流水号，可在 客户应收明细 / 应付账款 / 供应商账户 菜单查到；
- 总账侧：应付 2202 随总账「一键引入业务期初」引入；预付 1123 供应商辅助余额也由同一动作按供应商账户预付余额引入（PRD-36 M4）。

## 五、客户期初预收（PRD-35 M4 新增）

菜单：**财务管理 → 客户期初预收**。用于把上线时点客户已经预付、尚未核销应收的货款一次性建进**客户预收余额**
（即客户账户模块的预收一本账，后续可被预收核销单 XH、应收结算「使用预收款」消费）。
操作节奏与应收/应付期初完全相同（下载模板 → 导入/手工录行 → 核对 → 期初建账），差异点如下。

### 5.1 填模板

| 列 | 规则 |
|---|---|
| 客户编码 | **必填**，与客户档案完全一致，只认编码；名称列可留空，系统按编码回写 |
| 客户名称 | 可空 |
| 原单据号 / 原单据日期 | **仅留存备查**，可空，不生成收款单、不参与任何账龄计算 |
| 预收金额 | 必填，**>0**，填客户当前尚未核销的预收余额（不是历史收款全额） |
| 备注 | 可空 |

- 导入同样是**部分成功**：正确行进暂存（有效），错行留下标红并给原因，可页面改对/删除/清空重导，失败明细可在 系统管理 → 导入列表 下载；也可以直接「新增行」手工录入；
- 顶部显示行数与**预收合计**；存在错误行或一行有效行都没有时，「期初建账」按钮置灰。

### 5.2 建账后正式账里的样子

- 每个客户生成一笔 `ADV_OPENING` 预收流水（记账日期=建账日，来源号 **QCYK-批号-序号**），客户账户的**预收余额**一次性建立，
  可在 财务管理 → 客户账户 点预收余额查到这笔流水；
- **不会生成收款单、不写资金流水**——期初预收是往来余额，不是上线日新收一笔钱；
- 总账侧：2203 预收账款期初余额随总账**「一键引入业务期初」**引入（与应收 1122、应付 2202 同一动作），本菜单不单独生成凭证。

### 5.3 反建账的特殊守卫

客户期初预收的反建账除「已日结 / 总账已启用」两条通用红线外，还有一条专门守卫：

- 某客户的期初预收**已被预收核销单（XH）或预收退款单使用**时，该客户不能反建账，
  页面提示「客户「X」的期初预收已被预收核销或退款使用，不能反建账；请先反审核相关预收核销单或预收退款单」；
- 注意：**已经反审核过的下游单据不占用**（原流水被红字冲回），拦不住反建账；只有仍生效的核销/退款才算数——
  按提示先反审核这些单据，再反建账即可。

历史遗留的「多收款」（旧往来流水里沉淀、没有核销对象的钱）经财务核对客户后，也统一从本菜单录入；
系统不做自动划转。客户预收的日常业务（预收收款、退款、核销、结算用预收）见
`docs/操作手册-客户账户.md`。

## 六、供应商期初预付补录（PRD-36 M4 新增，上线后通道）

入口：**财务管理 → 供应商应付期初** 页面下方按钮「**期初预付补录**」（权限复用 `fin.init_ap.*`）。
用于系统**已经上线**（已日结/总账已启用）后，才发现某供应商上线时点的预付货款漏录了。

### 6.1 与第四章「初始化行」的区别

| 对比项 | 第四章 期初预付列（初始化） | 预付补录（本章） |
|---|---|---|
| 适用时点 | 首次业务日结、总账启用之前 | 上线之后任何时候 |
| 批次 | 与应付同一个批号，一次建账锁定 | **独立批号 APP 开头，可分多批**，没有建账锁定标志 |
| 暂存表 | fin_ap_init（line_kind=AP_INIT） | 同一张表（line_kind=PREPAY_SUPPLEMENT），两套行互不可见、互不影响 |
| 过账守卫 | 未日结 + 总账未启用 | **当天未封账 + 总账当月会计期间未「已结账/已冻结」** |
| 过账效果 | QCYF 预付流水 + QCAP 应付单（有应付列时） | 只生 **QCYF 预付期初流水**，不动资金、不造单 |
| 回退 | 整批反建账（应付+预付一起回退） | 可**按批号整批反建账**，不影响其他批次与初始化批 |

### 6.2 操作步骤

1. 下载补录模板（4 列：供应商编码 / 供应商名称 / 期初预付金额 / 备注），或直接「新增行」；
   金额必须 **>0**、两位小数，同一文件一个供应商只能一行；
2. 导入后核对有效行/错误行与预付合计——错误行可页面改、可删、可清空重来；
3. 顶部状态条显示**今天是否已封账、总账当月是否已月结**，任一命中则「补录过账」置灰；
4. 点「补录过账」：审核当日为过账日，逐户登 QCYF 预付流水，供应商账户预付余额立即增加；
5. 批号表留痕（批号、行数、合计、过账人、时间），下方还能看到**各供应商期初预付累计**（初始化批+补录批合计）；
6. 录错了：在批号表对该批点「反建账」并填原因——系统物理删除该批 QCYF 流水并重算账户链。

### 6.3 反建账守卫（任一命中即拒，中文提示）

- 过账日已封账，或过账当月总账期间已结账/冻结；
- 该批预付在此后已被**预付核销单（FX）、预付退款、厂家费用划转**使用（仍生效才算，已反审核的不拦）；
  按提示先反审核这些下游单据，再整批反建账。

### 6.4 特别提醒：负应付不要重复补录

- 有些供应商历史付款大于挂账，其应付单汇总是**负数（借方）**，资产负债表上已按「2202 负余额重分类」算作预付。
  补录面板会把这些供应商黄条列出来：**如果那笔负数就是漏录的预付，不要再补录**，否则 1123 与 2202 两边重复挂钱；
- 日结向导第 5 步对「同一供应商 2202 负应付与 1123 账户预付同时挂钱」会给红色**双计提示**（不阻断日结），看到后请财务核对。
- 补录后别忘了总账侧：在总账做 1123 供应商辅助凭证（手工凭证不回业务账，业财对账中体现为可解释差异），
  或下一版启用前用「一键引入业务期初」（仅总账未启用时可用）。

## 七、反建账（首次日结前的后悔药）

已建账状态下，页面出现「反建账」按钮（需要 `.reverse` 权限），必须**填写原因**（留痕）。

反建账会删掉该批号写入的全部正式账数据、暂存行恢复可编辑，可以改完重新建账。
**以下任一情况反建账会被拒绝**：

1. 系统已经有业务日结记录，或总账已启用；
2. 应收/应付行已经被收款/付款核销过；**客户期初预收行已经被仍生效的预收核销/预收退款使用过**（见 5.3）；
   **供应商期初预付行已经被仍生效的预付核销（FX）/预付退款/厂家费用划转使用过**——同批只要有一户被占用，整批反建账被拒；
3. 库存过账后又发生了出入库流水，或库存数量已不等于当时的建账数量（库位账同理）。

也就是说：**只要建账后的库存/往来被动过，就不能整批回退**，需要先把后续业务单据冲掉，再反建账。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 导入后整列都是空的 | 模板表头被改过（加了星号、删了列、改了字）。重新下载原始模板，把数据贴进去 |
| 行错误「商品不存在 / 仓库不存在」 | 编码与档案不一致或已删除；停用（STOPPED）商品可以建期初，删除（DELETED）的不行 |
| 行错误「该商品+仓库+批号已存在另一流程的暂存行」 | 按批次和按库位混用了；确定走一种，把另一批行清空 |
| 建账报错「商品+仓已有数量余额，请先清零」 | 系统里已有库存，先做其他出库/盘点清零再建期初（见 3.4） |
| 总账「一键引入」引不到 1122/2202/1405/2203/1123 | 业务期初还没建账；引入读的是正式账表（fin_ar/fin_ap/客户账户余额/供应商账户预付余额/库存余额），不是暂存行；2203 取客户账户预收余额、1123 取供应商账户预付余额，对应期初建账/补录过账后即有 |
| 客户期初预收反建账被拒「已被预收核销或退款使用」 | 该客户建账后做过 XH 预收核销或预收退款；先反审核这些单据（已反审核的不拦截），再反建账，见 5.3 |
| 已日结/总账已启用后才发现供应商预付漏录 | 不能再动第四章初始化（已锁定）；在供应商应付期初页点「期初预付补录」走第六章通道，可多批补录 |
| 补录过账按钮是灰的 | 当天已业务封账，或总账当月会计期间已结账/冻结；改天（或反封账）、等下月（或反结账）再操作 |
| 预付补录反建账被拒 | 该批预付已被预付核销/退款/厂家费用划转使用，或过账日已封账、过账当月已月结；先处理占用单据，见 6.3 |

| 建账按钮是灰的 | 有错误行、或没有有效行、或已被日结/总账锁定；看页面顶部黄色提示条 |
