# 业务期初初始化（库存 / 客户应收 / 供应商应付）— 操作手册

> 适用版本：PRD-34（Flyway V123）
> 适用对象：财务、仓库主管、系统管理员（新客户上线 / 新账套启用时使用）
> 配套文档：PRD 见 `docs/PRD-版本化产品需求/V1.0-ERP核心经营版/34-V1.0-业务期初初始化PRD.md`，
> 落地记录见 `docs/优化记录-PRD34-期初初始化.md`

---

## 一、这三个菜单是做什么的

系统正式启用当天，把启用时刻的存量数据导进来：

| 菜单 | 位置 | 作用 |
|---|---|---|
| **库存期初初始化** | 库存管理 → 库存期初初始化 | 把现有库存的商品、批次、数量、成本单价建进库存三账；启用了 WMS 的还要定位到库位 |
| **客户应收期初** | 财务管理 → 客户应收期初 | 把客户尚欠的未收货款逐笔建成应收单 |
| **供应商应付期初** | 财务管理 → 供应商应付期初 | 把尚欠供应商的未付货款逐笔建成应付单 |

三个模块操作方式完全一样：**下载模板 → 填数 / 手工录行 → 导入暂存核对 → 期初建账**。
建账只是把数据写进正式账表；首次业务日结之前发现错了，满足条件还可以**反建账**重来。

### 权限点（找系统管理员在角色里勾）

每个模块各有 6 个功能点，以库存为例：`inv.init_stock.view`（查看）、`.edit`（手工增改行）、
`.delete`（删除/清空）、`.import`（导入/下载模板）、`.post`（期初建账）、`.reverse`（反建账）。
应收/应付前缀分别为 `fin.init_ar.`、`fin.init_ap.`。超管默认自动拥有全部。

## 二、必须遵守的上线顺序

页面顶部蓝条写着固定顺序，**三个业务期初都要赶在首次业务日结之前完成**：

```
① 建库存 / 应收 / 应付期初  →  ② 总账「一键引入业务期初」  →  ③ 启用总账  →  ④ 首次业务日结
```

- 只要系统里**还没有任何业务日结记录、总账未启用**，期初数据就可以反复改、反复导入、反建账重来；
- **一旦做了首次业务日结，三个期初模块全部锁定**为只读，不能再改、再导、再反建账；
- 总账启用后同样锁定（此时调整应走总账凭证）。

## 三、库存期初初始化

### 3.1 先确认走哪个页签

| 页签 | 什么时候用 | 模板 |
|---|---|---|
| **按批次（未启用 WMS）** | 不上 PDA / 库位作业，库存只管到商品+批次 | 库存期初_导入模板（按批次），10 列 |
| **按库位（启用 WMS）** | 库存要定位到具体库位（PDA 上架/拣货依赖它） | 库存期初_导入模板（按库位），12 列（多库位编码、容器编码） |

⚠️ **同一「商品+仓库+批号」只能用一种流程**：要么所有行都定位库位，要么都不定位。
混着导，系统会在行里报错并拒绝建账。两个页签的数据在一次「期初建账」里一起过账。

### 3.2 填模板（红底表头是必填）

- **商品编码、仓库编码**：必须与系统档案完全一致；名称列可以不填，系统按编码回写标准名称；
- **批号**：可留空——留空且填了生产日期时，系统自动按生产日期 `yyyyMMdd` 生成批号；
- **生产日期 / 效期日期**：格式 `yyyy-MM-dd`；效期留空时按商品档案「保质期天数」自动推算；两个都没有就不设效期；
- **数量**：必填，>0。按批次模板最多 4 位小数，按库位模板最多 3 位小数；
- **成本单价**：必填，**允许填 0**，最多 6 位小数；
  - ⚠️ 填 0 的行会在页面顶部提示「N 行为 0 成本」。0 成本不拦截建账，但建账后该商品+仓的移动加权成本就是 0，
    要等第一次采购入库后才被重算，期间出库结转的成本会偏低——拿不准就填实际成本；
- **库位编码（按库位页签必填）**：库位必须已在 WMS 档案里建好、状态正常且未冻结；容器编码可空；
- 数字不要带千分位、不要写单位。

### 3.3 导入与核对

1. 点「导入」，可直接下载模板，按表头填好后选择文件导入；
2. 导入是**部分成功**的：对的行进暂存（绿色「有效」），错的行也会留下并标红（红色「错误」+ 失败原因），
   同时可到 系统管理 → 导入列表 下载失败明细 Excel（行号对应 Excel 物理行，第 1 行是表头）；
3. 错误行可以直接在页面「编辑」改对，也可以删掉 / 按批清空后整份重导；导入是追加的，不会覆盖上次的行；
4. 也可以不导 Excel，直接「新增行」手工录入；
5. 顶部汇总条显示：有效行数（批次/库位各多少）、错误行数、数量合计、成本合计、0 成本警示。

### 3.4 期初建账

点右上角「期初建账」并确认。系统在一个事务内完成：

- 按商品+仓库把多行数量加权平均出建账成本，写入库存余额、批次库存、库存台账（来源号 QTRK- 开头）；
- 按库位页签的行同时写库位库存、占用库位容量、库位流水；
- 页面状态变「已建账 · 批号 QCxxxxxxxx-nnnn」。

**整批拒绝的典型情况**（改完再点，不会写一半）：

- 还存在错误行；一行 VALID 都没有；
- **某商品+仓库在系统里已经有库存数量**：为避免重复建账，必须先把该商品仓的库存清零（走其他出库/盘点等），再建期初；
- 库位被停用/冻结；同一商品+仓+批号在两个页签混用。

## 四、客户应收 / 供应商应付期初

两个菜单操作完全一致，以应收为例。

### 4.1 填模板

| 列 | 规则 |
|---|---|
| 客户编码（供应商编码） | **必填**，必须与档案一致；只认编码不认名称（避免重名），名称列可留空 |
| 客户名称 / 供应商名称 | 可空，系统按编码回写 |
| 原单据号 / 原单据日期 | **仅留存备查**，可空；不进正式应收/应付单，**不参与账龄** |
| 应收金额（应付金额） | 必填，>0，含税，填**当前尚未收回/付完的余额**（不是原单全额） |
| 业务员 | 仅应收模板有，可空 |
| 备注 | 可空 |

- 同一文件里「客户编码 + 原单据号」不能重复（原单号留空时同客户多行请拆清备注）；
- 系统**不会**编造历史收款/付款/核销记录：期初行一律按「一分钱没收付」立账。

### 4.2 账龄怎么算

账龄**一律从建账日起算**，到期日 = 建账日 + 30 天。模板里填的原单据日期只是留着给人看的。
这样设计是为了保证首次业务日结的往来滚存硬平衡能对上——建账后到总账引数、日结之间不要隔太久。

### 4.3 建账后正式账里的样子

- 应收：生成状态为「未审核（UNVERIFIED）」的应收单（这样结算模块才能选到它去核销）、未开票、已收金额 0、
  来源号 QCAR- 开头；应付：未来票、已付金额 0、来源号 QCAP- 开头；
- 暂存行会回写生成的应收/应付单号，可在 客户应收明细 / 应付账款 菜单查到。

## 五、反建账（首次日结前的后悔药）

已建账状态下，页面出现「反建账」按钮（需要 `.reverse` 权限），必须**填写原因**（留痕）。

反建账会删掉该批号写入的全部正式账数据、暂存行恢复可编辑，可以改完重新建账。
**以下任一情况反建账会被拒绝**：

1. 系统已经有业务日结记录，或总账已启用；
2. 应收/应付行已经被收款/付款核销过；
3. 库存过账后又发生了出入库流水，或库存数量已不等于当时的建账数量（库位账同理）。

也就是说：**只要建账后的库存/往来被动过，就不能整批回退**，需要先把后续业务单据冲掉，再反建账。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 导入后整列都是空的 | 模板表头被改过（加了星号、删了列、改了字）。重新下载原始模板，把数据贴进去 |
| 行错误「商品不存在 / 仓库不存在」 | 编码与档案不一致或已删除；停用（STOPPED）商品可以建期初，删除（DELETED）的不行 |
| 行错误「该商品+仓库+批号已存在另一流程的暂存行」 | 按批次和按库位混用了；确定走一种，把另一批行清空 |
| 建账报错「商品+仓已有数量余额，请先清零」 | 系统里已有库存，先做其他出库/盘点清零再建期初（见 3.4） |
| 总账「一键引入」引不到 1122/2202/1405 | 业务期初还没建账；引入读的是正式账表（fin_ar/fin_ap/库存余额），不是暂存行 |
| 找不到菜单 | 找管理员授权对应 `inv.init_stock.*` / `fin.init_ar.*` / `fin.init_ap.*` 功能点，并重新登录 |
| 建账按钮是灰的 | 有错误行、或没有有效行、或已被日结/总账锁定；看页面顶部黄色提示条 |
