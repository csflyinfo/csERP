# 操作日志统一管理与审计追溯 —— 开发落地方案

> 文档定位：**可直接照着开发的技术方案**。表结构、字段清单、接口、组件、调用代码均给出具体内容。
> 对应需求：全模块业务操作可追溯（增/删/改/查/导入/导出/打印），修改留改前改后值，每张单据可查看操作记录，日志保留期可配置自动清理。
> 版本：v1.0 ｜ 日期：2026-08-24
> 编号：**PRD-31 / Flyway V92（均为预留，开分支时按 §13 流程现场核定，避免撞号）**

---

## 1. 目标与范围

### 1.1 必须达成
1. **一个公共服务**：所有模块写日志走同一个 `OperationLogService`，消灭现存 18 份逐字复制的私有 `log()`。
2. **一个公共组件**：所有业务单据用同一个「操作记录时间线」组件，按 `bizType + bizNo` 查看该单据的全部操作，含改前改后。
3. **改前改后可追溯（P0 五类对象）**：**商品、客户、供应商、销售订单、采购订单** 的修改必须记录关键字段的改前值/改后值，字段清单见 §7，逐字段落地。
4. **全操作覆盖**：增、删、改、查（仅单据详情/敏感数据查看）、导入、导出、打印、审核/反审核、启用/停用、核销/反核销、登录/登出。
5. **保留期可配置**：系统参数设置保留天数，后台每日自动清理超期日志，节省存储。

### 1.2 本期边界
| 项 | 本期 | 说明 |
|---|---|---|
| 统一服务 + 公共组件 + 日志页/登录日志页 | ✅ 全做 | 底座一次到位 |
| 改前改后 P0 五类对象 | ✅ 全做 | 商品/客户/供应商/销售订单/采购订单，字段清单见 §7 |
| 其他核心单据（出入库/收付款/退货/盘点等） | ✅ 接服务 | 记操作；改前改后按 §7.6 的标准关键字段集（状态/金额/数量/往来单位/仓库/日期），不逐字段枚举 |
| TMS / WMS / PDA | ⏸ 不动 | 已通过 `tms.TmsUtil.log` 写日志，新列对它们为 NULL，完全兼容；下一轮让 `TmsUtil.log` 委托统一服务 |
| 登录日志 | ✅ 独立表 `sys_login_log` | ERP 端 `/auth/login` 先落地；PDA/司机端登录下一轮 |
| 敏感操作日志 / 接口日志 | ⏸ 不单独建表 | 敏感操作在操作日志打 `sensitive=Y`；接口日志不在本期 |
| 列表查询/搜索/刷新 | ❌ 不记 | 「查」只记单据详情查看 + 敏感数据查看 |

## 2. 总体架构

```
业务 Controller ──调用──▶ OperationLogService（@Service，REQUIRES_NEW，try/catch 永不抛异常）
                              │  ├─ 自动取 RequestContext（操作人/IP/URL/耗时）
                              │  ├─ logUpdate() 做关键字段级 diff → before_value/after_value(JSON)
                              │  └─ INSERT sys_operation_log_runtime（独立事务提交，不受业务回滚影响）
RequestContextFilter（OncePerRequestFilter）
   └─ 请求进入：填 ThreadLocal（IP/URI/method/UA/开始时间/当前用户）；请求结束：clear
LogCleanupTask（@Scheduled 每日 03:30）
   └─ 读参数保留天数 → 分批 DELETE 超期日志 → 写一条 CLEANUP 日志

前端：
  GenericBusinessList 列表「记录」链接 ─┐
  BillDetailDrawer / 各单据抽屉「操作记录」页签 ─┼─▶ <OperationLogTimeline biz-type biz-no> 【公共组件】
  系统管理-操作日志 列表「详情」 ─────────────┘        └─ POST /system/operation-log/bill-timeline
  系统管理-操作日志/登录日志 ──▶ GenericBusinessList（只读列表）
  打印/导出按钮 ──静默打点──▶ /system/operation-log/print | /export
```

**关键不变量**
- 日志写入与业务事务分离：`@Transactional(propagation = REQUIRES_NEW)` + 全方法 `try/catch`。**日志失败绝不影响业务**；业务回滚也不回滚审计日志（审计语义）。
- 操作人取**真实登录用户**，不再硬编码「系统管理员」。
- 密码/令牌/密钥字段一律掩码 `***`；成本/进价类字段落库但仅管理员可查明文。

### 4.1 请求上下文 `RequestContext`（新建 `common/util/RequestContext.java`）

```java
public final class RequestContext {
    public record Ctx(String userId, String account, String displayName,
                      String ip, String uri, String method, String userAgent, long startMillis) {}
    private static final ThreadLocal<Ctx> HOLDER = new ThreadLocal<>();
    public static Ctx current() { return HOLDER.get(); }
    public static void set(Ctx c) { HOLDER.set(c); }
    public static void clear() { HOLDER.remove(); }

    /** 取客户端 IP：X-Forwarded-For 第一个非 unknown 跳，回落 remoteAddr。 */
    public static String clientIp(HttpServletRequest req) {
        String xff = req.getHeader("X-Forwarded-For");
        if (xff != null && !xff.isBlank()) {
            String first = xff.split(",")[0].trim();
            if (!first.isEmpty() && !"unknown".equalsIgnoreCase(first)) return first;
        }
        String real = req.getHeader("X-Real-IP");
        if (real != null && !real.isBlank()) return real.trim();
        return req.getRemoteAddr();
    }
}
```

### 4.2 过滤器 `RequestContextFilter`（新建 `auth/RequestContextFilter.java`）

- 继承 `OncePerRequestFilter`，用 `FilterRegistrationBean` 注册，**order = −90**（在 Spring Security 链 −100 之后、Controller 之前），这样能读到 `JwtAuthFilter` 设置的用户属性。

### 4.4 `OperationLogService`（新建 `system/OperationLogService.java`，核心）

```java
@Service
public class OperationLogService {
    private final JdbcTemplate jdbc;
    private final SysParamService sysParamService;
    private final ObjectMapper objectMapper;   // Spring 自带，构造注入

    /** 最通用：自由组装。REQUIRES_NEW + try/catch，永不抛异常。 */
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void log(OperationLogRecord rec) { /* 填默认值 → 掩码 → INSERT */ }

    // —— 便捷重载（都最终调 log()）——
    public void log(String moduleCode, String action, String bizNo, String content);
    public void log(String moduleCode, String action, String bizType, String bizId, String bizNo, String content);
    public void logSensitive(String moduleCode, String action, String bizType, String bizId, String bizNo, String content);
    public void logFail(String moduleCode, String action, String bizType, String bizId, String bizNo,
                        String content, String failReason);

    /**
     * 修改留痕：对 keyFields 做字段级 diff。
     * @param before 改前快照（Map<字段key, 值>，key 用数据库列名或 DTO 字段名均可，需与 after 一致）
     * @param after  改后快照
     * @param keyFields 需对比的关键字段 key 集合（见 §7）
     * 行为：
     *  - 仅对比 keyFields 中存在于 before/after 的字段，值不同才记入 before_value/after_value(JSON)
     *  - 自动生成 operation_content，如："状态: 草稿→已审核; 金额: 100.00→120.00"
     *  - 关键字段无变化但 before/after 整体不等（如改了备注）：content="修改了备注等非关键字段"
     *  - label 取 OperationField.label(key) 中文名
     */
    public void logUpdate(String moduleCode, String bizType, String bizId, String bizNo,
                          Map<String,Object> before, Map<String,Object> after, Set<String> keyFields);

    /**
     * 单据详情查看。受参数 OP_LOG_ENABLE_DETAIL_VIEW 控制；
     * sensitiveModules 内的模块无论开关都记录。
     */
    public void logView(String moduleCode, String bizType, String bizId, String bizNo);
}
```

**`log(rec)` 内部职责**
1. `logId = "LOG" + UUID12 大写`（沿用项目约定，参考 `TmsUtil.uuid`）。
2. `operateAt = now`；`costTimeMs = now − RequestContext.startMillis`（无上下文则 0）。
3. 操作人：`account` 取 SecurityContext name（无上下文回落 `SYSTEM`）；`operatorId/displayName` 取 RequestContext，缺失时按 account 查 `sys_user_runtime`（用 Caffeine 缓存，`@Cacheable` 或简易 Map 缓存，避免每次查库）。
4. IP/URL/method 取 RequestContext。
5. `moduleName = OperationModule.name(moduleCode)`；`actionName = OperationAction.name(action)`。
6. `before_value/after_value` 序列化前对 key 匹配 `(?i).*(password|passwd|token|secret|pwd).*` 的字段值掩码 `***`。
7. INSERT 语句列与 §3.1 对应；**整段 try/catch（Exception 忽略）**。

> 参数读取：保留天数/开关统一走 `SysParamService`（`getInt(key, fallback, min, max)` / `getBool(key, fallback)`），不要裸查表。

## 6. 后端接入模式（每个 Controller 照此改）

### 6.1 改造步骤（统一套路）
1. 注入 `OperationLogService`，**删除**控制器内私有 `log(...)`。
2. 新增/审核/删除/启用停用等：把原 `log(...)` 调用换成 `operationLogService.log(模块码, 动作码, bizType, bizId, bizNo, 中文摘要)`。
3. **修改（UPDATE）路径**：在执行更新**前**先查改前快照，更新后调 `logUpdate`：
```java
// 以采购订单修改为例
Map<String,Object> before = jdbc.queryForMap(
    "SELECT status, supplier_name, warehouse, bill_date, amount, unpaid_amount, settlement_method " +
    "FROM purchase_order WHERE order_id = ?", orderId);
// ... 执行原有更新逻辑 ...
Map<String,Object> after = jdbc.queryForMap(
    "SELECT status, supplier_name, warehouse, bill_date, amount, unpaid_amount, settlement_method " +
    "FROM purchase_order WHERE order_id = ?", orderId);
operationLogService.logUpdate("purchase.order", "PURCHASE_ORDER", orderId, orderNo,
    before, after, KeyFields.PURCHASE_ORDER);
```
4. **详情查看（GET detail）**：方法首行加 `operationLogService.logView(模块码, bizType, bizId, bizNo)`（Service 内部按开关决定是否落库，try/catch 零风险）。
5. 导入：记 IMPORT，content 含文件名 + 成功/失败行数；导出/打印：服务端导出直接记，客户端导出/打印由前端打点（§8.4）。
6. 动作码用 `OperationAction.*` 常量，**禁止中文字符串**（修掉 OrderController 现存的 `"创建"/"审核"`）。

### 6.2 调用示例（改造前后对比）
```java
// 改造前（18 处重复，操作人写死）
private void log(String moduleCode, String action, String bizNo, String detail) {
    jdbcTemplate.update("INSERT INTO sys_operation_log_runtime(...) VALUES (...,'系统管理员',...)", ...);
}
log("purchase.inbound", "CREATE", no, "创建采购入库单");

// 改造后

        "PURCHASE_INBOUND", inboundId, no, "创建采购入库单");
```

## 10. 权限与脱敏

- **操作日志/登录日志菜单**：仅管理员（ADMIN）可见；普通业务用户不进系统管理页，但可在自己经手的单据上看「操作记录」时间线。
- **敏感字段**：`sensitive=Y` 记录（客户价格、商品进价/成本、信用额度、收付款、成本调整）。列表页不展示明文 diff；详情接口对非 ADMIN 返回 `***`。
- **掩码**：序列化 before/after 时，字段名匹配 `password|passwd|token|secret|pwd`（忽略大小写）的值一律 `***`。
- 成本/进价：落库保留（审计需要），查看受限。
