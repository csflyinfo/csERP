## 一、本次已完成

### 1. 采购订单新建体验重塑

**采购订单 / 销售订单**共用的 `BillDrawer` 全面重写：

- **抽屉定位**：从菜单栏右缘再向内缩进 75px（`left: 299px`），顶栏下方 48px 起（`top: 48px`）
- **遮罩透明可穿透**：`background: transparent + pointer-events: none`；抽屉主体 `pointer-events: auto`。用户打开抽屉后**依然可以点击左侧菜单切换其他模块**
- **状态提升到全局 Pinia store**（[stores/app.js](../frontend/src/stores/app.js#billDrawer)）：`billDrawer` state + `openBillDrawer / closeBillDrawer` actions
- **AppShell 全局挂载唯一 BillDrawer**：切换其他菜单不销毁；只在 `route.meta.module === billDrawer.moduleCode` 时渲染出来
- **草稿保护**：当前模块已有草稿抽屉时，「新建采购订单」按钮阻止再次新建，toast 提示"请先保存或关闭"
- **头部字段精简**：只保留供应商、采购员、仓库、单据日期；**删除**结算方式和货主字段
- **供应商 → 采购员联动**：选择供应商后调 `GET /base/supplier/detail?code=xxx`，自动带出 `defaultBuyer`
- **采购员改为下拉**：从 `POST /base/employee/buyers` 加载 `is_buyer=true` 且 `status=NORMAL` 的人员姓名

### 2. GoodsAddDialog 商品添加窗口（新组件）

[frontend/src/components/GoodsAddDialog.vue](../frontend/src/components/GoodsAddDialog.vue)：

- **布局**：商品搜索独占一行 + 备注独占一行；中间 12 个字段两列 grid（条码 / 规格 / 小单位 / 采购单位 / 采购数量 / 小单位数量 / 单价 / 金额 / 供应商最近采购价 / 系统最近采购价 / 当前库存 / 可用库存）
- **窗口宽度**：780px 固定，紧凑显示所有字段
- **商品搜索**：输入关键字**回车触发查询**（不即时展开），下拉后 ↑↓ 高亮 / Enter 选中 / Esc 关闭
- **单位下拉**：从商品档案 `unit_config` 提取 `enabled=true` 的单位；`↑↓` 循环切换；默认大单位 → 中单位 → 小单位（有则取）
- **数量约束**：非称重品仅整数、不允许负数；称重品允许小数
- **单价约束**：最多 4 位小数、不允许负数
- **金额互算**：`qty × price` 保留 2 位；用户手动改金额则反算单价（4 位）
- **小单位数量**：`qty × convertQty`，只读
- **供应商 / 系统最近采购价**：调 `GET /base/goods/latest-purchase-price`（V1.0 兜底为 `base_goods.latest_purchase_price`；后续引入采购单表后按 supplier 拆分）
- **当前库存 / 可用库存**：调 `GET /base/goods/stock-summary`（V1.0 无锁定表，两者相同）
- **Enter 移到下一字段**：`unit → qty → price → amount → remark`；在备注按 Enter 直接确定
- **窗口按钮**：取消 (Esc) / 添加并继续 / 确定
- **下拉不遮盖 bug 修复**：`suppressSearchWatch` 标志避免 `pickGoods` 触发 watch 打开下拉

### 3. 全局键盘快捷键

**BillDrawer**：抽屉可见且 GoodsAddDialog 未打开时激活

- `Ctrl+S` / `Cmd+S` → 保存单据（preventDefault 阻止浏览器"保存网页"）
- `Ctrl+A` / `Cmd+A` → 打开商品添加窗口（在 input/textarea/select 内不触发，保留原生"全选文本"）

**GoodsAddDialog**：窗口可见时激活

- `Ctrl+S` / `Cmd+S` → 添加并继续（保留窗口，清空表单）

按钮文案带出快捷键：`保存 (Ctrl+S)` / `+ 添加商品 (Ctrl+A)` / `添加并继续 (Ctrl+S)`

### 4. 日期时间字段全局规范

新增系统级规范文档：[规范-日期时间字段格式.md](../docs/PRD-版本化产品需求/00-总览与规范/规范-日期时间字段格式.md)

- **字段分类判定**：时刻（含时分秒，`YYYY-MM-DD HH:mm:ss`）vs 日期（仅日期，`YYYY-MM-DD`）
- **后端存储规范**：DATETIME / DATE，命名 `_at` 后缀
- **后端 JSON 输出**：`application.yml` 配 `jackson.date-format` + `time-zone: Asia/Shanghai`；[JacksonConfig.java](../backend/src/main/java/com/erp/common/config/JacksonConfig.java) 自定义 `JavaTimeModule` 覆盖 `LocalDateTime` / `LocalDate` / `java.sql.Timestamp` / `java.sql.Date` 序列化
- **前端统一工具**：[utils/dateTime.js](../frontend/src/utils/dateTime.js) `formatDateTime / formatDate / autoFormatByTitle`，兼容 6 种输入
- **自动化应用**：[module-api.js](../frontend/src/module-api.js) `mapRecordToRow` 里对表头含「时间」/「日期」的列自动格式化
- **字段命名清单**：30+ 常见字段 → 表头 → 格式的对照表
- **接入 checklist**：新模块 6 步检查项

### 5. 采购订单模块 SQL 兼容性修复

[CustomerPriceController.java](../backend/src/main/java/com/erp/base/CustomerPriceController.java)：

- 去掉 `DATE_FORMAT(effective_time, '%Y-%m-%d %H:%i')`（H2 MODE=MySQL 下 `%i` 不完全兼容 → bad SQL grammar）
- 去掉 SQL 层 `CONCAT` 拼接，改在 Java 层拼装派生字段：`customer / effectiveModeText / statusText / creatorInfo`
- 创建单时的 `CONCAT('管理员 ', DATE_FORMAT(NOW(), ...))` 也移到 Java 层用 `DateTimeFormatter` 处理

## 二、待办（下一批优化）

### 🟡 MySQL 联调（阶段一遗留）

Flyway 骨架已就位，DDL / seed 都是 MySQL 兼容语法。**未在真实 MySQL 8 上跑过完整回归**。

### 🟡 TS 迁移

阶段一/二未做，保留。建议按 stores → api → 通用组件 → 业务页 分阶段推进。

### 🟡 配置拆分

`module-config.js` / `module-api.js` 分别接近 400 / 600 行；按业务域拆到 `src/modules/*/config.js`。

### 🟡 采购/销售订单后端持久化

当前 BillDrawer 保存调 `/purchase/order/create` — 该端点未实现（stub）。V1.0 需要真正建 `purchase_order / purchase_order_detail` 表，落地：
1. 单据编号生成规则（复用 `sys_bill_no_rule_runtime` 的 `SO/PO` 规则）
2. 状态机（草稿/待审核/已审核/已关闭）
3. 审核后写「采购在途」影响库存 & 生成应付账款

### 🟡 抽屉编辑模式的明细回填

BillDrawer 里 `props.mode === 'edit'` 分支目前只填头部；明细需要后端 `/purchase/order/detail` 返回后回填。

### 🟢 GoodsAddDialog 复用给销售订单

组件当前标题固定"添加采购商品"，实际字段（供应商最近采购价 → 客户最近成交价、单价含税/去税等）在销售场景需要调整。通过 prop `mode: 'purchase' | 'sale'` 区分。

### 🟢 页面级快捷键规范化

目前 Ctrl+S / Ctrl+A 在 BillDrawer / GoodsAddDialog 各自实现。若后续新增单据类型（收付款单、调价单等），建议抽 `useShortcut.js` composable 统一管理，避免多组件监听全局 keydown 造成难维护。
