## 一、背景与问题

PRD-25/26 把司机配送链路与参数化跑通后，实际装车环节又暴露五个体验/口径问题：

| # | 问题 | 根因 | 影响 |
|---|---|---|---|
| 1 | 首页顶部统计把**已交账**任务也算进去 | 统计未排除当日已交账单 | 交账后数字仍挂着，司机以为还有活 |
| 2 | 后台一指派，首页卡片就显示**【已装车】** | `/loading/start` 把整单 `status` 直接翻成 `LOADED`，货其实没装 | 状态语义错误，司机/调度都误判 |
| 3 | 「查看清单」「装车确认」点配送点看不到单据与商品 | 缺配送点维度的单据+商品查询接口 | 司机无法核对这一点装了什么 |
| 4 | 某家装不下，只能整趟取消 | 没有按配送点退回调度池的入口 | 被迫空跑或整单作废，调度无法重排 |
| 5 | 发车无公里数/里程照片留痕 | `/depart` 不采集里程 | 后续无法核算任务里程 |

---

## 二、目标与范围

- 首页统计只算**进行中任务**，当日已交账（PENDING/APPROVED）不再计入。
- 修正装车状态机：指派后=**待接单**，司机接单后=**待装车**，全部装完才=**已装车**。
- 查看清单/装车页点配送点，弹窗展示该点的单据及单据下商品（名称/规格/单位/数量），按单据号+类型分组。
- 装车页支持按**整个配送点**退回调度池，后台单据留痕「某某司机退回」并从调度任务删除；最后一个点退回则整单取消。
- 新增系统参数「司机发车需里程照片与公里数」（默认是），为是时确认发车必须填公里数并拍 1 张里程照片。

**不在范围**：地图调序、里程按区间自动核算（本次只采集发车里程留痕）。

## 三、状态机修正

```
tms_dispatch.status：
  ASSIGNED  ──接单(accept/start)──▶ ACCEPTED ──全部点装车──▶ LOADED ──发车──▶ DEPARTED ──首店签收──▶ DELIVERING ──▶ COMPLETED
（待接单）                       （待装车）              （已装车）
```

- `/loading/start`（接单/开始装车）：`ASSIGNED/ACCEPTED → ACCEPTED`，`tms_delivery_trip` 保持 `PLANNED`，`sales_receipt.dispatch_status` 保持 `DISPATCHED`。**不再**把整单置 LOADED。
- `/loading/confirm`（逐点装车）：把**明细** `load_status='LOADED'`；当该单全部 RECEIPT 明细都 LOADED 且无未装车点时，才把 `dispatch/trip` 置 `LOADED`、`receipt` 置 `LOADED`。部分装车停在 ACCEPTED。
- `/depart`：放行状态扩为 `{ACCEPTED, LOADED, DEPARTED, DELIVERING}`（支持部分装车直接发车）。
- APP 端状态文案（司机视角，与后台调度侧「已接单」有意区分）：`ACCEPTED → 待装车`。

## 四、功能设计

### 4.1 首页统计交账过滤

`/tms/app/today-tasks` 与 `/tms/app/home/overview` 的主调度单查询都增加：

```sql
AND NOT EXISTS (
  SELECT 1 FROM tms_settlement s
  WHERE s.driver_id = d.driver_id AND s.settle_date = d.dispatch_date
    AND s.status IN ('PENDING','APPROVED'))
```

交账=当日作业闭环：交账后即便仍处 `DELIVERING` 的单也从首页统计与待发车卡片消失；`settledToday` 标签照常显示。

### 4.2 配送点单据+商品清单

新增 `POST /tms/app/loading/point-bills`，入参 `{dispatchId, detailId}`：

- 用 `detailId` 定位 `customer_code`，取同调度单下同客户的全部明细（RECEIPT + RETURN），按 `bill_type, source_bill_no` 分组。
- RECEIPT：`sales_receipt_detail JOIN sales_receipt LEFT JOIN base_goods`，规格取 `base_goods.spec`。
- RETURN：`sales_return_apply_detail`（自带 spec/unit_name）。
- 返回 `{customerCode, customerName, customerAddress, bills:[{billType,billTypeText,sourceBillNo,qty,skuCount,items:[{goodsCode,goodsName,spec,unitName,qty}]}], totalQty, skuCount}`。
- 弹窗组件 `widgets/point_bills_sheet.dart`，查看清单页与装车页复用。

### 4.3 配送点退回调度池

新增 `POST /tms/app/loading/return-point`，入参 `{dispatchId, detailIds, reason}`（reason 必填，≤200 字）。

- 前提：明细 `depart_time IS NULL`（已发车不能退），调度单状态 ∈ `{ASSIGNED, ACCEPTED, LOADED}`。
- 前端装车页只展示发货单卡片，一个点还可能挂取退单，因此后端按所传 `detailId` 的 `customer_code` **展开同店全部明细（含 RETURN）**一并退回，避免只退半家。
- 事务内：
  1. 发货单 → `dispatch_status='UNDISPATCHED'`，清空 `dispatch_id/trip_id`；退货申请 → `logistics_status='已安排调度'`，清空 `driver_id/driver_name/dispatch_id/trip_id`。
  2. 留痕写在**单据** `remark` 上（明细行随即删除）：`[YYYY-MM-DD HH:mm 司机<姓名> 装车退回：<reason>]`，司机名取 JWT 而非前端传参。
  3. `DELETE FROM tms_dispatch_detail WHERE detail_id IN (...)`。
  4. 重算 `tms_dispatch.store_count/loaded_qty/return_qty`。
  5. 无任何明细 → `dispatch/trip` 置 `CANCELLED`。
  6. 写 `sys_operation_log_runtime`（action=RETURN_POINT）。
- APP：卡片右下角【退回】（仅未装车且已接单阶段可见）→ 填原因确认 → 刷新清单；`cancelled=true` 时退回上一页。

### 4.4 发车公里数 + 里程照片

- 新参数 `P0128 / TMS_DEPART_MILEAGE_REQUIRED`「司机发车需里程照片与公里数」，`Y/N`，默认 `Y`，分组 `TMS配送`。
- `/depart` 在 `force` 校验后、写库前读取参数：为 `Y` 且 `departMileage` 非正数或缺 `departPhotoUrl` → `fail("请填写发车公里数")/("请拍摄里程照片")`。
- `tms_dispatch` 与 `tms_delivery_trip` 新增列：`depart_mileage DECIMAL(10,1)`、`depart_photo_url VARCHAR(500)`、`depart_mileage_time TIMESTAMP`。全量/部分发车都写，补发用 `COALESCE` 不覆盖首次值。
- 上传复用 `POST /tms/app/upload/image`，`bizType='DEPART'`（已加入允许类型）。
- `/tms/app/params` 快照下发 `departMileageRequired`；APP 在确认发车（含未装车二次确认）后弹「发车留痕」弹窗：数字键盘填公里数（必填>0）+ 拍照（必拍 1 张，弹窗内即时上传），取消则不发车。

## 六、验收要点

1. 建单指派后首页显示**待接单**；接单后显示**待装车**（不是已装车）；逐点装车时保持待装车；全装完才已装车。
2. 当日提交/审核交账后，`home/overview` 的 `pendingDispatches` 为空、顶部统计归 0。
3. point-bills 对含发货+退货的配送点按单分组，商品带 spec/unit/qty，发货单 spec 来自 `base_goods`。
4. return-point：单据回池、remark 含「司机XX退回」、明细删除、快照重算；同店取退单被一并退回；已发车点退回被拒；最后一点退回整单 CANCELLED。
5. 参数 Y 时缺公里数/照片被拒；补齐后 `depart_mileage/photo_url/time` 落库；参数 N 时不弹窗直接发车。
6. `flutter analyze` 无 issue；后端编译通过。
