## 二、核心状态机

### 2.1 采购订单状态

```text
草稿 → 待审批 → 已审批 → 部分入库 → 入库完成 → 已关闭
  │       │          │          │
  │       └→ 已驳回 → 草稿       └→ 已终止
  └→ 已删除
```

| 状态 | 可执行操作 | 限制 |
|---|---|---|
| 草稿 | 编辑、删除、提交审批 | 不形成采购在途 |
| 待审批 | 审批通过、驳回、撤回 | 不可入库 |
| 已审批 | 入库、生成预付款、取消审核、终止 | 形成采购在途 |
| 部分入库 | 继续入库、终止、关闭 | 不可取消审核 |
| 入库完成 | 查看、关闭 | 不可再入库 |
| 已终止 | 查看 | 剩余未入库数量释放在途 |
| 已关闭 | 查看 | 业务结束 |

### 2.2 采购入库单状态

```text
草稿 → 清点中 → 待上架 → 待审核 → 已审核
                    │
                    └→ 已关闭
```

审核动作必须按顺序执行：

```text
校验批次/数量/库位 → 增加库存 → 生成库存流水 → 计算成本 → 回写采购订单 → 生成采购收货单 → 操作日志
```

### 2.3 采购收货单状态

```text
待审核 → 已审核 → 已对账 → 已付款/部分付款
   │
   └→ 已作废（未生成应付或已冲销时）
```

- 审核后生成应付。
- 若已生成应付并发生付款核销，不允许直接反审核，需先反核销或生成冲销单据。

### 2.4 销售订单状态

```text
草稿 → 待审核 → 已审核/待出库 → 部分出库 → 已出库/待签收 → 部分签收 → 已签收 → 已完成
  │       │              │              │               │
  │       └→ 已驳回 → 草稿 └→ 已关闭       └→ 拒收/异常      └→ 售后中
  └→ 已删除
```

| 状态 | 库存影响 | 财务影响 |
|---|---|---|
| 草稿 | 不锁库存 | 无 |
| 待审核 | 不锁库存 | 无 |
| 已审核 | 锁定库存 | 无 |
| 已出库 | 扣减库存，配送在途 | 可展示待签收应收预估 |
| 已签收 | 不再影响库存 | 生成正式应收 |
| 已完成 | 无 | 可收款核销、开票 |
| 已关闭 | 释放未履约库存 | 视已签收情况保留应收 |

### 2.5 配送单状态

```text
待调度 → 已派单 → 待装车 → 已装车 → 配送中 → 已到达 → 已签收/部分签收/拒收 → 已完成
```

关键规则：

- WMS负责拣货、复核、集货交接。
- 司机APP负责装车、配送、签收、拒收、退货回收。
- 装车确认归TMS/司机端，不归WMS。
- 签收结果回写销售收货单，触发应收。

### 2.6 应收状态

```text
未核销 → 部分核销 → 已核销
   │          │
   └→ 已冲销  └→ 已冲销
```

账龄状态：

```text
未到期 → 逾期1-30天 → 逾期31-60天 → 逾期61-90天 → 逾期90天以上
```

### 2.7 应付状态

```text
未核销 → 部分核销 → 已核销
   │          │
   └→ 已冲销  └→ 已冲销
```

### 2.8 B2B订单状态

```text
待支付/待确认 → 已确认 → 待同步ERP → ERP已接单 → 待发货 → 配送中 → 已签收 → 已完成
       │              │              │
       └→ 已取消       └→ 同步失败      └→ 售后中
```

V2.5阶段，B2B订单是交易订单；ERP销售订单是履约和财务订单。二者通过映射表关联。

### 2.9 入驻商订单状态

```text
待接单 → 已接单 → 已发货 → 配送中 → 已签收 → 已完成 → 待结算 → 已结算
   │        │
   └→ 已取消 └→ 拒绝接单
```

## 三、全局权限模型

### 3.1 权限维度

| 权限类型 | 说明 |
|---|---|
| 菜单权限 | 是否可见模块入口 |
| 功能权限 | 新增、修改、删除、审核、反审核、打印、导入、导出 |
| 数据范围权限 | 按货主、仓库、片区、客户、供应商、业务员、入驻商过滤 |
| 字段权限 | 金额、成本、毛利、采购价、供应商费用、客户欠款等敏感字段 |
| 操作授权 | 低价销售、超信用、负库存、反审核、反核销等高风险动作 |

### 3.2 典型角色

| 角色 | 核心权限 |
|---|---|
| 系统管理员 | 用户、角色、参数、日志、字典、审批配置 |
| 老板/管理层 | 经营概览、利润、销售、库存、应收应付、报表 |
| 销售内勤 | 客户、销售开单、订单跟踪、收款登记 |
| 业务员 | 负责客户、代客开单、拜访、回款、售后申请 |
| 采购员 | 供应商、采购订单、采购入库跟踪、采购报表 |
| 仓库主管 | 库存、WMS任务、盘点、调拨、异常处理 |
| 仓库作业员 | PDA收货、上架、拣货、复核、盘点、移库 |
| 财务 | 应收应付、收付款、核销、发票、资金、财务报表 |
| 调度员 | 配送任务、派车、路线、异常监控 |
| 司机 | 司机APP任务、装车、签收、拒收、回款 |
| B2B运营 | 商品上下架、促销、订单、售后、装修 |
| 入驻商 | 本商家商品、订单、售后、结算 |

## 四、异常场景统一处理

### 4.1 库存异常

| 异常 | 处理 |
|---|---|
| 销售审核库存不足 | 阻止审核或进入预售，按参数控制 |
| B2B下单库存不足 | 禁止下单，展示缺货/到货提醒 |
| 拣货缺货 | 标记缺货，回写订单部分出库或等待补货 |
| 库存为负 | 触发预警，禁止结账 |
| 库存锁定超时 | 自动释放并通知业务员/客户 |
| 库存同步失败 | B2B商品标记库存异常，禁止高风险下单 |

### 4.2 财务异常

| 异常 | 处理 |
|---|---|
| 超信用额度 | 提示/阻断/审批，按客户和系统参数控制 |
| 逾期未收款 | 生成应收预警并推送业务员、主管、财务 |
| 收款重复核销 | 通过核销记录幂等校验阻止 |
| 付款账户余额不足 | 阻止付款审核或需主管授权 |
| 已结账期间反审核 | 阻止，需反结账后处理 |
| 发票金额不一致 | 进入发票差异待处理 |

### 4.3 履约异常

| 异常 | 处理 |
|---|---|
| 客户部分签收 | 按实际签收生成销售收货单，未签收部分进入拒收/退回 |
| 客户全部拒收 | 司机APP记录原因，生成拒收入库任务 |
| 司机回收退货与仓库入库不一致 | 生成退货差异处理单 |
| 司机离线无法提交 | 本地暂存，网络恢复后上传；关键财务动作需在线确认 |
| 配送超时 | 推送调度员，标记异常配送 |

## 五、验收用例模板

每个模块必须按以下格式编写验收用例。

| 字段 | 说明 |
|---|---|
| 用例编号 | 模块缩写-TC-序号，例如 SALES-TC-001 |
| 场景名称 | 明确业务场景 |
| 前置条件 | 数据、权限、状态 |

| 预期结果 | 页面、数据、状态、日志、联动结果 |
| 优先级 | P0/P1/P2 |
| 是否自动化 | 是/否 |

## 六、P0级全链路验收场景

### 6.1 采购到应付

| 用例 | 步骤 | 预期 |
|---|---|---|
| 采购完整闭环 | 新建采购订单 → 审核 → 采购入库 → 审核入库 → 采购收货 → 审核收货 | 采购在途正确、库存增加、成本更新、生成应付 |
| 采购部分入库 | 采购100箱，到货60箱 | 订单为部分入库，库存增加60箱，剩余40箱仍在途 |
| 采购退货 | 对已入库商品发起退货 | 库存扣减，应付冲减，库存流水可追溯 |

### 6.2 销售到应收

| 用例 | 步骤 | 预期 |
|---|---|---|
| 销售完整闭环 | 新建销售订单 → 审核 → 出库 → 签收 → 收货单审核 | 审核锁库存，出库扣库存，签收生成应收 |
| 部分签收 | 出库10箱，客户签收8箱 | 应收按8箱生成，2箱进入拒收/退回处理 |
| 客户退货 | 对已签收商品退货 | 退货入库，冲减应收，库存回增 |

### 6.3 收付款核销

| 用例 | 步骤 | 预期 |
|---|---|---|
| 客户收款核销 | 生成应收 → 新建收款单 → 核销 | 应收未收金额减少，资金账户增加 |
| 供应商付款核销 | 生成应付 → 新建付款单 → 核销 | 应付未付金额减少，资金账户减少 |
| 部分核销 | 收款金额小于应收金额 | 应收状态为部分核销，剩余金额继续挂账 |

### 6.4 库存一致性

| 用例 | 步骤 | 预期 |
|---|---|---|
| 库存流水核对 | 查询某商品全部出入库流水 | 流水汇总等于库存余额 |
| 锁定释放 | 销售订单审核后取消 | 锁定库存释放，可用库存恢复 |
| 成本计算 | 连续两次不同价格采购入库 | 移动加权成本按公式正确计算 |

## 七、上线准入标准

每个版本上线前必须满足：

1. P0流程100%通过。
2. 影响库存、应收、应付、资金的单据均有操作日志。
3. 核心报表金额与明细合计一致。
4. 权限测试覆盖菜单、功能、数据范围、字段权限。
5. 异常流程有明确提示，不出现无反馈失败。
6. 反审核、反核销、作废、冲销均有约束条件。
7. 导入失败必须可下载失败原因。
8. 导出大数据走导出中心，不阻塞页面。
