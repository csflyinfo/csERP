## 一、产品总定位

本产品面向商贸流通、批发经销、快消品配送、区域供应链企业，建设一套覆盖 **B2B在线订货、ERP进销存经营管理、WMS仓储履约、TMS配送履约、财务结算与经营分析** 的一体化平台。

一句话定位：

> 面向商贸流通企业的 B2B订货 + ERP进销存 + WMS仓储 + TMS配送 + 财务结算全链路数字化平台。

产品不以“功能大而全”为第一目标，而以“业务闭环可落地、账实一致、钱货清楚、多端协同”为第一目标。

## 二、版本拆分原则

### 2.1 拆分逻辑

系统能力按业务成熟度拆为五个可交付版本：

| 版本 | 名称 | 核心目标 | 典型客户价值 |
|---|---|---|---|
| V1.0 | ERP核心经营版 | 打通进销存财最小闭环 | 老板能看账，业务能开单，仓库能出入库，财务能收付款 |
| V1.5 | 仓储作业版 | 强化库位、PDA、波次、盘点 | 仓库作业标准化，减少错拣漏拣和库存差异 |
| V2.0 | 仓配一体版 | 打通调度、司机、签收、拒收 | 配送过程可追踪，签收后准确生成应收 |
| V2.5 | B2B订货版 | 上线客户商城与B2B后台 | 客户自助下单，降低电话开单成本 |
| V3.0 | 平台多入驻商版 | 支持入驻商、统配、自配、结算 | 从单企业系统升级为区域供应链平台 |

### 2.2 版本建设原则

1. **先经营闭环，后作业精细化**：V1.0先确保订单、库存、应收应付、收付款准确。
2. **先自营，后平台招商**：B2B先做平台自营商品，不在首版引入多入驻商复杂度。
3. **先在线主链路，后离线增强**：PDA、司机APP先做弱离线，关键审核动作保持在线。
4. **先标准流程，后高级策略**：波次、调度、促销、结算均先提供标准可用版本，再迭代复杂策略。
5. **所有库存和财务动作必须可追溯**：任何影响库存、成本、应收、应付、资金的动作必须有来源单据和操作日志。

## 三、统一业务口径

### 3.1 核心单据触发点

| 业务事件 | 触发结果 | 版本要求 |
|---|---|---|
| 采购订单审核 | 形成采购在途，可进入采购入库 | V1.0 |
| 采购入库单审核 | 增加库存、生成库存流水、计算移动加权成本、生成采购收货单 | V1.0 |
| 采购收货单审核 | 生成正式应付账款 | V1.0 |
| 销售订单生成 | 占用库存（PRD-24 起，生成即占用，非审核才占） | V1.0 |
| 销售订单审核 | 库存占用延续，不重复占用；进入出库/履约流程 | V1.0 |
| 销售出库单审核 | 释放占用（批次层+商品仓库层）、扣减库存、生成库存流水、形成配送在途 | V1.0/V1.5 |
| 客户签收/销售收货单审核 | 生成正式应收账款 | V1.0/V2.0 |
| 收款单审核并核销 | 更新应收余额、资金账户流水 | V1.0 |
| 付款单审核并核销 | 更新应付余额、资金账户流水 | V1.0 |
| B2B订单支付/账期确认 | 同步生成ERP销售订单并锁定库存 | V2.5 |
| 入驻商订单完成 | 进入入驻商结算 | V3.0 |

### 3.2 库存口径

```text
实物库存 = 仓库实际存在数量
锁定库存 = 已下单/已分配但未出库数量
冻结库存 = 质检、盘点、异常等不可用数量
可用库存 = 实物库存 - 锁定库存 - 冻结库存
B2B可售库存 = 可用库存 - 安全库存 - 活动锁定库存 - 预留库存
```

### 3.3 成本口径

- 成本算法：移动加权平均法。
- 成本粒度：货主 + 商品 + 成本分组。
- 成本触发：采购入库单审核、采购费用分摊、采购改价、盘盈指定成本。
- 销售出库取出库时成本，不重算历史成本。
- 采购收货单用于应付结算，不作为库存成本的首要触发点。

### 3.4 财务口径

- 应收依据：客户签收/销售收货单审核。
- 应付依据：采购收货单审核。
- 销售出库可产生“待签收应收预估”，但不得作为正式应收核销依据。
- 采购入库可展示“待确认应付预估”，但正式应付仍由采购收货单生成。

## 六、V1.0必须守住的产品边界

### 6.1 V1.0必须做

- 用户、权限、角色、数据权限。
- 商品、客户、供应商、仓库、价格、资金账户。
- 采购订单、采购入库、采购收货、采购退货基础流程。
- 销售订单、快速开单、销售出库、销售收货、销售退货基础流程。
- 库存余额、库存锁定、库存流水、移动加权成本。
- 应收、应付、收款、付款、核销、账期基础规则。
- 经营概览、销售报表、采购报表、库存报表、应收应付报表。

### 6.2 V1.0明确不做或弱化

| 能力 | V1.0处理方式 |
|---|---|
| AI采购预测 | 可预留菜单，V1.0不作为主链路依赖 |
| 固定资产 | 暂不做 |
| 凭证自动化 | 可预留凭证模板，V1.0以业务财务为主 |
| 多入驻商 | 暂不做 |
| B2B商城 | 暂不做 |
| 复杂波次策略 | 暂不做，仅保留标准出库单 |
| 复杂运费结算 | 暂不做 |
| 完整离线能力 | 暂不做，后续在PDA/司机APP迭代 |

## 七、后续开发使用说明

1. 产品、UI、开发、测试均以本目录新版PRD和 `docs/子系统/` 为准。
2. 如新版PRD与历史参考资料冲突，以新版PRD和 `docs/子系统/00-子系统文档索引与统一口径.md` 为准。
3. 每个版本进入开发前，应先完成：页面原型、接口契约、数据库设计、测试用例。
4. 每个版本验收必须验证：正常流程、异常流程、权限控制、状态流转、库存/财务联动、操作日志。
