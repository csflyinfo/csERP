# 全局规范 — 日期时间字段格式

> 生效范围：V1.0 及以后所有模块（后端 + 前端）
> 生成日期：2026-07-17

本文件是**开发强制规范**，所有新增/改造模块必须遵循。已有模块逐步收敛。

---

## 一、字段分类

| 语义 | 示例字段 | 显示格式 | 存储类型 |
|---|---|---|---|
| **时刻**（含时分秒） | `created_at`、`updated_at`、`audit_time`、`submit_time`、`operate_at` … | `2026-07-17 22:35:54` | `DATETIME` / `TIMESTAMP` |
| **日期**（无时分秒） | `bill_date`、`business_date`、`expected_arrival_date`、`due_date` … | `2026-07-17` | `DATE` |
| **有效期段** | `effective_time`、`expire_time` | 按上面对应类型 | `DATETIME` / `DATE` |

**判定原则**：
- 只要业务上关心「什么时候发生的」→ 用「时刻」；
- 只要业务上关心「哪一天」→ 用「日期」；
- 时间点的精度不能低于对应等级：`created_at` 用 `DATE` 是错误的。

---

## 二、后端存储

- MySQL：`DATETIME` / `DATE`。不用 `TIMESTAMP`（避免时区隐式转换）。
- H2 dev：`TIMESTAMP` 兼容 `DATETIME`；`DATE` 保持一致。
- 数据库列命名统一 `snake_case`：`_at` 结尾表示时刻，`_date` / `_time` 结尾按语义。
- 全部字段使用 UTC+8 存储，V1.0 不做多时区。

---

## 三、后端返回给前端

| 类型 | JSON 序列化格式 |
|---|---|
| 时刻 | `"2026-07-17 22:35:54"` (String, no `T`, no `Z`) |
| 日期 | `"2026-07-17"` (String) |

**关键**：不要直接把 `LocalDateTime` / `Timestamp` 交给 Jackson 默认序列化（会输出 `2026-07-17T22:35:54.123456` 或 epoch 毫秒）。

**推荐方案（V1.0 已采用）**：`application.yml` 加：

```yaml
spring:
  jackson:
    date-format: "yyyy-MM-dd HH:mm:ss"
    time-zone: "Asia/Shanghai"
```

针对个别字段需要不同格式的，在 DTO 上打 `@JsonFormat(pattern = "yyyy-MM-dd")`。

JdbcTemplate `queryForList` 返回的 `Map<String, Object>` 里 H2 会给 `LocalDateTime`，MySQL 会给 `Timestamp`。**前端呈现前必须格式化**，见下节。

## 四、前端展示

**统一工具**：`frontend/src/utils/dateTime.js`（本次新建）。

```js
import { formatDateTime, formatDate } from '@/utils/dateTime'

formatDateTime(row.createdAt)  // '2026-07-17 22:35:54'
formatDate(row.billDate)       // '2026-07-17'
```

工具会**兼容 6 种输入**：
1. `'2026-07-17T22:35:54.123456'`（ISO 带 T）
2. `'2026-07-17 22:35:54'`（已是目标格式，原样返回）
3. `'2026-07-17T22:35:54Z'` / `'...+08:00'`（带时区）
4. `epoch 毫秒`（Number）
5. `Date` 对象
6. 空 / `null` → 返回空串

**规则**：
- 列表列（表头含"时间/日期"）由 `GenericBusinessList` **自动应用**格式化（在 `mapRecordToRow` 前处理）。
- 详情/抽屉/单据表头**手动调用** `formatDateTime` / `formatDate`。
- 导出 xlsx 时也用同一工具，保证 Excel 里的展示与页面一致。

## 五、字段命名清单（含格式）

### 5.1 时刻（`YYYY-MM-DD HH:mm:ss`）

后端字段驼峰 → 前端展示表头：

|后端字段|前端表头|
|---|---|
|`createdAt`|创建时间 / 变价时间|
|`updatedAt`|更新时间|
|`operateAt`|操作时间|
|`auditTime`|审核时间|
|`submitTime`|提交时间|
|`createTime`|制单时间 / 创建时间|
|`effectiveTime`|生效时间|
|`expireTime`|过期时间|
|`printTime`|打印时间|
|`lastMoveTime`|最近出入库时间|

### 5.2 日期（`YYYY-MM-DD`）

|后端字段|前端表头|
|---|---|
|`billDate`|单据日期|
|`businessDate`|业务日期|
|`expectedArrivalDate`|预计到货日期|
|`dueDate`|预计收款日 / 预计付款日 / 到期日|
|`cutoffDay`|截账日|
|`paymentDay`|付款日|
|`productionDate`|生产日期|
|`expiryDate`|到期日期|

### 5.3 已知例外

- 「变价时间」逻辑上是**时刻**（含时分秒），前端表格显示 `2026-07-17 22:35:54`（本次修复的 case）。
- 客户价格调整单里 `effectiveTime` 是**时刻**（用户可选定时生效到某分钟）。

## 六、接入 checklist（新模块开发时对照）

- [ ] DB 列：DATETIME 或 DATE，命名符合 §一
- [ ] Java 实体：`LocalDateTime` 或 `LocalDate`（**不用** `Date`）
- [ ] 若返回给前端时格式不匹配 Jackson 全局配置 → DTO 上打 `@JsonFormat`
- [ ] 前端表头文案：含"时间"用时刻，含"日期"用日期
- [ ] 前端展示：调用 `formatDateTime` / `formatDate`
- [ ] 前端导出 xlsx：同上（保持展示一致）
- [ ] 前端筛选控件：时刻/日期段都用 `<input type="date">` 两个（V1.0 精度到日；如需精确到时分秒后续再加 datetime-local）
