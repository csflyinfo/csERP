# 原型评审1.0 — V1.0 ERP核心经营版原型评审报告

> 评审对象：`prototype/v1-erp-complete/index.html`  
> PRD基线：`docs/PRD-版本化产品需求/V1.0-ERP核心经营版/` 目录下V1.0相关文档  
> 评审日期：2026-06-13  
> 评审目的：检查当前原型是否覆盖V1.0 ERP核心经营版PRD要求，识别菜单、页面、字段、交互、状态、验收支撑等方面的问题，并提出优化建议。

---

## 一、评审结论

当前 `prototype/v1-erp-complete/index.html` 是一个**功能骨架级原型**，已经具备基础的后台系统外壳、菜单导航、列表页、表单页和部分单据页面展示能力，适合用于初步演示系统结构。

但对照 `V1.0-ERP核心经营版` 目录下的PRD文档来看，当前原型距离“可直接指导UI高保真设计、前端开发、测试验收”的标准还有明显差距。

核心问题集中在：

1. 财务管理模块结构不符合PRD要求，应收/应付/结算/预收/预付/核销缺失或过于简化。
2. 高频开单体验不足，销售快速开单、采购订单未真正实现键盘快捷操作、商品快速添加、行内编辑和合并规则。
3. 通用网格交互未落实，字段设置、拖拽排序、表头排序、固定列、分页、查询总合计等缺失。
4. 采购发票、采购费用、调拨、初始化、库存流水、库存锁定、库存预警等关键页面覆盖不足。
5. 状态、异常、权限、必填校验、空态、加载态等UI状态不完整。

总体评价：

| 维度 | 评分 | 说明 |
|------|:---:|------|
| 菜单覆盖 | 3.5/5 | 大部分模块入口已有，但仍缺若干P0/P1页面 |
| 页面结构 | 3/5 | 有统一布局，但业务差异化不足 |
| 字段完整度 | 2.5/5 | 多数单据使用通用字段，未体现PRD细节 |
| 高频交互 | 2/5 | 快捷键和网格交互基本未实现 |
| 财务闭环 | 2/5 | 应收/应付/核销/预收预付不足 |
| 测试验收支撑 | 2.5/5 | 缺少异常态、状态流和验收级交互 |

## 三、P0级问题：必须优先修复

## 3.1 财务管理模块结构不符合PRD要求

### 问题说明

PRD中对应收、应付、预收、预付、结算、核销有较完整设计。尤其是 `18-V1.0-期初初始化预收预付与调拨管理PRD.md` 中明确：

```text
应收账款
├─ 应收明细
├─ 应收结算
├─ 预收款
├─ 收款记录
├─ 账龄分析
└─ 逾期预警

应付账款
├─ 应付明细
├─ 应付结算
├─ 预付款
├─ 付款记录
├─ 账龄分析
└─ 付款排期
```

当前原型只有：

```text
应收账款/结算
应付账款/结算
收款单/付款单
```

且页面仍为通用单据列表，缺少实际结算和核销交互。

### 影响

- 财务人员无法通过原型理解实际收付款操作。
- 预收款、预付款功能未体现。
- 收款核销、付款核销流程无法评审。
- 测试人员无法据此设计应收/应付验收用例。

### 优化建议

将应收账款页面改为多页签：

```text
应收账款
├─ 应收明细
├─ 应收汇总
├─ 应收结算
├─ 预收款
├─ 收款记录
├─ 账龄分析
└─ 逾期预警
```

将应付账款页面改为多页签：

```text
应付账款
├─ 应付明细
├─ 应付汇总
├─ 应付结算
├─ 预付款
├─ 付款记录
├─ 账龄分析
└─ 付款排期
```

应收结算/应付结算页面需体现：

- 对象选择：客户/供应商/往来单位
- 待结算单据列表
- 本次结算金额
- 折让金额
- 收款/付款方式
- 资金账户
- 生成收款/付款单并核销
- 结算后余额

当前原型中销售快速开单页面虽然显示了快捷键文字，例如 F2、F3、F4、F7，但没有实际交互逻辑：

- 无明细表格单元格跳转

### 优化建议

至少在以下页面优先实现快捷键模拟：

1. 销售快速开单
2. 采购订单
3. 采购入库
4. 应收结算
5. 应付结算
6. 采购费用单

并在页面右上角增加：

```text
快捷键帮助 [?]
```

# 五、与PRD不一致点

## 5.1 工作台销售额口径有歧义

原型工作台指标中有：

```text
今日销售额 = 今日销售收货单审核金额或销售订单金额，可配置
```

但最新统一口径是：

```text
正式销售额 = 销售收货单/客户签收确认金额
```

建议：

- 今日销售额：按销售收货单审核金额
- 今日订单金额：按销售订单金额

不要混用。

---

## 5.2 销售出库页面命名需谨慎

原型将“销售出库”放在销售管理下。若该页面只是查询销售出库单，可以保留；若承担出库作业，则应放入WMS/库存模块。

建议命名为：

```text
销售出库单
```

或：

```text
销售出库查询
```

---

## 5.3 采购发票和销售发票不对称

原型已有采购发票，但没有销售发票。

PRD已明确需要销售发票管理。建议补：

```text
销售发票
销售开票跟踪
```

# 六、UI体验优化建议

## 6.1 高频开单页面应升级为工作台式页面

销售快速开单、采购订单不应只是普通表单，而应更适合高频录入：

- 顶部固定客户/供应商信息
- 中间大搜索框
- 明细表支持键盘录入
- 底部固定金额汇总
- 右侧风险提示
- 快捷键帮助
- 商品选择弹窗
- 常购/历史/分类/促销/预测商品 TAB

---

## 6.2 风险页面必须有强提示

| 页面 | 风险提示 |
|------|----------|
| 采购费用单 | 审核后重算成本，可能影响后续出库成本和毛利 |
| 成本调整单 | 不改变库存数量，但改变库存金额 |
| 报损单 | 直接减少库存并形成公司损失 |
| 采购发票 | 勾稽后影响来票状态和进项税额 |
| 反审核 | 可能影响下游单据 |
| 付款单 | 审核后扣减资金账户余额 |

---

## 6.3 所有表单需要必填校验

建议：

- 必填字段 label 后加红色 `*`
- 保存失败时定位到第一个错误字段
- 错误字段红框
- 显示错误提示
- 金额/数量字段限制负数
- 日期字段限制逻辑错误

---

## 6.4 补充页面空态、加载态、异常态

| 状态 | 示例 |
|------|------|
| 空数据 | 暂无数据，去新建 |
| 加载中 | 骨架屏/Loading |
| 接口失败 | 加载失败，点击重试 |
| 权限不足 | 无权限访问该页面 |
| 数据锁定 | 当前单据已审核，不可编辑 |
| 下游存在 | 存在下游单据，不允许反审核 |

## 第三优先级：补高风险页面细节

1. 采购费用单
2. 成本调整单
3. 报损单
4. 调拨单
5. 数据初始化向导

## 第四优先级：补状态和异常

1. 完整状态颜色
2. 必填校验
3. 空态
4. 加载态
5. 权限态
6. 下游存在无法反审核提示

# 八、结论

当前 [index.html](../../../../prototype/v1-erp-complete/index.html) 已经是一个可演示的ERP V1.0骨架原型，但还不能完全支撑V1.0 ERP核心经营版PRD落地。

最需要优先补的不是视觉细节，而是：

1. 财务闭环页面结构；
2. 库存流水/锁定/预警；
3. 采购发票详情与勾稽；
4. 销售发票；
5. 快捷键和网格交互；
6. 调拨、初始化、预收预付；
7. 状态、异常、必填校验。

建议先围绕“销售快速开单、采购订单、采购费用单、采购发票、库存余额/流水、应收应付结算”几个核心页面做一轮增强，再推进其他页面。
