# PRD-34 业务期初初始化（库存 / 客户应收 / 供应商应付）

- 版本：V1.0 ERP 核心经营版
- 状态：已完成（功能分支 `feat/finance-opening-init`，待 squash 合并 main）
- 分支：`feat/finance-opening-init`（squash 合入 main 即删）
- Flyway：V123（`inv_stock_init` / `fin_ar_init` / `fin_ap_init` / `biz_init_post`）
- 关联：PRD-32 总账初始化（一键引入业务期初实时读取 `fin_ar`/`fin_ap`/`inv_stock_balance`）、PRD-33 业务日结（日结后期初锁定）

## 1. 背景与目标

新客户上线 / 新账套启用时，系统启用时刻的存量数据必须有落账入口：

- **库存期初**：旧通道「其他入库单-期初库存」只写财务三层账（商品+仓+批次），不写 WMS 库位库存，启用 WMS 后 PDA / 波次无库位可拣；
- **客户应收 / 供应商应付期初**：此前无录入入口（首次日结向导只有「往来期初已核对」勾选框），`fin_ar`/`fin_ap` 只能由业务单据审核生成；
- 总账初始化（PRD-32）的「一键引入业务期初」实时汇总 `fin_ar`、`fin_ap`、`inv_stock_balance`——业务期初不落地，1122 应收 / 2202 应付 / 1405 库存商品科目就引不到数。

目标：三个互相独立的期初模块，统一范式 **Excel 导入 + 手工增改删行 → 暂存核对 → 一次性期初建账（过账）写正式账表 → 锁定**；首次业务日结前允许有条件反建账重来。

## 2. 已拍板产品决策

1. **库存期初双流程**：页面两个页签 + 两套模板——「按批次（未启用 WMS）」只导商品+批次；「按库位（启用 WMS）」必导库位，过账同时写 `wms_bin_stock`。同一 **商品+仓+批次** 不得混导（要么全部定位库位、要么全部不定位），文件内 / 跨批暂存 / 手工行三处拦截。
2. **支持手工新增 / 编辑 / 删除行**，不只靠导入。
3. **允许有条件反建账**：无任何业务日结记录 + 总账未启用 + AR/AP 行未被核销 + 库存无后续出入库流水且余量等于过账量。
4. **成本单价必填，允许填 0**；0 成本行页面警示但不阻断，建账后由首次采购入库重算移动加权成本。
5. **账龄按建账日立账**：`fin_ar.created_at = 建账日`、AR/AP `due_date = 建账日 + 30 天`；模板的原单据号 / 原单据日期仅留存期初表供查询，不进正式账表；模板不设到期日列。
6. 商品+仓库在 `inv_stock_balance` **已有数量余额时整批拒绝过账**，必须先清零后再建账。
7. **只导未达余额**：AR `received_amount=0`、AP `paid_amount=0`，不造历史收付款 / 核销流水。

## 4. 数据模型（V123）

四张表，约定同 V93：VARCHAR(32) PK、DECIMAL、中文状态码、`IF NOT EXISTS` 幂等、无外键。

### 4.1 `inv_stock_init` 库存期初暂存行

关键列：`line_id`、`import_batch_no`（SC/SK+ 批次号）、`row_no`（Excel 物理行号）、`init_mode`（BATCH/BIN）、商品/仓库编码名称、`bin_code`/`container_code`（BIN 模式）、`batch_no`（规则推导后最终批号，可空）、`batch_no_input`、`production_date`、`expiry_date`、`qty` DECIMAL(18,4)、`unit_price` DECIMAL(18,6)、`amount`、`line_status`（VALID/ERROR）、`error_msg`、`task_no`、`posted`、`post_no`、`generated_ledger_ids`（台账来源号清单）、`generated_bin_stock_ids`、审计三列。

### 4.2 `fin_ar_init` / `fin_ap_init` 往来期初暂存行

客户/供应商编码名称、`original_bill_no`/`original_bill_date`（**仅留存**）、`ar_amount`/`ap_amount`（未达余额）、AR 多 `salesman`、`remark`、状态/错误/任务/过账回写列、`generated_ar_no`/`generated_ap_no`、审计三列。

### 4.3 `biz_init_post` 过账主表

`post_no` UNIQUE（`QC` + yyyyMMdd + 4 位流水，MAX+1）、`init_type`（STOCK/AR/AP）、`line_count`、`total_qty`、`total_amount`、`status`（POSTED/REVERSED）、建账人/时间、反建账人/时间/原因。

建账标志存 `sys_param_runtime`：`biz.init.stock_posted` / `biz.init.ar_posted` / `biz.init.ap_posted`（Y/N）及对应 post_no 键，懒创建。

## 5. 业务流程

### 5.1 暂存（导入 / 手工）

- Excel 导入：逐行解析校验，**VALID / ERROR 全行落库**；部分成功部分失败，不整批回滚；ERROR 原因随「导入列表」失败文件（`data/import-failures/{taskNo}.xlsx`）可下载，页面行内也可见。
- 手工行：弹窗新增 / 编辑 / 删除；手工行固定批次号 `MANUAL`。
- 可追加导入；可按导入批次或整表清空未建账行。
- 建账前置守卫（三个模块公共）：本模块 posted=N、`BizDayCloseGuard.lastClosedDate()==null`（无任何日结）、`fin.gl.initialized<>Y`（总账未启用）。

### 5.2 库存过账（单事务）

1. 存在 ERROR 行即拒绝；至少 1 行 VALID。
2. **余额守卫**：任一（商品+仓）`inv_stock_balance.physical_qty > 0` → 中文报错整批拒绝；physical=0 的零数量残留行先删除，确保期初单价真正建立成本价。
3. 按（商品+仓）聚合加权平均成本 `Σ(qty×单价)/Σqty`（6 位小数 HALF_UP）；按（商品+仓+批次）调一次 `InventoryCostService.inboundAtCurrentCost(...)`，来源单号 `QTRK-{postNo}-{seq}`。
4. 批次规则：手填批号 > 生产日期 yyyyMMdd > 空；效期：显式填写 > 生产日期 + `base_goods.shelf_life_days`，引擎不写效期时显式 UPDATE `inv_batch_stock.expiry_date`。
5. BIN 行聚合到（批次+库位+容器）调 `BinStockService.addInboundBinStock` 写位置账（upsert `wms_bin_stock` + `wms_bin.used_qty += qty` + `wms_bin_stock_log`，来源号同 QTRK 前缀），过账时复核库位存在、status=NORMAL、未冻结。
6. 暂存行回写 posted=Y / post_no / generated 两类来源号；写 `biz_init_post`、置参数键。合计金额按 Σ(qty×加权均价) 2 位。

### 5.3 AR / AP 过账（单事务）

- 逐行真实插入 `fin_ar` / `fin_ap`，ar_no/ap_no 走 `BillNoGenerator`（行真实插入，禁止借号不插行）。
- AR：金额=未收余额、received=0、overdue_days=0、invoice_status='未开票'、status='UNVERIFIED'（保证结算可选）、reconcile_status='未对账'、`created_at=建账日`、`due_date=建账日+30`、source_bill=`QCAR-{postNo}-{seq}`。
- AP：同构，invoice_status='未来票'、invoiced_amount=0、paid=0、`due_date=建账日+30`、source_bill=`QCAP-{postNo}-{seq}`（fin_ap 无 created_at 列）。
- 客户/供应商按编码解析存标准名称；不触发任何 GL hooks（直接 insert）。

### 5.4 反建账（单事务，原因必填留痕）

公共守卫：有 POSTED 过账主表、无任何日结、总账未启用。

- AR/AP：`fin_reconcile_record.business_no = ar_no/ap_no` 无核销记录；按 generated 单号删行。
- 库存四层余量守卫：① 同商品+仓 `inv_stock_ledger` 无来源号非 `QTRK-{postNo}-%` 的后续流水；② balance 物理/可用量合计 == 过账量；③ batch 余量合计 == 过账量；④ wms_bin_stock 按 bin_stock_id 存在且数量 == 过账量。
- 回退顺序：删台账（LIKE 前缀）→ 删批次账 → 删余额 → 删库位账并回减 `wms_bin.used_qty`（GREATEST 兜底）→ 删库位流水；暂存行回 posted=N、清空 post_no/generated；主表置 REVERSED、清参数键，可重新过账。

### 5.5 与总账 / 日结的衔接（强制顺序）

页面顶部蓝色引导条固定提示：

> 先建应收/应付与库存业务期初 → 总账一键引入业务期初（1122/2202/1405）→ 启用总账 → 首次业务日结。

建账后、日结前仍可反建账；**一旦发生首次业务日结，三个期初模块全部只读锁定**。

## 6. 校验规则

### 6.1 库存

- 必填：商品编码、仓库编码、数量、成本单价；BIN 模式加库位编码必填。
- 商品 / 仓库编码必须存在；商品 DELETED 拒、STOPPED 放行；名称列留空取档案标准名，填写不一致仅作核对不阻断（以编码为准）。
- 日期 `yyyy-MM-dd`，效期 < 生产日期拒绝；数量 > 0（BATCH 4 位小数 / BIN 3 位小数）；成本单价 ≥0（6 位小数）。
- 库位：（仓库名, 库位编码）必须存在且 NORMAL、未冻结；BATCH 模式填库位列直接拒。
- 重复键：文件内（商品+仓+批次 [+库位+容器]）重复判行失败；同键跨模式（含历史暂存、手工行）判失败。

### 6.2 AR / AP

- 必填：客户/供应商**编码**、金额；金额 > 0（2 位小数）；编码不存在行失败（不靠名称匹配，规避重名）。
- 原单号可空；同文件（编码 + 原单号）重复判失败。
- 原单据日期 `yyyy-MM-dd`，仅留存不参与账龄。

### 6.3 通用

非法编码 / 数字 / 日期即行失败并给中文原因；rowNo = Excel 物理行号（含表头，首行数据=2）；追加导入，按批清空。

## 10. 验收标准

1. 四个模板下载 200 且为合法 xlsx，含「导入说明」页签，表头与 fieldMap 逐列一致。
2. 混合行导入（坏编码 / 冻结库位 / 负金额 / 重复键 / 跨模式混用）：inserted/failed 计数正确、ERROR 行行内可见原因、失败文件可下载。
3. 手工增 / 改 / 删 / 清空生效；ERROR 存在时过账被中文报错拒绝；已有数量余额的商品仓整批拒绝。
4. 过账核账：库存三账数量 / 加权均价 / 金额、批次量与效期、台账（QTRK-、IN）、BIN 模式 wms_bin_stock + used_qty + log；fin_ar（QCAR-、UNVERIFIED、未开票、received=0、created_at=当天、due_date=+30）、fin_ap（未来票、paid=0）。
5. 过账当天执行首次业务日结成功（tieAr/tieAp/库存滚存全过）；日结后所有写操作与反建账被拒，status.dayCloseLocked=true。
6. 总账一键引入：1122/2202/1405 辅助金额 = 三模块合计；GL 启用后期初过账 / 反建账被拒。
7. 全新账套反建账全链路回退干净（暂存行恢复、正式账无残留、参数清除、可重新过账）；存在核销 / 后续流水时反建账被拒。
8. 浏览器三页面真实交互：菜单可见、权限码生效、超管自动授权。
