# 新建/编辑交互方式设计建议

> 适用范围：ERP+WMS+TMS+B2B Web后台系统  
> 输出目的：统一“新建 / 编辑 / 查看 / 审核 / 作废”等操作的页面承载方式，为后续原型设计、UI设计、前端开发提供交互规范建议。  
> 日期：2026-06-13

---

## 一、结论

市场上通行的 Web 管理系统在“新建 / 编辑”时，主要采用以下几种方式：

1. **小弹窗 Modal**
2. **右侧抽屉 Drawer**
3. **独立页面 / 全屏表单**
4. **表格行内编辑**
5. **详情页内分区编辑**

对于本项目这种 ERP + WMS + TMS + B2B 全链路系统，不建议所有新增/编辑都统一使用小弹窗。正确做法应按业务复杂度、字段数量、操作频率和风险等级分层设计。

推荐总原则：

> **简单字典用小弹窗，中等资料用右侧抽屉，核心业务单据用独立页面，高风险确认用确认弹窗，高频录入页面必须支持键盘快捷键。**

---

## 二、市场通行的新建/编辑方式

## 2.1 小弹窗 Modal

### 适用场景

适合字段少、操作简单、没有复杂联动的新增/编辑。

典型场景：

- 新增品牌
- 新增单位
- 新增费用类型
- 新增用户字典值
- 修改排序号
- 修改备注
- 审核驳回原因
- 作废原因
- 反审核原因
- 删除确认

### 推荐尺寸

| 类型 | 宽度 | 说明 |
|------|------|------|
| 小弹窗 | 480px | 1-3个字段 |
| 标准弹窗 | 560px | 4-8个字段 |
| 中弹窗 | 640px | 字段稍多但不复杂 |

高度建议：

```text
内容自适应，最大高度不超过 80vh，超出后弹窗内部滚动。
```

### 示例

```text
┌──────────────────────────────┐
│ 新增品牌                       │
├──────────────────────────────┤
│ 品牌名称 *   [____________]    │
│ 品牌编码     [自动生成]         │
│ 状态         [正常 ▼]          │
│ 备注         [____________]    │
├──────────────────────────────┤
│             [取消] [保存]      │
└──────────────────────────────┘
```

### 交互规范

- 支持 Esc 关闭。
- 点击遮罩不建议关闭，避免误关导致数据丢失。
- 保存失败时不关闭弹窗，并定位到错误字段。
- 必填字段使用红色 `*`。
- 保存成功后关闭弹窗并刷新当前列表。
- 危险操作按钮使用红色或强调样式。

### 优点

- 快速轻量。
- 不离开当前列表。
- 适合低风险操作。

### 缺点

- 不适合复杂表单。
- 不适合多明细表。
- 不适合多Tab、多状态流、多金额计算。

## 2.2 右侧抽屉 Drawer

### 适用场景

适合中等复杂度表单，需要保留列表上下文，或适合“查看详情 + 快速编辑”的页面。

典型场景：

- 客户资料编辑
- 供应商资料编辑
- 员工资料编辑
- 仓库资料编辑
- 资金账户编辑
- 往来单位编辑
- 客户价格设置
- 商品价格设置
- 发票详情查看
- 操作日志详情
- 审批详情

### 推荐尺寸

| 类型 | 宽度 | 场景 |
|------|------|------|
| 普通抽屉 | 640px | 一般资料维护 |
| 中型抽屉 | 720px / 800px | 字段较多资料 |
| 大型抽屉 | 960px | 带Tab、附件、子表的详情 |

### 示例

```text
┌──────────────────────────────────────────────┐
│ 页面列表                                      │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ 右侧抽屉：编辑客户资料                    │ │
│ │------------------------------------------│ │
│ │ 基本信息                                  │ │
│ │ 联系信息                                  │ │
│ │ 结算信息                                  │ │
│ │ 开票信息                                  │ │
│ │ 附件 / 操作日志                           │ │
│ │------------------------------------------│ │
│ │            [取消] [保存]                  │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

### 交互规范

- 抽屉标题区显示：标题 + 状态 + 关键操作。
- 底部按钮固定，避免滚动后找不到保存按钮。
- 内容较多时使用分组或Tab。
- 关闭时如果存在未保存修改，应弹出确认。
- 保存成功后抽屉保持或关闭可按场景配置。

### 优点

- 保留列表上下文。
- 比弹窗可容纳更多内容。
- 适合详情查看和中等表单。
- 用户关闭后仍回到原列表位置。

### 缺点

- 不适合复杂业务单据。
- 不适合大量明细行录入。
- 不适合复杂金额计算。

## 2.3 独立页面 / 全屏表单

### 适用场景

适合复杂业务单据、多字段、多明细、多金额计算、多状态流、多联动的场景。

ERP系统中的核心单据不建议使用小弹窗或普通抽屉，应使用独立页面。

典型场景：

- 销售快速开单
- 销售订单
- 采购订单
- 采购快速开单
- 采购入库单
- 采购费用单
- 采购发票勾稽
- 销售发票勾稽
- 调拨单
- 盘点单
- 报损单
- 成本调整单
- 应收结算
- 应付结算
- 收款单
- 付款单
- B2B促销活动
- 入驻商结算单

### 推荐结构

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部：返回 + 单据标题 + 状态 + 操作按钮                       │
├────────────────────────────────────────────────────────────┤
│ 基本信息区：客户/供应商/仓库/日期/业务员/结算方式              │
├────────────────────────────────────────────────────────────┤
│ 明细表格区：商品/数量/单位/价格/金额/税率/库存/赠品/备注       │
├────────────────────────────────────────────────────────────┤
│ 关联信息TAB：附件 / 操作日志 / 关联单据 / 发票 / 核销          │
├────────────────────────────────────────────────────────────┤
│ 底部固定栏：合计金额 / 风险提示 / [保存] [提交] [审核]         │
└────────────────────────────────────────────────────────────┘
```

### 交互规范

- 支持保存草稿。
- 支持返回列表并保留列表查询条件。
- 支持快捷键。
- 明细表支持行内编辑。
- 金额汇总区固定在底部。
- 高风险单据显示风险提示。
- 复杂单据详情页建议包含：基本信息、明细、关联单据、附件、操作日志。

### 优点

- 空间充足。
- 适合复杂明细表。
- 适合快捷键和连续录入。
- 适合金额汇总、风险提示、关联单据。
- 更利于开发和测试验收。

### 缺点

- 页面跳转成本高。
- 需要保存返回状态。

## 2.4 表格行内编辑

### 适用场景

适合少数字段快速维护，特别是列表型数据批量调整。

典型场景：

- 排序号
- 启用/停用状态
- 商品库存上下限
- 起订量
- 起订倍数
- 价格组名称
- 客户价格
- 建议采购量调整
- 库存预警阈值

### 示例

```text
商品名称 | 库存下限 | 库存上限 | 状态
农夫山泉 | [ 100 ] | [ 500 ] | [正常▼]
```

### 交互规范

- 修改后字段高亮。
- 支持批量保存。
- 支持撤销修改。
- 保存前统一校验。
- 有风险字段修改需二次确认。

### 优点

- 高效。
- 适合批量维护。
- 减少弹窗数量。

### 缺点

- 容易误操作。
- 不适合复杂校验。
- 不适合强业务流转。

---

## 2.5 详情页内分区编辑

### 适用场景

适合字段多、信息分区明显，但不是高频业务单据的资料详情。

典型场景：

- 商品资料
- 客户资料
- 供应商资料
- 入驻商资料
- 员工资料
- 仓库资料

### 示例

```text
商品详情
├─ 基本信息        [编辑]
├─ 多单位信息      [编辑]
├─ 价格信息        [编辑]
├─ 供应商关系      [编辑]
├─ 库存上下限      [编辑]
├─ 图片附件        [编辑]
└─ 操作日志
```

### 优点

- 信息结构清晰。
- 避免一次性超长表单。
- 适合复杂资料维护。

## 四、复杂度决策规则

## 4.1 按字段数量判断

| 字段数量 | 推荐方式 |
|----------|----------|
| 1-5个字段 | 小弹窗 |
| 6-15个字段 | 右侧抽屉 |
| 15个以上字段 | 独立页面 / 分区详情页 |
| 有明细表 | 独立页面 |
| 有多Tab | 独立页面或大抽屉 |
| 有金额计算 | 独立页面 |
| 有状态流 | 独立页面 |
| 有附件/日志/关联单据 | 独立详情页 |

## 4.2 按操作频率判断

| 操作频率 | 推荐方式 |
|----------|----------|
| 高频录入 | 独立页面 + 快捷键 |
| 中频维护 | 右侧抽屉 |
| 低频配置 | 小弹窗 |
| 批量维护 | 行内编辑 + 批量保存 |
| 查看详情 | 右侧抽屉 / 独立详情页 |

## 4.3 按业务风险判断

| 风险等级 | 推荐方式 |
|----------|----------|
| 低风险 | 小弹窗 |
| 中风险 | 抽屉 |
| 高风险 | 独立页面 + 二次确认 |
| 影响库存 | 独立页面 |
| 影响应收应付 | 独立页面 |
| 影响成本 | 独立页面 + 风险提示 |
| 影响资金 | 独立页面 + 审批/确认 |
| 影响发票税额 | 独立页面 + 勾稽明细 |

## 六、统一弹窗/抽屉/页面规范

## 6.1 小弹窗规范

### 适用

简单新建、简单编辑、确认操作。

### 规范

- 默认宽度：560px。
- 最大高度：80vh。
- 底部按钮右对齐。
- 保存成功自动关闭。
- 保存失败定位错误字段。
- 点击遮罩不关闭。
- 危险操作按钮使用红色样式。

### 按钮示例

```text
[取消] [保存]
[取消] [确认作废]
[取消] [确认反审核]
```

## 6.2 抽屉规范

### 适用

资料详情、中等复杂表单、列表上下文查看。

### 规范

- 默认宽度：640px。
- 中型宽度：800px。
- 大型宽度：960px。
- 底部保存按钮固定。
- 内容过多时使用Tab或分组。
- 关闭有未保存内容时提示确认。

## 6.3 独立页面规范

### 适用

核心业务单据、高频开单、复杂结算、影响库存/成本/资金/发票的操作。

### 规范结构

```text
顶部：返回 + 单据标题 + 状态 + 操作按钮
基本信息区
明细表格区
金额汇总区
关联信息TAB
底部固定操作栏
```

### 必须支持

- 保存草稿。
- 快捷键。
- 明细表行内编辑。
- 金额实时计算。
- 风险提示。
- 操作日志。
- 关联单据。

---

## 七、最终建议

当前系统不应滥用小弹窗。针对 ERP+WMS+TMS+B2B 的业务复杂度，推荐采用以下统一规则：

```text
1. 简单字典：小弹窗
2. 中等档案：右侧抽屉
3. 复杂档案：独立详情页
4. 核心业务单据：独立页面
5. 审核/驳回/关闭/作废：小确认弹窗
6. 列表详情查看：右侧抽屉
7. 高频开单：独立页面 + 键盘快捷键
8. 金额/库存/成本/发票相关操作：独立页面 + 风险提示
```

一句话总结：

> **简单资料用弹窗，中等资料用抽屉，复杂单据用独立页面，高风险操作用确认弹窗，高频开单必须支持键盘。**
