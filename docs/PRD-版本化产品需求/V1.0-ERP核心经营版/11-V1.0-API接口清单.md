>
> - 真实前缀：`/api/`（无 `/erp` 段）
> - 反审核后缀：`/reverse-audit`（不是 `/unaudit`）
> - 采购/销售**收货单没有 create 端点** —— 由入库/出库审核自动生成
> - 采购/销售**入库/出库单没有 reverse-audit** —— V1.0 暂不支持，V2.0 补
> - `submit` / `terminate` 端点未落地 —— PENDING → APPROVED 一步到位

## 一、接口设计约定

### 1.1 URL约定

```text
/api/{service}/{module}/{resource}/{action}
```

示例：

```text
/api/erp/sales/order/page
/api/erp/sales/order/audit
/api/erp/inventory/stock/balance/page
```

### 1.2 通用响应

```json
{
  "code": "0",
  "message": "success",
  "data": {},
  "traceId": ""
}
```

### 1.3 分页请求

```json
{
  "pageNo": 1,
  "pageSize": 20,
  "filters": {},
  "sorts": []
}
```

### 1.4 通用接口类型

| 类型 | 方法建议 | 说明 |
|---|---|---|
| 分页查询 | POST | `/page` |
| 详情 | GET | `/detail/{id}` |
| 新增 | POST | `/create` |
| 修改 | POST | `/update` |
| 删除 | POST | `/delete` |
| 审核 | POST | `/audit` |
| 反审核 | POST | `/unaudit` |
| 关闭/终止 | POST | `/close`、`/terminate` |
| 导入 | POST | `/import` |
| 导出 | POST | `/export` |
| 打印 | POST | `/print` |

### 1.5 鉴权与审计

所有接口必须携带登录Token。以下接口必须写操作日志：新增、修改、删除、审核、反审核、关闭、终止、导入、导出、打印、核销、反核销。

### 1.6 商品明细单位与仓库字段约定

所有涉及商品数量的业务单据接口，明细行必须统一提交和返回以下字段：

```json
{
  "goodsId": "商品ID",
  "warehouseId": "明细仓库ID，调拨单除外",
  "businessUnitId": "业务开单单位ID",
  "businessUnitName": "业务开单单位名称",
  "businessQty": 10,
  "conversionRate": 24,
  "baseUnitId": "基本单位ID",
  "baseUnitName": "基本单位名称",
  "baseQty": 240,
  "price": 35.00,
  "amount": 350.00,
  "costPrice": 1.30,
  "costAmount": 312.00,
  "batchNo": "B202606"
}
```

接口处理原则：

- 前端选择商品时，通过商品接口带出可选单位、默认销售/采购单位、换算率、默认仓库。
- 后端保存时必须校验 `baseQty = businessQty × conversionRate`。
- 出库类单据审核时按 `warehouseId + goodsId + batchNo + baseQty` 校验可用库存，禁止负库存。
- 库存、成本、批次、流水统一按基本单位数量计算。

### 3.5 资金账户

V1.0 实际以「主档统一端点 `/api/base/master/save|delete|stop|freeze|unfreeze`」+ 专用分页/详情接口方式实现，兼容旧路径。

|接口|方法|说明|
|---|---|---|
|`/api/base/master/fund-account/page`|POST|资金账户分页；返回字段包含 `parentCode / isSystem`|
|`/api/base/master/save`|POST|新建/修改资金账户；`moduleCode=fundAccount`；新建时 `parentCode` 必填|
|`/api/base/master/stop`|POST|停用资金账户；`moduleCode=fundAccount`|
|`/api/base/master/freeze` / `/unfreeze`|POST|冻结 / 解冻|
|`/api/base/master/delete`|POST|删除资金账户|

**系统内置一级账户（`isSystem=true`）**：`01 现金 / 02 银行卡 / 03 微信 / 04 支付宝 / 05 三方账户 / 06 其他`。任何 save-edit / delete / stop / freeze / unfreeze 请求命中 `isSystem=true` 记录，一律返回 400「系统默认记录不允许{动作}」。

### 3.6 主档通用接口（片区/线路/部门/费用类型/人员/货主/往来单位/资金账户/价格组）

V1.0 后端将上述九个主档统一通过 `/api/base/master/*` 路由维护，前端 `moduleApis` 里各模块的 `save/update/stop/delete` 均指向对应统一端点：

|接口|方法|说明|
|---|---|---|
|`/api/base/master/{module}/page`|POST|分页；`{module}` ∈ territory / route-line / department / expense-type / employee / owner / counterparty / fund-account / price-group|
|`/api/base/master/save`|POST|新建/编辑；请求体必含 `moduleCode`（驼峰）+ `mode`（`add`/`edit`）+ 该模块的字段|
|`/api/base/master/stop`|POST|停用（`status=STOPPED`）|
|`/api/base/master/freeze` / `/unfreeze`|POST|冻结 / 解冻|
|`/api/base/master/delete`|POST|删除；按 `bizId`（编码或主键 ID）定位|

**关键规则**：

- `save` 端在 `mode=add` 且 `code` 已存在时返回 400「编码 XX 已存在」，防止「新增」意外覆盖同码记录。
- `moduleCode=fundAccount` 时校验 `parentCode` 必填，且父级必须存在于同表。
- 人员编码留空自动按 `E00001` 递增流水生成；货主编码同理生成 `H0000x`。
- `PageResult.of` 内部会跳过 `roleCode / treeNode="全部..."` 这类非数据过滤字段，避免误伤。

## 九、关键业务接口入参摘要

### 9.1 销售订单审核 `/api/erp/sales/order/audit`

入参：

```json
{
  "orderId": "",
  "forceCredit": false,
  "creditReason": "",
  "minPriceAuthUserId": "",
  "remark": ""
}
```

处理：客户状态校验、价格校验、信用校验、库存校验、库存锁定、状态变更、日志。

### 9.2 销售出库审核 `/api/erp/sales/outbound/audit`

入参：

```json
{
  "outboundId": "",
  "remark": ""
}
```

处理：扣减库存、扣减锁定、生成流水、记录成本、回写订单、生成销售收货单。

### 9.3 采购入库审核 `/api/erp/purchase/inbound/audit`

处理：增加库存、生成流水、成本计算、扣减采购在途、回写订单、生成采购收货单。

### 9.4 收款核销 `/api/erp/finance/receipt-writeoff/confirm`

入参：

```json
{
  "customerId": "",
  "writeoffDate": "2026-06-13",
  "items": [
    {
      "receiptId": "",
      "receivableId": "",
      "amount": 100.00
    }
  ]
}
```
