## 一、闭环流程图

### 1.1 采购闭环

```text
┌──────────────┐  audit          ┌──────────────┐  「生成入库单」
│  采购订单     │ ─────────────→ │  APPROVED    │ ─────────────────┐
│  purchase_   │   inbound_      │  inbound_    │                  ▼
│  order       │   status=       │  status=     │        ┌──────────────────┐
│  PENDING     │   NULL          │  待入库       │        │  拆行入库抽屉      │
└──────────────┘                 └──────────────┘        │  (Drawer + 拆分) │
                                                         └────────┬─────────┘
                                                                  │ create
┌──────────────┐      audit                       ┌───────────────▼────────┐
│  fin_ap      │ ◄─────────────┐            ┌────►│  pur_inbound (PENDING) │
│  (UNVERIFIED)│               │            │     │  + pur_inbound_detail  │
│  含税金额     │               │            │     │  + 批次号/生产日期     │
└──────────────┘               │            │     └────────┬───────────────┘
                              audit          │              │ audit
                          ┌───────┐          │              ▼
                          │ 收货单 │◄─────────┘   ┌──────────────────────────┐
                          │(PENDING│  auto-gen    │ 1. InventoryCostService  │
                          │ pur_   │              │    → inv_batch_stock     │
                          │receipt)│              │    → inv_stock_balance   │
                          └────────┘              │    → 移动平均法 cost      │
                          审核=财务确认            │ 2. base_goods            │
                                                 │    .latest_purchase_     │
                                                 │    price 同步            │
                                                 │ 3. purchase_order.       │
                                                 │    inbound_amount 累加   │
                                                 │    inbound_status:       │
                                                 │      未入库/部分入库/     │
                                                 │      已入库              │
                                                 └──────────────────────────┘
```

### 1.2 销售闭环（结构对称）

```text
销售订单(PENDING) → audit → APPROVED(outbound_status=待出库) → 生成出库单
                                                                    ↓
                        sales_receipt(PENDING) ← 自动生成 ← sales_outbound(PENDING → APPROVED)
                            ↓ audit                            ↑ audit
                        fin_ar(UNVERIFIED)                     ├─ InventoryCostService.salesOutbound
                                                              │   → 扣 inv_batch_stock（指定批次）
                                                              │   → 更新 inv_stock_balance
                                                              └─ sales_order.outbound_amount 回写
```

反审规则：
- 收货单反审 → 需 `fin_ap.paid_amount = 0` / `fin_ar.received_amount = 0` 才允许，反审时删对应 fin_ap/fin_ar 记录
- 入库/出库单反审 → **本轮未实现**，V2.0 加

## 三、数据库表结构（Flyway V14~V17）

### 3.1 采购订单补字段（V14）

```sql
ALTER TABLE purchase_order ADD COLUMN audit_time TIMESTAMP;
ALTER TABLE purchase_order ADD COLUMN audit_user VARCHAR(100);
ALTER TABLE purchase_order ADD COLUMN inbound_amount DECIMAL(18, 2) DEFAULT 0;
```

- `inbound_amount` = `SUM(pur_inbound.amount WHERE source_order = ? AND status = 'APPROVED')`
- `inbound_status` = 未入库 / 部分入库 / 已入库（accumulated vs order.amount）

### 3.2 采购收货单（V16）

```sql
CREATE TABLE pur_receipt (
  receipt_id VARCHAR(32) PRIMARY KEY,
  receipt_no VARCHAR(50) NOT NULL UNIQUE,
  source_inbound_no VARCHAR(50) NOT NULL,   -- UNIQUE 保证 1:1
  source_order_no VARCHAR(50),
  supplier_code VARCHAR(50), supplier_name VARCHAR(200),
  warehouse VARCHAR(100),
  receipt_date DATE NOT NULL,
  goods_amount DECIMAL(18, 2),  -- Σ 明细金额（不含税）
  tax_amount DECIMAL(18, 2),    -- Σ 逐行税额
  expense_amount DECIMAL(18, 2), -- V1.0 占位 0
  final_amount DECIMAL(18, 2),  -- goods + tax + expense
  ap_status VARCHAR(20),        -- 未生成 / 已生成
  pay_status VARCHAR(20),       -- 占位（V1.0 未使用）
  status VARCHAR(20),           -- PENDING / APPROVED / CANCELLED
  ...
);
CREATE UNIQUE INDEX uk_pur_receipt_source_inbound ON pur_receipt(source_inbound_no);

CREATE TABLE pur_receipt_detail (
  detail_id, receipt_id, goods_code, goods_name, unit_name,
  qty, price, amount, tax_rate, tax_amount, remark
);
```

### 3.3 销售订单补字段 + 销售收货单（V17）

```sql
-- sales_order 补审核字段（对齐 V14）
ALTER TABLE sales_order ADD COLUMN audit_time TIMESTAMP;
ALTER TABLE sales_order ADD COLUMN audit_user VARCHAR(100);
ALTER TABLE sales_order ADD COLUMN outbound_amount DECIMAL(18, 2) DEFAULT 0;

-- 结构对称 pur_receipt
CREATE TABLE sales_receipt (
  receipt_id, receipt_no,
  source_outbound_no VARCHAR(50) NOT NULL,  -- UNIQUE
  source_order_no,
  customer_code, customer_name, warehouse, receipt_date,
  goods_amount, tax_amount, expense_amount, final_amount,
  ar_status,        -- 未生成 / 已生成
  receive_status,   -- 未收款 / 部分收款 / 已收款（占位）
  status, ...
);
CREATE UNIQUE INDEX uk_sales_receipt_source_outbound ON sales_receipt(source_outbound_no);

CREATE TABLE sales_receipt_detail (
  detail_id, receipt_id, goods_code, goods_name, unit_name,
  qty, price, amount, tax_rate, tax_amount, remark
);
```

### 3.4 批次库存（V15，上轮）

```sql
CREATE TABLE inv_batch_stock (
  batch_stock_id, goods_code, warehouse, batch_no,
  production_date, expiry_date, qty, cost_price, stock_amount
);
CREATE UNIQUE INDEX uk_batch_stock_gwb ON inv_batch_stock(goods_code, warehouse, batch_no);
```

采购入库审核按 `(goods_code, warehouse, batch_no)` upsert；销售出库审核在指定 `batchNo` 时从对应行扣减 qty，未指定则只扣 `inv_stock_balance` 不扣批次层。

## 四、税额计算（决策 A：逐行）

**输入**：`purchase_order_detail.tax_rate` / `sales_order_detail.tax_rate`，格式 `"13%"` / `"13"` / `"0.13"` 三种任一

**代码**：`PurchaseReceiptController.parseTaxRate()` / `SalesReceiptController.parseTaxRate()`

```
if 末尾是 %: 去掉 %，然后 v / 100
elif v > 1:   v / 100（把 13 当 13%）
else:         v 原样（0.13 就是 13%）
默认值:       0.13
```

**行税额**：`line.tax_amount = line.amount × parseTaxRate(tax_rate)`（HALF_UP 到 2 位小数）

**头部税额**：`header.tax_amount = Σ line.tax_amount`

**多档税率场景**：假设一张收货单里商品 A tax_rate=13%、商品 B tax_rate=9%，头部税额自动是各行相加，非按整单一档算。

## 五、H2 大小写字段兼容注意

`OrderController` / `FinanceController` 的 SELECT 用了 `AS orderNo` 这种混合大小写别名。H2 会将其转为全大写返回（`ORDERNO`），而其他 controller（`PurchaseReceiptController` / `SalesReceiptController` / `SalesOutboundController`）用了手写 `camelize()` 会转小写下划线为驼峰（`sourceOrderNo` OK）。

**前端和测试脚本消费方**必须容忍：

```js
const orderNo = row.orderNo || row.ORDERNO || row.orderno
```

未来统一：改造 `camelize()` 或全部 SELECT 用 `snake_case AS snake_case`。

## 六、冒烟测试断言（[v1-core-smoke-test.js](../../../development/06-testing/scripts/v1-core-smoke-test.js)）

### `testPurchaseCloseLoop()` — 采购闭环

1. 建仓库 / 供应商 / 商品（后缀 `Date.now()` 保证幂等）
2. POST 订单 100 件@35 → amount = 3500
3. 订单审核 → status = APPROVED
4. `from-order` 预填：remainQty === 100，price === 35（只读）
5. 拆行 60(BATCH-A) + 40(BATCH-B) 创建入库单
6. 超量测试：qty=999 必须被 `超过订单剩余` 拒绝
7. 入库审核：
   - `receiptNo` 以 `PR` 开头
   - `base_goods.latest_purchase_price === 35`
   - `purchase_order.inbound_status === '已入库'`
   - 收货单 `goodsAmount=3500 / taxAmount=455 / finalAmount=3955`
   - 收货明细：两批次聚合为 1 行、qty=100
8. 收货审核：`apNo` 以 `AP` 开头，`fin_ap.ap_amount === 3955`
9. 反审收货 → `fin_ap` 记录消失

### `testSalesCloseLoop()` — 销售闭环

先跑一遍采购入库让库存有货（60+40 两批次）；然后：

1. 建客户，创建销售订单 100@35 → amount=3500
2. 订单审核 → outbound_status='待出库'
3. `from-order` + `available-batches`（至少 2 个批次可选）
4. 拆行出库 60(A) + 40(B)
5. 出库审核：
   - `receiptNo` 以 `SR` 开头
   - `sales_order.outbound_status === '已出库'`
   - 收货单 3500/455/3955
6. 收货审核 → `arNo` 以 `AR` 开头，`fin_ar.ar_amount === 3955`
7. 反审 → `fin_ar` 消失

**运行**：先 login 取 JWT → 依次跑两条闭环 → 输出 `V1 core smoke test passed`。
