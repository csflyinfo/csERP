## 〇、通用明细单位与仓库规则

所有涉及商品数量的采购、销售、库存类业务单据明细，必须同时记录“业务开单单位”和“库存基本单位”字段，详见 `20-V1.0-业务单位与基本单位换算规则PRD.md`。

### 0.1 明细必备字段

```text
商品
仓库（调拨单除外）
业务单位
开单数量
换算率
基本单位
基本单位数量
业务单价
金额
成本单价
成本金额
批次
备注
```

### 0.2 默认单位规则

| 单据 | 默认业务单位 |
|---|---|
| 采购订单 | 商品默认采购单位 > 大单位 > 基本单位 |
| 销售订单/快速开单 | 商品默认销售单位 > 基本单位 > 大单位 |
| 其他入库/其他出库/报损/库存调整 | 基本单位 |
| 调拨单 | 基本单位，可选择业务单位，但仓库取单据头调出/调入仓 |

### 0.3 库存计算口径

```text
库存、成本、批次、流水统一按基本单位数量计算。
基本单位数量 = 开单数量 × 换算率。
```

**入口**：列表页「新建采购订单」/ 行「编辑」按钮。

**头部信息**（4 个字段）：

|字段|控件|规则|
|---|---|---|

**其它规则**：

- 同模块已有草稿抽屉时，「新建采购订单」按钮阻止再次新建，toast 提示
- 保存后调 `/purchase/order/create` 落地（V1.0 stub，后续实现真持久化）

### 1.6 商品添加窗口（GoodsAddDialog）

**目的**：单据明细录入的标准化组件。780px 宽度紧凑窗口。

**布局**：商品搜索独占一行 + 备注独占一行 + 中间 12 个字段两列 grid：

|字段|说明|
|---|---|
|条码|选择商品自动带出小单位条码，只读|
|规格|来自商品档案 spec，只读|
|小单位|选择商品自动带出，只读|
|采购单位|下拉（源自 `unit_config` 中 enabled=true 的单位）；默认大 → 中 → 小；↑↓ 循环切换|
|采购数量|非称重品仅整数、不允许负数；称重品允许小数|

|单价|最多 4 位小数、不允许负数|
|金额|`qty × price` 保留 2 位；手改金额则反算单价（4 位）|

|系统最近采购价|同上，只读|
|当前库存|`GET /base/goods/stock-summary?goodsCode=X`，只读|
|可用库存|同上，只读（V1.0 无锁定表，等于当前库存）|

**搜索交互**：

- 输入商品名称/编号/条码关键字；按 **Enter 触发查询**（不即时展开下拉）
- 下拉展开后 ↑↓ 高亮、Enter 选中、Esc 关闭
- 选中商品后光标自动切到「采购数量」

**Enter 移到下一字段**：`unit → qty → price → amount → remark`；在备注按 Enter 直接确定。

**按钮**：

- 取消 (Esc)
- 添加并继续 (Ctrl+S) — 保留窗口，清空表单，光标回到搜索框
- 确定 — 添加到明细并关闭窗口

## 二、采购入库页面

### 2.1 页面入口

`采购管理 → 采购入库`

### 2.2 流程

```text
新增采购入库 → 选择采购订单 → 引入未入库明细 → 填实收数量/批次 → 审核 → 增加库存/成本/流水/生成采购收货单
```

### 2.3 查询条件

入库日期、入库单号、采购单号、供应商、仓库、状态、商品。

### 2.4 列表字段

入库单号、入库日期、采购单号、供应商、仓库、入库数量、入库金额、状态、是否更新库存、是否生成收货单、操作。

### 2.5 编辑字段

| 字段 | 必填 | 说明 |
|---|:---:|---|
| 来源采购订单 | 是 | 已审核且未完全入库 |
| 供应商 | 自动 | 来源订单 |
| 仓库 | 自动/可选 | 默认订单仓库 |
| 入库日期 | 是 | 默认当天 |
| 商品 | 是 | 引入订单明细 |
| 应入数量 | 自动 | 订单剩余数量 |
| 实收数量 | 是 | 不超过应入数量 |
| 批次号 | 批次商品必填 | 可自动生成 |
| 生产日期 | 批次商品必填 | 用于效期 |
| 到期日期 | 自动 | 生产日期+保质期 |
| 入库库位 | 否 | V1.0可选 |

### 2.6 审核处理

审核时依次执行：

1. 校验入库状态、数量、批次。
2. 增加库存余额。
3. 扣减采购在途。
4. 生成库存流水。
5. 计算移动加权成本。
6. 回写采购订单已入库数量和状态。
7. 生成采购收货单。
8. 写操作日志。

### 2.7 验收用例

| 编号 | 场景 | 预期 |
|---|---|---|
| PUR-IN-001 | 采购订单100，入库60 | 库存+60，订单部分入库，在途剩余40 |
| PUR-IN-002 | 批次商品未填生产日期 | 审核阻断 |
| PUR-IN-003 | 入库审核后查看流水 | 有入库流水和成本单价 |

### 2.8 V1.0 落地实现说明

> 与 [PurchaseController.java](../../../backend/src/main/java/com/erp/purchase/PurchaseController.java) 保持同步。

**入口**：

- 入口 A —— 采购入库列表点「新建采购入库」，抽屉打开后在头部下拉选择已审核未完成入库的采购订单
- 入口 B —— 采购订单列表已审核行点「生成入库单」，抽屉预填订单头部与明细

**拆行 UI**（[PurchaseInboundDrawer.vue](../../../frontend/src/components/PurchaseInboundDrawer.vue)）：

- 默认每商品一行，实收数量 = 订单剩余数量
- 每行支持「拆 2」「拆 3」按钮 → 按数量平分成多批次行；批次号带尾号 `-1/-2/-N`
- 单价随订单单价预填**只读**（改价需回订单改）
- 生产日期变更 → 批次号自动同步为 `B + yyyyMMdd`（除非用户手动改过批次号）
- 前端 + 后端双重校验：Σ本次实收 ≤ 商品订单剩余数量

**审核回写**：

- `base_goods.latest_purchase_price` 同步为本次入库单价
- `purchase_order.inbound_amount` 由所有 APPROVED 状态的入库单金额一次性汇总；`inbound_status` 按累计 vs 订单金额判定为「未入库/部分入库/已入库」
- 审核成功后自动调用 `PurchaseReceiptController.generateFromInbound(inboundId)` 生成 `pur_receipt`（PENDING），入库单与收货单 1:1 幂等

## 三、采购收货单页面

### 3.1 页面入口

`采购管理 → 采购收货单`

### 3.2 页面定位

采购收货单是采购结算依据，审核后生成正式应付。

### 3.3 查询条件

收货日期、收货单号、采购单号、入库单号、供应商、状态、应付生成状态。

### 3.4 列表字段

收货单号、来源入库单、采购单号、供应商、仓库、商品金额、税额、最终金额、状态、应付生成状态、操作。

### 3.5 操作

| 操作 | 说明 |
|---|---|
| 查看 | 查看来源入库和明细 |
| 审核 | 生成应付 |
| 反审核 | 未付款核销时允许 |
| 打印 | 打印收货结算单 |
| 查看应付 | 跳转应付单 |

### 3.6 业务规则

- 采购收货单由采购入库单自动生成。
- 审核后生成应付账款。
- 已生成应付且已核销时不可反审核。

### 3.7 V1.0 落地实现说明

> 与 [PurchaseReceiptController.java](../../../backend/src/main/java/com/erp/purchase/PurchaseReceiptController.java) 保持同步。

**自动生成**：

- 入库单审核末尾调用 `generateFromInbound(inboundId)`，把入库明细按 `goods_code` 聚合成 1 行（合并所有批次，不含批次号/生产日期）
- `pur_receipt.source_inbound_no` 唯一约束保证 1:1；重复调用返回既有 `receiptNo`（幂等）

**税额计算**（决策 A）：

- 逐行按对应订单明细的 `tax_rate` 计算行税额；头部 `tax_amount = Σ 明细税额`
- 支持 `"13%"` / `"13"` / `"0.13"` 三种输入格式
- 最终应付金额 = `goods_amount + tax_amount + expense_amount`

**审核 → fin_ap**：

- 写一条 `fin_ap` 记录（`source_bill = receipt_no`，`status = UNVERIFIED`，`due_date = 当天 + 30 天`）
- 回写 `pur_receipt.ap_status = '已生成'`、`status = 'APPROVED'`

**反审核**：

- 仅当关联 `fin_ap.paid_amount = 0`（未产生付款/核销）才允许
- 反审核时删除对应 `fin_ap` 记录，恢复 `ap_status = '未生成'`、`status = 'PENDING'`

## 四、销售快速开单页面

### 4.1 页面入口

`销售管理 → 销售快速开单`

### 4.2 页面定位

销售快速开单是V1.0最高频页面，面向电话销售、内勤、门店开单。要求键盘友好、扫码友好、信息反馈快。

### 4.3 页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 客户搜索[F2]  仓库  业务员  结算方式  客户欠款/信用额度         │

├──────────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────────┤
```

### 4.4 客户选择后带出

| 信息 | 用途 |
|---|---|
| 客户等级 | 匹配价格 |
| 业务员 | 业绩归属 |
| 默认仓库 | 出库仓库 |
| 默认地址 | 配送地址 |
| 结算方式 | 应收账期 |
| 信用额度/可用额度 | 超信用提醒 |
| 应收余额/逾期金额 | 风险提示 |
| 常购商品 | 快速选品 |

### 4.5 商品添加规则

- 扫条码直接添加。
- 支持商品编码、名称、简拼搜索。
- 同商品同单位同价格同销售类型自动合并数量。
- 赠品行不与正常行合并。
- 库存不足红色提示并阻断审核。

### 4.6 价格匹配

```text
客户专属价 → 客户等级价/价格组 → 标准售价 → 手工价
```

低于最低售价时，显示红色提示并按参数要求授权。

### 4.7 收款

支持组合收款：现金、微信、支付宝、银行卡、预收款、赊账。

如已收金额 < 应收金额，差额进入应收账款。

### 4.8 快捷键

| 快捷键 | 动作 |

| F4 | 常购商品 |

## 六、销售出库页面

### 6.1 页面入口

`销售管理 → 销售出库`

### 6.2 流程

```text
选择已审核销售订单 → 引入待出库商品 → 填实际出库数量 → 审核 → 扣库存/流水/生成销售收货单
```

### 6.3 审核动作

- 扣减实物库存。
- 扣减锁定库存。
- 生成出库库存流水。
- 写入出库成本。
- 回写销售订单状态。
- 生成待审核销售收货单。

### 6.4 规则

- 出库数量不可超过未出库数量。
- 出库不生成正式应收。
- 出库后不可直接修改数量，需反审核或退货处理。

### 6.5 V1.0 落地实现说明

> 与 [SalesOutboundController.java](../../../backend/src/main/java/com/erp/sales/SalesOutboundController.java) 保持同步。

**入口**：

- 入口 A —— 销售出库列表点「新建销售出库」，抽屉打开后下拉选择已审核未完成出库的销售订单
- 入口 B —— 销售订单列表已审核行点「生成出库单」，抽屉预填订单头部与明细

**拆行 UI**（[SalesOutboundDrawer.vue](../../../frontend/src/components/SalesOutboundDrawer.vue)）：

- 默认每商品一行，出库数量 = 订单剩余数量
- 每行支持「拆 2」「拆 3」按钮 → 按数量平分成多行；**每行独立选批次**（下拉自 `inv_batch_stock` 中 qty>0 的批次）
- 单价随订单单价预填**只读**
- 前端 + 后端双重校验：Σ本次出库 ≤ 商品订单剩余数量

**审核回写**：

- 走 `InventoryCostService.salesOutbound()` 扣减 `inv_batch_stock` + `inv_stock_balance`
- `sales_order.outbound_amount` 由所有 APPROVED 状态的出库单金额一次性汇总；`outbound_status` 按累计 vs 订单金额判定为「未出库/部分出库/已出库」
- 审核成功后自动调用 `SalesReceiptController.generateFromOutbound(outboundId)` 生成 `sales_receipt`（PENDING）

## 七、销售收货单页面

### 7.1 页面入口

`销售管理 → 销售收货单`

### 7.2 页面定位

销售收货单确认客户实际签收，是正式应收生成依据。

### 7.3 功能

| 功能 | 说明 |
|---|---|
| 确认签收数量 | 可少于出库数量 |
| 修改签收日期 | 影响账期 |
| 修改签收单价 | 需填写原因 |
| 审核 | 生成应收 |
| 查看应收 | 跳转应收单 |

### 7.4 业务规则

- 签收数量不可大于出库数量。
- 审核后生成应收。
- 已核销应收的收货单不可直接反审核。
- 部分签收差异需进入拒收/退货处理。

### 7.5 V1.0 落地实现说明

> 与 [SalesReceiptController.java](../../../backend/src/main/java/com/erp/sales/SalesReceiptController.java) 保持同步。

**自动生成**：

- 出库单审核末尾调用 `generateFromOutbound(outboundId)`，把出库明细按 `goods_code` 聚合成 1 行（合并所有批次，不含批次号）
- `sales_receipt.source_outbound_no` 唯一约束保证 1:1；重复调用返回既有 `receiptNo`（幂等）

**税额计算**（决策 A）：

- 逐行按对应订单明细的 `tax_rate` 计算行税额；头部 `tax_amount = Σ 明细税额`
- 最终应收金额 = `goods_amount + tax_amount + expense_amount`

**审核 → fin_ar**：

- 写一条 `fin_ar` 记录（`source_bill = receipt_no`，`status = UNVERIFIED`，`due_date = 当天 + 30 天`）
- 回写 `sales_receipt.ar_status = '已生成'`、`status = 'APPROVED'`

**反审核**：

- 仅当关联 `fin_ar.received_amount = 0`（未产生收款/核销）才允许
- 反审核时删除对应 `fin_ar` 记录，恢复 `ar_status = '未生成'`、`status = 'PENDING'`
