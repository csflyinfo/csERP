# 35 - V1.0 飞单直发全链路与报表窗口固定 PRD

> 状态：已实现（2026-09，分支 `feat/sales-fly-direct-chain`，迁移 V133）
> 落地记录：`docs/优化记录-飞单直发全链路与报表窗口固定.md`
> 关联：`09-V1.0-采购销售库存财务页面级PRD.md`（飞单/快速开单基线）、`19-V1.0-单据明细仓库规则补充PRD.md`（仓库口径）、报表中心一/二/三期

## 一、需求背景

飞单（快速开单）用于「供应商直送客户」的过账场景。原有实现审核时只生成**采购订单 + 销售订单 + fin_ap + fin_ar**，
订单仓库为 NULL、入库/出库状态写「无需入库/无需出库」，不生成出入库单据、不写库存，
导致飞单数据在采购明细（入库/退货）、商品销售明细（签收/退货）等**单据流水类报表中完全缺失**，
采销执行链路也不完整。

同时，报表中心各报表在数据量大时需要拖动整个窗口/页面，操作不便。

## 二、功能需求

### 2.1 飞单增加【仓库】

1. 飞单**列表、新建/编辑抽屉、详情（查看）**均展示「仓库」。
2. 新建/编辑时仓库**必填**，且**只可选择状态为 NORMAL 的虚拟仓**
   （`base_warehouse.warehouse_type='虚拟仓'` AND `status='NORMAL'`）；实物仓、停用仓不可选。
3. 校验在前后端同时生效：后端校验不通过抛 `IllegalArgumentException`（400 中文提示），
   如「仓库仅可选择虚拟仓」「仓库 XX 已停用，无法选择」。

### 2.2 审核生成采销全链路（一次操作，全部自动审核）

审核飞单后，按**正常采销流程**在同一事务内生成并审核以下单据：

| 链路 | 生成顺序 |
| --- | --- |
| 采购 | 采购订单 CGDD → 采购入库单 CGRK（审核）→ 采购收货单 CGSH（审核）→ 应付 fin_ap |
| 销售 | 销售订单 XSDD → 销售出库单 XSCK（审核）→ 销售发货单 XSFH（全部签收并审核）→ 应收 fin_ar |

- 发货单按**全部签收、零拒收**自动签收（供应商直送客户，不存在拒收中转）。
- 六张采销单据头表均写 `biz_type='FLY_DIRECT'`，标识「飞单直发」。
- 同商品采购入库与销售出库使用**同一批次**（飞单行指定批次，未指定时按审核日 `yyyyMMdd` 生成）。
- 库存效果：虚拟仓内采购入库 +qty、销售出库 −qty，批次库存与商品仓库余额**最终结存为 0**；
  飞单不经过实物仓，不影响实物库存。
- 价格口径：采购价取商品档案参考进价；销售价按销售订单取价逻辑；
  AP/AR 金额均为**含税金额**（价内税口径）。
- 审核完成后主动刷新当日 DWS 分区（采购/销售），飞单数据立即可在报表查询，无需等待定时刷新。

### 2.3 反审核

已审核飞单可反审核（沿用封单守卫：已封单日不可反审核），反审核时：

1. **付款守卫**：对应 AP 已有付款金额（paid_amount > 0）或 AR 已有收款金额（received_amount > 0）时拦截。
2. **批次安全校验**：该批次在虚拟仓批次库存数量为 0，且库存台账中该批次不存在来自其他单据的流水，
   否则提示「批次已被其他单据引用，无法反审核」；存在销售退货申请时同样拦截。
3. 删除全部六张采销单据（含明细）、应收应付、虚拟仓库存台账/批次/余额记录，
   飞单回到「待审核」（DRAFT），全部单据引用字段清空。
4. 按飞单存储的业务日期刷新 DWS 分区。
5. 反审核后可修改并重新审核。

### 2.4 报表区分正常单与飞单直发

1. 四张明细报表（采购订单明细、采购明细查询（入库/退货）、销售订单明细、商品销售明细表（签收/退货））
   增加「**业务类型**」列，取值「正常 / 飞单直发」。
2. 全部采购/销售明细与汇总报表的筛选条增加「**业务类型**」下拉（全部 / 正常 / 飞单直发）：
   - 明细 4 张：列 + 筛选；
   - 汇总 7 张（商品采购汇总、供应商商品采购汇总、商品销售汇总、业务员商品销售汇总、客户商品销售汇总、业务员销售汇总、客户销售汇总）：仅筛选，不加列。
3. 汇总报表钻取/联查时携带业务类型条件，钻取结果与汇总口径一致。
4. 历史单据 `biz_type` 默认回填 `NORMAL`，口径不变。
5. 财务账龄/资金类报表不另加业务类型列（fin_ap/fin_ar 中自然包含飞单数据）。

### 2.5 报表窗口固定（纯样式）

报表中心下各报表页面：**页头、筛选条、分组维度条、分页栏固定不动，只有表格主体上下滚动**。

- 表头（thead）纵向滚动时吸顶；
- 合计行（grand row）纵向滚动时吸底；
- 横向超宽时在表格区域内横向滚动；
- 页面整体不再出现整页滚动条；
- 例外：报表运维（ReportAdmin）是表单卡片页，保留整页滚动。

## 三、数据模型（V133）

1. `fly_order` 增加：`warehouse_code`、`warehouse_name`，
   以及 `inbound_id/inbound_no`、`receipt_id/receipt_no`、`outbound_id/outbound_no`、`delivery_id/delivery_no` 四组单据引用。
2. `purchase_order`、`pur_inbound`、`pur_receipt`、`sales_order`、`sales_outbound`、`sales_receipt`
   增加 `biz_type VARCHAR(20) DEFAULT 'NORMAL'`（取值 `NORMAL` / `FLY_DIRECT`）。
3. DWS：
   - `rpt_dws_purchase_d`、`rpt_dws_sales_d` 增加 `biz_type NOT NULL`，主键末尾追加 `biz_type`
     （同一商品+仓库下正常单与飞单行分别落库）；
   - `rpt_dws_sales_bill_d` 增加普通列 `biz_type`（一单一类型，主键不变）。
4. DWD 视图 `v_rpt_purchase_detail`、`v_rpt_sales_detail` 重建：
   正常出入库/签收分支从头表取 `biz_type`，退货分支给字面量 `'NORMAL'`，外层透出。

## 四、不在本次范围

- 飞单的采购/销售退货链路：直发后如发生退货，走现有正常退货模块。
- 历史已审核老飞单的链路补生成（保持现状：仅订单 + AP/AR，无仓库）。
- 财务账龄/资金类报表增加业务类型列。
