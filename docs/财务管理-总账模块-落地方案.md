## 〇、v2 相对 v1 的关键变更（决策记录）

| # | 决策点 | v1 | **v2（采纳调研结论）** | 理由 |
|---|---|---|---|---|
| 1 | 业务→凭证衔接 | 业务审核**同事务**生凭证、失败回滚业务、过账禁弃审 | **事件池模式**：业务事务提交后丢事件（吞异常），会计在"待生成凭证"工作台批量生成**草稿**凭证，再审核→过账；弃审丢反向事件 | ① 外账凭证必经会计审核，自动凭证直接过账不符实务；② 结账后业务不能停（期间已关、业务照走，事件带业务日期躺池里）；③ 模板配错/科目停用不应让仓库审核报错；④ 事件池天然是业财对账与追溯的数据源。Spring 原生 `@TransactionalEventListener(AFTER_COMMIT)` 实现，无新依赖 |
| 2 | 模板金额取值 | 固定槽位（含税/不含税/税额/轧差） | **安全表达式引擎**（`amt_tax_incl / (1 + tax_rate)` 类四则表达式 + 变量白名单），辅助核算取值同样表达式化 | 价外费用、净额结算、按税率分组等场景槽位表达不了；Django 用 AST 白名单解析验证可行。Java 自研递归下降解析器（约 200 行，零依赖），不用 SpEL 以收窄攻击面 |
| 3 | 报表取数 | "科目:取数类型"前缀匹配 | **公式语言**：`QM(1001)+QM(1002)`、区间 `1001:1012`、子科目前缀汇总、年初数机械派生；函数 QM/QC/FSD/FSC/LJ | 区间、四则混合、年初列、现金流量项目取数都需要；种子数据驱动，会计可改公式 |
| 4 | 科目准则口径 | 标称《小企业会计准则》，损益类却用 6xxx（企业准则码） | **全套统一为《小企业会计准则》(2013) 编码**：损益 5xxx、权益 3xxx | 名实相符；金蝶 KIS/用友 T3 默认科目体系即此，导出对接零映射；商贸小微企业主流。详见第四章 |
| 5 | 凭证字 | 只用"记"字 | **记/收/付/转 分字**，期间+凭证字内连号 | 收/付款业务用收/付字、折旧/结转/自动转账用转字，是外账惯例且导出文件含凭证字列；手工凭证默认"记" |
| 6 | 固定资产 | 只实现直线法，双倍/工作量预留字段 | **四种折旧方法全实现**（直线/双倍余额递减/年数总和/工作量）+ 拆分/合并/清理/盘点全套规则 | 提纲要求"按标准财务系统设计"；Django 实现已验证且测试覆盖具体数值 |
| 7 | 业财对账 | 仅 1122 提示性勾稽 | **新增业财对账**：应收/应付/资金账户三条线月度对账，差异逐户列示 | Django 版完全没有这块，是我方超越点；也是事件池模式的配套验收 |
| 8 | 现金流量表 | 分录级指定流量项目（T 型账法） | **维持 v1 不变**（Django 版公式留空纯手填，我方设计更优）；净额行用 `QM(现金)-QC(现金)` 做交叉校验 | — |
| 9 | 余额存储 | 实时聚合不建物化表 | **维持实时聚合**；但账簿/报表以科目主档 LEFT JOIN 聚合结果（零发生科目也出场），结账检查加"期末=期初+本期"恒等校验 | Django 物化方案经测试可行但多一处一致性维护点；我方月凭证量几千条，聚合无压力 |
| 10 | 进项税科目方向 | 未明确 | **2221 下所有明细（含 22210101 进项、222103 待认证）余额方向一律"贷"** | Django 实测坑：进项标"借"则 QM 聚合时加而不减，资产负债表差额=进项税×2 |

## 一、背景与现状结论

### 1.1 业务背景

系统已具备完整的**业务财务（往来账）层**，但缺**总账会计层**。本模块补齐：科目、核算项目、初始化、凭证（手工+自动）、固定资产、期末结账、账簿、三大报表，形成"业务单据 → 会计事件 → 凭证 → 账簿 → 报表"闭环，同时支持凭证导出金蝶/用友作为外账对接逃生舱。

### 1.2 已有能力（阶段六 V32~V44 已上线，禁止重建）

| 能力 | 表 | 状态 |
|---|---|---|
| 应收 / 应付（含税口径、对账状态） | `fin_ar` / `fin_ap` | ✅ |
| 收款单 / 付款单 + 明细 + 审核核销 | `fin_receipt_bill(+detail)` / `fin_payment_bill(+detail)` | ✅ |
| 费用单 + 明细（含税/不含税/税额，审核自动生成收付款或往来；含其他收入类型） | `fin_expense_bill(+detail)` | ✅ |
| 核销流水 / 往来流水 / 资金流水 / 资金账户余额 | `fin_reconcile_record` / `fin_counterparty_ledger` / `fin_fund_ledger` / `base_fund_account` | ✅ |
| 客户/供应商对账单 | `fin_customer_statement(+detail)` / `fin_supplier_statement(+detail)` | ✅ |
| 基础档案：客户/供应商/部门/员工/商品 | `base_customer` / `base_supplier`(V6) / `base_department`(V1) / `base_employee`(V1) / `base_goods*` | ✅ |
| 采购发票登记与勾稽（PRD-30） | `pur_invoice*`（V89） | 🚧 开发中 |

**业务钩子全部就位**（审核即生成 AR/AP，均为 `@Transactional`）：

| 钩子 | 文件位置 | 现有动作 |
|---|---|---|
| 销售签收（自动审核） | `sales/SalesReceiptController.approveAndGenerateAr()` | 按**含税**签收金额生成 `fin_ar` |
| 销售出库审核 | `sales/SalesOutboundController.auditOutbound()` | 扣库存（`InventoryCostService` 移动加权平均成本）→ 自动生成发货单 |
| 采购收货审核 | `purchase/PurchaseReceiptController.auditReceipt()` | 按**含税**商品金额生成 `fin_ap` |
| 销售/采购退货审核 | `sales/SalesReturnController` / `purchase/PurchaseReturnController` | 生成**负向** AR / AP |
| 飞单审核 | `sales/FlyOrderController` | 同时生成 AP + AR |
| TMS 拒收 | `tms/TmsCustomerRejectController` | 按拒收金额冲减 AR |
| 收/付款、费用单审核 | `finance/FinanceController` | 核销 + 资金流水 + 往来流水 + 账户余额 |

> **成本时点**：Django 版销售成本要等每日 FIFO 冲抵后才知道（个别计价），事件挂在批处理之后；我方成本是**商品+仓库移动加权平均**，出库审核时 `InventoryCostService` 已有成本，**事件直接挂 `auditOutbound()`**，无需等批处理。

### 1.3 缺口（本模块范围）

**无科目、无凭证、无账簿、无期末结账、无三大报表、无固定资产。** 现有 `financeReport` 菜单是空壳。

### 1.4 技术约定（必须遵守）

- 后端：Spring Boot + **JdbcTemplate 原生 SQL**；`ApiResponse`/`PageResult.of`；业务校验 `throw new IllegalArgumentException("中文提示")`；事务加在业务服务方法上；操作日志写 `sys_operation_log_runtime`；全部接口 POST + JSON。
- 前端：**Vue 3 + Vite + 自研组件（无 UI 组件库）**；列表页走 `views/GenericBusinessList.vue` 配置引擎（`module-config.js` + `module-api.js` + `router/index.js`）；树形主档参考 `fundAccount`/`expenseType` 的 `tree:true`；单据抽屉参考 `components/ReceiptDrawer.vue`。
- 菜单**双份维护**：后端 `system/SystemController.userMenuTree()` 硬编码树（主）+ 前端 `fallback-menus.js`（兜底）。
- Flyway：`CREATE TABLE/INDEX IF NOT EXISTS` 幂等、**不写外键、不写 DROP**；主键 `VARCHAR(32)`（UUID 截段）；单号列 `VARCHAR(50) UNIQUE`；金额 `DECIMAL(18,2)`；状态值统一**中文**；审计四件套 `creator_name/create_time/auditor_name/audit_time`。
- H2 坑：查询列名走 `queryCamel()`；`UPDATE...FROM` 改 `MERGE INTO ... KEY(pk)`；JOIN 列加表别名；日期运算 `DATEADD`；SQL 用普通字符串显式写空格（文本块行尾空格被裁致粘连 500）。
- 开关参数放 `sys_param_runtime`；单号走 `common/util/BillNoGenerator`（凭证号为**期间+凭证字**流水，需新增按 `period(yyyyMM)+word` 取 MAX 的模式并注册表白名单）。
- **不引入任何新 jar / npm 依赖**。

## 二、设计原则

1. **业务不被财务阻塞、凭证必经会计审核**：业务单据审核在**事务提交后**向会计事件池丢事件（hook 吞掉一切异常，财务故障绝不回滚/阻塞业务）；事件按凭证模板渲染为**草稿**凭证，会计在工作台批量生成、逐张审核、过账。生成失败的事件带错误原因可见可重生成。
2. **总账与往来账并行、期末强制对账**：`fin_ar/fin_ap/资金账户` 是业务口径，凭证是会计口径，互不替代；期末提供业财对账（1122 客户辅助 vs `fin_ar`、2202 供应商辅助 vs `fin_ap`、1002/1001 vs `base_fund_account`），差异逐户列示。
3. **不建物化余额表**：账簿/报表从"已过账凭证 + 期初"实时聚合；科目主档 LEFT JOIN 聚合结果，**零发生科目也出场**；结账检查"期末=期初+本期"恒等式。
4. **规则全部数据驱动**：科目、凭证模板（金额表达式）、报表项目（取数公式）、自动转账、现金流量项目、资产类别全部预置种子，会计可微调不动代码；表达式用自研白名单解析器，禁用任何动态执行。
5. **预置优先、口径统一**：按《小企业会计准则》(2013) 预置科目与报表；纳税人身份（小规模/一般纳税人）做系统参数，模板分录按参数条件启停。
6. **可进可出**：内置完整总账，凭证可导出金蝶 KIS、用友 U8/T+ CSV 文件（后端直接出文件流，闭环到"下载文件"）。
7. **零重建**：复用现有收付款单、费用单、基础档案，不新建重复表；不做多账套/受托代销（单体公司用不上）。

## 三、总体架构

```
业务单据审核（采购收货 / 销售出库 / 销售签收 / 收付款 / 费用 / 退货 / 飞单 / 盘点）
        │  业务事务提交后（@TransactionalEventListener AFTER_COMMIT）
        │  hook 内 try-catch 吞异常；总账未启用/未初始化 → 静默跳过
        ▼
┌────────────────────────── 总账层（本模块新增）──────────────────────────┐
│  fin_gl_event 会计事件池（业务单据快照 payload_json，待生成/已生成/失败/忽略）│
│  fin_account 会计科目（4-2-2-2 树 + 7 维辅助核算 + 现金类标记）             │
│  fin_accounting_period 会计期间（未开始/进行中/已结账/已冻结）             │
│  fin_init_balance 科目+辅助核算期初（期初/本年累计，试算平衡门控）         │
│  fin_voucher + fin_voucher_entry 凭证（草稿→已审核→已过账；作废/红冲）     │
│  fin_voucher_template(+entry) 凭证模板（事件码→分录行，金额表达式驱动）    │
│  fin_cash_flow_item 现金流量项目（分录指定，现金流量表取数）               │
│  fin_auto_transfer(+entry) 自动转账（月末计提/摊销/结转未交增值税）        │
│  fin_fixed_asset_category / fin_fixed_asset / _dep / _change / _check(+detail) │
│  fin_report_item 报表项目取数公式（BS/IS/CF 种子，QM/QC/FSD/FSC/LJ）      │
│  fin_voucher_export_log 凭证导出日志（金蝶/用友）                         │
└─────────────────────────────────────────────────────────────────────────┘
        │ 会计工作台：待生成凭证（事件→草稿）→ 审核 → 过账
        │ 实时聚合（不建物化余额表）
        ▼
账簿：总账 / 明细账 / 序时账 / 科目余额表 / 多栏账 / 辅助核算账 / 业财对账
报表：资产负债表 / 利润表 / 现金流量表
```

**凭证状态机**：

```
录入/事件生成 → 草稿 ──审核──→ 已审核 ──过账──→ 已过账 ──（归档）
              │  ↑            │  ↑              │
              │  └─反审核──────┘  └─反过账───────┘
              └──作废→ 已作废（留号不可复用）
已过账凭证发现错误：红字冲销 → 生成负金额草稿凭证（双向关联 red_source_id），需审核过账
已结账期间：冻结一切凭证增改，需反结账（仅最后一个已结期间、强制填原因）→ 反过账 → 反审核
年度结账（12 期）：状态"已冻结"，不可反结账
```

**事件状态机**：

```
业务审核 → 待生成 ──生成成功──→ 已生成（关联凭证草稿）
              ├──生成失败──→ 生成失败（err_msg 中文原因，改配置后可重新生成）
              └──会计忽略──→ 已忽略（可重置回待生成）
业务反审核 → 写反向事件（金额取负、reverse_of 关联原事件）：
              原凭证未过账（草稿/已审核）→ 自动反审核+删除凭证，两事件置"已冲回"
              原凭证已过账              → 反向事件生成红字草稿凭证，会计审核过账
```

## 四、科目管理

**入口**：`财务管理 → 总账 → 会计科目`。左树右表（复用 GenericBusinessList 的 `tree:true`）。

### 4.1 编码规则与准则口径

- 4 级树形，**4-2-2-2 连续数字编码**（如 `1002` → `100201` 工行基本户 → `10020101`）。不用点分制（点分无法导入金蝶/用友）。
- **科目体系全套采用《小企业会计准则》(2013)**：资产 1xxx、负债 2xxx、所有者权益 **3xxx**、成本 4xxx（商贸不用，不预置）、损益 **5xxx**。金蝶 KIS/用友 T3 建账默认科目即此体系，导出对接零映射。
- 科目编码全局唯一；新增科目编码 = 上级编码 + 本级两位序号；**末级科目才能录凭证**。

### 4.3 业务规则

- 预置科目（`is_system=是`）不可删除、不可改编码，可停用；用户新增科目自动为末级，已有凭证引用的科目不可删除。
- 科目类别决定默认余额方向，建账后不可改类别。
- **余额方向聚合规则（重点）**：报表/余额表按科目自身 `balance_direction` 取净值（借方科目=借-贷，贷方科目=贷-借）。**2221 应交税费下所有明细科目方向一律"贷"**——进项税额、待认证进项税额实务中是借方余额，但方向标"借"会被 QM 聚合加总而非抵减，导致资产负债表差额=进项税×2（Django 实测坑）。1602 累计折旧、1702 累计摊销同理标"贷"，报表公式中显式 `QM(1601)-QM(1602)`。
- 辅助核算维度勾选后，该科目的凭证分录**必填**对应辅助项；维度已有分录引用后不可取消。
- `is_cash=是` 标记 1001/1002/1012 及其下级——现金流量表取数与现金分录必填流量项目的依据。

### 4.4 业务档案与科目映射（凭证自动生成的科目来源）

业务档案上挂"对应会计科目"字段，模板占位符（@FUND/@EXPENSE）运行时解析；总账未初始化前字段可空，初始化向导引导补全。

| 档案表 | 新增字段 | 取值范围 | 用途 | 不设时的默认 |
|---|---|---|---|---|
| `base_fund_account` 资金账户 | `gl_account_code` | 仅 is_cash=是 的末级科目（1001/1002/1012 下级） | 收付款凭证银行科目；业财对账资金线 | 收款默认 1001 库存现金并在事件上标警告 |
| `base_expense_type` 费用类型（含收入类） | `gl_expense_account_code` | 支出类→5601xx/5602xx/5603xx/5403 末级；收入类→5051/5301 | 费用单**按明细行**展开：每行费用类型映射自己的费用科目（办公费→5602xx、运费→5601xx、手续费→5603xx、附加税→5403） | 支出→5602、收入→5051，并在事件上标警告 |

> **费用类型为什么挂科目而不做辅助核算维度**：① 费用类型要跨一级科目分流（5601 销售费用/5602 管理费用/5603 财务费用/5403 税金及附加），辅助核算挂在同一科目下做不到；② 金蝶/用友实务中费用类型档案与费用明细科目一一对应，再挂辅助是双重分类；③ 费用的分析维度是**部门**（5601/5602 已挂部门辅助核算），费用类型分析在业务层费用单明细中已有。
> **同一费用单多费用类型**：费用单明细行各带费用类型，模板 `expand_by=EXPENSE_LINE` 按明细行展开渲染（同科目+同辅助键合并），一张费用单生成多条费用借方分录、一条贷方分录。
| `base_goods_category` 商品分类 | `gl_income_account_code` / `gl_cost_account_code` | 收入类/成本类末级科目，可空 | 兼营服务/运费类商品入 5051 其他业务收入、5402 其他业务成本 | 统一 5001 / 5401 |

**不设映射的档案**：客户统一 1122（挂客户辅助核算）、供应商统一 2202（挂供应商辅助核算）——金蝶/用友惯例，往来单位不按单位设科目；预收 2203/预付 1123 业务量小，发生时手工凭证。部门/员工/片区/项目是辅助核算维度本身，不映射科目。

档案维护表单（资金账户、费用类型、商品分类）加"对应会计科目"下拉，仅列末级+启用科目；凭证生成时映射缺失不阻塞事件（事件照落池），但生成结果带警告提示会计补档案。

#### 4.4.1 业务类型科目映射（其他出/入库类型——不剥离字典）

其他出/入库单的"出库类型/入库类型"现状是 `sys_dictionary` 字典（`other_outbound_type` / `other_inbound_type`，各 6 个值：内部领用/样品/借出/活动消耗/内部加工/其他 等），不同类型的对方科目不同（领用→5602、促销样品→5601、借出→1221、赠品入库→5301、内部加工→4001）。

**决策：类型继续留在字典，科目映射放 GL 侧独立表 `fin_gl_biz_subject_map`，不剥离、不给字典表加财务列。**

| 方案 | 结论 | 理由 |
|---|---|---|
| 剥离字典、新建"业务类型"档案模块 | ❌ 不做 | 类型是纯分类标记（6 个值、无自身属性、字典已有完整维护界面）；剥离要改 inv_other_outbound/inv_other_inbound 字段语义、前端下拉、详情、查询、测试脚本、数据迁移，跨库存模块大重构，零业务收益 |
| 给 sys_dictionary 加 gl_account_code 列 | ❌ 不做 | 通用字典表被财务字段污染，且字典值被多模块共用，科目映射是 GL 关注点，不应反向侵入基础表 |
| **GL 侧映射表 + 模板 @BIZ 占位符** | ✅ 采用 | 与 @FUND/@AP/@AR/@EXPENSE 同一套解析机制；会计在一个页面维护全部"业务类型→科目"；不动业务模块一行代码 |

`fin_gl_biz_subject_map`（V93 建表）：`event_code`（OTHER_OUT/OTHER_IN，通用可扩展）+ `biz_type_code`（字典 code）联合唯一；`biz_type_name`（冗余快照，字典改名/删值不影响历史凭证与事件）；`counter_subject_code`（对方末级科目，**空值=该类型不生成凭证**）；预置 12 行种子：

| 事件 | 类型 | 默认对方科目 | 事件 | 类型 | 默认对方科目 |
|---|---|---|---|---|---|
| OTHER_OUT | 0 内部领用 | 5602 管理费用 | OTHER_IN | 0 期初库存 | 空（钩子不丢事件） |
| OTHER_OUT | 1 样品出库 | 5601 销售费用 | OTHER_IN | 1 样品入库 | 5301 营业外收入 |
| OTHER_OUT | 2 借出出库 | 1221 其他应收款 | OTHER_IN | 2 赠品入库 | 5301 营业外收入 |
| OTHER_OUT | 3 活动消耗 | 5601 销售费用 | OTHER_IN | 3 盘外发现 | 5301 营业外收入 |
| OTHER_OUT | 4 内部加工 | 4001 生产成本 | OTHER_IN | 4 内部加工 | 4001 生产成本 |
| OTHER_OUT | 5 其他 | 5602 管理费用 | OTHER_IN | 5 其他 | 5301 营业外收入 |

> 内部加工走 4001 过渡：出库 借 4001/贷 1405（原料），成品入库 借 1405/贷 4001，加工费月末手工凭证归集，4001 余额=在制加工成本。纯商贸无加工业务可停用 4001 并改映射。
> 报损单无类型字段，DAMAGE 事件固定 1901 待处理财产损溢，不需要映射；收/付款对方科目按 source_ar_no/source_ap_no 有无用 condition_expr 分流 1122/2202 与 1221/2241，也不需要映射表。
> **字典联动**：字典新增类型值未配映射 → 事件生成失败，err_msg 中文指明"出库类型'XX'未配置总账科目，请在 总账→业务类型科目映射 中配置"，补配后工作台重试即可（复用既有失败-重试链路）；`inbound_type='0'` 期初库存是建账前数据，钩子层直接不丢事件（映射空值双保险）。

## 六、初始化（建账）

**入口**：`财务管理 → 总账 → 初始化`。

流程：**设置会计期间 → 录入科目期初 → 录入辅助核算期初 → 试算平衡 → 启用总账**。

1. **会计期间 `fin_accounting_period`**：自然月 1~12 期，状态 `未开始/进行中/已结账/已冻结`；启用年份取参数 `fin.gl.start_year`，启用时生成 12 期；年末提供"生成下年期间"。
2. **科目期初 `fin_init_balance`**：按末级科目录入（上级自动汇总）；挂辅助核算的科目必须**逐辅助项**录入。每行含：
   - `open_debit/open_credit`：启用期间期初余额；
   - `ytd_debit/ytd_credit`：本年累计发生额（1 月～启用前一月），用于利润表本年累计列；
   - 数量核算科目带 `open_qty`。
3. **试算平衡（门控）**：期初借合计=贷合计、本年累计借合计=贷合计，容差 0.005；不平衡页面红字显示差额，**禁止启用、禁止生凭证**。
4. **一键引入业务期初**（降低建账工作量）：期初录入页提供按钮，从业务层自动带出差额类期初，会计核对后可改：
   - 1122 应收账款按客户辅助 ← `fin_ar` 各客户未收余额；
   - 2202 应付账款按供应商辅助 ← `fin_ap` 各供应商未付余额；
   - 1002/1001 按资金账户 `gl_account_code` 归集 ← `base_fund_account.balance`；
   - 1405 库存商品按商品辅助（含数量）← 库存结存数量与移动加权平均成本（`InventoryCostService`）。
   引入后试算必然不平（差额是实收资本/未分配利润等业务层没有的科目），会计补录权益类期初至平衡。
5. **启用**：平衡后"启用总账"，写参数 `fin.gl.initialized=是`，首个期间自动置"进行中"；启用后期初**锁死只读**（反启用要求当期无任何凭证）。

## 七、凭证管理

**入口**：`财务管理 → 总账 → 凭证管理`。

### 7.1 凭证字号

- **凭证字：记 / 收 / 付 / 转**。号段 = 期间(yyyyMM) + 凭证字内 4 位流水（`记-202609-0001`），作废留号不复用、红冲用新号。BillNoGenerator 新增"期间+字"取号模式。
- 凭证字来源：手工凭证默认"记"（可选收/付/转）；事件模板带字（收款类→收、付款类→付、折旧/结转/自动转账→转、其余→记）。
- `source`：手工录入 / 业务事件 / 期初 / 结转损益 / 自动转账 / 折旧计提 / 红字冲销。

### 7.2 凭证头与分录

- 凭证头：字号（自动）、日期（默认今天，必须落在**未结账**期间）、附件数、摘要（取首行分录）。
- 分录网格（至少 2 行）：行号 / 摘要 / 科目（**仅末级、启用状态**）/ 辅助核算（按科目配置动态显隐 7 个下拉，必填项未填行内 warning）/ 借方金额 / 贷方金额；**现金类科目分录显示现金流量项目下拉（必填）**；数量核算科目显示数量/单价。
- 一行只许借或贷一边有值；底部实时借方合计、贷方合计、差额（0 绿色/非 0 红色）+ **中文大写金额**。
- 支持插入行/删除行/复制上行摘要/统一摘要填全行；草稿不校验平衡，**审核强校验**：借贷差 ≤0.005、末级启用科目、必填辅助核算齐全、期间未结账。

### 7.3 操作与留痕

| 操作 | 前置状态 | 后置状态 | 说明 |
|---|---|---|---|
| 保存草稿 | — | 草稿 | 不校验平衡 |
| 修改/删除 | 草稿 | 草稿 | 事件生成的草稿可改科目/金额/辅助项 |
| 审核 | 草稿 | 已审核 | 强校验平衡、辅助核算、期间开放 |
| 反审核 | 已审核 | 草稿 | 已过账不可反审核 |
| 过账 | 已审核 | 已过账 | 入账簿/报表；支持批量审核、批量过账 |
| 反过账 | 已过账 | 已审核 | 仅最近未结账期间 |
| 作废 | 草稿 | 已作废 | 留号 |
| 红字冲销 | 已过账 | 生成**草稿**红字凭证 | 金额全取负、is_red、red_source_id 双向关联、摘要"红字冲销 记-202609-0007"；同一凭证只许冲一次；目标期间须开放 |

- 制单人与审核人不能同一人：参数 `fin.gl.maker_checker_separate`（默认关，小微企业常一人多岗）。
- 审核/过账/红冲写 `sys_operation_log_runtime`；凭证头留 maker/checker/poster 三人+时间。

### 7.4 打印与查询

- 打印：后端按标准记账凭证格式输出打印数据（含中文大写金额），前端新窗口 `window.print`（本模块做最简可用版）。
- 列表过滤：期间/凭证字/号/科目/辅助核算/状态/制单人/审核人/来源；业务单据**联查凭证**、凭证**反查来源单据**（source_bill_type/no）。

## 八、会计事件池与凭证模板（P2 核心）

### 8.1 事件池 `fin_gl_event`

业务侧不直接生凭证，只丢事件：

| 字段 | 说明 |
|---|---|
| event_code | 事件码（见 8.4） |
| source_bill_type / source_bill_no | 来源单据类型/单号（联查、幂等去重） |
| biz_date | 业务日期（决定凭证期间） |
| amount | 事件金额（列表展示用） |
| payload_json | **单据全量快照**（含税总额/税率/成本/数量/客户/供应商/商品行/部门/资金账户/费用科目等），渲染凭证的唯一数据来源 |
| status | 待生成 / 已生成 / 已忽略 / 生成失败 / 已冲回 |
| voucher_id | 生成的凭证 |
| err_msg | 失败中文原因 |
| reverse_of | 反向事件关联的原事件 id |

- 幂等：唯一键 (source_bill_type, source_bill_no, event_code, reverse_of)；同单重复审核不重复丢事件。
- hook 铁律（照搬 Django）：① 业务事务**提交后**触发（`@TransactionalEventListener(phase=AFTER_COMMIT)`），hook 内 try-catch 吞一切异常；② 总账未启用/未初始化 → 静默跳过；③ 反审核丢反向事件（金额取负）。

### 8.2 凭证模板 `fin_voucher_template(+entry)`

模板 = 事件码 + 凭证字 + 摘要规则 + 分录行。每类事件预置一张模板，可停用、可复制修改，预置模板不可删。

**分录行字段**：

| 字段 | 说明 |
|---|---|
| line_no / direction（借/贷） | |
| summary_pattern | 摘要，变量 `{bill_no}` `{customer_name}` `{supplier_name}` `{month}` 等 |
| account_code | 固定科目编码；或占位符 `@AR`（应收，自动带客户辅助）、`@AP`（应付，带供应商）、`@FUND`（资金账户映射科目）、`@EXPENSE`（费用类型映射科目）、`@BIZ`（按单据业务类型查 `fin_gl_biz_subject_map` 映射对方科目，用于其他出/入库） |
| **amount_expr** | **金额表达式**，白名单四则运算，变量取 payload。如不含税 `amount_tax_incl / (1 + tax_rate)`、税额 `amount_tax_incl - amount_tax_incl / (1 + tax_rate)` |
| qty_expr | 数量表达式（数量核算科目用） |
| aux_expr | 辅助核算映射 JSON：`{"customer":"customer_code","goods":"goods_code"}`；固定值语法 `"=CODE|名称"` |
| cash_flow_item | 现金类分录预置流量项目编码 |
| condition_expr | 行启用条件，如 `taxpayer == 'GENERAL'`（小规模纳税人自动跳过税分录）；为空=始终生效 |
| expand_by | 行展开方式：`NONE`（整单一行，如 1122 应收）/ `GOODS_LINE`（按商品明细行展开，科目固定 1405/5401、辅助带商品+数量，同科目同辅助合并）/ `EXPENSE_LINE`（按费用明细行展开，科目取该行费用类型映射科目、金额取行金额，辅助带部门） |

**表达式引擎 `GlExprEngine`（自研，约 200 行，零依赖）**：词法分析 + 递归下降，白名单节点仅允许 数字、+ - * /、括号、一元负号、payload 变量、比较运算（条件行用）；除零保护；结果 `BigDecimal` HALF_UP 保留 2 位；未知变量/非法语法抛中文错误。**禁止** SpEL/JS/反射一切动态执行。冒烟测试含注入用例（`__import__`/`open`/`getClass` 类输入必须报错）。

**生成规则**：零金额行自动跳过；行 condition 不满足跳过；借贷差 >0.005 拒绝；科目必须末级+启用；必填辅助核算缺失报中文错（含模板名、科目、缺哪个维度）。合并规则先只做**一单一凭证**（按日/按客户汇总预留字段不实现）。

### 8.3 待生成凭证工作台（前端新页面）

- 菜单角标提醒"有 N 条待生成/失败事件"，防遗忘。

### 8.5 费用单/收入单两种结算方式的事件策略（防重复生凭证）

费用单审核有两条业务链路（V38 现状）：**填了资金账户→自动生成收/付款单并审核（直接结算）**；**没填账户→生成往来（挂应收/应付）**。事件策略：

| 场景 | 业务链路 | 丢的事件 | 凭证 |
|---|---|---|---|
| 费用单**有账户**（直接结算） | 费用单审核→自动生成付款单（`business_source='EXPENSE'`）并审核→资金流水 | 只丢 **EXPENSE** 事件；自动付款单在收付款钩子中**识别 business_source='EXPENSE' 跳过 PAYMENT 事件** | 借 费用科目（明细行展开）/ 贷 @FUND 银行，一张凭证 |
| 费用单**无账户**（挂往来） | 费用单审核→生成应付往来；后续手工付款单核销 | 丢 **EXPENSE** 事件（贷 @AP 2202 或 2241）；后续付款单（`business_source='BACKOFFICE'`）正常丢 **PAYMENT** 事件 | 两张凭证：费用单 借费用/贷应付；付款 借应付/贷银行 |
| 收入单**有账户** | 自动生成收款单（EXPENSE 来源） | 只丢 **OTHER_INCOME** 事件；自动收款单跳过 RECEIPT 事件 | 借 @FUND / 贷 收入科目 |
| 收入单**无账户** | 挂应收；后续手工收款核销 | OTHER_INCOME（借 @AR 1122 或 1221）+ 后续 RECEIPT 事件 | 两张凭证：收入单 借应收/贷收入；收款 借银行/贷应收 |

**收付款钩子统一规则**：`business_source='EXPENSE'` 的收/付款单（费用单自动生成）审核与反审核**都不丢事件**——它的银行对方科目已包含在 EXPENSE/OTHER_INCOME 凭证里，再丢 PAYMENT/RECEIPT 会重复（借应付贷银行，而应付从未挂起）。`business_source='DRIVER_SETTLE'`（司机交账 COD 货款）正常丢 RECEIPT 事件（借银行/现金、贷 1122，签收时已挂应收）；`BACKOFFICE` 手工收付款正常丢。

**反审核联动**：费用单反审核时业务层联动红冲自动收/付款单（EXPENSE 来源收付款本就没事件，无需处理）；总账侧只丢 EXPENSE 反向事件（红字）。挂往来场景下若后续付款单已审核，业务层反审核拦截在前，事件层照丢反向事件由会计处理。

**费用进项税**：费用单明细含税率/税额（V40），但费用票能否抵扣依发票。默认含税全额入费用；模板预留税行（借 222103 待认证进项税，condition：`taxpayer=='GENERAL' && expense_deductible==true`），由参数 `fin.gl.expense_deductible`（默认关）控制，PRD-30 费用发票认证联动时启用。

### 8.6 金额口径（价内税）

AR/AP/收付款均含税。拆税表达式：不含税 = `amount_tax_incl / (1 + tax_rate)`，税额 = 含税 - 不含税；税率取明细行税率（多税率按明细行生成多条税分录），无税率按参数 `fin.gl.taxpayer_type`：小规模 → 不拆税（全额入收入/库存，税分录 condition 不满足自动跳过）。成本取 `InventoryCostService`（内部 6 位、入凭证 2 位，尾差并入成本行轧差）。

### 8.7 开关参数

`fin.gl.enabled`（总账启用）、`fin.gl.initialized`（已建账）、`fin.gl.auto_event`（业务审核自动丢事件，默认开）、`fin.gl.taxpayer_type`（GENERAL/SMALL）、`fin.gl.maker_checker_separate`（制审分离，默认关）、`fin.gl.expense_deductible`（费用进项税抵扣，默认关）、`fin.gl.surtax_rate`（附加税费率，默认 0.12）。

## 九、固定资产管理（P4）

**入口**：`财务管理 → 总账 → 固定资产`（资产类别 / 资产卡片 / 折旧计提 / 资产盘点 / 资产台账）。规则整体参照已验证的 Django 实现，科目换小企业准则码。

### 9.1 资产类别 `fin_fixed_asset_category`

预置 7 类（V97 种子）：

| 类别 | 方法 | 年限(月) | 残值率 | 折旧费用科目 |
|---|---|---|---|---|
| 房屋及建筑物 | 直线 | 240 | 5% | 5602 管理费用-折旧费 |
| 机器设备 | 直线 | 120 | 5% | 5602 |
| 运输工具 | 直线 | 48 | 5% | 5601 销售费用-折旧费 |
| 电子设备 | 直线 | 36 | 3% | 5602 |
| 办公家具 | 直线 | 60 | 5% | 5602 |
| 仓储设备 | 直线 | 120 | 5% | 5601 |
| 冷链设备 | 双倍余额递减 | 120 | 5% | 5601 |

每类带资产科目 1601、折旧科目 1602、费用科目。

### 9.2 资产卡片 `fin_fixed_asset`

资产编码 `ZC+yyyy+4位流水`；名称/类别/品牌型号/使用部门/使用人/存放地点/原值/启用日期/折旧方法（**直线 LINE / 双倍余额递减 DOUBLE / 年数总和 SUM / 工作量 WORK / 不提 NONE**）/折旧年限/残值率（默认 5%）/累计折旧/净值/工作量总额（WORK 法）/已用月数/来源卡片号/状态（**使用中/已停用/已清理/已拆分/已合并**）。

- **建卡**默认同时生成入账凭证（借 1601 贷 1002/2202），写 ADD 变动记录。
- **变更** `fin_fixed_asset_change`：部门/地点/保管人/年限/方法可改留痕；**原值禁止直接改**（要走清理重建）。
- **拆分**：一卡拆多卡，按比例分摊原值/累计折旧/残值，**最后一张卡吃四舍五入尾差**保证合计不变；账面价值不变**不生凭证**；原卡置"已拆分"。
- **合并**：多卡并一卡，原值/累计折旧相加，**仅限同一类别**（方法年限一致）；不生凭证；旧卡置"已合并"。
- **清理**：转原值+累计折旧入 1606 固定资产清理；处置收入/费用进 1606；差额=收入-费用-净值 → 正数贷 **5301 营业外收入**、负数借 **5711 营业外支出**；卡片置"已清理"，DISPOSE 变动记录含损益与凭证。
- **盘点** `fin_fixed_asset_check(+detail)`：开盘点单拉使用中+已停用卡片 → 录结果 → **盘亏只写 CHECK 变动记录"待人工核实"，不自动清理/停用**。

### 9.3 折旧计提（月度向导）

规则（会计准则 + 已验证实现）：
- **当月新增次月计提**；提到净值=残值自动停（**最后一个月补齐到残值、不提超**）；已清理/拆分/合并不提；
- 直线法：(原值-残值)/使用月数；
- **双倍余额递减**：年率=2/年限、按月初净值（不扣残值），**最后两年自动改直线**；
- **年数总和**：剩余年数/年数总和；
- **工作量法**：当月工作量/总工作量 × 应计折旧额；
- (asset_id, dep_month) 唯一防重复，同月重提须先删本期折旧记录与凭证。

向导：预览当月应提清单（资产/月折旧额/费用科目/部门）→ 一键执行：逐卡写 `fin_fixed_asset_dep`（折旧前后累计、净值）+ 更新卡片，按"费用科目+部门"汇总生成一张**"转"字凭证**（借 5601xx/5602xx 折旧费，贷 1602 累计折旧），source=折旧计提、幂等键 `ZJ{period}`。

### 9.4 资产台账

按类别"期初→本期增减→期末"滚动表：期末取卡片当前值，期初=期末-本期 ADD+DISPOSE 转出，折旧取本期 dep 明细；附"期末原值=期初+增-减"校验（容差 0.02），净值=原值-累计折旧。

## 十、期末处理（P3）

**入口**：`财务管理 → 总账 → 期末处理`，结账向导分步页面，每步显示完成状态：

```
① 事件检查   事件池无"待生成/生成失败"事件（有则列清单直达工作台）
② 单据检查   本期业务单据全部审核（提示项，列未审核清单）
③ 折旧计提   固定资产月度折旧（P4 未上线则跳过）
④ 自动转账   月末固定分录（见下，可预览可跳过）
⑤ 结转损益   预览损益类科目本期净发生额 → 3103 本年利润，确认后生成"转"字凭证
⑥ 结账检查   四项硬检查（见下），全过才允许结账
⑦ 期末结账   期间→已结账并锁死；自动生成下年期间入口
⑧ 业财对账   应收/应付/资金账户三条线对账（结账后也可随时查）
```

- **自动转账 `fin_auto_transfer(+entry)`**：模板化月度固定分录，金额用报表公式语言；预置 2 张，房租摊销/工资计提等由会计自建；幂等键 `ZZ{transfer_no}{period}`，为零/不平跳过：
  1. 结转未交增值税：借 22210105 转出未交增值税 / 贷 222102 未交增值税，金额 `FSC(22210102)-FSD(22210101)`（一般纳税人，condition 纳税人参数）；
  2. 计提附加税费：借 5403 税金及附加 / 贷 2221 明细（城建税/教育费附加/地方教育附加），金额 = 应交增值税 × 附加税率（税率取参数 `fin.gl.surtax_rate`，默认 12%）。
- **结转损益**：损益类科目（5xxx）本期净发生额结转至 **3103 本年利润**：收入类净贷方→借收入贷 3103；成本费用类净借方→借 3103 贷费用；"转"字凭证、日期=期间最后一天、幂等键 `JZ{period}`（同期重复拦截）；生成草稿需审核过账。
- **结账四项硬检查**（`close_checks`，任一不过拒绝结账）：
  1. 本期凭证全部过账（无草稿/已审核）；
  2. 本期借贷发生额合计平衡，且逐科目"期末=期初+本期"恒等成立；
  3. 损益已结转（3103 结转凭证存在且已过账，或损益类科目无余额）；
  4. 上期已结账（期间连续）。
- **反结账**：仅最后一个已结账期间可反，**强制填写原因**（留痕 reopen 人/时间/原因）；反结账后结转损益凭证置为可删除（未过账）。**年度结账（12 期）状态"已冻结"，不可反结账**。
- 已结账期间凭证只读、账簿报表照常查询。

| 应付 | 2202 供应商辅助核算期末余额 | `fin_ap` 各供应商未付余额合计 |
| 资金 | 1002/1001 科目余额（按资金账户映射 gl_account_code） | `base_fund_account.balance` 各账户余额 |

## 十二、财务报表

**入口**：`财务管理 → 总账 → 财务报表`。实时查询不预生成；月报/季报/年报切换；导出 CSV；可下钻凭证明细。

### 12.1 取数公式引擎

报表项目存 `fin_report_item` 种子表（report_code: BS/IS/CF），公式由 `GlExprEngine` 报表模式解析（函数白名单）：

| 函数 | 含义 |
|---|---|
| `QM(1001)` | 期末余额（按科目方向取净值；前缀匹配自动汇总所有下级） |
| `QC(1001)` | 期初余额 |
| `FSD(5401)` / `FSC(5001)` | 本期借方 / 贷方发生额 |
| `LJFS(...)` | 本年累计发生额（利润表本年累计列） |
| `QM(1001:1012)` | 科目区间汇总 |
| `CF('01')` | 现金流量项目编码的本期金额（现金流量表用） |

- 四则运算任意组合；年初列公式由期末公式 `QM(`→`QC(`、`FSD/FSC`→上年累计 机械派生（种子里直接给 formula_begin）。
- 公式在报表页可微调（P5 提供编辑 UI），存 `fin_report_item` 不动代码。

### 12.2 三张报表

- **资产负债表**：左右结构，期末余额+年初余额两列。核心公式（小企业准则码）：
  - 货币资金 `QM(1001)+QM(1002)+QM(1012)`；应收账款 `QM(1122)`；存货 `QM(1405)`；
  - 固定资产净值 `QM(1601)-QM(1602)`；
  - 应交税费 `QM(2221)`；应付账款 `QM(2202)`；
  - **本年利润行（关键）**：`QM(3103)+QM(5001)+QM(5051)+QM(5301)-QM(5401)-QM(5402)-QM(5403)-QM(5601)-QM(5602)-QM(5603)-QM(5701)-QM(5711)`
    ——已结转的 3103 + 损益类科目**期末余额**：结转后损益为 0 不重复，结转前（期中）损益体现在权益侧，**期中未结转资产负债表也平**（这是很多小软件的通病）。
  - **验收红线**：资产总计 = 负债和所有者权益总计（容差 0.02），不平显示差额并提示常见原因（损益未结转、科目方向挂错、期初试算不平）。
- **利润表**：本月数+本年累计数。营业收入 `FSC(5001)+FSC(5051)`；营业成本 `FSD(5401)+FSD(5402)`；税金及附加 `FSD(5403)`；销售/管理/财务费用 `FSD(5601/5602/5603)`；营业外收入 `FSC(5301)`、支出 `FSD(5711)`；所得税 `FSD(5701)`。净利润累计应=3103 本年利润累计发生额（勾稽提示）。
- **现金流量表**：**直接法、分录级指定流量项目**（维持 v1，不学 Django 留空手填）。`fin_cash_flow_item` 预置经营/投资/筹资三类约 20 项；现金类科目分录在凭证录入/模板渲染时带流量项目，报表行 `CF('项目编码')` 取数；净增加额行用 `QM(1001)+QM(1002)+QM(1012)-QC(...)` 交叉校验；历史凭证提供"补录流量项目"批量工具。

## 十八、风险与坑点清单

1. **H2 兼容**：聚合 SQL 走 `queryCamel()`；JOIN 加表别名；期初 upsert 用 `MERGE INTO ... KEY`；日期 `DATEADD`；SQL 普通字符串显式空格；JOIN SELECT 同名列加表别名。
2. **事件钩子事务边界**：必须 `AFTER_COMMIT` 且 hook 内吞异常——业务事务回滚时事件不能丢出（否则业务回滚了事件还在），提交后财务报错也不能反滚业务；事件生成失败靠事件池 err_msg 兜底。**不要**在业务同事务里写 fin_gl_event。
3. **反向事件与红冲**：反审核时原凭证未过账→自动删凭证（已审核的先反审核）；已过账→反向事件走红字草稿；红冲凭证必须过账后才真正冲平，结账检查会拦住"已冲销事件未生成/未过账"。
4. **费用单防重复生凭证**：费用单自动生成的收/付款单 `business_source='EXPENSE'`，收付款钩子必须跳过丢事件（审核/反审核都跳）；EXPENSE 模板贷方按 `fund_account` 是否为空条件分流 @FUND / @AP(2202) / 2241。冒烟必测：有账户费用单只生成一张凭证（无重复付款凭证）、无账户费用单生成"费用+后续付款"两张凭证。
5. **凭证号**：BillNoGenerator 新增"期间(yyyyMM)+凭证字"取 MAX 模式；作废留号、红冲用新号。
6. **金额口径**：价内税，拆税用表达式按明细税率；小规模纳税人税分录 condition 跳过；成本取 `InventoryCostService`（6 位内部算、2 位入凭证，尾差轧差进成本行）。
7. **进项税方向**：2221 下所有明细科目方向=贷；新增税目明细时前端强制默认贷、后端校验。
8. **报表平衡**：BS 上线必查"资产=负债+权益"（容差 0.02）；本年利润行用"3103+损益期末余额"口径保证期中也平；利润表净利润=3103 发生额；不等给差额与排查提示。
9. **表达式安全**：GlExprEngine 白名单节点，禁用一切反射/动态执行；冒烟含注入用例。
10. **PRD-30 并行**：V89 属采购发票分支（当前所在分支），本模块 V90 起；P2 先合时进项税先入 222103 待认证，认证联动留接口。
11. **菜单双份**：`userMenuTree()` + `fallback-menus.js` 都要改。
12. **不引新依赖**：表达式解析、月度单号、CSV 导出（后端拼 text/csv 流、UTF-8 BOM）全部现有能力。
13. **多账套/受托代销不做**：Django 版的平台账/货主账/1407/2203 代销科目是三方物流定制，单体公司不引入。
14. **字典业务类型与映射联动**：其他出/入库类型留字典维护、不剥离；新增字典类型值后若未配 `fin_gl_biz_subject_map`，事件生成失败但 err_msg 必须指明类型名并引导到映射配置页，补配后工作台重试成功；映射表冗余 biz_type_name 快照，字典改名/删值不影响历史凭证；`inbound_type='0'` 期初库存钩子层直接不丢事件。冒烟必测：同一类单据两种类型生成不同对方科目、未配置类型事件失败提示中文可读。

## 十九、验收用例（冒烟测试，进 development/06-testing/scripts/）

- **P1**：建科目 → 录期初（故意不平衡被拦截）→ 试算平衡 → 启用 → 录 3 张凭证（含辅助核算、现金流量项目、数量科目）→ 审核（借贷不平被拦）→ 过账 → 总账/明细账/余额表勾稽一致（**期末=期初+本期逐科目**）→ 零发生科目在余额表出场 → 红字冲销（负金额、双重冲销被拦）→ 已过账反审核被拦截 → 作废留号。
