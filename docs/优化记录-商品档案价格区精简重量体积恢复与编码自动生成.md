# 优化记录：商品档案精简价格区、恢复单位重量体积、商品编码按大类自动生成

- 日期：2026-09-14
- 分支：feat/base-goods-price-weight-autocode
- 模块：base（商品档案）
- 涉及文件：
  - `frontend/src/views/goods/GoodsDrawer.vue`（移除价格信息区、编码非必填、重量体积同步顶层、默认表单带 categoryCode）
  - `frontend/src/views/goods/components/BaseInfoForm.vue`（编码输入框说明、分类选中携带 categoryCode）
  - `frontend/src/views/goods/components/MultiUnitMatrix.vue`（恢复「重量(kg)」「体积(m³)」两行）
  - `backend/src/main/java/com/erp/base/BaseController.java`（/goods/create 编码留空时自动生成）

## 一、需求

1. 去掉商品档案抽屉「价格信息」区域的批发价、会员价、零售价三个字段；
2. 商品的重量、体积字段不见了——原来在多单位设置里按单位设置，需要恢复；
3. 商品编号不输入时，默认根据所选择商品分类的大类自动生成：**商品大类编号 + 5 位流水号自增**，并在商品编号输入框中说明。

## 二、实现方案

### 1. 移除价格信息区

- 删除 GoodsDrawer 中整个「价格信息」section（批发价/会员价/零售价）及专属 CSS；
- 抽屉分区现为：基本信息、多单位设置、采购与库存、备注与介绍；
- 后端字段 `wholesale_price/member_price/retail_price` 与表单模型保留：编辑老商品时仍原样回传不丢历史数据，
  只是入口下线（商品实际售价以多单位矩阵的标准售价/最低价/建议零售价及价格组为准）。

### 2. 多单位矩阵恢复重量/体积

- 重量体积的数据链路一直在（默认单位对象含 `weight/volume`、保存时整体序列化进 `unit_config`、
  模板里也有对应输入分支），只是 `attributeFields` 配置漏配导致两行不渲染；
- 在「条码」后补回两行：**重量(kg)**（step 0.001）、**体积(m³)**（step 0.0000001 级，placeholder 0.000000），
  各单位独立设置，未启用单位行禁用（与其他行一致）；
- 保存时基本单位（小单位）的重量/体积同步到商品顶层 `baseWeight/baseVolume`，供物流计费等场景使用；
  编辑时从 unit_config 回显，已实测 1.5/0.012 保存再编辑一致。

### 3. 商品编码按大类自动生成

**前端**：

- 商品编码去掉红星必填，placeholder 改为「留空保存按大类自动生成（大类编号+5位流水号）」；
- 前端校验不再强制编码非空（商品分类仍是必填，编码生成依赖分类）；
- CategoryTreeSelect 选中末级时本就回传 `code`，BaseInfoForm 现把它写入 `modelValue.categoryCode`
  （不落 goods 表，仅随保存请求上送给编码生成逻辑），清空分类时一并清空；
- 编辑商品编码仍不可变（后端 update 保持原编码逻辑不变）；「复制新增」提示语同步更新。

**后端（BaseController#createGoods）**：

- 请求 `goodsCode` 为空时调用 `generateGoodsCodeByCategory`，否则沿用手工编码；
- 分类取数：优先按 `categoryCode` 查 base_category；只传分类名时要求同名分类唯一，重名/不存在抛
  IllegalArgumentException 中文报错；
- 沿 `parentCode` 链上溯到一级分类（大类），大类编码即前缀。实际数据：大类 2 位（10/15/…/65），
  如末级 100101（粗粮饼干）→ 大类 10 → 编码 `1000001`；
- 流水号：`SELECT MAX(goods_code) ... WHERE goods_code LIKE '大类码_____'`（下划线为单字符通配，
  恰好前缀+5 位；定长编码字典序即数值序），尾部非 5 位数字的手工编码不参与，取最大值 +1，
  从 00001 起；超过 99999 报中文错误；
- **软删商品仍占号**：删除是软删置 DELETED，行仍在表里，MAX 包含其编码，不复用号段，
  避免历史单据上的编码指向新商品；
- 生成方法 synchronized（单机部署并发安全，goods_code 唯一约束兜底），生成后写回请求 Map 走原有保存链路。

## 三、验证

- API 直测：编码留空 + categoryCode=100101 连续新建得 `1000001`、`1000002`；
  无分类时返回 `400 请先选择商品分类（商品编码留空时按商品大类自动生成）`；手工编码照常使用；
- Edge headless + CDP 16 项断言全过：价格区三字段不存在、编码输入框说明文案与非必填、
  矩阵两行存在且禁用态正确、留空编码保存成功（payload 编码为空、带 categoryCode=100101、
  返回 1000003）、unit_config 与顶层 baseWeight/baseVolume 数值正确、编辑回显一致；
- `npm run build` 与后端 `mvn -o package` 均通过；
- 4 条测试商品已软删并经 H2 Shell 物理清理。
