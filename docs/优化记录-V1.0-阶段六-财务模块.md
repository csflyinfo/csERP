# 优化记录 V1.0 — 阶段六：财务模块全面升级

> 涵盖收款单/付款单、费用单、客户应收明细、客户/供应商对账单、核销流水等模块的新建与重构。

---

## 一、收款单 + 付款单模块（V32 重构）

### 1.1 数据库（V32 + V37）

**改造 `fin_receipt_bill` + `fin_payment_bill`**，新增 13 列：收款/付款日期、往来单位类型/编码/名称、经手人、关联单号、摘要、业务来源、总金额、制单人/时间、审核人/时间。

**新建表**：
- `fin_receipt_detail` — 收款明细行（资金账户 + 金额 + 备注 + 供应商账户）
- `fin_payment_detail` — 付款明细行（同上）
- `fin_reconcile_record` — 收款核销流水表（V37 加 `ar_no`/`source_bill` 列）
- `fin_counterparty_ledger` — 往来流水表（方向 + 金额 + 余额）

### 1.2 后端（FinanceController）

| 端点 | 功能 |
|------|------|
| `POST /finance/receipt/page` | 收款单列表（支持往来单位类型、日期段、业务来源、核销状态过滤） |
| `POST /finance/receipt/create` | 新建（默认 SK 单号，明细行全量替换） |
| `POST /finance/receipt/update` | 编辑（仅 PENDING） |
| `POST /finance/receipt/audit` | 审核：①状态→APPROVED ②写核销记录+更新 AR/AP ③资金流水 ④更新 `base_fund_account.balance` ⑤往来流水 |
| `POST /finance/receipt/cancel-audit` | 取消审核：冲减流水 + 删除核销记录 + 回退 AR/AP → PENDING |
| `POST /finance/receipt/reconcile` | 核销结算：选未结算单据 + 每笔自定义结算金额 + 更新 AR/AP + 生成核销记录 |
| `POST /finance/receipt/unsettled-bills` | 查询往来单位未结算单据（数据源） |
| `POST /finance/receipt/batch-audit` | 批量审核 |
| `POST /finance/reconcile-record/page` | 核销流水只读查询 |
| `POST /finance/payment/*` | 付款单对称实现 |

### 1.3 前端

- **ReceiptDrawer.vue**：替换 FundBillDrawer，支持往来单位类型三选一（客户/供应商/往来单位），资金账户动态加载，明细行多行录入
- 付款单默认往来单位类型「供应商」，明细增加供应商收款账户列

## 二、费用单模块（V38 重构）

### 2.1 数据库（V38 + V39 + V40）

**改造 `fin_expense_bill`**，新增 15 列：费用日期、往来单位类型/编码/名称、经手人、部门、关联单号、外部凭证号、业务来源、收/付账户、备注、总金额、税额合计、不含税合计、创建/审核人。

**新建 `fin_expense_detail`**：费用类型、商品编码/名称、品牌、数量、单价、金额、税率、税额、不含税金额、备注。

### 2.2 后端

| 端点 | 功能 |
|------|------|
| `POST /finance/expense/page` | 列表（收支类型、往来单位类型、日期段、备注、关联单号过滤） |
| `POST /finance/expense/create` | 新建（FE 单号，明细行含商品/品牌/税率） |
| `POST /finance/expense/audit` | 审核：有收/付账户→自动生成收/付款单并审核；无账户→生成 AR/AP 往来 |

### 2.3 前端

- **ExpenseDrawer.vue**：左右分栏（左主单、右明细表），收支类型默认「支出」，经手人/部门下拉，明细含商品选择+品牌自动带出+数量/单价/金额/税率自动计算

## 三、客户应收明细表（原应收账款）

### 3.1 数据库（V41 + V44）

- `fin_ar` 新增 `reconcile_status`（默认"未对账"）、`created_at`
- `fin_ap` 新增 `reconcile_status`（V44）

### 3.2 后端

- `ar/page` 重写：LEFT JOIN `base_customer` 取 salesman、支持客户/状态/对账状态/日期段过滤、返回中文状态值
- `ar/settle`：按客户分组生成收款单+自动审核+抹零生成费用单+写核销记录

### 3.3 前端

- 模块改名「客户应收明细表」
- 列表列：应收单号、来源单据、客户、业务员(从客户档案)、应收/已收/未收金额、对账状态、核销状态

- 收款金额 = 资金账户实收合计，抹零≠0 时自动生成费用单并核销

## 四、客户/供应商对账单模块（V42/V43 新建）

### 4.1 数据库

- `fin_customer_statement` + `fin_customer_statement_detail`（客户对账单）
- `fin_supplier_statement` + `fin_supplier_statement_detail`（供应商对账单）

### 4.2 后端

| 端点 | 功能 |
|------|------|
| `POST /finance/customer-statement/page` | 列表（对账日期、客户、业务员、收款状态过滤） |
| `POST /finance/customer-statement/create` | 新建（CS 单号）+ 同步源单据对账状态→对账中 |
| `POST /finance/customer-statement/audit` | 审核 + 源单据对账状态→已对账 |
| `POST /finance/customer-statement/reverse-audit` | 反审核（仅未收款）+ 还原对账状态 |
| `POST /finance/customer-statement/delete` | 删除 + 还原源单据对账状态→未对账 |
| `POST /finance/customer-statement/available-bills` | 添加单据弹窗数据源（排除已对账 AR） |
| `POST /finance/customer-statement/settle` | 收款结算（校验同一客户、生成收款单+审核、更新对账单已收金额和收款状态） |
| `POST /finance/supplier-statement/*` | 供应商对称实现（SS 单号、查询 AP、付款结算生成付款单） |

### 4.3 对账状态联动

| 操作 | 源 AR/AP reconcile_status |
|------|--------------------------|
| 新建对账单 | 对账中 |
| 审核对账单 | 已对账 |
| 反审核 | 对账中 |
| 删除对账单 | 未对账 |

### 4.4 前端

- **CustomerStatementDrawer.vue**：客户选择→自动带出业务员/联系人/电话、对账日期默认今天、预计回款日默认+7天、添加单据弹窗（Teleport 到 body、列显示应收单据/业务单据/日期/类型/金额/已收/未收、勾选显示合计、"选择添加"不关窗/"确定"关窗）
- 供应商模式自动切换：加载供应商列表、调供应商 API、列显示 AP 数据
- **StatementSettlementDialog.vue**：收款/付款结算弹窗（经手人/记账日期/备注/应收金额/抹零/抹零费用类型/资金账户多行）
- 列表行操作：PENDING→编辑/审核/删除，APPROVED→收款结算/付款结算/反审核

## 五、其他优化

### 5.1 查询条件全局约定（CLAUDE.md 第 9 条）
查询条件只在点击「查询」按钮时生效，选择下拉、修改日期、输入关键字不自动触发查询。QueryBar 已移除所有 `@change="query"` 自动触发。

### 5.2 批量操作全局约定（CLAUDE.md 第 10 条）
支持批量操作的模块，勾选记录后才在列表左下角显示批量按钮，仅符合条件的记录才显示按钮。

### 5.3 简拼搜索（BaseController）
`/base/goods/page` 关键词增加 `simple_code` 字段（UPPER 双侧统一，解决 H2 大小写问题）。

### 5.4 BillNoGenerator 修复
`COUNT(*) + 1` → `MAX(no_column)` 后缀解析，消除反审核后单号碰撞的 UNIQUE 冲突。

### 5.5 FinanceController H2 大写下划线键修复
AR/AP/收付款/资金流水等列表查询全部使用 `queryCamel()` 转换键名，避免前端 `valueForTitle` 匹配不到。

### 5.6 销售发货单列表增强
LEFT JOIN `fin_ar` 取对账状态、新增 22 列展示、全部状态值中文化、结算状态/对账状态实时显示。

## 七、V1.0 收尾补充（2026-08-09）

### 7.1 供应商对账单单据选择窗适配

**前端 CustomerStatementDrawer.vue**：
- 添加单据弹窗表头根据供应商/客户模式动态切换：应付/应收单据、应付/应收金额、已付/已收金额、未付/未收金额
- 编辑模式详情加载修正：供应商对账单调用 `/finance/supplier-statement/detail` 而非写死的 customer-statement

### 7.2 付款结算流程完善

**3 端点增强**：

| 端点 | 改动 |
|------|------|
| `POST /finance/payment/audit` | 完善全流程：①核销 AP（逐明细匹配待付 AP） ②资金流水 OUT + 更新 `base_fund_account.balance` ③往来流水 OUT（余额减少） ④更新付款单状态 APPROVED |
| `POST /finance/payment/cancel-audit` | **新建**：①回退 AP 已付金额 ②删除核销记录 ③资金流水 IN（对冲） ④往来流水 IN（余额恢复） ⑤改回 PENDING |
| `POST /finance/customer-statement/settle` | 增强：写入收款单明细行、逐明细核销 AR、写资金流水 IN、写往来流水 IN |
| `POST /finance/supplier-statement/settle` | 增强：写入付款单明细行、逐明细核销 AP、写资金流水 OUT、写往来流水 OUT |

### 7.3 核销与往来流水链路

结算/审核后完整写入链路：

1. **核销记录 `fin_reconcile_record`**：逐笔 AR/AP 记录核销金额
2. **AR/AP 更新**：`received_amount`/`paid_amount`、`unreceived_amount`/`unpaid_amount`、`status`
3. **资金流水 `fin_fund_ledger`**：IN/OUT + `balance_after`
4. **资金账户余额 `base_fund_account.balance`**：实时更新
5. **往来流水 `fin_counterparty_ledger`**：IN/OUT + `balance_after`

反向操作（取消审核/反审核）完整冲减以上所有记录。
