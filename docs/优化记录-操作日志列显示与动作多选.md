# 优化记录：操作日志列显示修正 + 动作多选查询

- 日期：2026-09-28
- 分支：`feat/system-oplog-action-filter`（squash 合入 main）
- 范围：系统管理 - 操作日志（后端 + 前端），无 Flyway 迁移

## 一、问题与需求

操作日志集中查询页存在两个显示问题、一个查询能力缺失：

1. **「操作时间」「操作人」两列显示成「详情」按钮**，看不到时间和人员。
2. **操作人应显示用户名称**（如「系统管理员」），而非登录账号 `admin`。
3. **查询条件「动作」需要支持多选**（下拉复选），一次筛选多个动作。

## 二、根因

[GenericBusinessList.vue](../frontend/src/views/GenericBusinessList.vue) 中列与插槽的判定一律用 `/操作/.test(title)` 包含匹配：

- 列定义 `action: /操作/.test(title)`、单元格插槽 `v-else-if="/操作/.test(col.title)"` 把标题为「操作**时间**」「操作**人**」的两列也匹配成了动作列，渲染出行内的「详情」按钮。
- 本地导出函数的列过滤 `filter(t => !/操作/.test(t))` 也会误删「操作时间/操作人」（变价日志、库存流水等含这两列的导出受影响）。
- 操作人列映射为 `['operatorAccount', 'operatorName']`（账号优先），与期望的「姓名优先」相反。

## 三、改动

### 后端

- `SystemLogController`：
  - WHERE 拼装新增 `inList(col, val)`：值为 List 时去空去重展开为 `col IN (?,?…)`；非 List 退化为单值 `=`，兼容历史单值调用方。操作日志 page/export 共用，动作筛选改走它。
  - page/export 返回前 `fillActionName(rows)`：按当前映射实时回填 actionName——历史日志写入时动作码若还没有中文名，DB 存量 action_name 是原始码（实测 CONFIRM_MOVE 存量行就是如此），不能靠存量值。
- `OperationAction`：补 `CONFIRM_MOVE → 确认移库` 中文名（移库确认日志此前列表动作列显示原始码）。
- `OperationLogController.billTimeline`：单据时间线同样实时回填 actionName。

### 前端

- `components/QueryBar.vue`：新增字段类型 `multiSelect`——自定义复选下拉（全选/清空、选项按配置顺序、外部点击关闭），回传值为数组；单值 `select` 行为不变。
- `module-config.js`：操作日志「动作」筛选改 `type: 'multiSelect'`，选项扩充至 28 个（含反核销、取消签收、保存、生成、确认、确认移库、作废、驳回、终止、下发仓库等）。
- `module-api.js`：「操作人」映射改为 `['operatorName', 'operatorAccount']`（姓名优先，姓名缺失回落账号；其它模块的操作人记录本就只有 operatorName，不受影响）。
- `GenericBusinessList.vue`：
  - 三处 `/操作/.test(...)` 改为精确判等 `title === '操作'` / `col.title === '操作'`（列定义、单元格插槽、本地导出列过滤）。
  - 操作日志页 QueryBar `maxVisible=8`，8 个查询条件首屏全展示。
