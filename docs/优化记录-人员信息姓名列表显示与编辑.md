# 优化记录：人员信息姓名列表显示为空、编辑改名后看不到生效

- 分支：`fix/base-employee-name`
- 迁移：无（纯前端修复）
- 需求来源：用户反馈「人员信息新建保存后，姓名在列表没有显示。编辑时姓名无法编辑」
- 影响范围：人员信息列表姓名列；登录日志/系统用户姓名列做了回归
- 验收方式：Edge headless + CDP 真实操作（仓库外 `e:\work\verify-employee-name.mjs`），抓 `/base/master/save` 请求与响应

## 1. 问题

1. 人员信息新建保存成功（后端返回 `employeeCode`、`success:true`），但列表「姓名」列为空白，已有人员同样不显示姓名。
2. 用户反馈编辑时姓名「无法编辑」：改名保存后列表依旧空白，观感等同编辑没有生效。

## 2. 根因

`frontend/src/module-api.js` 的 `EXACT_TITLE_MAP`（列标题 → 后端字段名候选）是一个 JS 对象字面量，其中 **`'姓名'` 键被定义了两次**：

```js
// 人员信息段（296 行附近）
'姓名': ['employeeName', 'displayName'],
// ……
// 登录日志段（680 行附近）
'姓名': ['userName'],
```

JS 对象字面量出现重复键时，**后者静默覆盖前者**（仅严格模式/构建警告，运行时不报错），运行时 `EXACT_TITLE_MAP['姓名']` 只剩 `['userName']`。

而通用列表 `mapRecordToRow()` 对每个列标题调 `valueForTitle(title, record)` 取数：员工记录的名字字段是 `employeeName`，在只剩 `['userName']` 的候选里永远取不到值 → 姓名列空白。新建、编辑保存都正常写库，回显也正常（`_raw.employeeName` 有值），唯独列表这一列永远空。

编辑弹窗本身没有缺陷：`BaseInfoDrawer.vue` 员工字段 `{ key:'employeeName', label:'姓名', required:true }` 不带 `readonly`，`mode='edit'` 时姓名框可输入、保存 `mode=edit` 成功（CDP 实测：采购王→采购王X 保存返回 success）。用户看到的「无法编辑」实际是「编辑后列表仍不显示名字」的同一根因现象。

> 备注：行双击打开的是全站统一的只读「查看」弹窗（只有「关闭」按钮）；改名请点行内「编辑」。该交互全站一致，本次未改。

## 3. 改动

`frontend/src/module-api.js`：

1. 合并为 `'姓名'` 唯一定义，候选字段覆盖所有使用该列标题的模块：

```js
// 人员信息=employeeName；登录日志=userName；防御性保留 displayName 与大写键
'姓名': ['employeeName', 'userName', 'displayName', 'USERNAME', 'DISPLAYNAME'],
```

   - 员工记录只有 `employeeName`，登录日志记录只有 `userName`，互不为空串误取；
   - 系统用户页 `UserManage.vue` 不走 `mapRecordToRow`（自行做字段归一化后绑定 `u.displayName`），不受影响；大写键仅作防御性候选。
2. 删除登录日志段重复的 `'姓名': ['userName']`，并在两处加注释，禁止再次出现重复键。

## 5. 遗留隐患（本次未改，记录待排查）

脚本扫描发现 `EXACT_TITLE_MAP` 还有 28 个重复键（如 `创建时间`、`账号`、`审核人`、`税额` 等），均为后定义覆盖先定义。当前各模块恰好大多兼容（如 `创建时间` 两处候选都含 `createdAt`），但这是同类「列空白」问题的温床。建议后续安排一次专项清理：逐标题合并候选字段或改为模块级映射表，并在构建中加重复键检查（如 eslint-plugin-no-duplicate-keys 思路）。
