## 2026-08-06 两个查询模块限定只看已审核单据

- **当前任务**：客户价格查询 / 客户商品变价查询都只查询已审核的调整单

- **已完成**（均在 `CustomerPriceController`，无迁移）：
  - 两个查询 SQL 加 `EXISTS (... h.status = 'APPROVED')` 过滤
  - `auditAdjust()` 加状态校验：非 PENDING 拒绝审核
  - `cancelAdjust()` 重写：已审核单据作废时**连带停用**它产生的价格；重复作废拒绝

- **关键决策**：
  - **查询过滤 + 写入端把关，两处都做**：正常流程下价格只在审核时写入，查询过滤看似冗余，但能挡住历史脏数据与人工改库；写入端把关才是根治
  - **作废已审核单必须连带停用价格**：否则「客户价格查询」会显示一张已作废单据带来的价格，销售按错价出单。这是本次发现的**真实数据泄漏**，不是防御性编程
  - **变价日志不删只过滤**：日志是历史流水，作废本身也属于历史；物理删除会丢失审计线索

- **踩坑与结论**：
  - `cancelAdjust()` 原先只改单据状态、不管已生成的价格 → 已审核单作废后价格仍显示「生效中」
  - `auditAdjust()` 原先无状态校验 → 重复审核会把刚生效的价当成「旧价」再记一条变价日志，污染变价查询

- **验证状态**：
  - ✅ 6 个场景实测：未审核不可见 → 审核后可见 → 重复审核被拒(400) → 作废后两查询归 0 且**库内 is_active 确实为 false**（非仅查询过滤）→ 重复作废被拒 → 新单审核后恢复可见
