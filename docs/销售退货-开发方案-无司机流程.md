# 销售退货开发方案 — 无司机流程（V1.0）

> 本轮开发不含司机回收环节。货物由客户直接退回仓库，经仓库验收后入库入账。
> 设计完全对称于已有的采购退货三表实现（`pur_return_apply → pur_return_outbound → pur_return`），方向相反。

---

## 1. 方案概述

| 维度 | 采购退货（已有） | 销售退货（本方案） |
|------|-----------------|-------------------|
| 对方单位 | supplier | customer |
| 来源单据 | 采购入库单 pur_inbound | 销售出库单 sales_outbound |
| 库存方向 | 出库扣减 | **入库增加** |
| 成本计价 | 当前移动加权平均成本 | 当前移动加权平均成本 |
| 财务冲减 | 负向 fin_ap | **负向 fin_ar** |
| 退货方式 | BY_BILL / BY_GOODS | BY_BILL / BY_GOODS |
| 可退数量校验 | 入库数量 - 已退 | **出库数量 - 已退** |
| 单据编号 | CGTSQ/CGTHK/CGTH | **XTSQ/THRK/XSTH**（BillNoGenerator 已预留） |

三张表一一对应：

```
sales_return_apply      ←→  pur_return_apply        退货申请
sales_return_inbound    ←→  pur_return_outbound     退货入库（采购是出库，方向相反）
sales_return            ←→  pur_return              退货单（结算依据）
```

---

## 2. 三阶段流程

### 阶段 1：退货申请（sales_return_apply）

- 客户提出退货，客服创建退货申请单
- 两种模式：
  - **BY_BILL 按单退货**：关联原销售出库单，退款单价 = 原出库单价，数量 ≤ 已出库 - 已退
  - **BY_GOODS 按品退货**：不关联原单，退款单价 = 客户价格组当前售价，需主管审批
- 状态流转：`DRAFT → PENDING → APPROVED → INBOUNDED → COMPLETED`
- 审核后**自动生成退货入库单**（幂等，1:1）

### 阶段 2：退货入库（sales_return_inbound）

- 货物到达仓库，仓库人员验收
- 可修改实际入库数量（≤ 申请数量）
- 质检分流由 WMS 内部处理（合格品入正常库位，残次品入残次区），不影响财务入账
- 状态流转：`PENDING → APPROVED`
- 审核时执行：
  1. 调用 `InventoryCostService.purchaseInbound()` 增加库存（入参 costPrice = 当前移动平均成本）
  2. 写库存流水 direction=IN
  3. 回写申请状态 INBOUNDED
  4. **自动生成退货单**（幂等，1:1）

### 阶段 3：退货单（sales_return）

- 结算依据，由入库单审核自动生成
- 状态流转：`PENDING → APPROVED`
- 审核时执行：
  1. 写**负向 fin_ar**（ar_amount 为负数，source_bill 存退货单号）
  2. 回写申请状态 COMPLETED
- 退款通过 AR 系统自然处理：负向 AR 抵扣客户现有正向 AR，余额通过付款单退还

## 3. 数据库设计（V28__sales_return.sql）

### 3.1 退货申请主表

```sql
CREATE TABLE sales_return_apply (
  apply_id        VARCHAR(32) PRIMARY KEY,
  apply_no        VARCHAR(50) NOT NULL UNIQUE,       -- XTSQyyyyMMddNNNN

  customer_code   VARCHAR(50),
  customer_name   VARCHAR(100),
  warehouse       VARCHAR(100),
  bill_date       DATE NOT NULL,
  qty             DECIMAL(18,2) DEFAULT 0,
  amount          DECIMAL(18,2) DEFAULT 0,

  creator_name    VARCHAR(100),
  audit_user      VARCHAR(100),
  audit_time      TIMESTAMP,
  create_time     TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  remark          VARCHAR(500)
);
```

#### 核心审核逻辑

**退货入库审核（sales/return-inbound/audit）：**

```
对每条入库明细：
  1. costPrice = inventoryCostService.getCurrentCostPrice(goodsCode, warehouse)
  2. costAmount = qty × costPrice
  3. inventoryCostService.purchaseInbound(
         goodsCode, goodsName, warehouse, batchNo,
         qty, costPrice, inboundNo, productionDate)
     ↑ 复用采购入库方法，入参 costPrice = 当前移动平均成本
     ↑ 因为按当前均价入库，移动平均成本不会改变
  4. 回写明细 cost_price / cost_amount

更新入库单：status=APPROVED, stock_updated=TRUE, cost_amount=合计
更新申请单：status=INBOUNDED
自动生成退货单（幂等）
更新入库单：return_generated=TRUE
```

**退货单审核（sales/return/audit）：**

```
arAmount = -goods_amount  （负数，含税金额）

INSERT INTO fin_ar(ar_id, ar_no, source_bill, customer,
    ar_amount, received_amount, unreceived_amount, due_date, status)
VALUES (?, ?, returnNo, customerName,
    arAmount, 0, arAmount, DATEADD('DAY', 30, CURRENT_DATE), 'UNVERIFIED')

更新退货单：status=APPROVED, ar_status='已生成'
更新申请单：status=COMPLETED
```

#### 按单退货可退数量校验

> 只有按单退货（BY_BILL）有此校验。**按品退货（BY_GOODS）不做任何库存校验**：销售退货是入库类单据，
> 明细里的 `available_stock` 仅供参考展示，不是数量上限（2026-08-20 修正，原实现误加了
> 「退货数量 ≤ 可用库存」拦截，导致零库存商品无法开退货单）。

```sql
-- 可退数量 = 出库数量 - 已被未作废退货申请占用的数量
SELECT
  d.qty AS outbound_qty,
  COALESCE((
    SELECT SUM(rd.qty) FROM sales_return_apply_detail rd
    JOIN sales_return_apply rh ON rd.apply_id = rh.apply_id
    WHERE rd.source_detail_id = d.detail_id
      AND rh.status <> 'CANCELLED'
      AND (? IS NULL OR rd.apply_id <> ?)   -- 排除本单（编辑场景）
  ), 0) AS returned_qty
FROM sales_outbound_detail d
WHERE d.detail_id = ?
```

### 4.2 InventoryCostService — 无需修改

退货入库复用现有 `purchaseInbound()` 方法：

```java
BigDecimal costPrice = inventoryCostService.getCurrentCostPrice(goodsCode, warehouse);
inventoryCostService.purchaseInbound(goodsCode, goodsName, warehouse, batchNo,
    qty, costPrice, inboundNo, productionDate);
```

原理：`purchaseInbound` 按 `(oldAmount + qty×costPrice) / (oldQty + qty)` 重算均价。因为 `costPrice` 就是当前均价，`oldAmount = oldQty × costPrice`，所以新均价 = costPrice，**不变**。库存数量和金额增加，流水 direction=IN。

## 6. 退款处理（无司机场景）

没有司机现场退款，退款全部走 AR 系统：

```
退货单审核 → 写负向 fin_ar（ar_amount = -含税金额）
                    ↓
    客户有正向 AR？──是──→ 负向 AR 自动抵扣正向 AR 余额
                    ↓ 否
    负向 AR 形成客户预收/退款挂账
                    ↓
    通过 fin_payment_bill（付款单）退还客户现金
```

这与采购退货的负向 fin_ap 对称——采购退货冲减供应商应付，销售退货冲减客户应收。

## 8. 与全链路方案的衔接

本方案是 `docs/销售退货全链路设计方案.md` 的第一阶段实现。后续加司机环节时：

1. 在阶段 1（退货申请）和阶段 2（退货入库）之间插入**司机回收**阶段
2. 新增 `return_collection_task` 表和 TMS PDA 端点
3. 入账方式改为可配置（司机签收入账 / 仓库入库入账）
4. 差异处理用正常单据补差（销售单/采购退货单），不调账

本轮的三表结构不需要修改——司机回收阶段是独立的中间环节，不影响申请表和入库表的结构。

## 9. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 库存更新时机 | 退货入库审核时 | 货物实物到仓库才确认库存增加 |
| 成本计价方式 | 当前移动加权平均成本 | 复用 purchaseInbound，均价不变 |
| 退款路径 | 负向 fin_ar 走 AR 系统 | 无司机现场退款，通过 AR 抵扣或付款单退还 |
| 入库数量 | 可小于申请数量 | 仓库按实际验收数量入库 |
| 质检分流 | WMS 内部处理，不影响入账 | 残次品入库位是 WMS 物理管理，账上都是库存 |
| 差异处理 | 不调账，用正常单据补差 | 与全链路方案一致 |
