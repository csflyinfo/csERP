## 一、本次已完成

### 1. 账期管理规范落地（V9 迁移）

依据 [账期管理-产品说明.md](../账期管理-产品说明.md) V1.4。

- **V9 迁移**：`base_customer` / `base_supplier` 新增 `settlement_type / term_type / term_days / cutoff_day / payment_mode / term_months / payment_day`
- **[SettlementPanel.vue](../frontend/src/components/SettlementPanel.vue)**：结算方式（预付 / 货到付款 / 账期）+ 账期类型（固定 / 周结 / 半月结 / 月结）+ 月结付款模式 A/B 联动
- 单选控件 16px 尺寸；月结默认 paymentMode = A
- 通过 `role` prop 区分客户（销售出库/客户签收日）/ 供应商（采购入库/入库签收日）文案
- 后端 `settlementSummary()` 生成列表展示派生列 `settlementText`

### 2. 供应商多账户 & 交货方式（V6 迁移）

- **`base_supplier`** 新增 `delivery_method`（默认「送货上门」）、`default_logistics_company`
- **`base_supplier_bank_account`**（新建）：一供应商多收款账户，字段户名/开户银行/账号/支行/默认/备注/排序
- 供应商抽屉内嵌网格：行内新增/删除、单选默认账户；保存时**全量替换**避免脏数据
- V6 起前端表单**去除**发票抬头/税号字段（列保留兼容旧数据）
- 采购员改为下拉，`POST /base/employee/buyers`（`is_buyer=true & status=NORMAL`）

### 3. 数据字典模块（V7 + V8 迁移）

- **`sys_dictionary_type`**（V7 新建）：字典类型主表，全部由系统预置，界面禁编辑/删除
- **`sys_dictionary`**（V6 已建，V7/V8 补 seed）：字典值表；系统预置值编码按顺序号从 0 起（V8）
- **[DictionaryController.java](../backend/src/main/java/com/erp/base/DictionaryController.java)**：type/value 各 CRUD + 停用 + 导入 xlsx
- **[DictionaryPage.vue](../frontend/src/views/DictionaryPage.vue)**：左右布局；左侧字典类型只读；右侧字典值支持新建/编辑/停用/删除/导入/导出

### 4. 字典公共取值机制

**后端**：`GET /base/dictionary?type=xxx` → `[{ code, name, sortOrder }]`，只返回 `status=NORMAL`。

**前端**：[utils/dictionary.js](../frontend/src/utils/dictionary.js)
- `getDict(type, { force })`: 5 分钟内存缓存
- `invalidateDict(type?)`: 字典维护后主动失效
- H2 大写返回兼容（CODE / NAME）

### 5. 客户资料增强

- **客户表**（V10/V11）：新增 `shipping_address`、`longitude DECIMAL(11,7)`、`latitude DECIMAL(10,7)`；复用 V4 加的 `price_group_code`
- **customer/page**：一次查全表 `base_price_group` 建 code→name 索引，附加 `priceGroupName` 派生字段
- **客户抽屉**：
  - 渠道类型下拉 → 字典 `customer_channel`（V10 预置 5 项）
  - 片区下拉 → 片区管理**末级片区**
  - 线路下拉 → 线路管理正常记录
  - 业务员下拉 → `POST /base/employee/salesmen`（`is_salesman=true`）
  - **价格组**下拉 → 仅 `enabled=true` 价格组；新建默认「（空 - 取商品默认售价）」
  - **经度 / 纬度**数字字段
  - **收货地址**多行文本（独占一行）
  - **状态**下拉（仅编辑显示）
- **客户列表**新增列：价格组（显示 `priceGroupName`）

### 6. 后端增强

- [BaseController.java](../backend/src/main/java/com/erp/base/BaseController.java) `employeeRoleList(roleColumn)` 抽公用方法，衍生 `/employee/buyers` 与 `/employee/salesmen`
- `fillCustomerEntity` 支持保存 `longitude / latitude / priceGroupCode`；经纬度空值/非数字全部转 null

## 二、待办

### 🟡 MySQL 联调（阶段一/二/三遗留）

Flyway V1~V11 全部就位，DDL / seed 都是 MySQL 兼容语法。**未在真实 MySQL 8 上跑过完整回归**。

### 🟡 客户/供应商 - 收货地址子表

V1.0 用单字段 `shipping_address` + 经纬度。V2.0 拆到 `base_customer_address` 子表支持多地址（PRD §3.10 已有骨架）。

### 🟡 未启用价格组的引用校验

客户保存时若 `priceGroupCode` 引用了 `enabled=false` 的价格组应拦截（当前只前端下拉过滤，后端未校验）。

### 🟡 停用字典值的历史数据展示

停用后引用位置的下拉自动过滤；但已保存的历史数据依旧展示原值。需在管理界面对"已被使用"的字典值给出提示（当前未做统计）。
