# 自营仓配一体化 + COD 货到付款 — 系统详细设计方案

> 版本：V1.0 | 日期：2026-07-21 | 作者：产品/架构
> 适用范围：两法人主体（平台 / 自营&仓配联合体）下的 B2B 商城 + COD 货到付款场景

**与三主体方案的差异**：自营主体与仓配主体为同一法人实体，拥有统一的 ERP+WMS 系统。该实体既经营自营品，也承接入驻商的仓配服务。新增 COD（货到付款）模式，由 WMS 配送司机现场收款。

## 1. 文档目的与前提

### 1.1 核心场景

> **自营经销商**同时自建仓库并运营物流配送团队。它既在 B2B 商城售卖自有商品（自营品），也向外部入驻商开放仓储和配送服务（代发 FBP）。部分订单支持货到付款，由配送司机在交付时向买家收款。

### 1.2 两主体定义

| 主体 | 法人 | 拥有系统 | 核心业务 |
|------|------|---------|----------|
| **平台主体** | 商城运营公司 | **B2B 商城** + 结算中心 + 来源申报 | 商品展示、交易撮合、在线收款、多方法结算、来源申报 |
| **自营&仓配联合体** | 经销商（同一公司） | **ERP + WMS + PDA** | 自营品进销存+成本核算、多货主仓储管理、统仓订单履约（自营+FBP）、配送管理、COD 收款 |

> **关键差异**：自营与仓配是**同一法人**，ERP 和 WMS 归属同一实体。它和仓配的关系不是"甲方向乙方采购服务"，而是"自有团队运营自有仓库"。因此内部不需要结算仓配服务费——仓配成本直接体现为人工/场地/车辆等运营支出。

### 1.3 入驻商类型

| 入驻商类型 | 货在哪里 | 谁发货 | 谁收款 | 简称 |
|-----------|---------|--------|--------|------|
| 统配入驻商（代发） | 经销商仓库 | 经销商 WMS | 平台（在线支付）或司机（COD） | FBP |
| 自配入驻商 | 入驻商自有仓 | 入驻商自己 | 平台在线收 + 平台结算 | SOP |

自营品天然就是"统仓统配"——货在经销商自己仓库，由经销商自己发货配送。

### 1.4 核心设计原则

| # | 原则 | 说明 |
|---|------|------|
| **P1** | **平台统一收款（在线部分）** | 在线支付（微信/支付宝）统一进入平台主体商户号 |
| **P2** | **COD 由配送方代收** | 司机现场收现金/扫码 → 日终上缴联合体财务 → T+1 缴至平台 |
| **P3** | **谁收款谁结算** | 平台对在线收款部分统一结算；COD 部分平台须收到回款后再启动结算 |
| **P4** | **ERP+WMS 内联，对外接口不变** | 同属一个法人，ERP↔WMS 可走内部调用；但 B2B 对外接口保持 REST API 契约 |
| **P5** | **谁卖货谁记账** | 自营品的进销存和收入记入联合体 ERP；入驻商在自己系统独立记账 |
| **P6** | **来源溯源在 B2B 闭环** | 下单时 B2B 标记每行交易的实际货主；结算和税务申报以此为准 |

### 1.5 阅读本文前请先理解这个场景

> 买家小王在 B2B 商城下单：
> - 2 箱可乐（自营品，由经销商仓配，选择**货到付款**）
> - 3 箱矿泉水（入驻商老张的货，放在经销商仓库，FBP 代发，**在线支付**）
> - 5 箱方便面（入驻商老李的货，老李自己发货，SOP 自配，**在线支付**）
>
> 小王在线支付了矿泉水和方便面共 ¥350，可乐 ¥100 等货到付给司机。
>
> — 司机收了 ¥100 现金以后，这笔钱怎么回流到平台？平台怎么知道"已收款"可以结算了？
> — 可乐进了联合体 ERP 进销存，矿泉水不进——同一仓库、同一司机配送，ERP 怎么区分记账？
> — 老李的方便面不入任何下游系统，平台怎么通知他发货？
>
> 本方案回答的就是这一系列问题。

```
         │  • COD司机现场收款       │

                    │

                    ▼
            ┌──────────────┐
            │  FBP入驻商    │
            │ (老张的货在此) │
            └──────────────┘
```

### 2.2 两主体之间的合同体系

| 合同 | 甲方 | 乙方 | 核心条款 |
|------|------|------|----------|
| **平台入驻协议（自营）** | 联合体 | 平台主体 | 自营品上架、平台代收在线货款、按周期结算（自营→平台开票） |
| **平台入驻协议（FBP）** | FBP入驻商 | 平台主体 | FBP品上架、平台代收在线货款、COD部分由联合体代收后缴至平台 |
| **平台入驻协议（SOP）** | SOP入驻商 | 平台主体 | SOP品上架、平台代收货款、抽佣后结算、入驻商自行发货 |
| **仓储服务协议** | 联合体 | FBP入驻商 | 入库标准、仓租费/操作费/配送费费率、损耗责任、COD代收义务 |
| **平台-联合体服务协议** | 平台主体 | 联合体 | 履约状态回传、COD资金缴回时效、平台佣金费率 |

> **和三主体方案的关键区别**：不再有"平台主体→仓配主体"的独立服务协议。仓配是联合体自己的运营部门，服务费不再跨法人结算。

## 3. 支付模式定义

### 3.1 三种支付模式

| 支付模式 | 资金路径 | 适用履约方式 | 收款方 |
|----------|---------|-------------|--------|
| **在线支付** | 买家 → 微信/支付宝 → 平台商户号 | 自营/SOP/FBP 均可 | 平台主体 |
| **货到付款 (COD)** | 买家 → 配送司机 → 联合体财务 → 平台商户号 | 仅自营+FBP（统仓配送） | 司机代收→缴至平台 |
| **预付** | 买家 → 微信/支付宝 → 平台商户号（下单即付） | 同上 | 平台主体 |

> **COD 不可用于 SOP 自配**：SOP 入驻商自行配送，平台无法控制物流环节的收款，COD 的资金链路不可控。

### 3.2 COD 资金回流时间轴

```
D日 14:00  司机配送 → 买家签收 → 现金/扫码收款 ¥100
D日 18:00  司机回仓 → 交款至联合体财务 → WMS 标记「已收款」
D日 18:30  联合体财务清点 → 系统录入当日 COD 收款汇总
D+1 10:00 联合体财务 → 银行转账 ¥100 → 平台主体对公账户
D+1 10:30 平台主体确认到账 → B2B 标记对应订单「COD已回款」
          → 该订单进入可结算状态
```

### 3.3 COD 的核心约束

| 约束 | 说明 |
|------|------|
| **仅统仓配送可用** | 自营品 + FBP 品，由联合体自己的司机配送 |
| **司机收款上限** | 单司机单日 COD 累计 ≤ ¥50,000（风控，可配置） |
| **缴回时效** | 司机日终必须缴回；联合体财务 T+1 必须转账至平台 |
| **超时未缴回** | 超 48 小时未到账 → 触发风控告警 → 暂停该司机配送权限 |
| **资金归属** | COD 资金虽然由联合体司机代收，但法律上属于平台代收的买家货款 |
| **结算触发条件** | COD 订单必须在平台确认到账后才能进入结算池 |

### 4.2 ERP 和 WMS 的内联关系

自营与仓配是同一法人 → ERP 和 WMS 可以共享数据库，也可以分开数据库但走内网直连。对 B2B 而言，联合体是一个"接口端点"——订单下发、状态回传、COD 信息同步都通过统一的 API 网关。

```
B2B 视角：联合体 = 一个对端系统
   │
   │ POST /api/v1/order/sync          ← 统仓订单下发（自营+FBP混合）
   │ POST /api/v1/order/status         ← 联合体回传履约状态
   │ POST /api/v1/cod/reconciliation   ← COD收款日结对账
   │
   ▼
联合体内部：
   API网关 → 路由判断
     ├── SELF行 → ERP (成本核算+记账)
     │               └── 内部调用 WMS (下发发货单)
     └── FBP行  → WMS (直接履约)
                     └── 回传费用至 B2B
```

## 5. 基础资料管理

### 5.1 商品主数据：三层管理模型

| 层级 | 存储位置 | 维护方 | 包含字段 |
|------|---------|--------|----------|
| **展示层** | B2B | 各商户自行维护 | 标题、主图、详情、售价、促销价 |
| **履约层** | WMS | 联合体运营 | SKU、条码、规格、重量、体积、存储条件 |
| **财务层** | ERP（仅自营品） | 联合体财务 | 成本价、供应商、采购单位、税率 |

FBP 品不入 ERP 财务层——成本是入驻商的，联合体 ERP 不需要也不应该记录。

### 5.2 入驻商入驻流程（重点在统配FBP商户）

```
步骤1: 入驻商在B2B商户中心提交申请
  ├── 上传营业执照、法人身份证、银行开户许可证
  └── B2B OCR校验 + 人工审核

步骤2: 选择合作模式
  ├── SOP（自行仓配） → 入驻完成，开始上架商品
  └── FBP（委托联合体仓配） → 进入步骤3

步骤3: 签订仓储服务协议（联合体 ↔ 入驻商）
  ├── 约定费率：仓储费/配送费/操作费/入库费
  ├── 约定结算周期：周结/半月结/月结
  ├── 约定COD规则：是否允许COD、COD额度上限
  └── 系统录入费率至 WMS 费用测算引擎

步骤4: 入驻商送货至联合体仓库
  ├── WMS 创建入库单(owner_id=入驻商ID)
  ├── 质检 → 上架 → 入库确认
  └── WMS 推送入库结果 + 入库费 → B2B

步骤5: 入驻商在B2B商户中心维护FBP品
  ├── 标品关联：B2B的SKU ↔ WMS的SKU（与联合体确认条码一致）
  └── 售价与库存：B2B读取WMS的可售库存
```

### 5.3 合同费率配置（B2B 合同管理模块）

| 费率项 | 适用对象 | 配置位置 | 示例 |
|--------|---------|----------|------|
| 平台佣金率 | 所有商户（自营/FBP/SOP） | B2B 合同管理 | 自营1%、FBP 2%、SOP 3% |
| 仓租单价 | FBP入驻商 | B2B 合同管理（同步至WMS） | ¥0.1/件/天 |
| 配送单价 | FBP入驻商 + 自营品 | B2B 合同管理（同步至WMS） | ¥5/件 或 ¥0.5/kg |
| 操作费单价 | FBP入驻商 | B2B 合同管理（同步至WMS） | ¥2/件（含拣+复+打包） |
| COD 手续费 | 开通COD的商户 | B2B 合同管理 | COD金额的1% |

> **自营品不需要仓配费费率**——仓配是联合体自己的运营部门，成本直接在ERP中间接费用科目归集，不需要按单计算"自己收自己的仓储费"。

## 6. 商品与库存管理

### 6.1 三套库存视图

| 库存视图 | 系统 | 粒度 | 数据来源 | 说明 |
|----------|------|------|----------|------|
| **实物库存** | WMS | SKU + owner_id + 库位 + 批次 | 入库扫描 → 出库扫描 | 物理库存，权威来源 |
| **可售库存** | B2B | SKU + owner_id | 自营品从ERP同步；FBP品从WMS同步 | 展示给买家的可购买数量 |
| **财务库存** | ERP | SKU（仅自营品） | 采购入库 → 销售出库 | 进销存报表、成本核算依据 |

### 6.2 自营品库存同步链路

```
WMS 入库(自营品 owner_id=SELF)
  ├── 增加实物库存
  └── 内部触发 ERP 采购入库单
       ├── ERP 增加财务库存
       │   └── 移动加权平均重算成本
       └── ERP → B2B : 同步可售库存
            └── { sku: "P001", available: 500, owner_id: "SELF" }
```

### 6.3 FBP 品库存同步链路

```
WMS 入库(FBP品 owner_id=M001)
  ├── 增加实物库存
  ├── 记录入库费（仓储服务费→推送B2B）
  └── WMS → B2B : 同步可售库存
       └── { sku: "P002", available: 300, owner_id: "M001" }
```

## 7. 三种履约模式 + COD 收款完整流程

### 7.1 总览：履约模式 × 支付模式的 6 种组合

| | 在线支付 | COD 货到付款 |
|------|---------|-------------|
| **自营统配** | ① 标准自营 | ② COD自营 |
| **FBP统配** | ③ 标准FBP | ④ COD-FBP |
| **SOP自配** | ⑤ 标准SOP | ❌ 不支持 |

> COD 不可用于 SOP——物流由入驻商控制，平台无法保证资金回收。

---

### 7.2 模式①②：自营统配（在线支付 / COD）

```
阶段1: 下单与支付

阶段6: (仅COD) 资金缴回平台
```

### 7.4 模式⑤：SOP 自配（仅在线支付）

SOP 流程与三主体方案一致。COD 不适用于 SOP——物流不在联合体控制范围内。

```
阶段1: 下单与在线支付 → 钱入平台商户号
阶段2: B2B 通知入驻商（站内信 / Webhook）
阶段3: 入驻商自行发货，回传物流单号
阶段4: 入驻商给买家开票
阶段5: B2B 结算（货款 - 平台佣金 → 打款给入驻商）
```

**SOP 订单完全不进入联合体的 ERP 和 WMS。**

## 8. 订单路由与拆分规则

### 8.1 两维度路由矩阵

订单路由需要同时考虑**履约方式**和**支付方式**：

| 履约方式 \ 支付方式 | 在线支付 | COD |
|-----|---------|-----|
| **自营 (SELF)** | B2B → 联合体API → ERP → WMS | B2B → 联合体API → ERP → WMS(COD) |
| **FBP 代发** | B2B → 联合体API → WMS | B2B → 联合体API → WMS(COD) |
| **SOP 自配** | 仅B2B | ❌ 不支持 |

### 8.2 COD 订单的特别路由标记

COD 订单在下发联合体时，B2B 必须在请求中明确标记：

```json
{
  "order_id": "O001",
  "payment_method": "COD",
  "cod_amount": 100.00,
  "lines": [
    { "sku": "P001", "qty": 2, "owner_id": "SELF", "source_entity": "自营联合体" },
    { "sku": "P002", "qty": 3, "owner_id": "M001", "source_entity": "入驻商M001" }
  ]
}
```

联合体 API 网关据此：
- `payment_method=COD` → 所有行都生成 COD 收款任务
- `owner_id=SELF` → 路由到 ERP → 成本核算
- `owner_id=M001` → 路由到 WMS → 仅履约

## 9. 费用管理

### 9.1 费用全景（两主体简化版）

联合体内部（ERP↔WMS）不再做跨法人的仓配费结算。费用只发生在两个法人之间：

```
                      ┌──────────┐
                      │  买家    │
                      └────┬─────┘
                           │ 支付商品价款
                           ▼
                ┌─────────────────────┐
                │   平台主体 (B2B)     │
                │  收款后统一结算      │
                └──┬──────┬──────┬───┘
                   │      │      │
        平台佣金    │      │      │  平台佣金
                   ▼      ▼      ▼
           ┌──────────┐ ┌──────────┐ ┌──────────┐
           │自营&仓配  │ │FBP入驻商  │ │SOP入驻商  │
           │联合体     │ │(被扣佣金  │ │(被扣佣金) │
           │(被扣佣金) │ │ +仓配费)  │ │           │
           └──────────┘ └────┬─────┘ └──────────┘
                             │
                  仓配费开票  │（联合体→入驻商）
                             ▼
                    ┌──────────────┐
                    │ 自营&仓配联合体│
                    │ (仓配服务提供方│
                    │  向入驻商收费) │
                    └──────────────┘
```

### 9.2 费用类型对比（三主体 vs 两主体）

| 费用类型 | 三主体方案 | 两主体方案 |
|----------|-----------|-----------|
| 自营品仓配费 | 自营主体付给仓配主体（跨法人） | **不存在**——内部运营成本 |
| FBP品仓配费 | FBP入驻商付给仓配主体（跨法人） | FBP入驻商付给联合体（跨法人，联合体开票） |
| 平台佣金 | 平台收取 | 不变 |
| COD手续费 | 无 | 新增（可选，覆盖资金占用和操作成本） |

### 9.3 FBP 品费用计算（WMS 出库时测算）

和三主体方案一致，费用测算在 WMS 侧完成：

```
仓配费 = 仓储费 + 配送费 + 操作费 + 增值服务费

仓储费 = Σ(每件 × 仓租单价/天 × 实际存储天数)
配送费 = 按合同费率（按件/按重量/按距离，取高者）
操作费 = 拣货费 + 复核费 + 打包费
```

区别在于：费用开票方是联合体（而非独立的仓配主体），费用由 B2B 在结算入驻商时**代扣代转**——B2B 扣下仓配费金额 → 打款给入驻商净额 → 同时通知联合体"入驻商M001的仓配费已扣收，请开票"。

### 9.4 费用数据流

```
WMS 出库(FBP品)
  │
  ├──→ 回传 B2B: 出库结果 + 费用明细
  │    { fee: { storage: 4.5, delivery: 15, operation: 6 } }
  │
  ▼
B2B 结算中心
  │
  ├── 按 merchant_id 汇总本周期所有费用
  │    M001: 仓储费¥45 + 配送费¥150 + 操作费¥60 = ¥255
  │
  ├── 生成 FBP 入驻商结算单:
  │    货款¥1,000 - 佣金¥20 - 仓配费¥255 = 净结算¥725
  │
  ├── 打款¥725给M001 + 通知联合体"M001仓配费¥255已扣收"
  │
  └── 联合体开"仓储服务费"发票给M001(¥255)
```

## 10. 结算管理（含 COD 对账）

### 10.1 结算全景

```
本周期 COD回款确认
        +
本周期 在线支付收入（已进入平台商户号）
        │
        ▼
   ┌─────────────────┐
   │  B2B 结算中心    │
   │  按结算周期汇总   │
   │  COD未回款=不纳入 │
   └────────┬────────┘
            │
   ┌────────┼────────┬────────────┐
   ▼        ▼        ▼            ▼
┌──────┐┌──────┐┌──────┐    ┌──────────┐
│联合体 ││FBP   ││SOP   │    │ 仓配费    │
│结算单 ││结算单 ││结算单 │    │ 扣收通知   │
│(自营) ││      ││      │    │ (给联合体) │
└──┬───┘└──┬───┘└──┬───┘    └────┬─────┘
   │       │       │             │
   ▼       ▼       ▼             ▼
┌──────────────────────────────────────────┐
│              打款执行                      │
│                                           │
│ 联合体     ← 自营品货款 - 平台佣金          │
│ FBP入驻商  ← FBP品货款 - 佣金 - 仓配费     │
│ SOP入驻商  ← SOP品货款 - 佣金             │
│                                           │
│ 仓配费已在入驻商打款中扣除，无需单独打款    │
└──────────────────────────────────────────┘
```

### 10.2 各模式结算公式

#### 联合体（自营品）结算

```
自营净结算 = Σ自营品销售金额（在线+COD已回款）
            - 平台佣金
            - COD 手续费（如有）

说明: 联合体用自己的仓库和自己的司机履约，不产生额外仓配服务费。
```

#### FBP 入驻商结算

```
FBP净结算 = Σ该入驻商FBP品销售金额（在线+COD已回款）
            - 平台佣金
            - 仓配费（仓储+配送+操作费+增值服务费）
            - COD 手续费（如有）

说明: COD未回款的订单不纳入本期结算，滚入下期。
      仓配费由B2B代扣后通知联合体开票给入驻商。
```

#### SOP 入驻商结算

```
SOP净结算 = Σ该入驻商SOP品销售金额（仅在线支付）
            - 平台佣金
```

### 10.3 COD 对账流程

这是两主体方案**最重要的新增流程**。

```
D日 18:30  联合体提交日结报告 → B2B
  { date: "2026-07-21",
    orders: [{id:O001, amt:100}, {id:O002, amt:50}],
    total: 150,
    collected_by: "司机张三" }

D+1 10:00 联合体转账 ¥150 → 平台对公账户

D+1 10:30 平台财务确认银行到账 → B2B系统标记"已回款"
  → B2B 自动匹配：银行到账金额 vs 日结报告金额
  → 匹配成功 → 对应订单进入可结算池
  → 不匹配（差额 > ¥0.01） → 触发对账差异工单

D+1 14:00 对账差异处理
  ├── 少收（司机未全额收） → 联合体补足 或 订单改部分收款
  ├── 多收（司机多收）     → 联合体退款给买家 或 计入买家余额
  └── 未收（买家拒收）     → 订单标记COD失败 → 退货处理
```

### 10.4 COD 结算的特殊规则

| 规则 | 说明 |
|------|------|
| **未回款不结算** | COD订单必须在平台确认回款后，该笔销售金额才进入对应商户的结算池 |
| **跨期滚动** | 本周期截止日仍未回款的COD订单，滚入下一结算周期 |
| **回款超时告警** | COD订单出库超过 5 个自然日仍未确认回款 → B2B 告警 |
| **司机对账** | 每司机每日 COD 应收（系统） vs 实收（缴款）必须匹配 |
| **联合体与平台对账** | 每月末：联合体缴款总额 vs B2B标记回款总额，差额归零 |

### 10.5 结算周期

| 结算对象 | 可选周期 | 默认 |
|----------|---------|------|
| 联合体（自营品） | 周结 / 半月结 / 月结 | 月结 |
| FBP入驻商 | 周结 / 半月结 / 月结 | 月结 |
| SOP入驻商 | 周结 / 半月结 / 月结 | 月结 |

## 11. ERP 与 WMS 一体化设计

### 11.1 为什么需要"一体化"

自营和仓配是同一法人，ERP 和 WMS 之间不再有"跨系统对账"的需求——它们是同一公司内部的两个业务模块。这带来了整合红利：

| 三主体方案的痛点 | 两主体一体化解决 |
|-----------------|-----------------|
| ERP↔WMS 之间需要 REST API 通信 | 可走内部 Service 调用或共享数据库 |
| ERP 和 WMS 库存可能不一致 | 实时同步，同一数据库内事务保证 |
| 自营品出库后需要在两个系统确认 | 一次确认即可 |
| COD 收款需要两个系统分别记录 | 统一在 WMS PDA 收款，ERP 自动同步 |

### 11.2 推荐架构：统一数据库 + 模块隔离

```
联合体内部数据库 (MySQL Schema)

┌─────────────────────────────────────┐
│  erp_ 前缀表（自营进销存）            │
│  ├── erp_product (自营品主数据)      │
│  ├── erp_inventory (财务库存)       │
│  ├── erp_sales_order (销售订单)      │
│  ├── erp_cost_log (成本计算日志)     │
│  └── erp_voucher (记账凭证)          │
├─────────────────────────────────────┤
│  wms_ 前缀表（仓储管理）              │
│  ├── wms_inventory (实物库存)        │
│  ├── wms_delivery (发货单)           │
│  ├── wms_cod_log (COD收款记录)       │
│  ├── wms_fee_calc (费用测算记录)     │
│  └── wms_owner (货主管理)            │
├─────────────────────────────────────┤
│  shared_ 前缀表（共享基础资料）        │
│  ├── shared_sku (统一SKU)            │
│  ├── shared_warehouse (仓库/库位)     │
│  └── shared_driver (司机)            │
└─────────────────────────────────────┘
```

**关键约束**：
- `erp_` 表仅操作自营品（`owner_id = SELF`）的数据
- `wms_` 表操作所有 owner_id 的数据
- ERP 模块**不能**读写 FBP 品的财务数据（不入成本、不记收入）
- WMS 出库时触发一个事务：同时更新 `wms_inventory` 和 `erp_inventory`（仅自营品）

### 11.3 联合体内部订单处理逻辑

```
联合体 API 网关接收 B2B 订单
        │
        ├── 拆单: 按 owner_id 分组
        │
        ├── SELF 行:
        │   ├── ERP 创建销售订单
        │   ├── ERP 锁定库存 (erp_inventory)
        │   ├── ERP 内部调用 WMS → 生成发货单
        │   ├── WMS 出库确认 → 事务:
        │   │   ├── wms_inventory 扣减
        │   │   ├── erp_inventory 扣减 (仅SELF)
        │   │   └── erp_cost_log 记录成本快照 (仅SELF)
        │   └── ERP 记账: COGS + 收入
        │
        └── FBP 行:
            ├── WMS 创建发货单 (不进ERP)
            ├── WMS 锁定库存 (wms_inventory, owner_id=M001)
            ├── WMS 出库确认:
            │   ├── wms_inventory 扣减
            │   ├── wms_fee_calc 测算仓配费
            │   └── wms_cod_log 记录COD (如有)
            └── WMS 回传 B2B: 出库完成 + 费用 + COD
```

### 11.4 COD 在联合体内部的处理

```
WMS PDA (司机端)
  │
  ├── 配送员到达 → 扫描包裹确认交付
  ├── COD 订单 → PDA 弹出收款界面
  │   ├── 应收金额: ¥100
  │   ├── 收款方式: [现金] [微信扫码] [支付宝扫码]
  │   ├── 司机选择收款方式 → 确认收款
  │   └── 系统记录: wms_cod_log
  │       { order_id, cod_amount, collected_amount,
  │         payment_method, driver_id, collected_at }
  │
  ├── 日终: 系统自动汇总
  │   ├── 司机张三: COD应收¥500, 实收¥500, 差异¥0
  │   ├── 司机李四: COD应收¥300, 实收¥280, 差异¥20 ⚠️
  │   └── 生成日结报告 → 推送 B2B
  │
  └── ERP 自动同步:
      ├── COD收款记录 → ERP COD日记账
      ├── 自营品 COD: 应收账款-COD 增加一笔待确认
      └── D+1 B2B确认回款 → ERP 自动核销
```

## 12. SOP 自配不入下游系统处理

SOP 模式与三主体方案完全一致。再次明确：

**SOP 订单仅在 B2B 系统内流转，不推送给联合体（ERP/WMS）**。

| 环节 | 处理方式 |
|------|----------|
| 下单 | B2B 创建订单，校验入驻商自行维护的可售库存 |
| 支付 | 仅在线支付（不开放 COD） |
| 通知 | B2B → 入驻商：站内信/Webhook/短信 |
| 发货 | 入驻商自主执行，不涉及 WMS |
| 物流 | 入驻商通过商户中心或 API 回传物流单号 |
| 开票 | 入驻商直接开票给买家 |
| 结算 | B2B 统一结算：货款 - 平台佣金 → 打款给入驻商 |
| 售后 | B2B 提供退换货流程，入驻商自行处理 |

## 13. COD 货到付款专题

### 13.1 COD 订单的全生命期状态

```
下单(COD标记) → 已下发联合体 → 拣货中 → 已出库(待配送)
  → 配送中 → 已签收+已收款 → 司机已缴款 → 联合体已转账 → 平台已回款 → 可结算
                    ├── 已签收+未收款(差异) → 异常处理
                    └── 拒收 → 退货回仓
```

### 13.2 COD 风控规则

| 规则 | 阈值 | 动作 |
|------|------|------|
| 买家单日COD上限 | ¥2,000（可配置） | 超限则本次下单不允许选COD |
| 买家COD欠款 | 有未支付的COD历史 | 暂停该买家COD权限 |
| 司机单日COD上限 | ¥50,000 | 超限则系统不分配该司机新的COD订单 |
| COD未缴回超时 | > 48小时 | 风控告警 + 暂停司机配送 |
| COD差异（司机少交） | > ¥10 | 生成差异工单 → 财务介入 |

### 13.3 COD 与在线支付的混合订单

一个订单可以同时包含在线支付行和 COD 行：

```
Order#001:
  ├── SKU-A(自营) × 2  → 在线支付 ¥70
  └── SKU-B(FBP)  × 3  → COD ¥100

B2B 下单时:
  online_paid: ¥70（立即进入平台商户号）
  cod_amount: ¥100（配送时司机现场收取）

结算时:
  SKU-A 的 ¥70 → 立即进入自营结算池
  SKU-B 的 ¥100 → 等COD回款确认后进入M001结算池
```

> **建议**：前端购物车在混合支付时拆为两笔订单（在线订单 + COD订单），降低系统复杂度和买家认知负担。

### 13.4 COD 退款场景

| 场景 | COD 处理 |
|------|----------|
| 出库前取消 | 未收款 → 直接取消 |
| 配送中取消 | 通知司机停止配送 |
| 已收款后退货 | 联合体财务从已收 COD 中退款给买家（线下），系统记录 COD 退款 |
| 部分拒收 | 司机只收接收部分的金额，WMS 记录差异 |

## 14. 税务来源申报设计

### 14.1 来源溯源逻辑（与三主体方案一致）

税务系统抓取微信/支付宝全量交易流水 → **等待平台申报来源主体**：

| 来源标记 | 记税归属 | 发票流 |
|----------|---------|--------|
| source_entity=自营联合体 | 平台记税（自营品） | 联合体 → 开票 → 买家 |
| source_entity=入驻商M001 | M001记税（FBP品） | 入驻商M001 → 开票 → 买家 |
| source_entity=入驻商M002 | M002记税（SOP品） | 入驻商M002 → 开票 → 买家 |
| source_entity=未匹配 | **强制记入平台**（平台损失） | — |

### 14.2 COD 订单的来源申报

COD 订单的特别之处：微信/支付宝流水里**没有**COD交易——资金走了线下（现金/司机扫码）。税务系统也不会自动抓取到 COD 交易。

**COD 来源申报由平台主动上报**：

```
月末: B2B 汇总本周期 COD 已回款订单
  → 按 source_entity 分类
  → 生成 COD 来源申报补充表
  → 主动提交税务（不同于在线支付的自动抓取）
```

COD 的税务风险**高于**在线支付——因为资金不走微信/支付宝，税务系统不能自动抓取，完全依赖平台的主动申报。

## 18. 关键设计决策

| # | 决策项 | 结论 | 理由 |
|---|--------|------|------|
| 1 | 联合体 ERP↔WMS 集成方式 | 共享数据库，模块隔离 | 同一法人无需跨系统对账，减少数据不一致风险 |
| 2 | FBP 品是否进 ERP | **不进** | 不是自营品，不入进销存和成本核算 |
| 3 | B2B 对外接口 | 联合体作为一个接口端点 | B2B 不关心联合体内部 ERP/WMS 如何分工 |
| 4 | COD 资金归属 | 法律上属于平台代收的买家货款 | 司机是"平台委托代收人"而非"联合体自有资金" |
| 5 | COD 回款时效 | T+1 必须转账 | 超时则平台面临资金被挪用的合规风险 |
| 6 | COD 未回款不结算 | COD订单回款确认后才进入结算池 | 平台不垫资 |
| 7 | SOP 不支持 COD | COD仅统仓配送可用 | 物流不可控则资金链路不可控 |
| 8 | 仓配费结算方式 | B2B代扣代转，联合体向入驻商开票 | 平台不做"仓配服务转售"，保持服务合同甲方为入驻商 |
| 9 | 自营品不产生仓配费 | 内部运营成本 | 同一法人不自己收自己的服务费 |
| 10 | 混合订单建议拆分 | 前端在线+COD拆为两笔订单 | 降低系统复杂度 |

## 19. 风险与缓解

| # | 风险 | 等级 | 缓解措施 |
|---|------|------|----------|
| 1 | COD 司机携款跑路 | 🔴🔴 极高 | 单司机日限额、GPS轨迹追踪、保证金制度、48h未缴报警 |
| 2 | COD 假币/扫码欺诈 | 🔴 高 | PDA扫码走平台商户号收款（资金不过司机个人账户）、现金收款配验钞设备 |
| 3 | COD 资金挪用 | 🔴 高 | T+1强约束、财务独立复核、超时自动锁司机权限 |
| 4 | COD 未申报被税务稽查 | 🔴 高 | COD补充申报表、主动上报税务、全量保留COD交易记录 |
| 5 | COD 回款与订单匹配错误 | 🟡 中 | 银行到账自动匹配日结报告、差异自动工单 |
| 6 | ERP 误将 FBP 品入成本 | 🟡 中 | owner_id 硬约束：ERP模块仅处理 SELF，代码层断言 |
| 7 | 联合体与平台对账不一致 | 🟡 中 | 日结对账+月末对账，差异分级处理 |
| 8 | 司机收错金额 | 🟢 低 | PDA 显示应收金额、多收/少收均触发差异告警 |
