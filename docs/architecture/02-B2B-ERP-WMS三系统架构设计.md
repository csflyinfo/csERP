## 1. 文档目的

本文档定义 B2B 商城、ERP、WMS 三个系统的职责边界、数据归属、接口契约和部署架构。

## 2. 业务场景

### 2.1 角色定义

| 角色 | 说明 | 使用的系统 |
|------|------|-----------|
| 经销商（平台运营方） | 既是 B2B 平台的运营者，也是自营卖家，拥有实体仓库 | B2B（管理端）、ERP、WMS |
| 入驻商（第三方卖家） | 在 B2B 商城开店，商品可由经销商代发或自配 | B2B（商户中心） |
| 买家（下游客户） | 在 B2B 商城浏览、下单、支付 | B2B（买家端） |
| 仓储操作员 | 经销商仓库的拣货、复核、打包人员 | WMS、PDA |
| 配送司机 | 经销商配送车队 | TMS（本文不展开） |

### 2.2 三种履约模式

```
┌─────────────────────────────────────────────────────────┐
│                    B2B 商城订单                            │
│                                                         │
│  ① 自营品         ② 入驻商品-平台代发      ③ 入驻商品-商家自配   │
│  经销商自己货       经销商帮入驻商发货        入驻商自己发货       │
│  B2B→ERP→WMS      B2B→ERP→WMS            B2B→入驻商自处理    │
└─────────────────────────────────────────────────────────┘
```

| 模式 | 货主 | 仓储方 | 配送方 | 订单经过系统 |
|------|------|--------|--------|-------------|
| ① 自营 | 经销商 | 经销商仓库 | 经销商配送 | B2B → ERP → WMS |
| ② 代发（FBP） | 入驻商 | 经销商仓库 | 经销商配送 | B2B → ERP → WMS |
| ③ 自配（SOP） | 入驻商 | 入驻商仓库 | 入驻商配送 | 仅 B2B |

## 3. 系统职责矩阵

### 3.1 B2B 商城

| 模块 | 职责 | 不管什么 |
|------|------|----------|
| 商品展示 | 多商户商品目录、搜索、详情、分类导航 | 成本价、采购价 |
| 交易下单 | 购物车、下单、拆单、支付 | 库存实物操作 |
| 商户中心 | 入驻商上架商品、管理订单、查看结算单 | 仓库作业 |
| 开放 API | 订单通知（自配模式）、物流回传接口 | 不做入驻商自己的 ERP |
| 平台运营 | 商户审核、类目管理、佣金配置 | 财务核算 |

### 3.2 ERP

| 模块 | 职责 | 不管什么 |
|------|------|----------|
| 订单处理 | 接收 B2B 下发的自营+代发订单、审核、生成发货单 | 商城展示 |
| 库存中心 | 可用量计算、库存占用/释放、成本核算（移动加权平均） | 实物库位管理 |
| 财务核算 | 应收应付、与入驻商结算仓配费、采购成本 | 买家支付（那是 B2B 的事） |
| 采购补货 | 自营品采购订单、入库、对账 | 商城促销 |
| 基础资料 | 商品主数据（自营+代发品）、往来单位、仓库 | 商户资料（那是 B2B 的事） |

### 3.3 WMS

| 模块 | 职责 | 不管什么 |
|------|------|----------|
| 入库作业 | 收货、质检、上架（支持多货主） | 采购单据审核（ERP 的事） |
| 出库作业 | 接收发货单、波次、拣货、复核、打包、交接 | 订单拆分（ERP 的事） |
| 库内作业 | 移库、盘点、报损、批次管理 | 成本计算（ERP 的事） |
| PDA 终端 | 手持设备扫码操作 | 商城交互 |
| 库存实物 | 库位级实物库存（权威来源） | 财务记账 |

## 4. 数据归属矩阵

这是设计核心——每类数据的权威来源（Source of Truth）只有一个系统。

| 数据域 | 权威来源 | B2B 侧存什么 | ERP 侧存什么 | WMS 侧存什么 |
|--------|----------|-------------|-------------|-------------|
| **商品 SPU/SKU** | ERP（自营+代发）<br>B2B（自配品） | 展示用：标题、图片、描述、价格 | 主数据：编码、规格、单位、成本、税率 | 不存 |
| **商品价格** | B2B | 销售价、促销价、会员价 | 成本价、采购价 | 不存 |
| **实物库存** | WMS | 不存 | 不存（但读 WMS 快照做可用量计算） | 库位 × SKU × 批次 × 货主的实物数量 |
| **可用库存** | ERP | 读 ERP 快照（下单校验用） | 可用量 = WMS 实物 - 已占用 | 不感知"可用量"概念 |
| **订单** | B2B | 所有订单全量数据 | 自营+代发订单副本（处理用） | 不存订单，只存发货单 |
| **发货单** | ERP | 不存 | 创建方 | WMS 存执行记录 |
| **物流轨迹** | WMS（出库扫描） | 读 ERP 同步的物流状态 | 从 WMS 同步 | 出库扫描时间、物流单号 |
| **商户资料** | B2B | 入驻信息、资质、合同 | 代发商户的结算账户 | 货主 ID（owner_id） |
| **应收应付** | ERP | 不存 | 销售应收、采购应付、与入驻商结算 | 不存 |
| **平台佣金** | B2B | 费率配置、分账记录 | 不存 | 不存 |

### 关键原则

1. **ERP 和 WMS 不存订单全量**——B2B 是订单的唯一权威来源，ERP 只存处理需要的字段子集
2. **WMS 不知道成本和价格**——WMS 只管实物数量，成本和金额是 ERP 的事
3. **库存可用量由 ERP 统一计算**——B2B 和 WMS 都从 ERP 读取可用量，口径唯一
4. **商户信息 B2B 管，货主 ID WMS 管**——通过 `owner_id` 映射，WMS 不需要知道商户名称电话

## 5. 库存模型设计

### 5.1 WMS 侧的实物库存（权威来源）

```sql
-- WMS 库位级库存表（核心）
wms_stock (
    id,
    owner_id,           -- 货主（经销商自营 = 0，入驻商 = merchant_id）
    sku_id,             -- SKU
    location_id,        -- 库位
    batch_no,           -- 批次号
    production_date,    -- 生产日期
    quantity,           -- 实物数量
    locked_quantity,    -- 锁定数量（拣货中）
    version             -- 乐观锁
)
UNIQUE (owner_id, sku_id, location_id, batch_no)
```

### 5.2 ERP 侧的库存可用量（计算视图）

```sql
-- ERP 库存余额表（从 WMS 同步，聚合到 SKU 级别）
erp_stock_balance (
    id,
    sku_id,
    warehouse_id,
    owner_id,           -- 区分自营库存 vs 代管库存
    total_quantity,     -- 实物总量（从 WMS 同步）
    locked_quantity,    -- 订单占用（ERP 自己管理）
    available_quantity, -- 可用量 = total - locked
    cost_price,         -- 成本单价（移动加权平均）
    total_cost          -- 库存金额
)
```

### 5.3 库存同步机制

```
WMS 出库确认
  → WMS 扣减 wms_stock.quantity
  → 同步通知 ERP（REST API）：{ sku_id, warehouse_id, owner_id, change_qty }
  → ERP 重算 erp_stock_balance.total_quantity、cost_price
  → ERP 释放 locked_quantity
  → ERP 推送库存快照到 B2B（异步）
```

| 同步策略 | 说明 |
|----------|------|
| 入库/出库/盘点 | 实时 REST 回调 |
| 定时全量对账 | 每天凌晨对比 ERP 和 WMS 的 SKU 级别库存，差异 > 阈值告警 |
| B2B 查库存 | 读 B2B 自己的缓存（ERP 定时 5 分钟推送），下单时实时查 ERP 接口兜底 |

## 6. 订单生命周期

### 6.1 自营模式订单流（①）

```
B2B                            ERP                          WMS
 │                              │                            │
 │  ──下单请求──→               │                            │
 │             查可用库存 ←──    │                            │
 │             锁定库存 ────→   │                            │
 │  ←──下单成功──               │                            │
 │                              │                            │
 │  ──支付完成/推送订单──→      │                            │
 │                              │ 接收订单                    │
 │                              │ 审核                        │
 │                              │ 生成发货单                  │
 │                              │ ──下发发货单──→             │
 │                              │                            │ 接收发货单
 │                              │                            │ 波次生成
 │                              │                            │ 拣货
 │                              │                            │ 复核
 │                              │                            │ 打包
 │                              │                            │ 出库扫描
 │                              │ ←──出库确认（含物流单号）──  │
 │                              │ 更新库存成本                │
 │                              │ 释放占用                    │
 │  ←──物流状态回传────────────  │                            │
 │  买家看到物流信息             │                            │
```

**状态映射**：

| B2B 订单状态 | ERP 发货单状态 | WMS 发货单状态 |
|-------------|--------------|---------------|
| 待支付 | — | — |
| 待发货 | 待审核 | — |
| 待发货 | 已审核 | 待拣货 |
| 待发货 | 拣货中 | 拣货中 |
| 待收货 | 已出库 | 已出库 |
| 已签收 | 已签收 | 已签收 |

### 6.2 代发模式订单流（②）

流程与自营一致，区别在于：

| 环节 | 自营 | 代发 |
|------|------|------|
| 货主 | `owner_id = 0`（经销商） | `owner_id = merchant_id`（入驻商） |
| WMS 库存扣减 | 扣自营库存 | 扣该入驻商的代管库存 |
| ERP 成本核算 | 按移动加权平均核算 | 不核算成本，记录代发出库数量 |
| 出库后结算 | 无额外结算 | ERP 生成：① 应付入驻商货款 ② 应收入驻商仓配费 |

### 6.3 自配模式订单流（③）

```
B2B                              入驻商
 │                                │
 │  ──下单支付成功──              │
 │  订单状态 = 待发货              │
 │                                │
 │  ──订单通知（站内/Webhook）──→  │
 │                                │ 入驻商在自己的系统处理
 │                                │ 拣货 → 打包 → 发货
 │                                │
 │  ←──物流回传（API/商户中心）──  │
 │  订单状态 = 待收货              │
 │  买家看到物流信息               │
```

自配模式**完全不经过 ERP 和 WMS**。B2B 只需提供：
- `POST /open/orders/pull` — 入驻商拉取待发货订单
- `POST /open/orders/{id}/ship` — 入驻商回传物流单号

## 7. API 契约设计

### 7.1 B2B → ERP（内部调用）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/erp/orders/create` | POST | B2B 推送自营/代发订单到 ERP |
| `/erp/orders/{orderId}/cancel` | POST | B2B 取消订单通知 |
| `/erp/stock/available` | GET | 实时查询 SKU 可用库存（下单校验） |
| `/erp/stock/snapshot` | GET | 批量拉取库存快照（B2B 定时同步） |
| `/erp/logistics/callback` | POST | ERP 回推物流状态更新 |

**订单推送数据结构**（核心字段）：

```json
{
  "b2bOrderId": "B2026072100001",
  "fulfillmentType": "SELF",      // SELF=自营, FBP=代发, SOP=自配
  "merchantId": "M001",
  "buyerId": "B001",
  "lines": [{
    "skuId": "SKU001",
    "quantity": 10,
    "salePrice": 25.50
  }],
  "shippingAddress": {},
  "buyerRemark": "周一送货"
}
```

### 7.2 ERP → WMS（内部调用）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/wms/ship-order/create` | POST | ERP 下发发货单 |
| `/wms/ship-order/{id}/cancel` | POST | ERP 取消发货单 |
| `/wms/stock/callback` | POST | WMS 库存变动回调（出入库确认后） |
| `/wms/ship-order/{id}/status` | GET | ERP 查询发货单状态 |

**发货单数据结构**：

```json
{

  "ownerId": "M001",              // 货主
  "warehouseId": "WH01",
  "orderType": "SALES_OUTBOUND",

    "quantity": 10,

## 8. 结算模型

### 8.1 自营模式

```
买家付款 → B2B 收款（平台账户）
         → ERP 记销售收入
         → ERP 减库存成本 → 记销售成本
         → 毛利 = 收入 - 成本

无分账环节，全部内部核算。
```

### 8.2 代发模式（FBP）

```
买家付款 → B2B 收款（平台账户）
         → ERP 出货后：
             ① 记「应付入驻商货款」（= 商品结算价 × 数量）
             ② 记「应收入驻商仓配费」（= 仓储费 + 配送费）
             ③ 净结算 = ① - ②
         → 按结算周期（T+N）打款给入驻商
```

核心数据：

| 字段 | 来源 | 说明 |
|------|------|------|
| 商品结算价 | B2B → ERP（下单时带） | 入驻商设置的供货价 |
| 仓储费 | ERP 配置 | 可按件/按体积/按重量，支持阶梯价 |
| 配送费 | ERP 配置 | 按距离/按重量/固定价 |
| 结算周期 | B2B 商户配置 | 默认 T+7 天 |

### 8.3 自配模式（SOP）

```
买家付款 → B2B 收款（平台账户）
         → B2B 扣除平台佣金
         → B2B 按结算周期打款给入驻商
         → 不经 ERP
```

## 9. 数据库设计原则

### 9.1 三个系统独立数据库

| 系统 | 数据库 | 核心表族 |
|------|--------|----------|
| B2B | `b2b_mall` | 商品目录、订单、支付、商户、会员 |
| ERP | `erp_v1` | 订单副本、库存余额、成本、应收应付、基础资料 |
| WMS | `wms_v1` | 库位库存、发货单、作业任务、PDA 日志 |

### 9.2 跨系统数据同步规则

| 数据 | 同步方向 | 频率 | 方式 |
|------|----------|------|------|
| 自营/代发商品 | ERP → B2B | 商品变更时实时 | REST API 推送 |
| 库存快照 | ERP → B2B | 每 5 分钟 | REST API 批量推送 |
| 库存实时查询 | B2B → ERP | 下单时 | REST API 实时查询 |
| 订单 | B2B → ERP | 支付完成时 | REST API 推送 |
| 发货单 | ERP → WMS | 审核通过时 | REST API 推送 |
| 库存变动 | WMS → ERP | 出入库确认时 | REST API 回调 |
| 物流状态 | ERP → B2B | 状态变更时 | REST API 回推 |
| 结算单 | ERP → B2B | 日终生成 | REST API 推送 |

### 9.3 关联键对照

| 实体 | B2B 侧 ID | ERP 侧 ID | WMS 侧 ID | 映射方式 |
|------|-----------|-----------|-----------|----------|
| 商品（自营/代发） | `b2b_product_id` | `erp_sku_id` | — | ERP 维护映射表 |
| 入驻商 | `merchant_id` | `counterparty_id` | `owner_id` | `owner_id = merchant_id` |
| 订单（自营/代发） | `b2b_order_id` | 存 `b2b_order_id` | — | 透传 |
| 发货单 | — | `erp_ship_order_id` | 存 `erp_ship_order_id` | 透传 |
| 仓库 | 不存 | `warehouse_id` | `warehouse_id` | 一致 |

## 10. 部署架构

### 10.1 初期部署（V1.0，日单量 < 1000）

```
┌──────────────┐   ┌─────────────────┐   ┌──────────────┐
│  B2B 商城     │   │  ERP + WMS       │   │  MySQL 8.0  │
│  Spring Boot │   │  Spring Boot     │   │  (独立实例)  │
│  :8080       │   │  :8081          │   │  :3306      │
│              │   │                 │   │              │
│  DB: b2b_mall│   │  DB: erp_v1     │   │  DB: wms_v1  │
└──────┬───────┘   └───────┬─────────┘   └──────┬───────┘
       │                   │                     │
       └───────────────────┴─────────────────────┘
                    同一 MySQL 实例，不同 database

Nginx :80  →  /            → B2B :8080
           →  /erp/*        → ERP+WMS :8081
```

**初期 ERP 和 WMS 合并在一个 Spring Boot 应用内**，`com.erp.wms` 包通过 Service 层调用而非 HTTP。等 WMS 需要独立部署时，仅需把 Service 调用改为 REST API 调用。

### 10.2 中期部署（V2.0，日单量 1000-5000）

```
Nginx :80 → B2B :8080 / ERP :8081 / WMS :8082

┌──────────┐  ┌──────────┐  ┌──────────┐
│ B2B      │  │ ERP       │  │ WMS       │
│ :8080    │  │ :8081     │  │ :8082     │
│ DB:b2b   │  │ DB:erp    │  │ DB:wms    │
└─────┬────┘  └─────┬─────┘  └─────┬─────┘
      │             │              │
      └─────────────┴──────────────┘

## 12. 关键设计决策

| # | 决策项 | 结论 | 理由 |
|---|--------|------|------|
| 1 | 三个系统是否共享数据库 | **否**，各自独立 DB | 避免跨系统锁竞争，独立扩缩容 |
| 2 | ERP 和 WMS 初期是否合并部署 | **是**，同一应用 `com.erp.wms` 包 | 降低初期基础设施成本，后期可拆分 |
| 3 | 订单权威来源 | **B2B**，ERP 和 WMS 不存订单全量 | 防止三系统订单状态不一致 |
| 4 | 库存可用量权威来源 | **ERP**，从 WMS 同步实物量后计算 | 统一口径，避免 B2B 和 WMS 各自算 |
| 5 | WMS 是否知道价格/成本 | **否**，WMS 只管数量 | 职责单一，安全和性能 |
| 6 | B2B 库存查询策略 | 先读本地缓存，下单时查 ERP 兜底 | 避免每次查库打到后端 |
| 7 | 三者通信方式 | V1.0 全 REST 同步，V3.0 引入 MQ | 初期量小不需要异步，别过早优化 |
| 8 | 多货主库存如何隔离 | WMS 在 SKU × 库位 × 批次基础上加 `owner_id` | 同一库位可放多个货主的货 |
| 9 | 代发模式成本核算 | 代发品不进入 ERP 成本核算，只记数量 | 货权归入驻商，经销商不承担库存成本 |
| 10 | 自配订单是否进 ERP | **否**，仅 B2B 处理 | 自配订单经销商不碰货，与 ERP 无关 |

## 13. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| ERP 和 WMS 拆不开 | 后期 WMS 独立部署改造成本高 | 从第一天起 WMS 包不直接访问 ERP 的 Mapper，只通过 Service 接口调用 |
| B2B 和 ERP 库存数据不一致 | 超卖或少卖 | 定时全量对账 + 差异告警；下单时实时查 ERP 兜底 |
| 代发模式入驻商货款纠纷 | 财务风险 | 出库扫描时记录数量+批次+时间戳，结算单附带明细 |
| 三个系统 API 版本不兼容 | 上线故障 | API 统一加版本号 `/v1/`，契约测试 |
