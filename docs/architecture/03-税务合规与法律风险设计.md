# B2B-ERP-WMS 三系统 — 税务合规与法律风险设计

> 版本：V1.0 | 日期：2026-07-21 | 作者：产品/架构
> 配套文档：`docs/architecture/02-B2B-ERP-WMS三系统架构设计.md`
> 
> **声明**：本文档为产品架构层面的合规设计参考，不构成正式法律意见或税务咨询。正式上线前须由企业法务和注册税务师审核确认。

---

## 1. 文档目的

B2B 商城存在经销商自营、代发、自配三种履约模式，每种模式的货权归属、开票主体、资金流向各不相同。如果系统设计时不把税务和法律边界界定清楚，上线后将面临以下核心风险：

| 风险类型 | 典型后果 |
|----------|----------|
| 增值税发票错开 | 进项税不得抵扣、虚开发票嫌疑、罚款 |
| 收入确认错误 | 企业所得税少缴/多缴、税务稽查 |
| 资金二清违规 | 被央行认定为无证经营支付业务 |
| 电子商务法违规 | 平台责任不清、消费者维权时平台被连带 |
| 入驻商纠纷 | 货权争议、结款纠纷无法举出合规证据 |

本文档从**税法定位 → 发票流 → 资金流 → 合同体系 → 电子商务法义务**五个维度，为三种模式逐一设计合规方案。

---

## 2. 三模式税法定位总览

在设计发票流和资金流之前，必须先确定每种模式在法律上的**业务实质**（实质重于形式原则）。

| 模式 | 货权归属 | 对外销售方 | 资金经手方 | 税法定位 |
|------|----------|-----------|-----------|----------|
| ① 自营 | 经销商 | 经销商 | 经销商 | 经销商直接销售，开票给买家 |
| ② 代发（FBP） | 入驻商 | **由合同约定** | 经销商代收 | 可选"代销"或"购销"两种架构 |
| ③ 自配（SOP） | 入驻商 | 入驻商 | 经销商代收（平台） | 平台居间服务，入驻商开票给买家 |

> **核心原则**：谁在法律上"销售"商品（承担货权风险和定价权），谁就是开票主体。资金由谁收、货由谁发，不能替代货权归属的判断。

---

## 3. 模式① 自营 — 税务设计（风险最低）

### 3.1 业务实质

经销商自有库存、自主定价、承担滞销和跌价风险。买家在 B2B 下单，法律上的买卖关系发生在**经销商 ↔ 买家**之间。

### 3.2 发票流

```
经销商 ──增值税专用/普通发票──→ 买家
```

- 发票类型：增值税专用发票（买家为一般纳税人时）或普通发票
- 开票时点：发货完成后（纳税义务发生时间 = 货物发出当天）
- 税率：按经销商适用税率（一般纳税人 13% / 小规模纳税人 3% 或 1%）

### 3.3 资金流

```
买家 → B2B 平台收款账户 → 经销商对公账户
```

B2B 平台的资金归集账户应为**经销商自己的企业账户**（或经销商控股的支付机构账户），资金归属清晰。

### 3.4 系统设计要求

| 要求 | 说明 |
|------|------|
| 发票台账 | ERP 记录每张发票的发票号、金额、税率、购方税号 |
| 税控接口 | ERP 预留对接电子发票平台/税控盘的接口 |
| 红冲流程 | 退货时自动触发红字发票申请流程 |

### 3.5 合规结论

✅ 风险最低。与普通商贸企业线上线下销售无本质区别，按常规增值税申报即可。

---

## 4. 模式② 代发（FBP）— 税务设计（风险最高，须重点设计）

### 4.1 为什么这是高风险模式

代发模式的"风险三角"：

```
        买家付钱给平台
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
  货是入驻商的    仓库是经销商的    钱是经销商代收的
```

三流（货物流、资金流、发票流）天然分离。如果不通过合同和系统明确架构，税务局可能认定为：
- ❌ **经销商是实际销售方** → 要求经销商开票，但经销商没有进项票 → 全额 13% 税负
- ❌ **虚开发票** → 入驻商开票给买家但货是经销商发的 → 三流不一致

### 4.2 两种合规架构选择

代发模式必须在以下两种架构中**明确选择其一**，并在入驻合同中固化，**绝不能混合、模糊、或按订单自选**。

#### 架构 A：代销模式（推荐）

**法律关系**：入驻商委托经销商代销，经销商收取仓储配送服务费。

| 维度 | 设计 |
|------|------|
| 销售方 | **入驻商**（货主） |
| 开票方 | **入驻商** → 买家（增值税发票） |
| 经销商开票 | 经销商 → 入驻商（仓储配送服务费发票，税率 6% 或 13%） |
| 货权转移 | 不入驻商 → 经销商，始终是入驻商 → 买家 |
| 定价权 | 入驻商决定销售价 |
| 退货风险 | 入驻商承担 |

**发票流**：
```
入驻商 ──商品销售发票──→ 买家
入驻商 ←──仓配服务费发票── 经销商
```

**资金流**：
```
买家 → B2B 平台商户账户（入驻商子账户）
     → 自动分账：
         ① 商品货款 → 入驻商账户（扣除仓配费后净额）
         ② 仓配服务费 → 经销商账户
```

**优势**：入驻商对买家直接承担商品质量责任，经销商只收服务费，风险隔离清晰。
**劣势**：入驻商须具备开票能力（一般纳税人或小规模均可）。

---

#### 架构 B：购销模式（备选）

**法律关系**：经销商向入驻商"采购"商品（视同买断），再向买家销售。

| 维度 | 设计 |
|------|------|
| 销售方 | **经销商**（向买家销售） |
| 开票方1 | 入驻商 → 经销商（商品采购发票） |
| 开票方2 | 经销商 → 买家（商品销售发票） |
| 货权转移 | 入驻商 → 经销商 → 买家（两次转移） |
| 定价权 | 经销商决定最终售价 |
| 退货风险 | 经销商承担（已买断） |

**发票流**：
```
入驻商 ──采购发票──→ 经销商 ──销售发票──→ 买家
```

**资金流**：
```
买家 → 经销商账户
     → 经销商按月向入驻商支付采购款（按结算周期）
```

**优势**：买家只面对经销商一个主体，开票简单。
**劣势**：
- 经销商承担库存成本和跌价风险（即便货在仓库没卖出去也已"买入"）
- 经销商需缴纳两笔交易的印花税
- 入驻商和经销商的定价如果偏离市场价，可能触发转让定价调查

---

### 4.3 推荐选择

| 场景 | 推荐架构 |
|------|----------|
| 入驻商具备开票能力（一般纳税人/小规模） | **架构 A 代销模式** |
| 入驻商为个人或无法开票 | 架构 B 购销模式（经销商全额开票，同时做无票采购成本入账） |
| 入驻商希望经销商承担全部销售责任 | 架构 B |

**强烈建议默认采用架构 A（代销模式）**。架构 B 仅作为入驻商无法开票时的兜底方案，且须在入驻合同中明确"视同买断"条款。

### 4.4 代发模式系统设计要求

| 要求 | 所属系统 | 说明 |
|------|----------|------|
| 入驻商纳税人资质登记 | B2B 商户中心 | 一般纳税人/小规模/个人，上传税号 |
| 代销合同条款固化 | B2B 商户中心 | 明确选择架构 A 还是 B，不可中途切换 |
| 商品结算价记录 | B2B 下单时传入 ERP | 生成结算单的基础数据 |
| 仓配费自动计算 | ERP 结算模块 | 按合同费率，出库时自动生成 |
| 发票台账（双发票） | ERP | 代销模式：仓配服务费发票 + 入驻商销售发票回执 |
| 入驻商发票回传通道 | B2B 商户中心 | 入驻商开票后上传发票影像（PDF/OFD），ERP 存档 |
| 结算单对账 | B2B 商户中心 | 入驻商可查看每笔结算明细（货款 - 仓配费 = 净额） |

## 5. 模式③ 自配（SOP）— 税务设计

### 5.1 业务实质

B2B 商城是纯粹的交易撮合平台。入驻商自己管货、自己发货、自己开票。平台提供信息展示、订单传递、资金代收付服务，收取平台佣金/技术服务费。

### 5.2 发票流

```
入驻商 ──商品销售发票──→ 买家
B2B 平台 ──平台服务费发票──→ 入驻商
```

### 5.3 资金流

```
买家 → B2B 平台商户子账户（入驻商子账户）
     → 自动分账：
         ① 商品货款 → 入驻商账户（扣除佣金后净额）
         ② 平台佣金 → 经销商/平台账户
```

### 5.4 关键合规要点 — 资金二清问题

**资金二清**：平台先收买家的钱，再结算给入驻商，形成了事实上的"二清"（二次清算）。如果平台不具备《支付业务许可证》，这可能被央行认定为无证经营支付业务。

**合规方案（必须执行）**：

| 方案 | 说明 | 适用阶段 |
|------|------|----------|
| **持牌支付机构托管**（推荐） | 接入支付宝/微信支付/银行虚拟账户体系，资金由持牌机构托管，平台只发起分账指令，不实际触碰资金 | 上线即实施 |
| **银行资金存管** | 在合作银行开立商户资金存管专户，平台和入驻商的资金隔离存放 | 交易量大时升级 |

**系统设计要求**：

| 要求 | 说明 |
|------|------|
| 资金不落地 | B2B 平台账户不滞留买家资金，实时/准实时分账或托管 |
| 分账指令接口 | B2B → 支付机构：下发分账指令（金额、收款方、用途） |
| 分账对账 | 每日与支付机构对账，差异自动告警 |
| 入驻商提现 | 入驻商在 B2B 商户中心发起提现，平台审批后由支付机构执行 |

### 5.5 自配模式系统设计要求

| 要求 | 所属系统 | 说明 |
|------|----------|------|
| 入驻商开票能力登记 | B2B 商户中心 | 同代发 |
| 平台服务费发票管理 | ERP | 平台向入驻商开具的佣金/服务费发票台账 |
| 分账记录 | B2B | 每笔订单的分账明细（买家付款额、平台佣金、入驻商实收） |

## 7. 电子商务法合规要点

根据《中华人民共和国电子商务法》（2019.1.1 施行），B2B 商城作为电子商务平台经营者，须履行以下法定义务：

### 7.1 平台经营者义务清单

| 义务 | 法条 | 系统实现 |
|------|------|----------|
| **入驻商主体登记和核验** | 第 27 条 | B2B 商户中心：入驻时必须上传营业执照，系统校验证件有效期并到期提醒 |
| **入驻商信息公示** | 第 15、27 条 | 商品详情页展示入驻商名称、营业执照号（或"已认证"标识） |
| **服务协议和交易规则公示** | 第 33、34 条 | B2B 提供标准入驻协议模板，修改时提前 7 天公示并通知入驻商 |
| **信用评价制度** | 第 39 条 | 买家可评价入驻商，平台不得删除差评 |
| **知识产权保护** | 第 41-43 条 | B2B 设置侵权投诉入口，收到通知后及时采取删除/屏蔽/断开链接措施 |
| **交易信息保存** | 第 31 条 | 交易记录保存不少于 3 年（订单+支付+物流+发票全链路） |
| **网络安全与个人信息保护** | 第 23、30 条 | 买家个人信息加密存储，明示隐私政策，不得默认勾选同意 |
| **平台责任提示** | 第 38 条 | 对关系消费者生命健康的商品，平台未尽审核义务或未采取必要措施的，承担连带责任 |

### 7.2 三种模式下的平台责任差异

| 模式 | 平台责任等级 | 说明 |
|------|------------|------|
| 自营 | **高**（经销商自身就是销售者） | 经销商直接承担《产品质量法》《消费者权益保护法》项下销售者全部责任 |
| 代发 | **中高** | 经销商虽不是销售者，但因实际控制仓储配送，对商品质量有一定管理义务 |
| 自配 | **中**（平台经营者） | 平台履行入驻商审核、信息披露、协助维权等法定义务即可 |

### 7.3 系统设计要求

| 要求 | 系统 | 实现要点 |
|------|------|----------|
| 入驻商资质管理 | B2B | 营业执照上传、OCR 识别、有效期管理、到期前 30 天提醒 |
| 商品详情页标识 | B2B | 自营标"自营"、代发标"平台仓配"、自配标入驻商名称 |
| 订单数据归档 | B2B | 订单完成后超过 3 年的数据迁移至归档库，不可物理删除 |
| 投诉举报入口 | B2B | 商品详情页/订单详情页均提供投诉按钮 |
| 入驻商退路 | B2B | 入驻商退出时，保留其在平台上的交易记录至少 3 年 |

## 8. 合同体系设计

系统架构依赖合同保障。三类合同缺一不可：

| 合同 | 签署方 | 核心条款 |
|------|--------|----------|
| **平台入驻协议** | 经销商 ↔ 入驻商 | 履约模式选择（自配/代发）、结算周期、佣金费率、发票开立义务、违约责任 |
| **代发补充协议** | 经销商 ↔ 入驻商 | 代销或购销模式声明、货权归属、仓配费计价、损耗标准、对账规则 |
| **买家服务协议** | 经销商/入驻商 ↔ 买家 | 退换货规则、发票开具义务、争议解决 |

> **关键**：代发补充协议中，必须用明确语言界定代销还是购销（参照第 4.2 节），这是税务机关判断开票合规性的第一份证据。

## 9. 税务登记与申报要求

### 9.1 经销商侧

| 税种 | 申报内容 | 系统支持 |
|------|----------|----------|
| 增值税 | 自营销售收入（13%/3%）；代发仓配服务费收入（6%/13%）；自配平台服务费收入（6%/13%） | ERP 收入科目按业务类型分拆 |
| 企业所得税 | 主营业务收入（自营销售）+ 其他业务收入（服务费） | ERP 利润表按板块输出 |
| 印花税 | 购销合同（自营销售合同、代发-购销模式）；仓储合同（代发-代销模式）；服务合同（自配） | ERP 合同台账管理 |
| 附加税 | 城建税 + 教育费附加 + 地方教育附加 | ERP 自动计提 |

### 9.2 入驻商侧（平台提示义务）

在 B2B 商户中心的帮助文档中，应提示入驻商自行履行以下义务：

- 按实际销售收入申报增值税
- 向买家依法开具发票
- 如实申报企业所得税/个人所得税

```
│            │ 分账指令（平台下发）                                    │
│     ┌──────┼──────┬──────────────┐                                │
│     ▼      ▼      ▼              ▼                                │
│  ┌────┐ ┌────┐ ┌──────┐   ┌──────────┐                          │
│  │自营 │ │代发 │ │代发   │   │自配入驻商  │                          │
│  │货款 │ │货款 │ │仓配费 │   │货款(扣佣金)│                          │
│  │→经销│ │→入  │ │→经销商│   │→入驻商    │                          │
│  │商   │ │驻商 │ │      │   │          │                          │
│  └────┘ └────┘ └──────┘   └──────────┘                          │
│                                                                  │
│  关键：所有买家资金进入持牌支付机构托管账户，                            │
│        平台仅下发分账指令，不形成资金池。                               │
└──────────────────────────────────────────────────────────────────┘
```

## 11. 风险清单与缓解措施

| # | 风险 | 严重程度 | 缓解措施 |
|---|------|----------|----------|
| 1 | 代发模式未在合同中明确代销/购销 → 税务机关认定为经销商销售 → 全额补税 | 🔴 高 | 入驻协议必须选择架构 A 或 B，条款由法务审核，不可缺失 |
| 2 | 平台直接收买家款再转付入驻商 → 资金二清 → 央行处罚 | 🔴 高 | 必须接入持牌支付机构/银行托管，一期即实施 |
| 3 | 代发模式下入驻商未给买家开票 → 买家投诉至税务局 → 连带调查 | 🟡 中 | 系统自动校验：发货后 N 天入驻商未上传发票影像 → 自动提醒 → 超时冻结店铺 |
| 4 | 仓配费未申报增值税 → 视同销售漏税 | 🟡 中 | ERP 对仓配服务费单独设收入科目，开票时自动匹配税率 |
| 5 | 自营和代发库存混放 → 无法举证货权 → 纠纷败诉 | 🟡 中 | WMS 的 owner_id 字段从第一天就严格区分（见架构文档 5.1 节） |
| 6 | 平台未保存交易记录超 3 年 → 电商法违规 | 🟡 中 | B2B 数据库归档策略：3 年内不可物理删除，3 年后移至归档库 |
| 7 | 入驻商营业执照过期未被发现 → 平台未尽审核义务 | 🟢 低 | B2B 定时任务每天扫描即将过期（30 天）和已过期的执照 → 自动提醒/限制 |
| 8 | 各系统金额精度不一致 → 对账差异 → 结算纠纷 | 🟢 低 | 全系统统一使用 `DECIMAL(18,2)` 金额字段，API 传 JSON Number 保持 2 位小数 |
