# V1.0 关键风险优化 — 阶段五交付说明

> 生成日期：2026-07-22
> 依据：采购流程闭环计划 v2 + 销售模块整体迁移
> 本次范围：**采购流程 + 销售流程双闭环真实落地**（订单 → 入库/出库 → 收货单 → fin_ap/fin_ar），批次库存 + 移动平均法 + 逐行税率

## 一、本次已完成

### 采购模块

#### 1. 老 `pur_order` / `/order-legacy/*` 全清（Step A）

老 `PurchaseController` 里的 7 个 `/order-legacy/*` 端点 + 3 个请求 record 全部删除；`PurchaseOrder` / `PurchaseOrderDetail` entity + service + service impl + mapper 共 8 个孤儿文件删除。采购订单唯一路径为 `OrderController` 的 `/purchase/order/*`（新 `purchase_order` 表）。

#### 2. V14 采购订单审核字段 + V15 批次库存

- V14：`purchase_order` 加 `audit_time` / `audit_user` / `inbound_amount`
- V15：新表 `inv_batch_stock`（`goods_code + warehouse + batch_no` 唯一），入库按批次写，聚合到 `inv_stock_balance`；移动平均法 cost_price

#### 3. 采购入库单改造（Step B）

**后端**：[PurchaseController.java](../backend/src/main/java/com/erp/purchase/PurchaseController.java)

- 新增 `GET /purchase/inbound/from-order?orderNo=X` —— 按订单预填明细，返回 `orderQty / inboundedQty / remainQty / price`
- 重写 `POST /purchase/inbound/create` —— 接受前端拆行 payload（`details[]` 每行含 `batchNo` / `productionDate` / `expiryDate` / `receivedQty`）；校验来源订单 APPROVED + Σ实收 ≤ 商品订单剩余
- 重写 `POST /purchase/inbound/audit`：
  - 走 [InventoryCostService](../backend/src/main/java/com/erp/inventory/service/InventoryCostService.java)`.purchaseInbound()` 按批次写 `inv_batch_stock` + 移动平均更新 `inv_stock_balance`
  - **同步 `base_goods.latest_purchase_price = 本次入库单价`**
  - **按累计 vs 订单金额精确计算 `inbound_status`**：未入库 / 部分入库 / 已入库
  - 尾部调用 `receiptController.generateFromInbound()` 自动生成收货单

**前端**：[PurchaseInboundDrawer.vue](../frontend/src/components/PurchaseInboundDrawer.vue)（新）

- 入口 A：入库列表点「新建采购入库」→ 抽屉内下拉选择已审核未完成入库的采购订单
- 入口 B：采购订单已审核行点「生成入库单」→ 预填订单头部与明细
- 每行支持「拆 2」「拆 3」按数量平分成多批次行，批次号带 `-N` 尾号
- **单价随订单单价预填只读**（决策 A：改价必须回订单改）
- **生产日期变更 → 批次号自动同步为 `B + yyyyMMdd`**（除非用户手动改过）
- 前端 + 后端双重 Σ实收 ≤ 订单剩余校验

#### 4. V16 采购收货单 + fin_ap（Step C）

- V16：新表 `pur_receipt`（含 `source_inbound_no` 唯一约束）+ `pur_receipt_detail`
- 新建 [PurchaseReceiptController.java](../backend/src/main/java/com/erp/purchase/PurchaseReceiptController.java) —— `page` / `detail` / `audit` / `reverse-audit` / `generateFromInbound(inboundId)`
- **税额策略（决策 A）**：逐行按订单明细的 `tax_rate` 计算行税额，头部 `tax_amount = Σ 明细税额`
- 收货单审核 → 写 `fin_ap`（走既有应付表，决策 B）；反审需 `fin_ap.paid_amount = 0` 才允许
- 修复历史 SQL bug：`DATE_ADD(CURRENT_DATE, INTERVAL 30 DAY)` (MySQL) → `DATEADD('DAY', 30, CURRENT_DATE)` (H2 兼容)

### 销售模块

#### 5. `OrderController` 补齐销售订单 5 个端点（Step E）

老 `SalesController` 在采购阶段被清理时留下了 5 个端点空缺（前端一直 404）。补：`/sales/order/update` / `/audit` / `/reverse-audit` / `/close` / `/delete` 全部走 JdbcTemplate 直查新字段；`sales/order/page` SELECT 补 `outbound_status` / `outbound_amount`。

`/sales/quick-order/create-and-audit` 从 SalesController 迁移到 OrderController，走 JdbcTemplate 内联审核，避免 Spring 代理自调用绕过事务。

#### 6. V17 迁移 + `SalesOutboundController`（Step F/G）

- V17：`sales_order` 补 `audit_time` / `audit_user` / `outbound_amount`；新表 `sales_receipt` + `sales_receipt_detail`
- 新建 [SalesOutboundController.java](../backend/src/main/java/com/erp/sales/SalesOutboundController.java)：`page` / `detail` / `from-order` / `available-batches` / `create` / `audit`
- 出库审核走 [InventoryCostService](../backend/src/main/java/com/erp/inventory/service/InventoryCostService.java)`.salesOutbound()` 按批次扣 `inv_batch_stock`
- 回写 `sales_order.outbound_amount` / `outbound_status`（未/部分/已出库）；尾部自动生成 `sales_receipt`
- **支持拆行指定批次**：`GET /sales/outbound/available-batches?goodsCode=X&warehouse=Y` 返回 qty>0 的批次列表
- 新建 [SalesReceiptController.java](../backend/src/main/java/com/erp/sales/SalesReceiptController.java)：`page` / `detail` / `audit` / `reverse-audit` / `generateFromOutbound(outboundId)`
- 收货单审核 → 写 `fin_ar`（决策：审核在收货单，不在出库；对称采购）；反审需 `fin_ar.received_amount = 0`

**前端**：[SalesOutboundDrawer.vue](../frontend/src/components/SalesOutboundDrawer.vue)（新）

- 入口 A / 入口 B 对称采购
- 拆行 UI 每行独立批次下拉，选项来自 `available-batches`
- 单价只读；Σ本次出库 ≤ 商品订单剩余

#### 7. 老 SalesController 全清（Step H）

- 删除 [`SalesController.java`](../backend/src/main/java/com/erp/sales/SalesController.java)（原文件不再存在）+ 12 个孤儿文件：
  - `entity/`：SalesOrder / SalesOrderDetail / SalesOutbound / SalesOutboundDetail
  - `service/`：4 个接口 + 4 个 Impl
  - `mapper/`：4 个 Mapper
- 新建 [SalesReturnController.java](../backend/src/main/java/com/erp/sales/SalesReturnController.java) 单独保留销售退货端点（V1.0 简化版，沿用 `biz_simple_bill`）

#### 8. 冒烟脚本双闭环（Step I）

[v1-core-smoke-test.js](../development/06-testing/scripts/v1-core-smoke-test.js) 新增 `testPurchaseCloseLoop()` + `testSalesCloseLoop()`：

- 采购闭环：建资料 → 下 PO → 审核 → `from-order` 预填 → 拆 60+40 两批次入库 → 审核（校验 latest_purchase_price / inbound_status / 收货单自动生成）→ 收货审核（fin_ap AP-开头，含税 3955）→ 反审核（fin_ap 删除）
- 销售闭环：预置库存（走一遍采购入库）→ 创建 SO → 审核 → 从两个批次出库 60+40 → 出库审核（校验 outbound_status / 收货单自动生成）→ 收货审核（fin_ar AR-开头）→ 反审核
- 双方向超量拒绝：`sourceOrder + qty=999` 必须返回 `超过订单剩余`
- 双向反审断言：`fin_ap` / `fin_ar` 在反审后从 finance 列表消失

## 二、决策记录

| 决策点 | 选择 | 影响 |
|---|---|---|
| 采购老端点 | 直接删除（不 -legacy 归档） | Step A 清 8 个孤儿文件 |
| pur_inbound 表 | 继续沿用（不重建） | 应用层对接新 `purchase_order`，最小化迁移 |
| supplier_settlement 独立表 | 不建，直接走 fin_ap | Step C 只 2 张新表 |
| 入库跳过收货单 | 不允许 | 收货单审核是应付生成唯一入口 |
| 入库单单价 | 只读（预填订单价） | 改价必须回订单改，三单金额一致 |
| 采购收货税额 | 逐行按 tax_rate（决策 A） | `tax_amount = Σ 行税额`，多档税率场景更真实 |
| 冒烟测试策略 | 扩展现有 v1-core-smoke-test | 双闭环追加，不新建独立脚本 |
| 销售拆行 | 支持拆行指定批次 | UI 每行独立批次下拉 |
| 销售收货反审 | 同采购（需 received_amount = 0） | 已收款拒绝反审 |
| 销售 fin_ar 生成时机 | 收货单审核时 | 出库审核只扣库存 + 生成收货单 |

## 三、待办

### 🟡 采购付款单 + 销售收款单（决策 B 的延续）

`pur_receipt.pay_status` / `sales_receipt.receive_status` 字段已就位但为占位 `未付款` / `未收款`。付款单/收款单模块（写 `fin_payment_bill` / `fin_receipt_bill`）落地时需回写这两个状态和 `fin_ap.paid_amount` / `fin_ar.received_amount`。当前反审规则已经预设了 `paid_amount = 0` / `received_amount = 0` 的门槛，付款/收款联动后自动生效。

### 🟡 费用分摊 + 采购发票

`pur_receipt.expense_amount` / `sales_receipt.expense_amount` 字段已就位但为 0。V1.0 PRD §5.5「采购收货」提到费用分摊到成本；V2.0 落地时按金额/数量分摊到 `pur_inbound_detail` 影响成本，同时和采购发票（`purchase_invoice`）勾稽。

### 🟡 H2 大小写字段名兼容

`OrderController` / `FinanceController` 返回的字段名 H2 会全大写化，前端和测试脚本需 `orderNo || orderno || ORDERNO` 三 fallback。后续可统一改造 `camelize` 或在 SELECT 用 `snake_case AS snake_case`。**不阻塞业务功能**，只是前端代码稍显冗余。

### 🟡 FIFO 自动扣批次

`InventoryCostService.salesOutbound()` 当前必须指定 `batchNo` 才会扣到 `inv_batch_stock` 批次层，`batchNo` 为空时只扣 `inv_stock_balance`。V2.0 可实现 FIFO/LIFO 自动扣批次，减少 UI 交互。
