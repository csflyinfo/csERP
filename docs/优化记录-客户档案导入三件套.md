# 优化记录：客户档案导入新增 / 导入修改 / 导入查询（三件套）

- 分支：`feat/base-customer-import`（squash 合入 main）
- 参照：商品档案导入三件套（`GoodsImportController`，提交 77d0cb7 / cff9048）
- 范围：base 模块（后端 + 前端），无 Flyway 迁移

## 一、需求

参照商品模块，给客户档案增加「导入新增 / 导入修改 / 导入查询」三个入口（客户列表工具栏「导入」下拉）。导入新增/修改覆盖新建客户页面的全部字段；必填列表头标红；字段依赖在模板「导入说明」页写清；导入时逐行校验，错误不中断整批，失败行落失败文件，可在【导入列表】下载。

## 二、已确认口径

1. **客户编码选填**：留空自动生成 `K + 6 位流水`（K000001…，取库内同规则最大号 +1）；手填编码做库内 + 批内查重，重复整行失败。
2. **地址**：本期只导默认收货地址（`shipping_address` 一列）；多地址簿仍在客户编辑页维护。
3. **账期依赖严格校验**：不符合依赖整行失败，返回中文原因。
4. **格式校验**：手机号必填且为 11 位大陆手机号（`^1[3-9]\d{9}$`）；税号选填，填了须为 15-20 位大写字母数字（`^[0-9A-Z]{15,20}$`，小写自动转大写）。

## 四、账期依赖校验（新增、修改共用）

- 预付 / 货到付款：账期类型、账期天数、截账日、付款模式、账期月数、付款日 6 列必须全空。
- 账期：账期类型必填。
  - 固定账期天数 / 周结 / 半月结：账期天数必填（0-365）；截账日/付款模式/账期月数/付款日必须空。
  - 月结：截账日（1-31）与付款模式（A/B）必填。
    - A：账期天数必填（0-365）；账期月数、付款日必须空。
    - B：账期月数（≥0）、付款日（1-31）必填；账期天数必须空。
- 导入修改在「实体现值 + 本次非空列」合并后的完整客户上跑同一套校验；目标结构不适用的列若本次误填，整行失败（不静默丢弃）。

## 五、实现要点

### 后端

- 新增 `CustomerImportController`（`/base/customer`）：
  - `GET /import-template`：下发静态模板 `templates/customer-import-template.xlsx`。
  - `POST /import`：逐行 try/catch（行号=Excel 行号，首行数据为 2），IllegalArgumentException 中文消息即失败原因，整批不中断；自动编码、主数据解析、全部格式与依赖校验；写操作日志；尾部落导入任务。
  - `POST /import-update`：body 带 `fields` 勾选白名单（强制含客户编码）；按编码定位，查无失败；**空单元格不更新**；账期字段在合并值上校验。
- 新增 `CustomerImportSupport`：K 码生成（synchronized + 唯一约束兜底）、片区末级解析、线路/业务员存在性、价格组编码优先+名称兜底解析。
- 新增 `com.erp.system.ImportTaskRecorder`：从 `GoodsImportController` 抽出的共用导入任务记录设施（任务号 `IMP+毫秒+3位随机`、失败文件 `data/import-failures/{taskNo}.xlsx`、落 `sys_import_task_runtime`，moduleCode/taskName 参数化）。**商品导入改为调用它，行为不变，需回归**。
- `BaseController.customerPage` 新增 `filters.customerCodeList`（逗号分隔 → distinct → `customer_code IN (...)`），供导入查询。
- 权限点 `base.customer.import` 由 PermissionRegistry 标准动作自动派生。
- 静态模板双 sheet：「客户档案」23 列表头（5 个必填表头红色加粗 FFFF0000：客户名称/联系人/手机号/业务员/收货地址；客户编码选填不标红），5 处下拉到第 500 行（渠道类型/客户等级/结算方式/账期类型/付款模式）；「导入说明」30 行写清必填项、自动编码、主数据依赖、账期 4 条依赖、经纬度成对、税号手机号格式、修改空单元格规则。模板用 ZIP/XML 手术制作（SheetJS 社区版重写丢样式）。

### 前端

- `importPresets.js`：新增 customerAdd / customerUpdate / customerQuery 三个 preset（23/24 字段元组与后端逐列对齐）；修改 preset 默认仅锁定勾选客户编码，支持全选/取消全选，含账期依赖与空单元格两条警示；查询 preset 走 filter 模式；goodsQuery 补 filterKey/filterListKey/filterToast。
- `module-config.js`：客户 actions 「导入修改」→「导入」（下拉三入口）。
- `GenericBusinessList.vue`：handleImport 的 filter 分支由写死 goodsCode 改为读 preset.filterKey/filterListKey/filterToast（商品行为不变）；成功 toast 改为商品/客户共用「有 res.message 就显示」。
- 旧 mock 端点 `/excel/import/customer` 保留不删（入口摘除后不可达）。

### 验证中发现并修复的问题

- **账期结构切换时旧列未清空**：MyBatis-Plus `updateById` 默认 NOT_NULL 字段策略，`setTermType(null)` 等不进 UPDATE SET，导致 FIXED→预付后旧账期类型/天数残留。修复：账期 7 列在结构变动时改用 `LambdaUpdateWrapper.set(...)` 全量重写（含显式 null），已用 4 种结构切换用例回归。
- 模板说明页两处措辞与实际口径对齐：发票抬头留空即为空（页面无默认值）、客户名称无查重约束（唯一约束仅客户编码）。
