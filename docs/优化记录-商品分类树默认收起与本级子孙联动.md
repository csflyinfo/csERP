# 优化记录：商品分类树默认收起 + 点击节点右侧显示本级及所有下级

- 分支：`feat/base-category-tree-collapse`
- 迁移：无（纯前端交互优化）
- 需求来源：用户反馈（商品分类优化）
- 影响模块：商品分类（category）；共享左树右表框架的部门管理 / 资金账户 / 费用类型 / 片区管理 / 人员信息同步生效
- 验收方式：Edge headless + CDP 真实登录断言（脚本位于仓库外 `e:\work\verify-category-tree.mjs`）

---

## 1. 优化前问题

1. 左侧分类树进入即**全量平铺展开**（480 条分类全部渲染在一个扁平列表里，用 `└` 表示层级），一级节点被大量下级淹没，找大类要滚动很久。
2. 点击分类节点只有**视觉高亮**，右侧列表仍显示全部分类，无法按分类定位。
3. 树由「当前页」记录构建（服务端分页 pageSize 100），分类超过 100 条后树本身就不完整（本次实测 480 条、12 个一级分类）。

## 2. 优化后交互

1. **进入页面自动收起**：左侧只显示「全部分类」根节点 + 一级分类（本次数据为 全部 + 12 个一级）。
2. 有下级的节点显示 `▶` 箭头：
   - **点节点名称**：选中该节点（高亮、箭头变 `▼`、自动展开其下级），右侧列表只显示**所选分类本级 + 所有下级及子级**；再次点「全部分类」恢复全量。
   - **点箭头**：只展开/收起下级，不改变右侧选中结果。
3. 右侧列表为本级+子孙过滤后的结果，分页器总条数=子树条数，翻页正常（前端切片分页）。
4. 人员信息原有「按部门本级+下级过滤」行为不变，同时获得相同的收起/展开交互。
5. 往来单位、价格组商品查询的扁平树维持原样（两级结构，一次展示全部）。

## 3. 实现要点（`frontend/src/views/GenericBusinessList.vue`）

| 改动 | 说明 |
| --- | --- |
| 树数据结构 | `dynamicTree` 扁平数组 → `treeRoots` 嵌套树 + `expandedTreeKeys` 展开集合；`visibleTreeNodes` 计算属性按展开状态拍平 |
| 全量拉取 | 新增 `fetchAllPages()`：后端单页硬上限 200（`PageRequest.safePageSize`），循环翻页取全量后建树/过滤，50 页安全阀 |
| 右侧过滤 | 新增 `subtreeCodeSet()`（父→子索引递归收集本级+子孙），在 `loadRows` 内客户端过滤；选中节点时列表请求也走全量翻页，未选中时保持服务端分页不变 |
| 树缓存 | `treeDirty/treeLoaded`：翻页/切节点复用缓存；新增、编辑、停用、删除、导入成功后置脏，下次加载刷新树 |
| 切模块复位 | 路由模块切换时清空选中节点、展开集合、树缓存、页码，保证每个模块进入时都是收起态 |
| 模板/样式 | 箭头 `▶/▼` 独立点击区（`@click.stop` 只折叠不选中）；`app.css` 新增 `.tree-caret` / `.tree-label`，节点改 flex 布局 |

其他：`module-config.js` 商品分类 `desc` 同步更新为新交互说明。
