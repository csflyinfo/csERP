## 业务规则（落地口径）

1. **期末凭证一律生成"转"字草稿**，月末日期（期间 end_date），会计在凭证管理审核、过账后才能结账；事件不自动过账的口径不变。
2. **结转损益 JZ{period} 幂等**：损益类（5 开头）已过账发生按科目+辅助核算 7 维分组；收入类（科目编码 < 5400，贷方余额方向）净贷发生 → 借收入/贷 3103，成本费用类（≥5400）净借发生 → 贷费用/借 3103；辅助核算逐组带出（辅助余额同步轧平）；已存在非作废 JZ 凭证时拒绝重复结转。
3. **自动转账 ZZ{transferNo}{period} 幂等**：条件表达式不满足跳过、计算金额为零跳过、借贷不平跳过（并提示检查公式）、科目非末级启用跳过；已存在非作废 ZZ 凭证返回 exists。
4. **结账四项硬检查**：① 本期无草稿/已审核凭证；② 本期借贷发生合计相等且期初（启用余额+以前期间发生）试算平衡（容差 0.02）；③ JZ 凭证已过账，或损益类无净发生；④ 上期已结账/冻结（启用首期豁免）。任一不过返回逐条中文原因。
5. **结账推进**：当前期 → 已结账（记结账人/时间），下一期间 → 进行中；**12 月结账为年结**：期间置已冻结、自动生成下年度 12 个期间并开下年 01 期；冻结期间永远不能反结账。
6. **反结账**：仅最后一个已结账期间、原因必填（≥2 字，写 reopen_name/time/reason 留痕）；反结后期内 JZ/ZZ 凭证回退草稿（清空凭证号与审核/过账痕迹，可改可删，重新过账后即可重结）。

## 过程中修复的缺陷

- **GlReportCalc 重载聚合翻倍（本里程碑最隐蔽 BUG）**：`invalidate()` 只置 `loaded=false`，未清空 initAgg/postedAgg/cfAgg 等实例 Map，而 rollup 是**累加写入**——第二次 ensureLoaded 在旧值上再加一遍，取数随重载次数翻倍（冒烟表现：转账预览 130、执行时变 260）。修复：invalidate() 同时 clear 全部聚合 Map。此 BUG 若带入 M6，报表金额会随页面刷新次数线性放大。
- **SQL 聚合别名踩 camelize 陷阱（两处）**：GlPeriodService 结账检查的三段合计 SQL 与 GlReportCalc 的期初/发生/现金流聚合 SQL 都用了 `d`/`c`/`od`/`oc`/`yd`/`yc` 短别名，经 TmsUtil camelize 后取不到 `debitAmount/creditAmount/openDebit...`，取数静默为 0（表现：平衡检查发生额显示 0、自动转账金额恒为零）。统一改为下划线原列名别名（`debit_amount`/`credit_amount`/`open_debit`...）。
- **期末凭证 INSERT 占位符错位**：fin_voucher 头 INSERT 把 attachments 的字面量 0 放错位置（14 值对 13 列）、fin_voucher_entry 分录 INSERT 辅助核算段 8 个占位符少 1 个（18 值对 19 列），运行期 BadSqlGrammarException。已按列顺序重排。
- **冒烟脚本辅助核算维度补全（测试侧）**：500101 商品销售收入种子配置了 `customer,goods,area` 强制辅助核算，手工凭证缺维度被「必须填写辅助核算：客户」拦截；saveVoucher 测试辅助改为透传全部 7 维。
