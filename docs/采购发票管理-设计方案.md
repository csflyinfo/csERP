## ★ V1.4 改版说明（2026-09-08，Flyway V94，以此节为准）

验收反馈两点：① 勾稽审核后的已勾稽金额也要回写**源单据商品行**（此前只回写收货单头），引入勾稽时带出**剩余未开票金额**；② 报表中心菜单点不开。

1. **库表（V101__pur_receipt_detail_invoiced.sql）**：`pur_receipt_detail ADD invoiced_qty DECIMAL(18,4) DEFAULT 0`、`ADD invoiced_amount DECIMAL(18,2) DEFAULT 0`（含税）；存量按「收货单+商品」汇总已审核发票勾稽行回填。
2. **行级回写 `refreshReceiptLineInvoiced(receiptNo)`**：按收货单全量重算两列 = 该收货单所有**已审核**发票 `pur_invoice_match_line` 的 `this_qty/this_amount` 按商品汇总（草稿不计、作废不计，与单据级 `pur_receipt.invoiced_amount` 口径一致）。调用时机均在**发票状态翻转之后**：审核后（本发票行此刻才计入）、update-matches 后（新旧涉及的全部收货单）、反审核后、作废后（后两者本发票行已剔除）。
3. **选单接口 `/available-lines` 增金额列**：占用子查询在 `SUM(this_qty) AS occ_qty` 旁增 `SUM(this_amount) AS occ_amt`（草稿占量、排除本发票 `excludeInvoiceId` 口径与数量一致）；外层返回 `invoicedAmount`（已开票金额）= occ_amt、`uninvoicedAmount`（剩余未开票金额）= 收货行含税金额 − occ_amt；行过滤仍以「有剩余未开票数量」为准。
4. **前端**：勾稽商品弹窗与勾稽明细表增「已开票金额/未开票金额」两列；选行带入时**本次金额默认 = 剩余未开票金额**（原为数量×单价，尾差场景与真实剩余额不一致）；`PurchaseReceiptDrawer.vue` 已审核收货单详情显示头「来票状态/已来票金额（含税）」与商品行「已开票数量/已开票金额/未开票金额」（`/purchase/receipt/detail` SELECT * 经 queryCamel 自动带出新列）。
5. **报表中心菜单修复（router/index.js）**：侧边栏一级分组展开条件 `activeTop === 分组`，`activeTop = moduleToCategory[route.meta.module] || '首页'`。报表中心第一个菜单项「图表报表」的路由 `chart-report` 缺 `meta.module`，点击后 activeTop 回落「首页」，整个报表中心子菜单（含 5 个发票报表）永不渲染。补 `meta.module: 'chartReport'`；同患同治补 `dashboard`（首页/经营概览）、`todo`（待办中心）、`notification`（消息通知）三条路由。

## ★ V1.3 改版说明（2026-09-08，Flyway V93，以此节为准）

验收反馈三点：① 发票审核后可继续勾稽（不必反审核）；② 勾稽明细表铺满抽屉下部；③ 勾稽时数量、金额都可改，增税率字段（默认带源单据税率），填金额自动算税额。

1. **库表（V100__pur_invoice_match_tax_rate_and_applied.sql）**：
   - `pur_invoice_match_line ADD tax_rate VARCHAR(20)`——勾稽行税率，默认取收货明细税率、可改（票面税率可能与收货不一致）；
   - `pur_invoice_match ADD applied_amount DECIMAL(18,2) DEFAULT 0`——**本发票对该收货单来票额的实际贡献**（置平/封顶后可能 ≠ this_amount）；存量已审核数据回填 `applied_amount = this_amount − diff_amount`。
2. **回退模型由「快照整体复位」改为「按贡献精确剥离」**：V1.1 及以前反审核/作废按 `matched_before` 把收货单来票额整体复位到本发票审核前——隐含「该单只被本发票动过」。审核后可继续勾稽后，同一收货单可被多张发票先后勾稽，整体复位会误伤后来者的贡献。新模型：
   - 审核（audit）：`applied = 审核后来票额 − 审核前来票额`，落 `pur_invoice_match.applied_amount`；
   - 审核后保存勾稽（update-matches）：每张收货单 `base = max(当前来票额 − 本发票 applied_old, 0)`，`目标来票额 = base + 本次勾稽额`，复用 1 元容差置平/超额拒绝规则；`applied_new = 目标 − base`；
   - 反审核/作废：逐单 `目标 = max(当前来票额 − applied, 0)`，只剥本发票贡献。
3. **新接口 `POST /purchase/invoice/update-matches`**：仅**已审核**发票可用（草稿走 update、已作废拒绝）。入参 `{invoiceId, matchLines:[{receiptNo, goodsCode, thisQty, thisAmount?, taxRate?}]}`；`thisAmount` 缺省=数量×收货单价（支持手工金额，2 位小数，负数拒绝）；`taxRate` 缺省取收货明细税率再缺省 13%。校验（供应商/收货单已审核/数量占量，占量统计排除本发票）通过后：重算各收货单来票额并回写 `pur_receipt + fin_ap`、重建 match/match_line/invoice_line 三表、刷新头 `untaxed_amount/tax_amount/matched_amount/match_status`、记 MATCH_SAVE 日志；任何校验失败整体不动（无半写）。
4. **税额口径不变（价内税）**：行税额 = 含税金额 × 税率 ÷ (1+税率)；头税额/不含税额由勾稽行聚合（`buildInvoiceLines`），草稿与已审核同一套口径。
5. **前端（PurchaseInvoiceDrawer.vue）**：勾稽区在「草稿+已审核」两态可编辑（头信息仅草稿可改）；已审核态出「**保存勾稽**」主按钮（调 update-matches 后原地刷新）；勾稽表增**税率**（可编辑）、**本次税额**（实时计算）列，**本次金额**可手工编辑（未手改前随数量联动，amountTouched 标记）；勾稽商品弹窗增税率列；抽屉体改 flex 纵向布局，勾稽明细卡片 `flex:1`、表区 `flex:1; overflow:auto` + 粘性表头，铺满窗口下部。
6. 公共校验收敛为 `collectMatchLines(...)`（create/update/update-matches 共用）+ `matchSumOf(...)` + `buildInvoiceLines(...)`。

## 一、背景与目标

### 1.1 业务诉求

供应商供货后会开具增值税进项发票（专票/普票/电子发票/全电发票）。财务需要：

1. **来票登记**：收到供应商发票后登记票面信息（号码、代码、开票日期、金额、税额、附件）；
2. **来票核销（勾稽）**：把发票对应到具体的采购收货单，回答"这张票是给哪批货开的"；
3. **来票跟踪**：随时回答"**哪些采购商品/哪批货来了发票、哪些没来票**"——未来票/部分来票/已来票；
4. **报表统计**：供应商来票率、未票金额、进项税额、认证进度，支撑付款审批与税务合规。

典型场景（商贸批发/经销企业）：

- 月底付款前，财务拉出"未票采购"清单，**未到票的暂缓付款或扣减税点**；
- 税务申报前，统计本月进项发票份数、税额，跟踪**已认证/未认证**；
- 与供应商对账时，核对对账单上的"是否开票"与实际来票是否一致；
- 商品维度核查：某商品采购入库 1000 件，发票只开了 600 件，催促供应商补票。

### 1.3 目标与非目标

**目标（一期 P0）**

- 进项发票登记（含红字发票字段预留）、审核、反审核、作废；
- 发票与采购收货单勾稽：一票多单、一单多票、部分勾稽、差异提示；
- 收货单/应付单**来票状态**自动回写（未来票/部分来票/已来票）；
- **商品级来票跟踪**：发票商品明细与收货商品明细双向比对；
- 报表：来票跟踪表（单据级+商品级）、供应商来票统计、发票台账（含认证状态）、未勾稽/差异明细；全部支持导出。

- ❌ 发票审核生成/调整应付：本系统应付在收货审核时已定（票账分离架构，见 §5.1），发票不动应付、不动成本；
- ❌ 暂估应付凭证、进项税会计凭证（属 V2.0 财务深化，见 `V2.0-财务核算管理模块PRD.md` 4.4）；
- ❌ 税局验真接口、OCR/扫码识票（预留状态字段与附件位，三期）；
- ❌ 销售发票（销项）模块，菜单 `salesInvoice` 继续占位。

## 二、竞品调研

> 网络检索不可用，以下基于主流 ERP 产品的通行功能体系整理，作为功能取舍参照。

### 2.1 金蝶云星空（K/3 Cloud）—— 钩稽 + 暂估冲回

- **采购发票**分"采购专用发票/普通发票/费用发票"，支持手工新增与**由采购入库单下推/勾稽生成**；
- **钩稽**：发票与入库单（及费用发票）进行钩稽，是成本核算与暂估的枢纽；支持**一票多单、一单多票、部分钩稽**；钩稽后入库单与发票建立关联；
- **暂估冲回**：入库未到票月末暂估入账，票到后钩稽，按"月初一次冲回/单到冲回"处理暂估与发票差异，差异入成本或应付调整；
- **进项税认证**：发票税额进进项税科目，另有税务云模块做勾选认证、验真；
- 报表：采购发票汇总表/明细表、**未钩稽明细表**、暂估明细账、供应商来票统计。

### 2.2 用友 U8 / YonSuite —— 采购结算

- **采购发票**（专用/普通/运费发票）与采购入库单做"**采购结算**"（自动结算/手工结算），即三单匹配（订单-入库-发票）；
- **暂估方式**：月初回冲、单到回冲、单到补差；结算成本处理把暂估与发票差异回写存货成本与应付；
- 发票在**应付款管理**中审核形成应付（未审核发票不进应付账龄）；
- 进项发票**勾选认证**在税务模块（税务工作台），有认证期限预警；
- YonSuite/好业财（云端轻量版）：发票管理支持**票货匹配**、扫码/OCR 录入、进项发票看板（未匹配/未认证预警）。

### 2.3 SAP Business One —— 三单匹配的教科书实现

- 链路：采购订单 PO → 收货采购订单 GRPO（收货时借库存、贷 **GR/IR 暂估清算**）→ **应付发票 A/P Invoice**（基于 GRPO 复制创建，借 GR/IR + 进项税、贷应付）；
- **Three-way matching**：发票数量/金额与 PO、GRPO 自动比对，超出容差（容差可配）阻止过账或进入差异审批；
- 价格差异计入价格差异科目；**贷项凭证 A/P Credit Memo** 处理退货/折让（红字）；
- 报表：未清收货单（货到票未到，即 GR/IR 余额）、应付账龄、进项税清单。

### 2.4 Odoo —— Vendor Bill + 匹配控制

- 供应商账单 Vendor Bill 可由采购订单/收货单自动生成（bill control：基于收货数量开票）；
- **3-way matching** 开关：账单必须匹配 PO 与收货数量，否则阻塞；
- 账单审核生成会计凭证（借费用/进项税、贷应付）；退款单 Add Credit Note 处理红冲；
- 强在账单审批流与 analytic 分析，弱在税务本地化（中国进项认证需插件）。

### 2.5 轻量进销存（管家婆、精斗云、好生意/好业财）

- 不做暂估凭证，核心就是**进项发票登记 + 与采购单勾对 + 未开票统计**；
- 发票字段简化：票号、供应商、日期、金额、税额、附件照片；
- 报表主打"**采购未开票明细**""供应商开票统计"，直接服务催票与付款控制；
- 与本系统定位最接近：商贸流通、票账分离、财务要的是"来没来票"的台账。

**关键架构取舍说明**：SAP/金蝶/用友都是"发票过账才形成应付、收货挂暂估"；本系统 V1.0 落地时应付在**采购收货单审核**即按含税金额生成 `fin_ap`（收货单即"采购结算依据"）。因此本方案采用**票账分离**：

- 收货/应付 = 债务事实（收货审核即定，付款核销照此进行，**不因发票改动**）；
- 发票 = 税务凭证事实（来票登记 + 勾稽来票状态 + 进项税统计）；
- 两者通过勾稽关系关联，**差异只记录与提示，不回写成本/应付**；确属价格错误的，走既有**采购改价单**流程修正债务。这样不动已稳定的应付/付款/成本链路，风险最小，且与轻量竞品的实务做法一致。

## 三、业务流程设计

### 3.1 总流程

```
采购订单 → 采购入库单 → 采购收货单(审核→生成fin_ap应付) ──→ 付款核销（既有，不变）
                                  │
                                  │  供应商开票、财务收票
                                  ▼
                          【采购发票登记】（草稿）
                            ├─ 录票面：票号/代码/类型/供应商/开票日/金额/税额/附件
                            ├─ 选勾稽对象：同供应商「未完全来票」的收货单（自动带出商品明细）
                            ├─ 录本次勾稽金额（可部分；一票多单）
                            └─ 保存草稿 → 审核
                                  │
              ┌───────────────────┼───────────────────────┐
              ▼                    ▼                       ▼
      写 pur_invoice_match   回写收货单来票状态       回写 fin_ap 来票状态
      （勾稽关系流水）       未来票/部分/已来票        未来票/部分/已来票
              │
              ▼
      认证登记（未认证→已认证，收票后随时操作）
      作废（未认证蓝字票；已认证须走红字发票，二期）
```

- **一单多票**：一张收货单 10000 元，先到 6000 元发票勾稽 → 部分来票；后到 4000 元发票勾稽 → 已来票。
- **一票多单**：一张发票 10000 元，同时勾稽 3 张收货单（3000+3000+4000）。
- **票大于单**：发票 10000 元，当前只勾稽 8000 元收货单 → 发票"部分勾稽"，留 2000 元未勾稽余额，等后续收货单到了继续勾稽。
- **商品级跟踪**：勾稽选单时自动把收货单商品明细带入发票明细（商品、数量、单价、税率、金额），财务可按票面调整；商品来票报表按 `goods_code` 汇总比对。

### 3.2 发票登记规则

| 字段 | 必填 | 规则 |
|---|:---:|---|
| 采购发票单号 | 是 | 系统生成，前缀 **PINV**（`BillNoGenerator.BillType` 加常量） |
| 发票号码 | 是 | **同供应商不可重复**（蓝字+红字分别唯一；作废票号保留不允许复用） |
| 发票代码 | 否 | 全电发票无代码，允许空 |
| 发票类型 | 是 | 增值税专用发票 / 增值税普通发票 / 电子发票（增值税电子）/ 全电发票（数电票） |
| 红蓝标志 | 是 | 蓝字 / 红字（一期建字段，红字流程二期） |
| 供应商 | 是 | 选自正常状态供应商档案，勾稽对象限定同供应商 |
| 开票日期 | 是 | 不晚于当前日期；早于今天超过参数 `invoice.issue-date-back-days`（默认 365 天）强提示 |
| 收票日期 | 否 | 默认当天 |
| 不含税金额/税额/含税金额 | 是 | 明细行汇总；价内税口径：`税额 = 含税金额 × 税率 ÷ (1+税率)`，与收货单/退货单同一套算法（`taxInclusiveTax`）。专票默认税率 13%，可改 |
| 购买方信息 | 否 | 我方抬头/税号，从系统参数带出默认值，可改 |
| 认证状态 | 是 | 未认证 / 已认证 / 无需认证（普票、全电普票默认无需认证） |
| 附件 | 否 | 发票影像 PDF/图片，复用既有上传接口，存 URL |
| 备注 | 否 | |

### 3.3 勾稽（来票核销）规则

1. 勾稽对象：同供应商下 **已审核且未完全来票** 的采购收货单（`status=APPROVED`，`invoiced_amount < goods_amount`）。采购退货单（红字勾稽）二期开放。
2. 选单弹窗字段：收货单号、收货日期、订单号、仓库、收货金额（含税）、已来票金额、**未票金额**、本次勾稽金额、差异提示。
3. 校验：
   - 本次勾稽金额 > 0，且 ≤ 该收货单未票金额；
   - 一张发票本次勾稽合计 ≤ 发票含税金额（允许多余部分留作未勾稽余额）；
   - **金额差异**：本次勾稽金额与未票金额不一致即差异（部分勾稽除外——部分勾稽是正常的；差异特指"勾稽完但尾差≠0"或票面金额与收货金额拆分行不一致）：
     - 差异绝对值 ≤ 参数 `invoice.match-tolerance`（默认 1.00 元）：自动置平（勾稽到收货单上的金额按实际，差额计入差异列，报表可见）；
     - 超容差：**允许保存但必须填差异原因**，列表与报表标"有差异"；
   - 发票明细行合计（含税/税额）必须 = 发票头金额（保存时强校验，防止错录）。
4. 审核时点写勾稽关系并回写来票状态（草稿期勾稽可随意改，审核后锁定）。
5. 勾稽明细可在审核前增删；审核后只能**反审核**回退，不允许直接改。

### 3.4 审核 / 反审核 / 作废

**审核**（`/purchase/invoice/audit`，`@Transactional`）：

1. 状态 DRAFT → APPROVED，锁头锁明细；
2. 写 `pur_invoice_match` 勾稽关系（含快照：勾稽前已来票金额、本次金额、差异）；
3. 回写每张收货单：`invoiced_amount += 本次勾稽金额`，重算 `invoice_status`（0=未来票，≥goods_amount=已来票，之间=部分来票）；
4. 按 `fin_ap.source_bill = 收货单号` 同步回写对应 AP 的 `invoiced_amount/invoice_status`（退货负向 AP 二期）；
5. 发票头 `matched_amount = Σ勾稽金额`，重算 `match_status`；
6. 写操作日志（`sys_operation_log_runtime`，沿用 `log()`）。

**反审核**：仅 APPROVED 且**未认证**可反审核；逆向冲销上述 2~5（勾稽关系删除、回写金额扣减、状态重算）。

**作废**：

- 仅 DRAFT 可直接删除/作废；APPROVED 票作废 = 先自动反审核勾稽再置 VOID，必须填作废原因；
- **已认证发票禁止作废**（税法：已认证专票须由购买方开红字信息表），提示"请登记红字发票"（二期流程）；
- 作废后发票号码仍占用（同供应商不可再用），列表默认隐藏、可筛选。

### 3.5 认证登记

- 操作：已审核发票上"认证"按钮，置 `cert_status=已认证`、`cert_date=当天`；可撤销（未申报前）。
- 普票/全电普票默认"无需认证"。
- 二期：超期未认证预警（开票日起参数 `invoice.cert-warn-days` 默认 180 天；注：2020 年 3 月起专票认证确认期限已取消，此预警为企业内部管理用，可参数关闭）。

### 3.6 状态机

```
发票状态 status:    DRAFT(草稿) ──审核──→ APPROVED(已审核) ──作废──→ VOID(已作废)
                       ↑                    │
                       └────反审核──────────┘  （已认证不可反审核/作废）

勾稽状态 match_status: 未勾稽 ──部分勾稽──→ 已勾稽
                        （按 matched_amount 与 total_amount 比较；票>单时停留在部分勾稽）

认证状态 cert_status:  未认证 ──认证──→ 已认证  （可撤销回未认证）
                        无需认证（终态，普票默认）

收货单/应付来票状态 invoice_status:  未来票 ──部分来票──→ 已来票
                        （任何来票回写后 < 全额=部分来票；反审核/作废逆向回退）
```

## 六、报表设计（用户核心诉求）

报表统一走 `GenericBusinessList`（`type:'report', mode:'readonly'`）+ Excel 导出（复用 `/excel/export/*` 模式），图表看板二期加到 `ReportChartPage.vue`。

### R1 采购来票跟踪表（主报表，回答"哪些货/商品没来票"）

两个粒度，页签切换：

**单据级**（数据源：`pur_receipt` 已审核 LEFT JOIN 勾稽汇总）

| 列 | 取值 |
|---|---|
| 收货单号 / 收货日期 / 供应商 / 仓库 / 采购订单号 | 收货单头 |
| 收货金额（含税） | `goods_amount` |
| 已来票金额 | `invoiced_amount` |
| **未票金额** | goods_amount − invoiced_amount |
| 来票率 | invoiced_amount / goods_amount |
| 来票状态 | 未来票/部分来票/已来票（红/黄/绿色标） |
| 已勾稽发票号 | `GROUP_CONCAT(pur_invoice_match.invoice_no)` |
| 账龄 | 当前日期 − 收货日期（未票超 N 天提示催票） |

筛选：日期范围、供应商、仓库、来票状态、商品（穿透到明细）、关键字。

**商品级**（数据源：`pur_receipt_detail` 按 goods_code 汇总 FULL JOIN `pur_invoice_line` 按 goods_code 汇总，期间范围）

| 列：商品编码/名称/规格/单位 | 采购收货数量/金额 | 已来票数量/金额（发票明细汇总） | 未票数量/金额 | 来票率 |
|---|

> 商品级口径说明：发票明细行 `source_receipt_no` 可追溯到收货单；统计以"已审核发票"的明细行为准。数量比对允许尾差（分批开票），报表按金额来票率排序，**未票金额 TOP 商品排最前**，直接输出催票清单。

### R2 供应商来票统计

按供应商 × 月份（或期间）汇总：

| 供应商 | 采购收货金额 | 来票金额 | 未票余额 | 来票率 | 发票份数 | 进项税额 | 已认证税额 | 未认证税额 |
|---|

用途：月度供应商付款/催票例会；未票余额高的供应商付款时重点关注。

### R3 进项发票台账（列表页增强即可，不单独建报表）

发票列表页本身即台账，补两个看板统计条（列表顶部）：**本期发票份数 / 含税合计 / 税额合计 / 未勾稽金额 / 未认证份数**；认证状态列支持筛选；超期未认证行标红（二期预警）。

### R4 未勾稽与差异明细

- 上半部：**未勾稽/部分勾稽发票**（`match_status <> '已勾稽'`）：发票号、供应商、含税金额、已勾稽、未勾稽余额、开票日期——票到了但还没对应到货/单，或票多开；
- 下半部：**勾稽差异清单**（`pur_invoice_match.diff_amount <> 0`）：发票号、收货单号、差异额、差异原因——财务核查价格/折扣问题。

### R5（二期）图表

`ReportChartPage` 加 2 图：近 12 月采购来票趋势（收货额 vs 来票额双柱+来票率折线）、供应商未票余额 TOP10。

## 十、验收标准（一期）

1. 登记一张专票（10000 含税，13%），勾稽 2 张收货单（6000+4000），审核：发票"已勾稽"，两张收货单"已来票"，对应 `fin_ap` 来票状态=已来票；收货单列表/应付列表可见来票状态。
2. 一张收货单 10000 元，先后两张发票 6000/4000 勾稽：第一次后收货单"部分来票"、未票 4000；第二次后"已来票"。
3. 发票 10000 勾稽 8000：发票"部分勾稽"、未勾稽余额 2000；该 2000 出现在 R4 未勾稽清单；后续另一收货单勾稽 2000 后转"已勾稽"。
4. 勾稽尾差 0.5 元内自动置平；尾差 50 元必须填差异原因，R4 差异清单可见。
5. 反审核：勾稽关系清除，收货单/AP 来票金额与状态逆向回退；已认证发票反审核/作废被拒。
6. 作废已审核发票：状态已作废、勾稽全部回退、票号不可再用。
7. 同供应商重复发票号码保存被拒。
8. R1 单据级：未票金额、来票率、来票状态正确，发票号可反查；R1 商品级：某商品收货 1000 件/13000 元、来票 600 件/7800 元，未票 400 件/5200 元，来票率 60%。
9. R2 供应商统计：期间收货额、来票额、未票余额、份数、税额与明细一致。
10. 全部报表可 Excel 导出；草稿可删可改，审核后不可改头/明细。

## 十一、技术注意事项（本项目踩坑记录）

- 金额口径：采购为**价内税**，税额倒算 `含税 × 税率/(1+税率)`，与 `PurchaseReceiptController.taxInclusiveTax` 同一公式；应付/来票金额都按**含税**口径。
- SQL 一律普通字符串拼接并显式写空格，**不用 Java 文本块拼 SQL**（行尾空格被裁致片段粘连 500）。
- H2 `MODE=MySQL` 下 JOIN SELECT 同名列必须加表别名限定；不用 `UPDATE...FROM`，回写用循环 update。
- 后端在 `backend/` 目录启动（H2 相对路径）；冒烟测试会删单据，验证前备份 data/erp-v1。
- 编译用 `/c/Soft/apache-maven-3.9.16/bin/mvn -o`（mvnw 离线必失败），JDK21。
- 前端验证可参照 worktree + node_modules junction + 8081 空库后端的隔离方案。
