## 二、部署级待办（必须上线前确认）

以下项目**无法在代码里安全地默认改**，列在此处交运维/负责人决策。每项给出建议值与原因。

### 1. JWT 密钥必须轮换并外置（CRITICAL）

- 现状：`application.yml` 默认 `erp_jwt_secret_key_2024_change_in_production`，`docker-compose.yml` 生产环境仍用同一值；该字符串已进 Git 历史。
- 风险：拿到源码/镜像即可伪造任意用户（含 ADMIN）的 JWT。
- 建议：
  - 生产用 `JWT_SECRET` 环境变量注入，至少 64 字符随机串（`openssl rand -base64 64`）。
  - 轮换后所有已登录用户的 token 失效，需要重新登录——提前公告。
  - 不要把生产密钥提交到任何仓库，用 `.env`（已 gitignore）或 secret manager。

### 2. docker-compose 里的所有默认口令必须换（CRITICAL）

- 现状：compose 文件中 MySQL/Redis/MinIO 的账号密码、`JWT_SECRET` 全是弱默认值且已进 Git；端口 `3306`/`6379`/`8080` 直接映射到宿主机。
- 建议：
  - 所有服务口令改为随机强口令，通过 `.env`/secret 注入；
  - 数据库/缓存/对象存储端口**不要**暴露公网，只在 compose 内网可达；
  - 若必须暴露，绑 `127.0.0.1:` 并加防火墙白名单。

### 3. 强制 prod profile（HIGH）

- 现状：`application.yml` 默认 profile 是 `dev`，H2 console 开着、sa 空密码、SQL 错误可能更啰嗦。
- 建议：生产启动参数固定 `SPRING_PROFILES_ACTIVE=prod`；`application-prod.yml` 中：
  - `spring.h2.console.enabled=false`（生产用 MySQL/PostgreSQL，根本不需要 H2 console）；
  - 用真实数据源，不使用 H2 文件库；
  - 关闭 actuator 敏感端点或加 ADMIN 鉴权（`/actuator/health` 可保留，其它按需）。

### 4. H2 console 生产必须关闭/绑本地（HIGH）

- 现状：`/h2-console/**` 在 SecurityConfig 里 `permitAll`，且 dev profile 下 sa 空密码可直连。
- 建议：见上条；如临时排障需要，仅通过 SSH 隧道访问 `127.0.0.1:8080/api/h2-console`，用完即关。

### 5. 司机端验证码 888888 必须替换（HIGH）

- 现状：`TmsAuthService.DEV_VERIFY_CODE = "888888"`，`/tms/app/login` 对验证码固定放行。
- 风险：任意人知道司机手机号即可登录司机端；配合 #5 之前的越权还能清库。
- 建议：
  - 接真实短信通道（阿里云/腾讯云 SMS），验证码 5~10 分钟过期、按手机号 + IP 限频（如 1 分钟 1 次、1 小时 5 次）；
  - 固定 888888 只在 `dev` profile 保留，prod profile 启动时若读到该值直接 fail-fast。

### 6. TLS / HTTPS（HIGH）

- 现状：后端 HTTP 明文，JWT 在 Authorization 头里裸跑；HSTS 头已下发，但浏览器只在 HTTPS 下生效。
- 建议：在 Nginx/Ingress/负载均衡层终止 TLS，所有 HTTP 301 到 HTTPS；后端只监听内网。

### 7. 细粒度角色矩阵（MEDIUM，业务决策）

- 现状：Spring Security 只有一条规则——`/system/**` 要 ADMIN，其它登录即可；没有「财务只能审 AR/AP」「仓管只能动 WMS」「跨仓库数据隔离」「导出审批」等。
- 建议：结合实际岗位，在方法层用 `@PreAuthorize("hasAuthority('wms:release')")` 等细化；或在网关层按 URL 前缀分组授权。本次不动，避免把现有用户锁死。

### 8. ADMIN 默认密码与首次登录改密（MEDIUM）

- 现状：种子库 `admin/admin123`。
- 建议：首次登录强制改密；密码长度/复杂度策略；长期不用的账号自动停用。
- 说明：审计中确认了登录校验要求 BCrypt `$2a$` 前缀，老代码里的明文 `admin/admin123` fallback 实际不会通过验证（不是后门），但种子库本身的弱密码必须改。

### 9. data/*.trace.db 与种子库的取舍（LOW）

- 现状：仓库根 `data/erp-v1.mv.db` 是受控种子库（已决定保留跟踪），但 `*.trace.db` 是 H2 运行时临时文件。
- 建议：在 `.gitignore` 中确认 `**/*.trace.db` 已忽略；不要把它当成业务数据备份。

### 10. 前端 localStorage token 的 XSS 面（LOW）

- 现状：JWT 存 localStorage，任何 XSS 都能读走。
- 本次已做：所有入库 URL 协议白名单、CSP 头下发、全局异常不回显原始消息。
- 进一步：敏感操作（审核/反审核/删单）可考虑二次密码或短期 step-up token；CSP 在上生产后可收紧 `script-src`（去掉 `'unsafe-inline'`，需要前端构建配套 nonce）。

## 三、验收建议

1. 用普通账号（非 ADMIN）调 `POST /api/testing/cleanup-smoke` 应返回 403；ADMIN 仍可执行（先备份 H2）。
2. 对同一销售订单并发两次 `POST /api/wms/recheck/pass`：一次成功，另一次幂等返回相同发货单号；库存只扣一次。
3. 直接调 `/api/sales/outbound/audit` 重复审核同一张出库单：第二次返回「已审核（幂等返回）」，库存/发货单不重复。
4. 在司机端上报异常时，把 `photos[0].url` 改成 `javascript:alert(1)`，后端应返回 400 或直接丢弃该附件，前端不弹窗。
5. 故意传一个不存在的 orderId 给后端，响应里不应出现 SQL 表名/约束名/Java 堆栈。
6. 响应头应包含 `X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Content-Security-Policy`、（HTTPS 下）`Strict-Transport-Security`。
