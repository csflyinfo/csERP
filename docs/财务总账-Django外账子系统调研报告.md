## 一、总体结论（先看这段）

Django 这套财务外账是一套**骨架完整、自洽且经测试验证**的总账实现：账套→科目→期初→凭证模板→事件池→凭证（草稿/审核/过账/红冲）→余额表→期末结账/结转损益→三大报表→固定资产，全链路打通，并有 1369 行回归测试覆盖。

**对我方最有价值的 6 个设计**（详见第九章）：

1. **事件池模式**：业务审核只"丢事件"（AFTER 业务事务 + 吞异常），会计在"待生成凭证"页批量生成**草稿**凭证再审核过账。业务永远不被财务配置问题阻塞，月末结账不锁业务。
2. **AST 白名单表达式引擎**：凭证模板金额（如 `amt_tax_incl / (1 + tax_rate)` 算不含税）和报表取数公式（`QM(1001)+QM(1002)`）都是数据驱动的安全表达式，不用硬编码、不用 eval。
3. **资产负债表"期中也平"的本年利润公式**：`QM(4103) + 损益类科目期末余额`，结转前后期末数都对——注释里明确写"这是很多小软件的通病"。
4. **结账四检查 + 反结账约束**：全部凭证过账、本期借贷平衡、损益已结转、上期已结；反结账必须填原因、只能从最后一个月倒着反。
5. **固定资产全套业务规则**：当月新增次月提、提满残值自动停、双倍余额最后两年改直线、清理走 1606 固定资产清理算处置损益、拆分/合并不生凭证（账面价值不变）、变更不许直接改原值、盘亏只留痕不自动清理。
6. **过账即增量写余额表 + 开账铺行**：无发生额科目也铺余额行，保证期末合计恒平；测试用"期末=期初+本期逐行校验"兜底。

**必须避开/不能照搬的 5 点**：

1. **科目编码存在准则混搭**：主营损益科目（5001 收入 / 5401 成本 / 5601-5603 费用）用的是 2013《小企业会计准则》编码（与其标称一致），但营业外收支用了 6301/6711（《企业会计准则》编码，小企业准则应为 5301/5711）；明细科目用点分表示（2202.01/5001.01）。**我方落地方案存在同样的名实不符**——标称小企业准则，损益类却用 6001/6401/6601-6603（企业准则编码），开发前必须先统一口径（见第九章第 19 条）。
2. **金蝶/用友导出只做了"平铺 JSON + 科目映射"，没有真正生成文件**（全工程无 openpyxl/csv 写入），前端按钮是演示占位；**凭证打印完全未做**。这两块我方要自建到位。
3. **现金流量表公式留空、纯手工填**，仅净额一行用现金科目 QM-QC。我方落地方案的"分录级现金流量项目指定"比它强，应坚持。
4. **无 RBAC、无制审分离校验、无业务层与总账的对账功能**——测试再全，业务往来（AR/AP）与总账（1122/2202 辅助核算）是两套数，没有任何对账接口。
5. 多账套/受托代销（平台账/货主账、1407/2203/代销口径）是为其三方物流货主业务定制的，我方单体公司用不上，照搬只会增复杂度。

## 二、系统定位与架构

### 2.1 两个财务 app 的边界（与我方现状高度相似）

| app | 前缀 | 定位 | 表 |
|---|---|---|---|
| `apps/finance` | `/finance/` | **业务财务层**：收款/付款、应收/应付、费用/其他收入、资金账户 | 老库表只读 ORM 映射（`managed=False`，无迁移） |
| `apps/finance_gl` | `/finance-gl/` | **总账（外账）**：科目、凭证、账簿、报表、固定资产 | 24 张 `fin_*` 新表（Django migration 建） |

这与我方 erp-wms-tms 的分层完全同构：V32-V44 的 `fin_ar/fin_ap/fin_receipt_bill/fin_payment_bill/fin_expense_bill/fin_fund_ledger` 等是业务财务层，本次要建的总账是第二层。**Django 版没有做两层之间的自动对账**——这是它的缺口，也是我方可以超越的点。

### 2.2 多租户 / 多账套

- 多租户：所有表继承 `TenantModel`，`tenant_id` 由 thread-local + Manager 隐式注入，业务代码无感。
- 多账套：`FinBook` 一本一账——平台 1 本（book_type=1）+ 每个货主 1 本（book_type=2）。科目/期初/凭证/余额/期间全部按 `book_no` 隔离；凭证模板、核算维度、报表模板、自动转账、资产类别全租户共用，用 `book_scope`（平台/货主/全部）+ `condition_json`（如 `{"is_self_run": false}`）区分记账口径，专用模板优先匹配。
- **我方结论**：单体公司无需账套概念，期间表全局一份即可；模板的"条件匹配"思想可简化保留（同一事件码按业务属性选模板）。

### 2.3 技术栈与代码量

- Django + DRF（APIView），金额 `DecimalField(max_digits=19, decimal_places=6)` 存储、凭证层 quantize 到 0.01（HALF_UP）；接口金额一律字符串返回防浮点误差。
- 后端 4972 行（hooks 720 + views 818 + models 644 + asset_engine 653 + engine 564 + period_engine 506 + p2p3_views 418 + preset 378 + preset_report 188 + urls 83），另测试脚本 1369 行。
- 权限：接口仅 `IsJWTAuthenticated`（登录即可），finance_gl 前缀未进全局 RBAC 映射表，**fail-open 无功能权限**；制单/审核/过账只是状态机 + maker/checker/poster 留痕，不校验"不能审自己的凭证"。

## 四、核心机制详解

### 4.1 初始化流程（建账→期初→试算→启用→铺余额）

1. 建账套（status=0 筹建）时自动灌预置：10 个辅助核算维度、39 个科目（受托代销专用 1407/2202.02/2203/5001.02 只灌平台账）、18 个凭证模板、3 张报表模板、1 个自动转账（月末结转未交增值税）、8 个资产类别。
2. 期初**整表保存**（先删后插），每次查询实时返回试算平衡结果（借方合计=贷方合计，容差 0.005）。支持辅助核算期初（aux_key/aux_text）、数量期初、本年累计发生。
3. **启用账套**前强制试算平衡，不平拒绝；启用后 `is_init_done=true`，期初锁死不可再改，同时开首个期间。
4. `open_period()` 把期初（或上期期末）**铺成当期 FinBalance 行**——没有发生额的科目（如实收资本）也必须有余款行，否则期末合计平不了。这是个精心处理的细节。

> 借鉴：我方"初始化（期初+辅助核算期初+试算平衡）"直接按此状态门控实现——期初录入页实时试算、启用即锁死。

### 4.2 科目与辅助核算

- 科目树形：parent_code + level + is_leaf，新增下级自动把上级改非末级；凭证只能用末级+启用科目；预置科目编码不可改、可停用，停用后不影响老凭证。
- 辅助核算：科目挂维度（`fin_subject_aux`，is_required）；10 个维度中**引用式维度**（客户/供应商/商品/部门/片区/业务员/货主/账户/合作伙伴）值实时取基础资料，自定义维度（项目）才落 `fin_aux_item`。
- 分录上 9 个结构化列 + 冗余 `aux_key`（维度排序后 `TYPE:code` 用 `|` 拼接）+ `aux_text`（中文名串）。aux_key 是余额表、账簿按辅助核算聚合的主键。
- **必填校验**：模板配置 `OPTIONAL_AUX={'DEPT','AREA','EMPLOYEE','CUSTOM_PROJ'}`（分析类维度可选；往来单位类维度必填），生凭证时 `check_required_aux()` 拦截。

> 借鉴：我方落地方案的 7 个结构化辅助核算列（客户/供应商/商品/部门/片区/业务员/项目）+ aux_key 冗余键的设计与之一致，保持。aux_key 排序拼接规则要固定（保证同值同键）。

### 4.3 凭证模板与表达式引擎（亮点）

**模板 = 事件码 + 作用域 + 条件 + 借贷分录行**，每行含：方向、科目、金额表达式、数量表达式、辅助核算映射、摘要规则。

- 金额表达式是**安全算术表达式**，payload 为变量。典型：
  - 不含税金额：`amt_tax_incl / (1 + tax_rate)`
  - 税额：`amt_tax_incl - amt_tax_incl / (1 + tax_rate)`
- `eval_amount()` 用 `ast.parse(mode='eval')` 白名单解析：只允许 Add/Sub/Mult/Div/USub/UAdd 和数字常量，禁止任何 Name（除 payload 字段）、属性访问、调用；除零保护；结果 quantize 到 0.01。测试专门用 `__import__`/`open`/`__class__` 验证注入全拦。
- 辅助核算映射 JSON：`{"CUSTOMER":"consumer_no", "ITEM":"item_no"}` 取 payload 字段；固定值语法 `"=PLAT|平台结算户"`；`<field>_name` 自动解析中文名。
- 18 个预置模板覆盖：采购入库（货主/自营）、受托代销入库、销售出库（货主全额收入成本 / 平台代销 1122↔2202.02 + 2203↔1407 / 自营买断）、货主三费、客户收款、货主付款、供应商付款、销售退货（**金额取负=红字**）、费用、其他收入、库存盘点（1901 待处理财产损溢）。
- merge_rule 支持一单一凭证 / 按日汇总 / 按客户汇总。

> 借鉴：我方原方案模板金额用"固定值标签"（不含税/税额/金额几个固定槽位），表达力不够（价外费用、净额结算等场景要硬编码）。**建议升级为表达式驱动**：Java 侧无需引新依赖，用 **Spring 自带 SpEL 的 `SimpleEvaluationContext`**（默认禁类型引用/构造/Bean 引用，数据绑定白名单）即可达到同等安全级；或写一个几十行的递归下降四则运算解析器。报表公式同理（见 4.8）。

### 4.4 事件池与凭证生命周期（最大架构差异点）

**业务侧不直接生凭证，而是丢事件**：

```
业务单据审核（业务事务提交后）
  → hooks.on_xxx()：@safe_hook 吞掉一切异常
  → engine.push_event()：写 fin_acct_event（payload_json = 单据全量快照）
  → 会计在"待生成凭证"页：批量勾选 → generate_safe()
  → match_template()（事件码+作用域+condition_json，专用优先）
  → generate_voucher()：校验账套启用/期间开账/模板/末级启用科目/必填辅助核算，
     跳过零金额行，借贷差>0.005 拒绝 → 生成【status=0 草稿】凭证，事件置"已生成"
  → 会计审核 check_voucher()（0→1）→ 过账 post_voucher()（1→2）
```

- 生成失败：事件置 status=3 + err_msg，在待生成页可见原因，改完配置可重新生成。
- 会计可把不需要做账的事件置"已忽略"（status=2）。
- 凭证号：账套+期间+凭证字内 `MAX(voucher_no)+1`，作废号不复用。
- **红冲** `red_reverse()`：仅已过账可冲；生成金额全取负的凭证、is_red=true、red_source_id 互链、摘要"红字冲销 记-0007"；要求目标期间开账；同一凭证只许冲一次（双重冲销拦截）。未过账凭证可直接删除。
- 弃审业务单据 → `_reverse_events()`：写反向事件（金额取负、reverse_of 关联原事件），未过账的原凭证可删，已过账的走红字冲销。
- 幂等：`_already_pushed()` 按 source_type+source_no+event_code+book + 事件状态(0/1) 去重。

**为什么这么设计（hooks.py 开头三条铁律）**：
1. 每个 hook 吞所有异常——财务故障绝不阻塞业务审核；
2. 业务事务提交之后才调用；
3. 没建账套静默跳过。

> **对我方的核心建议（建议修订落地方案的同事务生凭证决策）**：
> 我方原方案选择"业务审核同事务生凭证、失败回滚业务、过账后禁止弃审"。Django 的落地实践证明事件池模式更适合外账场景：
> - **外账凭证必须经会计审核**，自动生成后直接过账不符合实务（金蝶/用友也是生成→审核→过账分步）；
> - **月末结账后业务不能停**：期间关账后，业务仍在发生（次月单据、补单），同事务生凭证会因"期间已结账"直接阻断业务审核；事件池让事件带着业务日期躺在池里，会计反结账或次月处理即可；
> - 模板配错/科目停用/辅助核算缺失在业务高峰期不应让仓库发货审核报错；
> - 事件池天然是"业务↔总账对账"的数据源（每张业务单据有无凭证、凭证号多少、失败原因）。
>
> 代价：多一张事件表 + 一个"待生成凭证"工作台页面；总账滞后业务（可加"未生成凭证事件"提醒）。Spring 实现无需新依赖：`@TransactionalEventListener(phase=AFTER_COMMIT)` 是 Spring 原生能力；hook 内 try-catch 兜底。
> **建议落地方案 P2 改为**：7 类业务钩子改为 AFTER_COMMIT 丢事件（payload 快照 JSON 存列），新增"待生成凭证"列表页（生成/忽略/重生成/查看错误），生成的凭证为草稿，走统一的审核→过账；弃审丢反向事件。

### 4.5 业务挂接点（hooks.py 实测清单）

### 4.6 过账与余额表

- `post_voucher()`：逐分录 `_apply_to_balance()`（select_for_update 行锁），按科目 balance_dir 滚动期末余额；`_carry_forward()` 上期期末→本期期初，无上期则取期初。
- 余额表带**数量四栏**（期初/入/出/结），支持数量核算科目（is_qty）。
- 测试交叉验证：逐科目"余额表期末数 = 已过账凭证分录汇总"，且"期末=期初+本期发生"逐行成立。
- 账簿查询全部读余额表 + 凭证分录：总账（科目×期间滚动）、明细账/序时账（传科目=带累计余额的明细账，不传=时间序列时账）、多栏账（选上级科目，子科目摊成列、一凭证一行）、科目余额表。

> 权衡：我方落地方案选择**不建物化余额表、从已过账分录实时聚合**（省去过账增量写的一致性风险）。Django 的物化方案经测试证明可行，且带来两个好处：报表/账簿查询快、数量余额天然支持。**建议维持实时聚合**（我方数据量小、H2/MySQL 聚合性能足够，少一处一致性维护点），但借鉴两点：
> ① 余额表报表/账簿查询时以科目主档 LEFT JOIN 聚合结果——**无发生额科目也要出场**（对应它的"开账铺行"）；
> ② 账簿与报表的取数口径统一为"期初+本期发生=期末"，结账检查里加这条恒等校验；
> ③ 数量核算（库存商品 1405 挂数量）如要支持，实时聚合需 SUM(qty)，分录表已有 qty/price 列，可行。

### 4.7 期末处理

**结账四检查**（`close_checks()`，任一不过拒绝结账，force 可强结但留痕）：
1. 本期凭证全部过账（无草稿/已审核未过账）；
2. 本期借贷发生额合计平衡；
3. 损益已结转（或损益类科目无余额）；
4. 上期已结账（期间连续）。

**结转损益** `carry_forward_profit()`：
- 损益类科目（编码 5/6 开头）按本期净额转 4103 本年利润：收入类净贷方→借收入贷 4103；费用类净借方→借 4103 贷费用；
- 凭证字"转"，source_no=`JZ{period}` 幂等（同期重复结转拦截），凭证日期=期间最后一天；
- 同样生成**草稿**，需审核过账。

**自动转账** `run_auto_transfer()`：预置 1 个——月末结转未交增值税（借 2221.01 销项、贷 2221.03 未交增值税，金额 `FSC(2221.01)-FSD(2221.02)`）；source_no=`ZZ{编号}{期间}` 幂等，借贷不平/为零跳过。

**结账/反结账**：结账 → 期间 status=2 锁死、账套 current_period 推进、自动 open_period 下期；**反结账必须填原因（留痕 reopen_by/time/reason）、只能反最后一个已结期间**（后面没有更晚的已结期间）。

> 借鉴：四检查、结转损益幂等键、反结账约束全部直接采纳。我方年结冻结（12 月结账转利润分配）在它这里没有（系统未到年结场景），按我方方案保留。

### 4.8 报表与取数公式语言（亮点）

**公式语言**（period_engine.py，AST 白名单解析，与模板表达式同一思路）：

| 函数 | 含义 |
|---|---|
| `QM(1001)` | 期末余额（按科目余额方向定借贷正负） |
| `QC(1001)` | 期初余额 |
| `FS(5001)` | 本期发生额（按方向） |
| `FSD/FSC(5001)` | 本期借方/贷方发生额 |
| `LJ(...)` | 本年累计发生 |

- 科目参数支持**区间** `1001:1012` 和**父子前缀**（点分编码 `startswith(code+'.')`；我方数字编码对应 `LIKE concat(code,'%')` 按层级匹配）。
- 报表项两行公式：`formula`（本期/期末）+ `formula_begin`（年初/上期）——年初数由期末公式里 `QM(` 机械替换成 `QC(` 生成。
- BS 平衡校验：is_total 行的资产总计 vs 负债权益总计，容差 0.015，不平禁止导出。
- **关键技巧——本年利润行公式**：
  `QM(4103)+QM(5001)+QM(6301)-QM(5401)-QM(5402)-QM(5601)-QM(5602)-QM(5603)-QM(6711)`
  即"已结转的 4103 + 损益类科目期末余额"。结转后损益科目余额为 0 不重复；结转前（期中）损益余额体现在未分配利润里，**期中未结转时资产负债表也平**。原注释："这是很多小软件的通病——期中看资产负债表永远不平，会计会以为账崩了。"
- **现金流量表**：除"现金净增加额=QM(现金科目)-QC(现金科目)"等 3 行外，**经营/投资/筹资各项目公式全部留空，由会计手工填**——即放弃了自动归集。
- 利润表：FSC(收入) 取贷方发生、FSD(成本费用) 取借方发生。
- 预置数据：BS 27 行、IS 11 行、CF 17 行，会计可改公式（FinReportItem 可编辑）。

> 借鉴：
> ① **报表公式引擎采纳**——比我方原方案"科目:取数类型"的前缀匹配表达力强得多（区间、四则混合、年初数机械派生），Java 侧用 SpEL 或小解析器实现，种子数据放 Flyway；
> ② **本年利润期中平衡公式必须采纳**，科目号随我方最终准则口径（见第九章第 19 条）：若统一小企业准则为 `QM(4103)+QM(5001)+QM(5301)-QM(5401)-QM(5402)-QM(5601)-QM(5602)-QM(5603)-QM(5711)`；若用企业准则为 `QM(4103)+QM(6001)+QM(6301)-QM(6401)-QM(6601)-QM(6602)-QM(6603)-QM(6711)`；
> ③ **现金流量表不要学它留空**——坚持我方分录级 `cash_flow_item` 指定（手工凭证必选现金科目时选择项目、自动模板带项目映射），报表按项目 FS 取数，净额行用它的 QM-QC 公式做交叉校验。

### 4.9 固定资产（asset_engine.py，规则可整体照搬）

- **四种折旧方法 + 不提折旧**：
  - LINE 直线法：(原值-残值)/使用月数；
  - DOUBLE 双倍余额递减：年率=2/年限、按月初净值（不扣残值）计提，**最后两年自动改直线**（准则要求）；
  - SUM 年数总和：剩余年数/年数总和；
  - WORK 工作量法：按当月工作量占比；
  - NONE 不提（土地使用权，走无形资产 1701/1702）。
- **共同规则**：当月新增当月不提、次月起提；提到净值=残值停止；已清理/拆分/合并不提；**最后一个月自动补齐到残值、不提超**（`return remain if amt > remain else amt`）。
- 月度计提：按"费用科目+部门"汇总生成一张"转"字凭证（借 5602/5601 费用、贷 1602 累计折旧），source_no=`ZJ{period}` 幂等；同期重提要先删折旧记录和凭证；逐卡写 fin_asset_depreciation（折旧前/后累计折旧、净值）并更新卡片。
- **建卡**：默认同时生入账凭证（借 1601 / 贷 1002），写 ADD 变动记录。
- **变更**：部门/地点/保管人/年限/方法可改，**原值禁止直接改**（要走清理重建），写 MODIFY 留痕。
- **清理**：转原值+累计折旧到 1606 固定资产清理，处置收入/费用进 1606，差额=收入-费用-净值 → 正数贷 6301 营业外收入、负数借 6711 营业外支出；卡片置已清理、写 DISPOSE 记录（含损益）。
- **拆分**：一卡拆多卡，按 ratio 分摊原值/累计折旧/残值，**最后一张卡吃四舍五入尾差**保证合计不变；账面价值不变故**不生凭证**；原卡置"已拆分"。
- **合并**：多卡并一卡，原值/累计折旧相加，**仅限同一资产类别**（折旧方法年限一致）；不生凭证；旧卡置"已合并"。
- **盘点**：开盘点单拉在用+停用卡片 → 录结果（found/实际地点/备注）→ **盘亏只写 CHECK 变动记录"待人工核实"，不自动清理/停用**。
- **资产台账报表**：按类别"期初→本期增减→期末"滚动；期末取卡片当前值，期初=期末-本期 ADD+DISPOSE 转出（不留历史快照），附"期末=期初+增-减"校验（容差 0.02）。
- 预置 8 个资产类别（房屋 240 月/机器 120/运输 48/电子 36/家具 60/仓储 120/冷链双倍 120/土地 NONE），残值率 3%-5%，各类别带 1601/1602/费用科目（运输工具→5601.03 销售费用，仓储/冷链→5601.02，其余→5602）。

> 借鉴：我方 P4 固定资产分支直接按这套规则实现（科目换成 1601/1602/1606/1701/1702/6301/6711，费用科目 6601 销售费用/6602 管理费用）。特别注意"双倍余额最后两年改直线""最后一月补齐残值""拆合并不生凭证、合并限同类、尾差末张吃""盘亏不自动处理"这几条实务规则。

## 七、优点总结

1. **事件池解耦**：业务与财务通过"事件+快照"衔接，故障隔离、可重放、可忽略、失败可见，天然带业务→凭证追溯链。
2. **一切规则数据驱动**：模板金额、辅助核算映射、报表取数、自动转账、资产类别科目都是配置，AST 白名单保证安全，新增业务类型不改代码。
3. **状态机严谨**：凭证草稿→审核→过账→红冲、期间未开/已开/已结、卡片 5 态，每个状态转换都有前置校验和留痕；幂等键齐全（JZ{period}/ZJ{period}/ZZ{no}{period}/事件去重四元组）。
4. **实务细节到位**：期中 BS 平衡公式、进项税方向、当月新增次月提、双倍余额末两年改直线、尾差处理、盘亏不自动处置、反结账强制原因。
5. **测试密度高**：33 组回归覆盖正常流+边界+注入，余额恒等和报表平衡有程序化校验。

## 八、不足与坑（我方规避）

1. **科目编码准则混搭、科目不全**：5001/5401/5601-5603 是《小企业会计准则》编码（名实相符），但营业外收支 6301/6711 用的是《企业会计准则》编码（小企业准则应为 5301/5711）；缺 5051 其他业务收入、5403 税金及附加、5701 所得税费用等科目，利润表"所得税费用"行公式硬编码 `'0'`。点分明细（2202.01）只是层级表示风格，金蝶/用友通用，不算错误。
2. **进项税额科目 balance_dir 必须标"贷"**：它是负债抵减项，若按常规标"借"，QM 聚合时方向算反，资产负债表差额=进项税×2。这是测试里实测出来的坑（preset.py 有注释）。我方 22210101 进项税额建科目时余额方向要定"贷"，报表/余额聚合按"上级负债方向汇总、子科目借余抵减"处理。
3. 现金流量表弃疗（手工填）；凭证打印未做；导出无真实文件。
4. 无功能权限、无制审分离、无业务财务与总账对账。
5. 多账套/受托代销复杂度高（1407/2203/5001.02/2202.02、平台货主双模板），单体公司不需要。
6. 金额字段 decimal(19,6) 精度过剩（凭证层仍 quantize 2 位）；事件列表无分页；hook 吞异常后若无事件池页面巡检，失败事件可能被遗忘（我方应加未处理事件角标提醒）。
7. 资产台账"期初=期末倒推"不留历史快照，卡片删除/改期会污染历史（我方台账可接受同口径，但需知其限制）。
