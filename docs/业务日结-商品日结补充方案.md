# 业务日结补充方案：商品（库存）日结定版

> PRD-33《业务日结-设计方案》补充件，版本 v1.4-supplement（评审定稿版）
> 分支：`feat/finance-goods-daily-close`（基于 PRD-33 squash 提交 ca15436，需先合入 PRD-33）
> 迁移：V121（V120 已用）
> 状态：**已评审定稿并开发完成，隔离库验收通过（2026-09-14）**
>
> **评审结论（2026-09-14 终审）**
> - **Q1 采纳**：签收口径四列（signed_qty/signed_amount/signed_cost_amount/gross_profit）**同期冻结**在 `biz_close_goods_daily`，与实物收发并列、互不勾稽。
> - **Q2 不做批次级定版**：不建 `biz_close_goods_batch_daily`。定版粒度只到 **日 + 商品 + 仓库**；批次/效期追溯维持现状（批次实时表 + 库存台账查询），如日后需要单独立项。

---

## 一、为什么要补

PRD-33 索引行承诺「固化库存/应收/应付/资金**四类**定版日余额」，但 V120 只落地了应收/应付/资金三张定版表，库存类只做了：

- 向导第 4 步 DWS 刷新与对账（`rpt_dws_stock_move_d`）；
- 第 5 步「前一日快照 + 当日收发 − 当前库存」的商品+仓库粒度硬勾稽，但**结果不落定版**；
- 反结时删 `inv_stock_daily_snapshot` 对应日行（分析快照，含在途/7 日动销等预测列，没有期初、分类收发、签收口径，也没有 close 烙印）。

缺口：已结日期的商品数据没有一张**带日结烙印、反结即删、重算不可改**的定版表，导致——

1. 商品进销存日报只能用「当前实存倒推期初」（报表 #8 现状），反结改动后历史会变形；
2. 每个商品的收发存与当前实存对不对得上，只有结账那一刻在向导里看得到，事后无据可查；
3. RJ 日结单上没有商品收发存数据。

本补充在**不改变封单守卫与 7 步向导结构**的前提下，补齐第 4 类定版：商品收发存定版日余额（粒度日+商品+仓，不到批次），并延伸出商品日结台账与 RJ 商品区。

## 二、口径（全部沿用既有权威口径，不新造）

1. **实物账口径**：归属日 = `inv_stock_ledger.occurred_at` 的日期，取数通道是 V117 的 `v_rpt_stock_move` → `rpt_dws_stock_move_d`（已做反审核/作废回库红字行，物理方向轧差）。
2. **单据类型分类与报表 #8《商品进销存汇总表》完全一致**（`InventoryRollSummaryDefinition`），避免同一系统两套分类：

   | 定版列前缀 | bill_type_code | 业务含义 |
   |---|---|---|
   | `purchase_in_*` | CGRK、WMS_INBOUND | 采购入库（含 WMS 桥接） |
   | `sales_return_in_*` | THRK | 销售退货入库 |
   | `other_in_*` | QTRK、JSRK、PDD（IN 侧）、WMS_ADJUST_GAIN、OTHER | 其他入库（含客户拒收回库、**盘盈**、WMS 盘盈桥接、未识别前缀兜底） |
   | `transfer_in_*` | DBRK | 调入（仅影响本仓，公司合计与调出跨日可有在途差，正常） |
   | `sales_out_*` | XSCK | 销售出库 |
   | `purchase_return_out_*` | CTCK | 采购退货出库 |
   | `other_out_*` | QTCK、BSD、PDD（OUT 当日盘亏）、OTHER | 其他出库（含**报损**、盘亏） |
   | `transfer_out_*` | DBCK | 调出 |
   | `adjust_amount` | direction='成本调整' | 成本调整金额（数量不动，金额并入金额恒等式） |
   | —（不入选） | **CGSH 采购收货** | 采购收货审核只立应付，**不动物账**，数量与金额均排除，与 #8 一致 |

3. **两套口径并列，不互相替代**（Q1 终审采纳）：XSCK 是实物发出；销售确认口径是司机**签收**（`rpt_dws_sales_d`：signed_qty_base / signed_amount / signed_cost_amount / gross_profit）。已出库未签收构成两套账差异（在途），定版表把签收口径作为**业务账备注列**同期冻结，财务和业务各取所需，不做硬勾稽。
4. **成本**：商品+仓库移动加权平均（系统既有口径，`inv_stock_balance.stock_amount` / cost_price 6 位小数；批次不独立计价）。
5. **精度**：数量 DECIMAL(18,4)（对齐 DWS 18,4）；金额 DECIMAL(18,2)；成本单价 DECIMAL(18,6)。
6. **行集合**：前日有定版行、或当日任一类收发存在、或日终实存 ≠ 0 的「商品+仓库」，满足其一即落一行；当日耗尽（期末 0）但有收发的必须落（否则历史断行）。
7. **连续性**：期初 = 前一已结日 `biz_close_goods_daily.ending_*`；首次日结没有前日定版行时期初 = 0，基线由向导第 1 步「期初入库单全部审核 + 期初已核对勾选」背书（期初库存走 QTRK 类其他入库流水，在首日收入中再现）。

## 三、表设计（V121 计划）

### 3.1 主表 `biz_close_goods_daily`（商品收发存定版日余额）

粒度：日 + 商品 + 仓库。主键 `(close_date, goods_code, warehouse)`。

| 字段 | 类型 | 含义 / 取数 |
|---|---|---|
| close_date | DATE NOT NULL | 日结日期 |
| goods_code | VARCHAR(50) NOT NULL | 商品编码（不可变维度） |
| warehouse | VARCHAR(100) NOT NULL | 仓库 |
| goods_name | VARCHAR(200) | 商品名称**快照**（结账时刻档案值，事后改名不动历史，同资金账户名快照规则） |
| spec | VARCHAR(200) | 规格快照 |
| barcode | VARCHAR(100) | 条码快照 |
| base_unit | VARCHAR(50) | 基本单位快照 |
| large_unit | VARCHAR(50) | 大件单位快照（无则空） |
| large_convert_qty | DECIMAL(18,4) | 大件换算率快照（件数 = 基本数 ÷ 此值，空/0 按 1） |
| brand_name | VARCHAR(100) | 品牌快照 |
| category_name | VARCHAR(100) | 分类快照 |
| storage_property | VARCHAR(50) | 温区快照 |
| **opening_qty** | DECIMAL(18,4) | 期初数量（前日定版期末；首日 0） |
| **opening_amount** | DECIMAL(18,2) | 期初成本金额 |
| purchase_in_qty / _amount | DECIMAL(18,4) / (18,2) | 采购入库 |
| sales_return_in_qty / _amount | 同上 | 销售退货入库 |
| other_in_qty / _amount | 同上 | 其他入库（拒收/盘盈/调整入库/OTHER） |
| transfer_in_qty / _amount | 同上 | 调入 |
| **in_qty / in_amount** | 同上 | 收入小计（四类 IN 合计；金额含成本调整前口径，见下） |
| **adjust_amount** | DECIMAL(18,2) | 当日成本调整金额（direction='成本调整'，可正可负） |
| sales_out_qty / _amount | 数量/金额 | 销售出库 |
| purchase_return_out_qty / _amount | | 采购退货出库 |
| other_out_qty / _amount | | 其他出库（报损/盘亏/OTHER） |
| transfer_out_qty / _amount | | 调出 |
| **out_qty / out_amount** | | 发出小计（四类 OUT 合计） |
| signed_qty | DECIMAL(18,4) | 【业务账】当日签收基本数量（Σ `rpt_dws_sales_d.signed_qty_base` − 退货，Q1 同期冻结） |
| signed_amount | DECIMAL(18,2) | 【业务账】签收含税净额（Σsigned_amount − Σreturn_amount） |
| signed_cost_amount | DECIMAL(18,2) | 【业务账】签收成本净额（−退货成本） |
| gross_profit | DECIMAL(18,2) | 【业务账】毛利 = signed_amount − signed_cost_amount（同 sales DWS 口径） |
| **ending_qty** | DECIMAL(18,4) | 期末数量（结账时刻 `inv_stock_balance` Σphysical_qty，批次合计） |
| **ending_amount** | DECIMAL(18,2) | 期末成本金额（Σstock_amount） |
| ending_cost_price | DECIMAL(18,6) | 期末移动加权单位成本快照（= ending_amount ÷ ending_qty，量 0 置空） |
| qty_diff | DECIMAL(18,4) | 勾稽差异：期初+收入−发出−期末（容差内置 0），来自第 5 步 per 商品+仓结果 |
| amount_diff | DECIMAL(18,2) | 金额差异：期初+收入金额+调整−发出金额−期末（容差 0.01） |
| tie_flag | CHAR(1) DEFAULT 'Y' | 勾稽标志：INSERT 后事务内 COUNT 超差行，>0 直接抛中文异常回滚整笔结账，**任何已提交行恒为 Y**；列保留是为直查与未来放宽预留 |
| negative_flag | CHAR(1) DEFAULT 'N' | 日终负库存标志（ending_qty < 0 即 Y；与向导第 3 步负库存清单同源，事后可查） |
| frozen_time | TIMESTAMP | 定版生成时刻（即 close_time；同主记录，冗余便于直查） |

索引：

```sql
PRIMARY KEY (close_date, goods_code, warehouse)
-- 商品维度区间查（商品日报/台账页主要访问路径）
CREATE INDEX IF NOT EXISTS idx_biz_close_goods_goods
    ON biz_close_goods_daily(goods_code, close_date);
-- 仓库数据范围查
CREATE INDEX IF NOT EXISTS idx_biz_close_goods_wh
    ON biz_close_goods_daily(warehouse, close_date);
```

恒等式（生成时在事务内断言，不等即结账失败，与第 5 步硬门同源）：

```
ending_qty    = opening_qty    + in_qty    − out_qty                     （数量容差 0.001）
ending_amount = opening_amount + in_amount + adjust_amount − out_amount  （金额容差 0.01）
```

与主表合计的闭环：`Σin_amount` 必须等于 `biz_day_close.stock_in_amount`、`Σout_amount` 等于 `stock_out_amount`（生成后断言，防止两套聚合口径漂移）。

### 3.2 评审未采纳项：批次日终定版表

Q2 终审**不做**批次级定版（不建 `biz_close_goods_batch_daily`）：定版粒度只到日 + 商品 + 仓。批次/效期追溯继续依赖批次实时库存与库存台账（报表 #9），如未来有日终批次冻结的硬性合规需求，另立小版本，届时再评估 `(close_date, goods_code, warehouse, batch_no)` 直抄方案与「批次合计 = 主表期末」断言。

## 四、生成与反结逻辑

### 4.1 结账事务内生成（`BizGoodsCloseSnapshotService`，dayclose 包）

顺序固定在 `performClose` 现有链路中：**第 4 步 DWS 已刷新、第 5 步四套勾稽全部通过之后**，与应收/应付/资金定版同一段事务：

0. **先同步刷新商品维度**：调 `ReportDimGoodsService.refreshAll()`（同事务 REQUIRED）。`rpt_dim_goods` 平时靠启动/30 分钟任务刷新，全新库首次日结可能从未跑过；定版不能依赖 ETL 时机，结账时刻自刷一次（含单位换算率维度），失败随结账一起回滚；
1. 键集：前日定版全部键 ∪ 当日 `rpt_dws_stock_move_d` 键 ∪ 日终 `inv_stock_balance` 键（UNION，与 #8 键集写法同构）；
2. 期初：左联前日 `biz_close_goods_daily` 取 ending_*，无行给 0（首日基线）；
3. 当日收发：按 §二.2 的 CASE 映射从 `rpt_dws_stock_move_d` 透视（SQL 直接复用 #8 的透视片段，仅把区间参数换成单日；in_amount 排除 CGSH）；
4. 期末：`inv_stock_balance` 按商品+仓 GROUP BY 取 Σphysical_qty / Σstock_amount，单位成本 = 金额/数量（6 位，HALF_UP）；
5. 签收四列（Q1 同期）：`rpt_dws_sales_d` 当日按商品+仓 GROUP BY，签收 − 退货净额；
6. 档案快照：LEFT JOIN 刚刷新的 `rpt_dim_goods`（V114 后已含 barcode、storage_property；large_unit/large_convert_qty 同表），名称取不到依次回落 `inv_stock_balance` / DWS 流水 goods_name；手输商品（档案不存在）档案列留空、名称仍可兜底；
7. `DELETE WHERE close_date=?` 后批量 INSERT（幂等），再在事务内 `COUNT(*)` 超差行（数量 0.001 / 金额 0.01），>0 抛中文异常回滚；随后与主表 stock_in/out_amount 做总额闭环断言（容差 0.01）；
8. `frozen_time` = CURRENT_TIMESTAMP。

（封单日重复 close 走现有 idempotent 路径直接返回，不重建定版。）

### 4.2 第 5 步勾稽的期初来源切换

`tieStock` 目前期初读 `inv_stock_daily_snapshot`（D-1）。V121 起：

- D-1 有 `biz_close_goods_daily` 行 → **期初取定版 ending**（更强：定版反结即删、重算不可改，快照是分析表可重建）；
- 无定版行（首次日结、或功能上线前历史日期）→ 维持现逻辑回落快照/0。

`inv_stock_daily_snapshot` 保留不动，仍是报表 #6/#7 的缺货/周转依据（在途、7/30 日动销等预测列继续由报表快照任务夜跑），封单日期的快照重建仍受现有 `assertRangeOpen` 守卫保护。两张表分工：**快照服务分析预测，定版服务台账与责任认定**。

### 4.3 反结联动

`performReopen` 现有 DELETE 链增加一条（Q2 不做批次表，故只有一条）：

```
DELETE FROM biz_close_goods_daily WHERE close_date = ?;
```

顺序在三张往来资金表之后、库存分析快照与主记录之前。反结后 DWS 与快照恢复可刷新（既有守卫），改单重结时按 4.1 重新生成。跨已月结期间硬拒、原因 ≥2 字、日志链等规则不变。

## 八、风险与取舍

1. **数据量**：商品数千 × 仓库数个 × 每日有动作键集约 <1 万行/日，年量级百万级，两个索引足够；不做分区/归档（H2/MySQL 双跑，不加专有语法）。
2. **调拨跨日在途**：调出日与调入日不在同一天时，公司层合计当日不平是正常的（在途），只做商品+仓恒等式，**不做**公司层调入=调出硬校验。
3. **两套销售口径**：XSCK 实物与签收并列冻结但不互校（已出库未签收是业务在途，本就允许）；前端明确标「实物发出 / 签收确认」。
4. **首日基线**：期初 0 + 当日全部历史流水重放不现实，因此首日期初只认「期初入库单已审核」背书，期初库存体现在首日 QTRK 收入里——与 PRD-33 v1.3 第 1 步既有设计一致，不引入新动作。
5. **依赖顺序**：本分支基于 PRD-33 squash（ca15436），PRD-33 必须先 ff-only 合入 main；V120 已落地后 V121 才能跑。
