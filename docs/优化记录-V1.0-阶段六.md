## 一、采购退货全流程（V23-V27）

### 1.1 数据库

**3 张主表 + 3 张明细表**（V23），后续扩展到 V24/V27：

| 表 | 说明 |
|---|------|
| `pur_return_apply` | 退货申请头，状态 DRAFT→PENDING→APPROVED→OUTBOUNDED→COMPLETED |
| `pur_return_apply_detail` | 明细含 `return_mode`（BY_BILL/BY_GOODS）、`source_inbound_no`、`source_detail_id`、`batch_no`、`production_date`、`cost_price` |
| `pur_return_outbound` | 退货出库头（WMS指令），申请审核后**自动生成**，`source_apply_no` 唯一 |
| `pur_return_outbound_detail` | 出库明细，`apply_detail_id` 与申请行一一对应（V27） |
| `pur_return` | 采购退货单头，出库审核后**自动生成** |
| `pur_return_detail` | 退货单明细，按 goods_code 聚合出库 |

### 1.2 后端

**PurchaseReturnController** (`/purchase`)

核心端点：
- `POST /return-apply/create` — 双入口：按单退货（关联入库单行）+ 按品退货（手工添加）
- `POST /return-apply/audit` — 审核申请 → 自动生成 `pur_return_outbound`（幂等）
- `POST /return-outbound/audit` — 审核出库 → `InventoryCostService.salesOutbound()` 扣库存 + 写流水 → 自动生成 `pur_return`
- `POST /return/audit` — 审核退货单 → 写**负向** `fin_ap`（`ap_amount` 为负数，`source_bill` 存退货单号）
- `POST /return/reverse-audit` — 删除负向 fin_ap

查询端点：
- `GET /return-apply/from-receipt` → `GET /return-apply/inbound-bills` + `inbound-detail`（来源改为采购入库单）
- `GET /return-apply/goods-options` — 三页签（历史采购/供应商商品/全部商品）
- `GET /return-apply/batch-options` — 有库存批次下拉

### 1.3 前端

**3 个抽屉组件**：
- `PurchaseReturnApplyDrawer.vue` — 双入口加商品：按单添加（`PurchaseInboundPickerDialog` 左右表选择入库明细）+ 添加商品（`PurchaseReturnGoodsPickerDialog` 三页签选商品），按 `returnMode` 差异化可编辑性
- `PurchaseReturnOutboundDrawer.vue` — 支持拆批次出库，`apply_detail_id` 一一对应，出库合计 ≤ 申请数量
- `PurchaseReturnDrawer.vue` — 只读查看 + 审核/反审核

### 1.4 已退数量口径

按 `source_detail_id` 汇总所有**未作废**退货申请明细（含 DRAFT/PENDING 草稿），避免多人同时建单超退。

## 二、税额价内税改造（采购收货单 + 采购退货单）

### 2.1 口径变更

| 项目 | 改前 | 改后 |
|------|------|------|
| 商品金额 | 标签误导"不含税" | **含税金额**（单价即含税单价） |
| 税额公式 | 金额 × 税率（价外税） | **价内税倒算**：含税 × 税率 ÷ (1+税率) |
| 最终金额 | 商品金额 + 税额 | 改为**不含税金额** = 商品金额 − 税额 |
| 应付(fin_ap) | 按 final_amount | 按 **goods_amount（含税）** |

### 2.2 验证

例：含税 ¥400、税率 13% → 税额 400×13/113=¥46.02、不含税 ¥353.98
验算：353.98 × 1.13 = 400.00 ✓

### 2.3 影响文件

- `PurchaseReceiptController.java` — `generateFromInbound` 税额 + `auditReceipt` 应付金额 + 新增 `update`/`syncPriceToInbound`/`adjustStockCost`
- `PurchaseReturnController.java` — `generateReturnFromOutbound` 税额 + `auditReturn` 应付金额

## 三、采购收货单改价级联

### 3.1 功能

未审核收货单可改**单价**（数量、税率不开放），改价只落在收货单上。**审核时**级联：

1. 回写来源入库单 `pur_inbound_detail.price/amount/after_cost`
2. 按差额重算 `inv_batch_stock` 批次成本
3. 按比例调整 `inv_stock_balance` 成本单价与库存金额
4. 写一条「成本调整」库存流水（方向=成本调整，qty=0）
5. 同步 `base_goods.latest_purchase_price`

### 3.2 改价抽屉

新增 `PurchaseReceiptDrawer.vue` — 未审核可取价，单价/金额互算（4位小数），改动行黄底+原价划线对比。

## 五、商品综合调价单（V36，新模块）

### 5.1 与原价格组调价单的关系

**完全独立**的两套表、控制器和页面，互不干扰。

### 5.2 数据库

| 表 | 说明 |
|---|------|
| `base_goods_price_adjust_order` | 头：无 `price_group_code`，有 `goods_code` / `goods_locked` |
| `base_goods_price_adjust_order_item` | 明细行=商品×单位级别，含 4 种价格(old/new) + `price_group_prices` JSON |

### 5.3 后端

**GoodsPriceAdjustController** (`/base`)

- `POST /goods-price-adjust/save` — 保存草稿（支持 goodsLocked）
- `POST /goods-price-adjust/submit` — 提交审核
- `POST /goods-price-adjust/approve` — 审核 → 写回 unit_config + `base_price_group_item` + 日志
- `POST /goods-price-adjust/confirm` — **快速调价一键确认**：保存+提交+审核一步完成
- `POST /goods-price-adjust/reject` / `delete` — 驳回/删除

### 5.4 前端

**GoodsPriceAdjustDrawer** — 多价格矩阵：
- 行 = 商品 × 启用的单位级别（1-3）
- 列 = 标准售价/参考进价/最低价/建议零售价（原价→新价）+ 动态价格组列
- 快速调价模式：仅「关闭」+「确定」，确认弹窗后一键保存审核
- 普通模式：完整状态流转按钮
- 商品选择窗：1000px 宽，商品编号/名称/规格/小单位/小条码/标准售价/品牌/分类/存储属性，品牌/分类/存储属性下拉筛选

### 5.5 快速调价入口

商品档案编辑 → 多单位矩阵【快速调价】→ `POST /goods-price-adjust/save`（`goodsLocked=true`, `items=[]`）→ 打开 `GoodsPriceAdjustDrawer` → 自动预填明细（按商品 unit_config + 价格组现价）
