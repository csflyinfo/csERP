# 技术架构草案

## 一、推荐技术栈

> 当前为开发启动草案，后续可按团队技术偏好调整。

### 前端

- 框架：Vue 3 + TypeScript 或 React + TypeScript
- UI：企业后台组件库 + 自定义业务组件
- 状态：Pinia/Zustand/Redux Toolkit
- 路由：前端动态路由，按后端菜单权限生成
- 表格：支持列配置、固定列、合计、导出、虚拟滚动预留

### 后端

- 框架：Java Spring Boot / Node.js NestJS 二选一
- 架构：单体模块化优先，后续可拆服务
- ORM：MyBatis Plus / Prisma / TypeORM 按技术栈选择
- 认证：JWT + Refresh Token 或 Session
- 权限：RBAC + 数据范围 + 字段权限

### 数据库

- 主库：MySQL 8.x
- 缓存：Redis，先用于会话、字典缓存、编号生成锁
- 文件：本地文件服务或对象存储，支持导入导出文件留档

## 二、模块边界

| 模块 | 说明 |
|---|---|
| system | 用户、权限、菜单、参数、编号、日志、导入导出 |
| base | 商品、客户、供应商、仓库、单位、价格、资金、费用 |
| inventory | 库存余额、流水、锁定、批次、成本 |
| purchase | 采购订单、入库、收货、费用、发票 |
| sales | 快速开单、销售订单、出库、收货、发票 |
| finance | 应收、应付、收款、付款、核销、资金流水 |
| report | 经营概览、销售、采购、库存、财务报表 |

## 三、核心架构原则

1. 保存草稿不产生业务影响。
2. 审核动作必须在事务内完成业务影响。
3. 库存、成本、应收、应付、资金都必须记录流水。
4. 单据明细保存业务快照，不依赖基础资料实时名称。
5. 字段权限在后端兜底，前端只做展示控制。
6. 导入先校验再入库，失败行可下载。
7. 导出大数据异步进入导出中心。
