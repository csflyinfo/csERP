# 测试策略

## 一、测试层级

| 层级 | 说明 |
|---|---|
| 单元测试 | 核心计算、状态流、价格匹配、库存成本 |
| 接口测试 | API 入参校验、权限、状态限制 |
| 集成测试 | 采购、销售、库存、财务链路 |
| UI测试 | 表单、列表、弹窗、抽屉、单据页 |
| 验收测试 | 按 PRD 验收用例执行 |

## 二、核心测试原则

1. 审核才产生业务影响。
2. 所有余额变化必须有流水。
3. 权限字段后端必须兜底。
4. 导入失败必须有失败原因。
5. 历史单据快照不能被基础资料修改影响。

## 三、Sprint 1 测试重点

- 登录成功/失败。
- 用户停用后不可登录。
- 权限组停用后用户不可继续使用权限。
- 菜单按权限展示。
- 系统参数可修改并记录日志。
- 商品分类新增：先选上级分类，分类编号两位，状态默认正常。
- 单位、品牌、仓库新增编辑可用。
